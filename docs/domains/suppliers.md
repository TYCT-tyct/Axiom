# 供应商

怎么把官方 API、中转站、号池接进来，读懂它们的余额、分组、价格和用量，并在调用时挑选凭证、发出请求。中转站与号池各系统的规则见[中转站与号池](suppliers-relay.md)，直连和云平台见[直连接口与云平台](suppliers-direct.md)。对应代码模块 `suppliers`，公开接口和不变量见[模块 README](../../internal/suppliers/README.md)。概念之间的关系见[术语与核心概念](../glossary.md)，成本计划和对账的钱见[计费](billing.md#供应商成本)。调研和被否决方案的推导在[存档](../archive/suppliers.md)。

## 要求

- 三类供应商通过同一套接口接入（见[产品需求的「供给侧」](../product.md#供给侧)）。
- 中转站多数基于 new-api、sub2api，约一成是自研系统；我们通常只有普通用户账号。
- 自研系统先看能不能用声明式适配器接；不能的单独写 Go 适配器。以后不再接入的，适配可以干净地移除。
- 号池一般是自建的 sub2api、new-api、CPA 等系统；除非必要，不自己写号池模块，但要预留。
- 官方 API：OpenAI、Anthropic、Google、DeepSeek、Kimi 等厂商和其他兼容接口贴 key 直连，Vertex AI、Bedrock、Azure OpenAI 贴凭证接入，都是第一版的平台货源（[产品需求的「范围」](../product.md#范围)）。规则见[直连接口与云平台](suppliers-direct.md)。账户自带 key（BYOK）用同一个 OpenAI 适配，只服务账户自己的 key（见[账户](accounts.md#自带的供应商-keybyok)）。
- 接入、同步、变化处理尽量自动，人只处理例外。

## 设计

### 适配器：管理面和调用面

| | 管理面 | 调用面 |
|---|---|---|
| 做什么 | 登录、读余额、读分组和价格并生成成本计划、读模型列表、读逐笔扣费记录、读和建 key | 用哪种协议发请求、鉴权方式、路径、把失败归类、取对账键 |
| 由什么决定 | 对方运行的系统 | 对方支持的协议；一个中转站通常支持好几种 |

- **两者独立组合**：一个管理面可以搭配多种调用协议。
- **能力声明**：适配器声明能否查逐笔记录、能否建 key、能否流式调用、是否把客户端断开传到上游，以及各接口的限速桶。查不到逐笔记录的供应商标为高风险；不能流式或不传递取消的端点在准入时一次预留足（见[计费](billing.md#预留与结算)）。是否传递取消只是默认值，按端点实测的覆盖它（见[计费的「客户端断开」](billing.md#客户端断开)）。
- **对账键**：调用面从上游响应头取出对方的请求号，记在尝试上，对账凭它对上逐笔扣费记录。这些头不返回给客户端（见[接入的「转发规则」](gateway.md#转发规则)）。结算时与账本同成同败地一次写入（见[模块 README 的「没有对账日志」](../../internal/suppliers/README.md#没有对账日志)）。
- **失败不带对方的文字**：适配器把非 2xx 归成固定的原因、作用范围（请求、出口、凭证、端点、分组、供应商）和执行状态；原因只带数字和时间。执行状态没把握时是"可能执行了"，成本按估算记、由对账补正；只有对方在执行前就拒绝的才是"未执行"，5xx 不论带什么错误码都不是。
- **出站**：适配器的每个请求都经统一出站客户端（见[安全基线](../security.md#安全基线)），只发往接入时的 origin，路径必须以单个 `/` 开头，响应正文上限 8 MiB。请求先占声明的全部限速桶，任一桶没有名额就不发、推迟而不是失败；429 把所占的桶封到 `Retry-After`。管理面的桶记在数据库里，所有节点共用：按 IP 的桶以 origin 加出口为键，同一站点的供应商共用；按账号的以供应商为键。调用面不走这些桶，不暗中重试 POST。

### 三档适配器

| 档 | 用于 | 怎么加 |
|---|---|---|
| 内置适配器 | 常见系统和官方 API | 写代码 |
| 声明式适配器 | 自研中转站中只是接口路径和字段名不同的那些 | 在部署目录加一份 JSON 声明，重启节点，不改代码 |
| 浏览器自动化 | 前两档做不到的事 | 运营 agent 操作网页 |

现有的内置适配器：

- **普通用户身份**：new-api 1.0（个人访问令牌；更早的版本和 one-api 识别时拒绝）、sub2api（邮箱密码或令牌，加刷新令牌）。
- **管理员身份，用于自建号池**：sub2api 管理接口、CPA（CLIProxyAPI，Go 适配器加常驻采集器），见[中转站与号池的「号池」](suppliers-relay.md#号池)和[「CPA」](suppliers-relay.md#cpacliproxyapi)。
- **官方 API（直连接口）**：只说 OpenAI 格式的厂商是 `vendors` 包里厂商表的行，Anthropic 和人填地址的兼容接口各一个包，共用 `direct` 包；OpenAI 那一行也服务账户自带的 key。三种主流协议的调用面同时是转换和检测的基准。云平台 Vertex AI、Bedrock、Azure OpenAI 共用 `cloud` 包。类型怎么描述见[直连接口与云平台的「渠道类型」](suppliers-direct.md#渠道类型)。

### 声明式适配器

自研中转站中只是路径和字段名不同的，用部署目录里的 JSON 声明接入，启动时编译成与内置适配器相同的接口。声明的格式、校验、部署与移除见[中转站与号池的「声明式适配器」](suppliers-relay.md#声明式适配器)。

### 代码组织：适配器可以干净地移除

- 每个适配器是 `suppliers` 内部的独立包，带录制样本和契约测试；其他模块在编译层面引用不到（见[总体架构的「AI 好写好维护」](../architecture.md#ai-好写好维护)）。
- 注册表一个内置适配器包一行（厂商表的包整体一行，表里删一行即删一个类型）。移除一个内置适配器只删它的目录和那一行；`just adapters-removable` 对每一行验证这一点。声明式的移除见[中转站与号池的「声明式适配器」](suppliers-relay.md#声明式适配器)。
- 适配器识别对方系统的版本并按版本选接口，不到处写特殊判断。
- **对真实系统实测**：`just relays` 用按摘要钉住的官方镜像（new-api v1.0.0-rc.51，sub2api 0.2.25 加它的 Postgres、Redis）起站点，只经它们自己的接口配置，跑两个适配器的识别、登录、余额、分组、模型、价格、key、扣费记录和对账键，并核对扣费与对方日志一致；`AXIOM_RECORD_TESTDATA=1` 时重录带版本后缀的样本。它不在 `check` 里；连不到本机的假上游时设 `AXIOM_TEST_HOST_NETWORK=1`。换镜像版本前先跑它、逐条看样本变化。

### 接入方式逐级兜底

1. 账号密码登录，调接口；
2. 遇到人机验证，由人登录一次，之后用刷新令牌或个人访问令牌保持登录；
3. 只用 API key 能访问的接口，例如 OpenAI 兼容的余额接口；
4. 浏览器自动化兜底，由运营 agent 操作。

### 接入流程

1. **填写网址和账号**：origin 规范成 `https://主机[:端口]`（小写，端口 1 到 65535、去前导零，443 省略），同一站点不会因写法不同成为两个供应商。探测和之后的一切访问都经出站客户端，拒绝内网、回环地址。能用令牌就不存密码，登录一律加密存储。名称由页面从网址生成、可改；结算币种由人选一次。同一 origin 和账号只能接入一次，地址和账号之后不能改。地址检查只在真正执行改动的那次请求里做，同一幂等键的重发直接得到第一次的响应，不再问网络。
2. **识别系统并选适配器**：按注册顺序问每个能接入的适配器，最多 45 秒；站点要人机验证时只列不需要密码的登录字段。识别只读公开接口，不存任何东西；认不出不是错误。
3. **读分组、模型和价格**：同步读出后算成本计划。从未被人选过的分组（`codename IS NULL`）只要有一个模型映射到上架目录模型、有调用格式且有成本计划，就被自动选中并得到代号；人选过（包括取消）的分组保持人的选择。代号是 `g` 加 8 个 base32 字符，第一次选中时随机生成，之后不变。
4. **自动建 key**：适配器能建 key 时（new-api、sub2api），key 清单读完一轮后，同步为每个可卖、没被人取消、还没有凭证、不在失败等待期的分组建一把专用 key。
   - **哪些分组**：适配器说它能用我们的 key 服务，或 sub2api 还没读出模型而 key 正是读模型的前提；订阅分组、按小时计价的分组不建。
   - **建什么**：不限额度、不过期、不限模型，名字是 `axiom-<供应商 ID 前 8 位>-<sha256(供应商 ID + 分组 ref) 前 8 位>`（23 个字符）。名字是标记：响应丢了或提交被栅栏挡下，下一轮完整清单按名字认领，不建第二把。
   - **原文**：按对方 ID 读出，在提交事务里用主密钥封存进 `credentials`，状态 `active`，并发 4、每分钟不限；明文不进状态、日志或接口。
   - **失败**：`not_permitted`（登录没有建或读 key 的权限）、`group_unavailable`（账号不能用这个分组）、`refused`（对方拒绝），按分组记、1 小时后重试，换登录清空；网络错误和 5xx 交给任务退避。建 key 和读原文都在事务外，失败不留半行。
   - **手动绑定是例外**：`BindKey` 把对方已有的 key 按 ID 绑到已选分组，状态 `binding`、没有密文；同步读出原文、封存并激活，模型清单等下一次完整清单，之前全拒。
5. **确认单位余额价值**：适配器读出提示值，人或运营 agent 确认 1 单位余额值多少结算币种（大于 0、至多 1000、至多 15 位小数）；只追加，币种与原生单位都匹配的最新一行生效，确认之前端点不进路由。换算见[计费的「供应商成本」](billing.md#供应商成本)。
6. **生成端点**：投影生成端点，进入检测队列（见[端点评估](quality.md)）。

### 管理操作

每个操作在调用方的平台范围事务里锁住供应商行、核对状态后再写，审计同事务写，带操作者和原因，不带登录、账号和邮箱。幂等键的指纹只含给了哪些登录字段，不含值；同一键换密钥重发得到第一次的结果。

- **状态**：`active`、`low_balance` 可暂停，`paused` 可恢复；`connecting`、`needs_attention` 只由同步改，移除后不能回头。已是目标状态时不动、不审计、不加配置代次。
- **换登录**：新登录封在原位置、版本加一，供应商回到 `connecting`、配置代次加一，同步状态在同一事务里复位（见「同步与变化」）。换登录就是恢复，没有单独的恢复操作。
- **移除**当场完成，一个事务：状态 `removed`、配置代次加一，删登录行，所有凭证的密文清空、标为 `erased`、行保留（成本行的外键指向它）；不等在途、不再读扣费记录。Axiom 不删对方那边的 key（包括自建的 `axiom-` key），要吊销的就是 `erased` 凭证上的 `upstream_key_ref`，审计只记个数（`keys_to_revoke_count`）。已移除的再移除不动；早先版本留下的 `removing` 再移除就完成它。排队的同步任务读到 `removed` 就结束。
- **分组**：`SelectGroup` 选用或取消，不能选用已不在清单里的分组，取消不受限。
- **凭证上限**：`SetLimits` 一起设并发（至少 1）和每分钟请求（1 到 100,000 或空，省略或 null 即清除）；值没变时不动、不审计；凭证已擦除或供应商已移除时拒绝。
- **端点**：`setSupplierEndpointEnabled` 启停端点，没变也审计；同步从不写这一列，停用的一直停着，各节点下一次重建快照生效；管理接口的启用同时重置端点熔断，运营工具 `endpoint_set_enabled` 不重置（见[端点评估](quality.md#三条摘除通道各归各的主人)）。`setSupplierEndpointQuantization` 记录或清除 OpenRouter 的 12 个量化级别之一，未记录是 NULL，不等于 `unknown`；路由按它匹配 `provider.quantizations`（见[接入的路由参数](gateway.md#路由参数)）。
- **确认基础价**：`confirmSupplierBasePrices` 按分组和上游名给对方不报价的模型定基础价（端点还没有也行），只对当时映射到的目录模型有效。价格按结算币种，默认目录官方价，除以现行单位价值向上取整成供应商单位，单位价值没确认的不收。目录任务当即提前，下一轮按基础价 × 分组倍率出计划、建端点；对方报了价总是优先，报了但表达不了的、乘倍率后超出单价上限的成本未知。`clearSupplierBasePrices` 取消，没读到模型的分组也一样；没有可取消的不审计。
- **接入分组**：`connectSupplierGroup` 在一个事务里选中没有凭证的分组并给它 key。`make` 先确认分组还在清单里、没有凭证，再经适配器的 `KeyMaker` 用同步给 key 起的名字建 key、读出文字：先建后查会在对方留下一把无限额、不到期、哪里都没存的 key。`paste` 先经适配器的 `KeyFinder` 找出对方列的那把 key，核对它在这个分组、状态正常（停用、过期、额度用尽的 422），并照对方清单存下它的模型限制和到期时间，下一次完整清单照常更新。凭证 `active`、并发 4、不设每分钟上限。对方的请求在幂等事务之外先发，重放直接回第一次的结果；事务里在锁下再查一次分组。
- **识别 key**：`identifySupplierKey` 问对方一段文字是哪把 key、在哪个分组，什么也不存，每会话每分钟 10 次。new-api 和 sub2api 实现 `KeyFinder`，都以文字整段相同为准，且文字和它的任何部分都不发给对方：两家的按文字搜索都把文字放在查询串里，会进对方的访问日志（new-api `middleware/logger.go`）。所以都翻同步用的那份 key 清单、在本地比：new-api 的清单把 key 遮成前四后四，遮法相同的是候选，读回候选的原文（关键限速桶）按常数时间比较，候选超过 5 个不算答案；sub2api 的清单直接给原文，逐页按常数时间比较。代价是 key 多的账号要翻多页（每页 100 个，至多 100 页）。CPA、声明式适配器 422。
- **贴 key**：`addSupplierKeys` 逐把处理：同一请求里重复的、对方的 ref 已经存过的是 `duplicate`；对方列在别的分组的、对方不列但检测能通过的（别的账号的 key）是 `wrong_group`；其余发一次检测，通过的才存，各成一条凭证（`source` 为 `pasted`，`hint` 是末四位），带上对方清单给的模型限制和到期时间。幂等指纹只含末四位。直连接口的 key 不带分组，见[直连接口与云平台](suppliers-direct.md)。
- **检测 key**：`GET /v1/models`，10 秒，对方不收费。2xx 通过；401 `credential_rejected`；403 适配器认出是 key 额度用尽为失败，否则 `not_permitted` 不可判定（可能是地区封锁）；429、5xx、超时、传输失败不可判定。存过的凭证：通过时 `rejected` 回到 `active`，401 改为 `rejected`，其余不改状态；结果写进凭证的 `checked_at` 等列并审计。`disabled`、`erased` 不检测。全部检测一次至多 200 条、8 条并发，与单条共用每会话每分钟 10 次。
- **停用与擦除**：`setSupplierCredentialEnabled` 关掉即 `disabled`，打开只把 `disabled` 改回 `active`，`rejected` 打开仍是 `rejected`；`removeSupplierCredential` 清空密文、标 `erased`，审计记要去对方吊销的 ref；`removeInvalidSupplierCredentials` 只擦此刻仍是 `rejected` 的。这几项提交后回答请求的节点当场重建端点快照和路由，其他节点在下一次 `Reload`（5 秒）。
- **同步记录**：`listSupplierSyncRuns` 读 `sync_events`，按版本成组、新的在前，分组的事件按 ref、模型的按 `ref/模型` 找回分组。`requestSupplierSync` 把未停止的任务提前到现在，不清退避、不清停止，只对 `connecting`、`active`、`low_balance` 的中转站；直连和云供应商没有同步（调度只扫中转站），请求是 409，免得页面显示同步成功、什么也没发生。
- **对账报告**：`getSupplierReconciliation` 按 UTC 天给当天尝试的估算合计（含检测）、当天扣费记录合计、对上、暂挂、按对账判定偏高偏低的笔数，和过了宽限仍没扣费的有键尝试数；差值按估算算基点，精确计算后四舍五入（远离零）。从没有扣费记录的供应商没有天。
- **测试端点**：`testSupplierEndpoint` 发一次真实生成，每会话每分钟 10 次，见[模块 README 的「用真实生成测试端点」](../../internal/suppliers/README.md#用真实生成测试端点)。
- **读**：调用方用 `Owners` 选读谁的供应商；运营接口只读平台的，管理后台读全部归属（含 BYOK）。`TopUpBasis` 给运营 agent 的充值提案读归属、状态、原生单位、结算币种和现行单位价值，不加锁，串行由运营的上限计数器负责（见 [operations 的「资金上限」](../../internal/operations/README.md#资金上限)）。

### 调用面

- **挑凭证**：`Acquire` 在本节点内存里挑负载最低的凭证（未冷却、未过期、并发位未满、账号这一分钟还有名额），对在途数做一次比较交换；拿不到返回 `ErrNoSlot`，gateway 跳过这个条目，最终回 429 `rate_limited`、`Retry-After: 1`。热路径不读库、不解密。路由冻结路线前用只读的 `Capacity` 做同一判断，满载时排队（见[路由的「容量感知」](routing.md#容量感知)）。
- **快照会过期**：端点来自每 5 秒一次的 `Reload` 快照。最后一次成功的 `Reload` 超过 30 秒，`Routable()` 返回 `ErrStale`，路由快照随后过期，节点约 1 分钟后对所有调用回 503 `overloaded`、`/readyz` 回 503，直到 `Reload` 成功；宁可整节点停路由，也不让期间被停用或移除的供应商无限期接流量。一家供应商的数据读不出来（key 打不开、缺适配器、成本计划或单位价值不合法）只让这一家离开本节点快照，记 `suppliers.unloadable` 日志和计数，不写库。
- **执行状态**：请求写完之前失败的是"未执行"（作用于出口）；写完后非 2xx 由适配器归类，断线、超时、5xx 是"可能执行了"。
- **冷却**：凭证被拒、额度用尽或被要求等待时，按适配器给的时间（没有就按配置）只在进程内歇着，到期重新参与挑选。端点熔断归[端点评估](quality.md#健康与熔断)。
- **余额不足**：作用于供应商的"余额不足"让这家的全部端点在本节点自动暂停，`Acquire` 返回 `ErrSupplierResting`。只有拒绝之后开始的正余额同步，或拒绝之后开始并完整成功的检测能恢复；零余额、失败或旧的同步、单纯等待都不能。暂停期间后台按供应商合并、每分钟至多一次提前请求余额同步，整轮数据库工作至多 5 秒，只提前余额任务、不动其他任务和退避。显式检测可以绕过这项暂停，quality 的自动恢复试探先查余额够不够；检测仍受凭证并发、RPM、到期和人工停用约束。
- **对方的拒绝话术**：拒绝请求本身的失败带上对方 `error` 对象的 `message`、`type`、`param`、`code`，去掉网址、本次凭证、对方域名及各级上级域名、形似凭证的串、请求号和 new-api/sub2api 的名字，`type` 只留 OpenAI、Anthropic 的通用取值，每项至多 2 KiB；流里的同类错误用同一份清洗。
- **请求头**：路径和鉴权只由调用格式定（Bearer，加 Anthropic 版本头）；gateway 白名单里的 `anthropic-beta`、`anthropic-version` 在默认值之上设置，凭证和内容类型不被客户端换掉，没写 `anthropic-version` 时补 `2023-06-01`。
- **计价**：回执带 `Acquire` 时快照里的成本计划、单位价值和它的行 id，一次尝试按它开始时的值计价，之后改的值只管之后的尝试；外币按路由冻结的汇率换算，精确相乘后向上取整一次。
- **价目行**（`getSupplierEndpointCost`）：在用的成本计划按服务等级、档位、计费项各一行。原生单价就是计价用的单价；结算币种单价是原生单价 × 单位价值，与 `Credits` 同一个乘法，只为契约的 15 位小数向上取整。每行的推导因子是计划随价格存下的乘数，按相乘的顺序，再加单位价值：new-api 公布的价按[「new-api」](suppliers-relay.md#new-api)的成本计划（倍率对方没给的按默认值写出），人确认的是基础价 × 分组倍率。因子乘出来向上取整到单价就是存下的原生单价（`Derivation.Check`，同步写入前核对，乘不出的不存）。带因子之前的计划和不给因子的适配器（CPA、声明式）没有因子。只按次收费、不含 token 计费项的端点给盈亏点：请求价按当前汇率换成站点币种，找最少的 token 数，使一次这么长的请求按近 24 小时各 token 计费项的用量比例分配（各项向下取整）后，售价按计费的同一算法（`Schedule.Cost`，含售价自己的按次价和长度落入的上下文档）收的钱不低于它；价格不一定随档位上升，更长的请求仍可能亏。没有流量时按全是输入算，偏保守；到 10¹⁰ token（单次用量上限）都覆盖不了时不给，售价没有 token 价、按次价又不够的也是。

### 供应商别名与待映射

上游名字按以下顺序映射到目录模型：

1. 查供应商别名：只在该供应商或分组内有效，同一写法在不同中转站可能指不同模型；`:free`、`:batch` 这类后缀也在这里映射。
2. 用目录的内部识别查公开和内部名字，归一化后匹配（见[模型目录的「名字解析」](catalog.md#名字解析)）；不去掉日期，不同日期的版本不合并。映射到的模型必须已上架。
3. 仍对不上，由运营 agent 映射：`supplier_model_map` 只给分组列为待映射的名字建分组别名，且只映射到分组里还没有名字的模型（否则新名字会接管那个模型的端点），以 agent 的名义审计；纠正已有别名、建整个供应商的别名由负责人在管理接口做（见[运营接口](operations.md#运营接口)）。
4. 映射后由真伪检测确认（见[端点评估的「真伪检测」](quality.md#真伪检测)）：通过填 `Verified`，矛盾时清掉并告警。不带日期的名字只是候选，端点照常生成并接流量，但 `:exacto` 和只走已验证端点的路由预设不选它。判定假冒后自动下线、退回待映射仍未做。

- **待映射**：没有结果的名字留在 `supplier_models`（`model_id` 为空），不生成端点，按首次列出时间排队。
- **分堆**（`listSupplierModels`）：投影已映射的名字按模型状态分；没映射的先看别名（当前修订），再看目录含草稿的内部识别：上架的 `listed`、草稿 `known`、已下线 `outdated`。都认不出的，`ft:` 开头或去掉结尾日期后认得出（旧快照）是 `outdated`，其余 `review`，并按去掉中转站路径前缀或冒号后缀的写法给一个建议模型。分堆只读不写、不映射任何名字；各堆数量在 `getSupplier` 的 `model_counts`。
- **修订**：供应商范围别名只建一次；分组别名可追加从 1 起的不可变修订。不带 `rev` 是新建，已有即冲突；修订须带读到的 `rev`，不符返回 `stale_revision`，模型相同不新增版本。供应商行锁串行化修订，审计记前后模型。投影取最新修订，已取得的尝试保留原快照的模型和成本计划，历史端点和成本行不重写。
- **声明格式**：适配器推不出的调用格式（如 new-api 的 OpenAI 类型不区分旧补全）由映射接口的 `formats` 声明，省略不改、空数组清除、未知格式 422；投影与适配器的格式取并集。

### 凭证

- 加密存储（见[安全基线](../security.md#安全基线)）；刷新令牌时比较版本后再写。
- **模型与到期**：同步完整 key 清单时投影上游的模型允许清单和到期时间：NULL 不限，空数组全拒，按实际发给上游的名字匹配。模型在重建快照时过滤，到期在每次 `Acquire` 按受控时钟判断（到期瞬间不可选）。清单里没有的 key、明确换了组的 key 全拒，凭证和密文保留、不自动擦除或重建，由运营确认后删除或重新绑定；部分清单不改策略。
- **上限**：每个凭证有并发上限（新绑定 4）和每分钟请求上限（1 到 100,000，空为不限）。RPM 按上游账号计数：中转站的全部凭证和端点共用一个滚动 60 秒窗口（登录的是一个账号），各凭证拿自己的上限与账号计数比较；共享一份额度的 key 应设相同值，未设上限的 key 也计入账号。直连接口贴进来的每把 key 各是一个账号，窗口各算各的。同一账号下各 key 的并发之和应不超过上游账号并发，账号级并发准入未做。窗口与多节点份额见[模块 README 的「并发与速率」](../../internal/suppliers/README.md#并发与速率)。
- **状态**：`credentials.status` 筛可用凭证（`active`）；冷却只在进程内，`cooldown_until` 列没有代码写入。持久化的例外是 `rejected`：调用或检测中对方拒绝凭证（适配器归为 `CredentialRejected`，多是 401），凭证改为 `rejected`，直到检测通过；人工停用是 `disabled`。
- **负载**：管理接口给的在途数和这一分钟的请求数是回答请求的节点内存里的数，每个节点各数各的；多节点合计要等共享计数。
- **列表**：`listSupplierCredentials` 只列平台供应商的凭证，新的在前；`mode` 筛的是凭证所属供应商自己的接入方式（`suppliers.mode`）。
- **来源**：`source` 记 key 是同步建的（`made`）、人绑定的（`bound`）还是贴进来的（`pasted`）；这一列之前的行只有贴进来的认得出。
- **出口**：凭证可以经一个出口代理发出（见「出口代理」），`credentials.egress_id` 为空即直连。线路上各凭证的出口不一致时，更换云凭证回 409，不悄悄改成直连。

### 出口代理

官方接口拒绝国内来源、或者要固定出口 IP 时，凭证经平台的出口代理发出（`egress_proxies` 表，管理接口 `listEgressProxies` 等；部署见[总体架构的「部署拓扑」](../architecture.md#部署拓扑)）。

- **代理**：`http`、`https`（用 CONNECT 建隧道）或 `socks5`；主机和端口创建后不改，换地址就是另一个代理。用户名可选，密码信封加密、只写不读。代理地址由运营指定，可以在内网；经它访问的目标照样按出站策略检查，写成或在本地解析成私网、内部地址的被拒，代理收不到。
- **备用**：代理停用时它的凭证走备用代理。备用是另一个自己没有备用的代理，链只有一跳；代理和备用都不能用时凭证不被调用、也不检测，不改直连。还有未擦除的凭证在用、或是别人的备用的代理不能删。
- **生效**：节点每次 `Reload` 读代理行，每个代理一个出站客户端，行不变就沿用它的连接；建不出客户端（密码打不开）的代理让用它的整家供应商不进快照。调用、检测（`CheckDirect`、`CheckCloud`、`CheckCredential`）和每小时重读走同一个出口。新建直连或云平台时给的 `egress_id` 用在存下的每条凭证上；更换云凭证沿用这条线路现有凭证共同的出口；之后追加的 key 直连，在凭证上单独改（`setSupplierCredentialEgress`）。
- **失败**：经代理的传输失败算出口的（`ScopeEgress`），请求写完后断开也一样，执行状态仍是"可能执行了"。

### 自带的供应商 key

账户自带 key 是一行账户归属的供应商（需要 `AXIOM_BYOK=on`，默认关）：`owner_scope='account'`、`status='byok'`、`kind='openai'`、地址 `https://api.openai.com`，没有登录行，不参与同步。`CreateByok` 一个事务写齐的分组、端点、全零成本计划和凭证见[账户](accounts.md#自带的供应商-keybyok)；金额 1 的 `usd` 余额和值 1 的单位价值让路由条件成立而成本为 0。

- **上游名字**取目录里厂商的公开名（`catalog.Snapshot.OfficialName`，固定版本只取带日期的）；没有可确认名字的模型不建端点，以免按旧规格调用或猜出厂商不认的名字。
- **接口**：`CreateByok`、`ListByok`、`SetByokEnabled`、`RemoveByok`、`RevealByok`、`SetByokTestResult`，控制台处理器用账户范围的事务调用；列表、测试和被拒见[账户](accounts.md#自带的供应商-keybyok)。测试经出站客户端，不写成本、不占并发位。

### 同步与变化

每个供应商一份同步引擎，只做决定；状态整份读出、整份提交，每一步的事件、成本计划版本、扣费记录和投影与状态同一事务，持租约栅栏。

- **频率**：余额 1 分钟、目录（分组、模型、价格）5 分钟、key 清单 5 分钟、扣费记录 2 分钟，每个任务各提交一次；同步严格遵守适配器声明的限速，先用便宜的接口，一次能拿到的不分多次拿。普通账号被限流或封号会连带损失预付余额。
- **失败**：网络错误和 5xx 指数退避（1 分钟起、上限 30 分钟、带抖动），别的任务照跑，成功清零；桶不够不算失败，到时再来；响应认不出（成功响应缺必需成员也算，不当成空结果）只停这个任务、什么也不写、发事件。**登录被拒**停掉这个供应商的全部轮询，状态 `needs_attention` 并告警，适配器不再登录。
- **换登录唤醒**：`ReplaceLogin` 在同一事务里复位同步状态：失败、退避和停止清零，所有任务立即到期；余额、已读完的清单和扣费位置保留，已读过的记录不重读；版本和租约栅栏加一，握着旧登录的节点写不进任何东西。
- **清单接着读**：报价和 key 清单可能比一个限速窗口长。被限速时这次读到的位置随提交存下、任务当场结束，下一次（任何节点）接着读，不占工人、不从头读、不跳页；一页可能读两次，按 ID 去重。位置读不懂、上游清单在下面变了（key 变少、分组变了）、或配置代次变了，就整份从头读。没读完时路由看到的是上一份完整的清单。位置里没有凭证。
- **变化即事件**：目录规范化后与上次比较，只把差异写成 `sync_events`：分组和模型增减、倍率、分组事实、格式和能力、资金来源、新成本计划、余额越过 0 和告警线。同一份响应读两次没有新事件、新计划，投影的表一行不写。
- **投影**：分组写 `supplier_groups`，上游名字及其映射写 `supplier_models`，端点写 `endpoints`，成本计划只追加进 `cost_schedules`（按指纹一版一行）。路由和后台读这些行。
  - 只有映射到上架目录模型、接入规则收下、且有成本计划的名字才有端点；同一分组两个名字指向同一模型时，取名字带日期的，都不带取排序第一个。
  - 下架的分组和模型标为不存在而不删，端点改为"成本未知"退出路由；清单再出现时还是原来那些行。分组卖不了给我们（订阅、按小时计价）时同样处理。
  - 人的开关（`enabled`）、量化级别、首次列出时间和对账写的"估算偏低"同步都不改，有价格不同的新一版计划时才清掉后者；只换推导因子的新版照样换上，判定保留。`last_seen_at` 是分组最后一次被改动的时间，不是最后一次出现。
  - `Reload` 读到不认识的格式只跳过那一个端点（`suppliers.unsupported_format`），不摘整家供应商。
- **可路由**：供应商 `active` 或 `low_balance`、余额大于 0（没读到过的也不行，新接入的在第一次余额同步前约 1 分钟不可路由，节点报 not ready 是预期的；不读余额的接入方式——直连、云平台——不看这一条，`Funds.Unbounded`）、单位价值已确认、分组选中、端点启用且成本已知、至少一个 `active` 有密文且模型匹配的凭证。按请求的完整生成成本上界过滤余额见[路由](routing.md#决策与理由)。余额低于告警线发一次 `BalanceLow`，回升后才再发；据此降权尚未接入。由运营 agent 补充值，受资金上限约束。
- **资金来源**：一笔不是从钱包扣的扣费记录（订阅）让供应商停为 `needs_attention`（`funding_not_wallet`）。new-api 没写 `billing_source` 的记录，账号没有生效订阅时算钱包，有就不是（见[中转站与号池的「决策与理由」](suppliers-relay.md#决策与理由)）。
- **调度**：每 15 秒扫一次到期且没人持租约的中转站（`mode='relay'`，`connecting`、`active`、`low_balance`），最久的先来，一次最多 200 个入队；每个供应商同时最多一个任务，失败不由队列重试，退避由引擎定。任务取到租约后先核对状态，已暂停、移除或需处理就直接结束。接不上的供应商（出口、适配器、origin 不可用）记为任务失败并退避，不挤占别人。租约 5 分钟，每次提交续期；一轮最多 50 页、一次任务最多 10 分钟；每节点同步队列 4 个工人。优雅停机时在跑的一轮最多等 `AXIOM_SHUTDOWN_TIMEOUT`，已提交的页保留；节点崩溃留下的任务运行满 15 分钟后被放弃，下一次扫描补上。
- **告警**：每分钟把登录失效、同步需处理、任务停止和低余额事件转成平台告警，每页 20 家、每家最多消费 1000 条，余下的跨分钟继续，消费位置与信号同事务。首次只上报当前未恢复的问题；信号只带内部标识和固定任务名，不带上游文字；登录和停止只在后续真正成功（版本更高、`LastOK` 变了）后恢复，换登录不算。同一消费者报告全平台货源耗尽 `suppliers.exhausted`，并每轮最多检查 100 家的 `suppliers.sources_unavailable`（N 家约 `ceil(N/100)+1` 分钟一圈）；暂停或移除不算恢复。规则见[告警设计](observability.md#告警信号事件与规则e5-3)。

### 接入规则

每个供应商一条 `intake_rules`，没有就是 `listed`：收已上架模型的名字，就是规则出现前的做法。`names` 只收与 `include` 之一整段匹配、且不匹配任何 `exclude` 的已上架模型名字（`*` 是任意一串，不分大小写）。`known` 还收草稿模型的名字：快照认不出的名字和别名指向的模型，在投影的事务里用目录含草稿的识别（`catalog.RecognizeIn`、`ModelsIn`，与分堆同一个来源）再查一次，只取草稿；端点照常生成，但网关只给已上架模型建路由条目，等模型过了上架门槛才被路由。不再收的名字仍记着映射，不进待映射；它的端点成本改为未知（原因是接入规则），规则再收时恢复。从没人选过的分组在规则收下它的一个有价名字时才自动选中，人的选择不改。投影每次提交读一次规则，改规则不加配置代次。规则只有同步的投影会用，直连和云供应商的模型在接入时来自 key 自己的清单，给它们设规则是 409。

### 待处理队列

`inbox_items` 每个供应商每个情况一条（种类加对象唯一），情况还在就留着，没了就删。同步每次读完整个报价（`OfferRead`）在同一个事务里观察一次全部种类：新出现的加进来，没了的删掉，内容变了的或被忽略后仍在的标为再次看到（`last_seen_at`），并清掉忽略；什么都没变一行不写。人的操作和调用路径开始或结束一个情况时（接入分组、检测、停用、擦除、调用中被拒）在同一事务里只删、只加，不算观察。

- `key_invalid`：凭证 `rejected`。调用路径标 `rejected` 时先锁供应商行、再改凭证，同一事务里写队列：直连和云供应商没有同步，等观察就永远不出现。每次检测也写一次队列，补上那次写入失败漏掉的。
- `group_added`：在清单里、没人选过（没有代号）也没选中的分组，带倍率。
- `unknown_model`：待映射的名字，一个分组一个名字一条。
- `ratio_changed`：选中分组近 7 天的倍率变化，取最新一次的前后值。
- `low_balance`：供应商 `low_balance`（余额低于告警线），带余额和按近 24 小时估算花费算的可用天数。
- `cost_mismatch`：近 7 个 UTC 天里，当天已对上的扣费合计与它们的估算合计相差超过估算的 1%（对账的相对容差）。
- `unlisted_model_called` 目前不产生：被拒的调用在调用日志里，本模块不读，也没有读它的模块接口（见「待定」）。契约保留这个种类，描述里写明它暂不出现，计数恒为 0。

忽略（`ignoreSupplierInboxItem`）只设 `ignored_at`；列表和计数不含被忽略的，下一次观察仍看到就再出现（目录任务默认 5 分钟一次）。

### 号池与各中转系统

号池的读数与反应，new-api、sub2api、CPA 各自的识别、登录、读取、成本计划、失败归类和扣费扫描见[中转站与号池](suppliers-relay.md)。

### 对账

- **入库**：同步把扣费记录写进 `charge_records`，按 `(supplier_id, charge_ref)` 唯一，读两次只存一次；保留每项数量、声明了哪些项、没有计费项的用量、等级和物理输入。
- **周期任务**：River leader 每分钟（启动和换主时也）投递一次，任何节点可执行；匹配、暂挂、摘牌、事件和下一页游标同一事务提交，重复执行不改归属、不重复加版本。不挂在同步后面，因为同步暂停时已有记录也要对账。
- **匹配**：只有一个尝试持有这个键时才对上，两个以上共用一个键都不对上；已暂挂或已人工归属的记录，尝试迟到时改归尝试。
- **判定**：只判估算完整的尝试，检测的尝试从不判。|实际 − 估算| ≤ 供应商取整（quota 1，美元 1e-10）+ 估算 × 1%。偏高且端点仍按这份估算计价时（同一版成本计划，或只换了推导因子、价格相同的新版），端点改为成本未知（`under_estimated`）退出路由；已换价格的不动，只记一次。偏低只报告。
- **暂挂**：过了宽限（30 分钟）没对上的扣费改为 `held`；有键的尝试过了宽限仍没有扣费，每个身份告警一次。人工经 `AssignToLostRequest`、`AssignUnattributed` 处理 `held` 记录，不按冻结路线猜用户。
- **有界**：每种语句每轮最多 20 批、每批 500 行，剩下的下一轮；等待的尝试按游标跨轮推进，最终都报告一次。
- **事件**：每次版本变化写一行 `charge_events`，billing 据此把暂估校正到供应商的用量（[暂估校正](../../internal/billing/README.md#暂估校正)）；检测的事件带 `test: true`，billing 跳过。差异按类计数并上报 `suppliers.reconciliation_difference`，具体对象记 `suppliers.reconcile.*` 日志。

## 决策与理由

中转站和号池适配器各自的决策见[中转站与号池的「决策与理由」](suppliers-relay.md#决策与理由)。

| 决策 | 理由 |
|---|---|
| 适配器分成管理面和调用面 | 对方运行的系统和支持的协议是两件独立的事，分开后自由组合 |
| 三档适配器 | 自研中转站大多只是路径和字段名不同，用配置就能接；配置做不到的才交给浏览器 |
| 基础价按分组和上游名、只对确认时的模型存，用单位价值换算；旧版 new-api、one-api 和 sub2api 的 TypeSafe、Gemini、Antigravity 分组暂不接 | 首次接入的模型还没有端点，改映射后旧价不该给新模型，各家单位不同；旧版对不了账（日志缺请求号或可关）、看不到倍率；TypeSafe 只接受 `/v1/systemone`，Gemini 分组漏报缓存 token、Chat 跳过混入的 Antigravity 账号 |
| 每个适配器独立成包，移除只删目录和一行 | 自研中转站的适配以后要能干净移除 |
| 别名和待映射归本模块，不进目录 | 上游名字只在该供应商内有意义；目录在依赖上位于本模块之下 |
| 接入只填网址、账号和单位价值，key 由同步自动建 | 产品要求添加供应商只填网址、账号并确认单位价值；确定性名字让响应丢失也不重复建 |
| 自动选中只碰 `codename IS NULL` 的分组 | 人的选择（包括取消）不被同步推翻 |
| 清单里消失的 key 只全拒，不自动擦除 | 清单短暂漏报不触发不可逆的销毁或换 key；擦除改变凭证销毁规则，要负责人批准 |
| 移除当场擦密文、保留凭证行，不删对方的 key | 密文留得越久越危险；成本行的外键要凭证行在；最后不到 2 分钟的扣费记录可能丢 |
| 地址和账号创建后不改；换登录、移除各是单独操作 | 凭证只发往原地址；高风险操作分开才能单独审批和审计 |
| 换登录就唤醒同步 | 多一步"恢复"会被忘掉，供应商看起来只是"需处理"却一直停着 |
| 分组别名用只追加修订 | 保留纠错历史；显式 `rev` 防止过期页面覆盖别人的选择 |
| 凭证模型限制在重建快照时过滤，到期在准入时判断 | 调用路径不读库、不扫清单；只在重建时判到期会漏掉快照期间的过期 |
| 单位价值按供应商存只追加表，回执带行 id | 它是余额的属性；复算按 id，不靠时间推断，旧账不动 |
| RPM 按上游账号共用、上限按凭证设、计数在节点内存 | 新增 key 不增加上游额度；调用路径只是一次比较交换和一次加锁计数 |
| 并发和有限 RPM 按存活核心静态分份额 | 守住调用路径预算；共享槽位每次调用多一次共享计数和清理 |
| 新绑定默认并发 4、每分钟不限 | 对方允许多少还不知道，并发保守；限流值猜错会拒掉能发的请求 |
| 快照 30 秒过期后整节点停路由 | 不往无法确认的端点发；一家读不出只摘那一家，不写全局状态 |
| 代理只做一跳的备用；代理和备用都不能用时凭证停下，不改直连 | 选代理就是因为直连不行或不允许，悄悄直连会从不该出现的 IP 发出请求；一跳不用判断链和环 |
| 经代理时先在本地按出站策略检查目标，再把主机名交给出口那端解析 | 理由和代价见[直连接口与云平台的「决策与理由」](suppliers-direct.md#决策与理由) |
| 限速桶放数据库 | 多节点共用一个出口时各自计数会超过对方的限速，被封的是预付账号 |
| 被限速时存下清单位置并结束任务 | 每节点只有 4 个工人，持租约等限速会堵住其他供应商 |
| BYOK 是 `status='byok'` 的账户供应商 | 复用加密、行级安全、容量、失败分类和路由，不另造一套（见[账户](accounts.md#自带的供应商-keybyok)） |
| 对账是独立周期任务 | 同步暂停、尝试迟到时已有记录也要核对；下一页游标不能只在某个 worker 内存里 |
| 贴 key 逐把检测，只存通过的；重复的和结果不明的不存，逐条回报 | 不知道能不能用的 key 进了路由，就要拿用户的请求去试；结果不明多半是限流或超时，重贴即可 |
| 凭证行的身份（凭证加区域的摘要）不变，换凭证是新行 | 成本行指向凭证行，换了 key 仍记在旧行会对错账 |
| 中转站接入分组（`connectSupplierGroup`）是「选中」加「给 key」一个事务：`make` 当场经适配器建 key，`paste` 先核对 key 属于这个分组 | 分两步时 key 被拒，分组会停在选中却没有 key；贴错分组的 key 会让成本按别的分组的倍率算 |
| 凭证状态加 `rejected`：供应商以 401 拒绝，检测通过才恢复；人工停用是 `disabled` | 与 BYOK 同一个状态；贴进来的 key 失效要看得见、能批量删；只在进程内冷却的话页面看不出 |
| 批量删除失效 key 只删请求列出、此刻仍是 `rejected` 的 | 只删人确认过的；页面打开期间检测通过的不会被误删 |
| 单把凭证的在途数和这一分钟的请求数取回答请求的节点内存里的值 | 计数本来只在节点内存（见「凭证」）；多节点合计要等 Valkey，页面写明是本节点的数 |
| 同步记录直接读 `sync_events`，按提交的版本成组；没有变化的同步不留记录，各任务最后成功的时间放在 `getSupplier` 的 `sync_tasks` | 事件本来就是与上一次的差异，不另存运行日志；空运行每分钟一条会淹没有用的记录 |
| 成本对账按 UTC 天给估算和供应商扣费记录两个合计，用供应商的原生单位，另给单位价值 | 是逐笔匹配那批数据的汇总；原生单位比较没有汇率误差，换成钱由页面乘单位价值 |
| 待处理队列是持久条目，条件消失即删；忽略只隐藏到下一次观察仍成立 | 负责人定的：忽略不是永久静音，问题还在就会再出现；条目持久才有稳定 ID 和首次出现时间。计数用 `getSupplierInboxSummary`，列表不带总数（[前端接口指南](../frontend-api.md#分页)） |
| 接入规则每个供应商一条、带修订号，默认 `listed` 就是现在写死的自动选择；`known` 也接草稿模型的名字，端点等模型上架才可路由 | 替换写死的选择而不改变已有供应商；修订号防两个页面互相覆盖；同步不替人上架模型，上架仍走目录的上架门槛 |
| 上游模型名的四堆（`review`、`listed`、`known`、`outdated`）由服务端按目录的识别和状态算，各堆数量放在 `getSupplier` | 分堆要目录的内部识别，前端做不到；与待映射同一个来源，`review` 就是这家的待映射 |
| 价目行给每个计费项的单价（原生单位和结算币种）和推导因子，不在接口里拼说明文字 | 因子是数据，页面按语言写出「模型倍率 × 分组倍率 × 单位价值」；服务端拼好的中文换了语言就不对 |
| 推导因子由适配器和确认的基础价给出，随计划只追加地存在 `sync_plans`、`cost_schedules` 的 `derivation`；有因子的计划指纹含因子，没有的仍只按价格算 | 读价目行时倒推倍率不唯一（2 × 1 和 1 × 2 一样），只能在算价时记下；没有因子的计划指纹不变，升级不给它们新版本，带因子的计划在下一次同步各出一个同价新版本，收费不变；对账的"估算偏低"跟着价格走，同价新版不解除，也照样被摘牌，因为因子只解释价格 |
| 按次收费上游的盈亏点按近 24 小时的输入输出比例算 | 按次买、按 token 卖，一次请求赚不赚只看它有多少 token，比例要用实测的 |
