# 供应商

怎么把官方 API、中转站、号池接进来，读懂它们的余额、分组、价格和用量，并在调用时挑选凭证、发出请求。对应代码模块 `suppliers`，公开接口和不变量见[模块 README](../../internal/suppliers/README.md)。概念之间的关系见[术语与核心概念](../glossary.md)，成本计划和对账的钱见[计费](billing.md#供应商成本)。调研和被否决方案的推导在[存档](../archive/suppliers.md)。

## 要求

- 三类供应商通过同一套接口接入（见[产品需求的「供给侧」](../product.md#供给侧)）。
- 中转站多数基于 new-api、sub2api，约一成是自研系统；我们通常只有普通用户账号。
- 自研系统先看能不能用声明式适配器接；不能的单独写 Go 适配器。以后不再接入的，适配可以干净地移除。
- 号池一般是自建的 sub2api、new-api、CPA 等系统；除非必要，不自己写号池模块，但要预留。
- 官方 API：实现主流的基础适配，暂不接入，只作预留；账户自带 key（BYOK）用的 OpenAI 官方适配是例外，它只服务账户自己的 key，不作为平台货源（见[账户](accounts.md#自带的供应商-keybyok)）。
- 接入、同步、变化处理尽量自动，人只处理例外。

## 设计

### 适配器：管理面和调用面

| | 管理面 | 调用面 |
|---|---|---|
| 做什么 | 登录、读余额、读分组和价格并生成成本计划、读模型列表、读逐笔扣费记录、读和建 key | 用哪种协议发请求、鉴权方式、路径、把失败归类、取对账键 |
| 由什么决定 | 对方运行的系统 | 对方支持的协议；一个中转站通常支持好几种 |

- **两者独立组合**：一个管理面可以搭配多种调用协议。
- **能力声明**：适配器声明能否查逐笔记录、能否建 key、能否流式调用、是否把客户端断开传到上游，以及各接口的限速桶。查不到逐笔记录的供应商标为高风险；不能流式或不传递取消的端点在准入时一次预留足（见[计费](billing.md#预留与结算)）。是否传递取消只是默认值，按端点实测的覆盖它（见[计费的「客户端断开」](billing.md#客户端断开)）。
- **对账键**：调用面从上游响应头取出对方的请求号，记在尝试上，对账凭它对上逐笔扣费记录。这些头不返回给客户端（见[接入的「转发规则」](gateway.md#转发规则)）。结算时这个请求全部尝试的成本和对账键在计费的结算事务里一次写入，与账本的供应商成本同成同败；请求进行中不另记（见[模块 README 的「没有对账日志」](../../internal/suppliers/README.md#没有对账日志)）。
- **失败不带对方的文字**：适配器把非 2xx 归成固定的原因、作用范围（请求、出口、凭证、端点、分组、供应商）和执行状态；原因只带数字和时间。执行状态没把握时是"可能执行了"，成本按估算记、由对账补正；只有对方在执行前就拒绝的才是"未执行"，5xx 不论带什么错误码都不是。
- **出站**：适配器的每个请求都经统一出站客户端（见[安全基线](../security.md#安全基线)），只发往接入时的 origin，路径必须以单个 `/` 开头，响应正文上限 8 MiB。请求先占声明的全部限速桶，任一桶没有名额就不发、推迟而不是失败；429 把所占的桶封到 `Retry-After`。管理面的桶记在数据库里，所有节点共用：按 IP 的桶以 origin 加出口为键，同一站点的供应商共用；按账号的以供应商为键。调用面不走这些桶，不暗中重试 POST。

### 三档适配器

| 档 | 用于 | 怎么加 |
|---|---|---|
| 内置适配器 | 常见系统和官方 API | 写代码 |
| 声明式适配器 | 自研中转站中只是接口路径和字段名不同的那些 | 在部署目录加一份 JSON 声明，重启节点，不改代码 |
| 浏览器自动化 | 前两档做不到的事 | 运营 agent 操作网页 |

现有的内置适配器：

- **普通用户身份**：new-api 1.0（个人访问令牌；0.13 只识别、不接入）、sub2api（邮箱密码或令牌，加刷新令牌）。
- **管理员身份，用于自建号池**：sub2api 管理接口、CPA（CLIProxyAPI，Go 适配器加常驻采集器），见「号池」和「CPA」。
- **官方 API**：OpenAI 适配器只服务账户自带的 key；Anthropic、Gemini 预留。三种主流协议的调用面同时是转换和检测的基准。

### 声明式适配器

声明是 `AXIOM_SUPPLIER_ADAPTERS` 指向的目录里的 JSON 文件。启动时注册表读取、校验并把每份编译成与内置适配器相同的接口，之后同步和调用都按同一套契约使用它。它只是固定操作的字段映射和少量开关，没有条件、循环、计算或任意 HTTP；需要这些就写 Go 适配器。

一份声明（`v: 1`）的部分：

| 部分 | 成员 | 内容 |
|---|---|---|
| 身份 | `kind`、`native_unit` | 稳定的小写种类，存进 `suppliers.kind`；余额的原生单位 `quota` 或 `usd` |
| 限速 | `buckets` | 每个接口组一个桶：按 IP 或账号、窗口、次数；必须有 `global`，操作不写桶时用它 |
| 登录与鉴权 | `auth.fields`、`auth.header`/`auth.query`、`auth.login` | 登录字段；令牌放哪个请求头或查询参数；登录的路径、请求体模板、令牌和过期字段 |
| 识别 | `detect` | 一个公开路径，和只有这个系统才有的响应头、版本、代次或人机验证标志 |
| 余额 | `account` | 余额、单位提示（或固定值）和资金来源字段 |
| 分组、模型、价格 | `offer.groups`、`offer.models`、`offer.prices`、`offer.formats` | 分组与倍率、每组的模型、每百万 token 价格及缩放、对方格式名到规范格式名的映射 |
| key | `keys.list`、`keys.secret`、`keys.create`、`keys.policy` | 分页清单、按对方 ID 读原文、按名字建 key、模型和到期限制 |
| 扣费 | `charges` | 按时间窗和页码读逐笔记录，映射请求号、key、时间、金额、模型、资金来源和 token 数 |
| 调用面 | `calls` | 格式、能否流式、是否传递取消、对账键响应头、状态码或错误码到固定原因和范围的映射 |

- **字段与模板**：字段位置是点分成员加数组下标（`data.items[0].key_id`），最多 16 步。路径模板只认操作允许的变量：登录 `{email}`、`{password}`，读原文 `{ref}`，读模型 `{group}`，分页 `{page}`、`{size}`，扣费 `{start}`、`{end}`、`{page}`、`{size}`（`charges.path` 必须带齐，起止是 Unix 秒）；页码从 1 起；`?` 之前按路径段转义、之后按查询值转义。金额按十进制字面量读，不经浮点、不接受指数；余额可以为负，扣费金额不行。时间接受 RFC3339 或 Unix 秒。`keys.create.body` 必须恰好有一个成员的值是 `{name}`；启用 `keys.create` 时 `keys.list` 必须能读回 `name` 和 `group`，否则响应丢了就认领不到、会重复建 key。
- **加载时校验**：未知成员、`v` 不是 1、`kind` 格式不对或重复（含与内置同名）、没有 `global` 桶、字段路径或模板变量不合法、路径不以单个 `/` 开头或含无效 `%` 转义、引用未声明的桶、原因/范围/执行状态不在固定表里、可能命中 5xx 的规则声称"未执行"、声明了 `detect.captcha` 却不接受 `access_token`，都让启动失败，错误带文件名。环境变量未设置表示没有声明；设置了但目录读不了是错误。随后 `CheckAdapters` 要求数据库里仍在用的每个 `kind` 都有适配器。
- **读管理面**：必需列表只接受 JSON 数组，`null`、对象和缺失都是"认不出"；有 `total` 的 key 清单提前空页或总数不符也报错，不清空已有 key、不推进位置。401/403 是登录被拒，429 是被限速（默认 1 分钟），5xx 是任务失败，其他 4xx 是认不出。
- **价格与格式**：价格先乘 `scale × 分组倍率`，向上取整到 10⁻¹⁵，再按平台单价上限（1000）校验，原始价超限而缩放后合法仍可读。分组没声明格式用 `calls.formats`，模型没声明用分组的；规范名本身总被接受。报价位置带声明指纹，声明（含 `scale`）一变就丢弃旧位置、重读分组和价格。
- **扣费扫描**：用模块共用的扫描（重叠 5 分钟、滞后 30 秒、初始 1 小时、最长 24 小时、每天补扫），页大小改变时从水位重开这一遍；保存的位置读不懂时只停这个任务。
- **调用面**：对账键只接受可打印 ASCII、最长 128 字符；错误规则先于通用默认生效，HTML 响应按出站拦截，未列出的 4xx 是未知，429 默认是限流。
- **探测**：多个适配器认出同一个站时按 `kind` 排序取第一个，所以声明不要模仿 new-api、sub2api 的通用状态接口。
- **登录**：没有刷新操作。`access_token` 由人提供，`expires_at` 到了要求重新提供；`email`/`password` 每次打开管理会话都重新登录，受登录桶限速，生产优先用令牌。
- **版本与身份**：`v` 是声明格式的版本，新增成员或改变含义时升到 2，旧程序拒绝而不是猜。`kind` 是供应商身份的持久键，改名等于新供应商；同一 `kind` 下改路径、字段和错误映射是普通配置发布。不热加载，改文件后重启；所有核心节点挂同一份目录。
- **部署与移除**：目录只读挂载，只给部署账号权限；文件里没有密码，但暴露内部管理接口的形状，按内部配置保护。移除时先移除用它的供应商（或确认已 `removed`），再从所有节点删文件并重启；反过来启动检查失败。声明不写数据库。
- **不支持**：解人机验证、阶梯价和上下文价、删对方的 key、非 JSON 管理面、分组/模型/价格列表分页、后台编辑器。CPA 的用量队列读一次就没，不能实现可重读的扣费读取，所以不在这一档（见「CPA」）。

### 代码组织：适配器可以干净地移除

- 每个适配器是 `suppliers` 内部的独立包，带录制样本和契约测试；其他模块在编译层面引用不到（见[总体架构的「AI 好写好维护」](../architecture.md#ai-好写好维护)）。
- 注册表一个内置适配器一行。移除一个内置适配器只删它的目录和那一行；`just adapters-removable` 对每个适配器验证这一点。声明式的移除见上。
- 适配器识别对方系统的版本并按版本选接口，不到处写特殊判断。

### 接入方式逐级兜底

1. 账号密码登录，调接口；
2. 遇到人机验证，由人登录一次，之后用刷新令牌或个人访问令牌保持登录；
3. 只用 API key 能访问的接口，例如 OpenAI 兼容的余额接口；
4. 浏览器自动化兜底，由运营 agent 操作。

### 接入流程

1. **填写网址和账号**：origin 规范成 `https://主机[:端口]`（小写，端口 1 到 65535、去前导零，443 省略），同一站点不会因写法不同成为两个供应商。探测和之后的一切访问都经出站客户端，拒绝内网、回环地址。能用令牌就不存密码，登录一律加密存储。名称由页面从网址生成、可改；结算币种由人选一次。同一 origin 和账号只能接入一次，地址和账号之后不能改。地址检查只在真正执行改动的那次请求里做，同一幂等键的重发直接得到第一次的响应，不再问网络。
2. **识别系统并选适配器**：按注册顺序问每个能接入的适配器，最多 45 秒；站点要人机验证时只列不需要密码的登录字段。识别只读公开接口，不存任何东西；认不出不是错误。
3. **读分组、模型和价格**：同步读出后算成本计划。从未被人选过的分组（`codename IS NULL`）只要有一个模型映射到上架目录模型、有调用格式且有成本计划，就被自动选中并得到代号；人选过（包括取消）的分组保持人的选择。代号是 `g` 加 8 个 base32 字符，第一次选中时随机生成，之后不变。
4. **自动建 key**：适配器能建 key 时（new-api、sub2api），key 清单读完一轮后，同步为每个可卖、没被人取消、还没有凭证、不在失败等待期的分组建一把专用 key。
   - **哪些分组**：适配器说它能用我们的 key 服务，或 sub2api 还没读出模型而 key 正是读模型的前提；订阅分组、按小时计价的分组不建。
   - **建什么**：不限额度、不过期、不限模型，名字是 `axiom-<供应商 ID 前 8 位>-<sha256(供应商 ID + 分组 ref) 前 8 位>`（23 个字符）。名字是标记：响应丢了或提交被栅栏挡下，下一轮完整清单按名字认领，不建第二把。
   - **原文**：按对方 ID 读出，在提交事务里用主密钥封存进 `credentials`，状态 `active`，并发 4、每分钟不限；明文不进状态、日志或接口。
   - **失败**：`not_permitted`（登录没有建或读 key 的权限）、`group_unavailable`（账号不能用这个分组）、`refused`（对方拒绝），按分组记、1 小时后重试，换登录清空；网络错误和 5xx 交给任务退避。建 key 和读原文都在事务外，失败不留半行。
   - **手动绑定是例外**：`BindKey` 把对方已有的 key 按 ID 绑到已选分组，状态 `binding`、没有密文；同步读出原文、封存并激活，模型清单等下一次完整清单，之前全拒。
5. **确认单位余额价值**：适配器读出提示值，人或运营 agent 确认 1 单位余额值多少结算币种（大于 0、至多 1000、至多 15 位小数）；只追加，币种与原生单位都匹配的最新一行生效，确认之前端点不进路由。换算见[计费的「供应商成本」](billing.md#供应商成本)。
6. **生成端点**：投影生成端点，进入检测队列（见[端点评估](quality.md)）。

### 管理操作

每个操作在调用方的平台范围事务里锁住供应商行、核对状态后再写，审计同事务写，带操作者和原因，不带登录、账号和邮箱。幂等键的指纹只含给了哪些登录字段，不含值；同一键换密钥重发得到第一次的结果。

- **状态**：`active`、`low_balance` 可暂停，`paused` 可恢复；`connecting`、`needs_attention` 只由同步改，移除后不能回头。已是目标状态时不动、不审计、不加配置代次。
- **换登录**：新登录封在原位置、版本加一，供应商回到 `connecting`、配置代次加一，同步状态在同一事务里复位（见「同步与变化」）。换登录就是恢复，没有单独的恢复操作。
- **移除**当场完成，一个事务：状态 `removed`、配置代次加一，删登录行，所有凭证的密文清空、标为 `erased`、行保留（成本行的外键指向它）；不等在途、不再读扣费记录。Axiom 不删对方那边的 key（包括自建的 `axiom-` key），要吊销的就是 `erased` 凭证上的 `upstream_key_ref`，审计只记个数（`keys_to_revoke_count`）。已移除的再移除不动；早先版本留下的 `removing` 再移除就完成它。排队的同步任务读到 `removed` 就结束。
- **分组**：`SelectGroup` 选用或取消，不能选用已不在清单里的分组，取消不受限。
- **凭证上限**：`SetLimits` 一起设并发（至少 1）和每分钟请求（1 到 100,000 或空，省略或 null 即清除）；值没变时不动、不审计；凭证已擦除或供应商已移除时拒绝。
- **端点**：`setSupplierEndpointEnabled` 启停端点，没变也审计；同步从不写这一列，停用的一直停着，各节点下一次重建快照生效；管理接口的启用同时重置端点熔断，运营工具 `endpoint_set_enabled` 不重置（见[端点评估](quality.md#三条摘除通道各归各的主人)）。`setSupplierEndpointQuantization` 记录或清除 OpenRouter 的 12 个量化级别之一，未记录是 NULL，不等于 `unknown`；路由按它匹配 `provider.quantizations`（见[接入的路由参数](gateway.md#路由参数)）。
- **测试端点**：`testSupplierEndpoint` 发一次真实生成，每会话每分钟 10 次，见[模块 README 的「用真实生成测试端点」](../../internal/suppliers/README.md#用真实生成测试端点)。
- **读**：调用方用 `Owners` 选读谁的供应商；运营接口只读平台的，管理后台读全部归属（含 BYOK）。`TopUpBasis` 给运营 agent 的充值提案读归属、状态、原生单位、结算币种和现行单位价值，不加锁，串行由运营的上限计数器负责（见 [operations 的「资金上限」](../../internal/operations/README.md#资金上限)）。

### 调用面

- **挑凭证**：`Acquire` 在本节点内存里挑负载最低的凭证（未冷却、未过期、并发位未满、账号这一分钟还有名额），对在途数做一次比较交换；拿不到返回 `ErrNoSlot`，gateway 跳过这个条目，最终回 429 `rate_limited`、`Retry-After: 1`。热路径不读库、不解密。路由冻结路线前用只读的 `Capacity` 做同一判断，满载时排队（见[路由的「容量感知」](routing.md#容量感知)）。
- **快照会过期**：端点来自每 5 秒一次的 `Reload` 快照。最后一次成功的 `Reload` 超过 30 秒，`Routable()` 返回 `ErrStale`，路由快照随后过期，节点约 1 分钟后对所有调用回 503 `overloaded`、`/readyz` 回 503，直到 `Reload` 成功；宁可整节点停路由，也不让期间被停用或移除的供应商无限期接流量。一家供应商的数据读不出来（key 打不开、缺适配器、成本计划或单位价值不合法）只让这一家离开本节点快照，记 `suppliers.unloadable` 日志和计数，不写库。
- **执行状态**：请求写完之前失败的是"未执行"（作用于出口）；写完后非 2xx 由适配器归类，断线、超时、5xx 是"可能执行了"。
- **冷却**：凭证被拒、额度用尽或被要求等待时，按适配器给的时间（没有就按配置）只在进程内歇着，到期重新参与挑选。端点熔断归[端点评估](quality.md#健康与熔断)。
- **余额不足**：作用于供应商的"余额不足"让这家的全部端点在本节点自动暂停，`Acquire` 返回 `ErrSupplierResting`。只有拒绝之后开始的正余额同步，或拒绝之后开始并完整成功的检测能恢复；零余额、失败或旧的同步、单纯等待都不能。暂停期间后台按供应商合并、每分钟至多一次提前请求余额同步，整轮数据库工作至多 5 秒，只提前余额任务、不动其他任务和退避。显式检测可以绕过这项暂停，quality 的自动恢复试探先查余额够不够；检测仍受凭证并发、RPM、到期和人工停用约束。
- **对方的拒绝话术**：拒绝请求本身的失败带上对方 `error` 对象的 `message`、`type`、`param`、`code`，去掉网址、本次凭证、对方域名及各级上级域名、形似凭证的串、请求号和 new-api/sub2api 的名字，`type` 只留 OpenAI、Anthropic 的通用取值，每项至多 2 KiB；流里的同类错误用同一份清洗。
- **请求头**：路径和鉴权只由调用格式定（Bearer，加 Anthropic 版本头）；gateway 白名单里的 `anthropic-beta`、`anthropic-version` 在默认值之上设置，凭证和内容类型不被客户端换掉，没写 `anthropic-version` 时补 `2023-06-01`。
- **计价**：回执带 `Acquire` 时快照里的成本计划、单位价值和它的行 id，一次尝试按它开始时的值计价，之后改的值只管之后的尝试；外币按路由冻结的汇率换算，精确相乘后向上取整一次。

### 供应商别名与待映射

上游名字按以下顺序映射到目录模型：

1. 查供应商别名：只在该供应商或分组内有效，同一写法在不同中转站可能指不同模型；`:free`、`:batch` 这类后缀也在这里映射。
2. 用目录的内部识别查公开和内部名字，归一化后匹配（见[模型目录的「名字解析」](catalog.md#名字解析)）；不去掉日期，不同日期的版本不合并。映射到的模型必须已上架。
3. 仍对不上，由运营 agent 映射：`supplier_model_map` 只给分组列为待映射的名字建分组别名，且只映射到分组里还没有名字的模型（否则新名字会接管那个模型的端点），以 agent 的名义审计；纠正已有别名、建整个供应商的别名由负责人在管理接口做（见[运营接口](operations.md#运营接口)）。
4. 映射后由真伪检测确认（见[端点评估的「真伪检测」](quality.md#真伪检测)）：通过填 `Verified`，矛盾时清掉并告警。不带日期的名字只是候选，端点照常生成并接流量，但 `:exacto` 和只走已验证端点的路由预设不选它。判定假冒后自动下线、退回待映射仍未做。

- **待映射**：没有结果的名字留在 `supplier_models`（`model_id` 为空），不生成端点，按首次列出时间排队。
- **修订**：供应商范围别名只建一次；分组别名可追加从 1 起的不可变修订。不带 `rev` 是新建，已有即冲突；修订须带读到的 `rev`，不符返回 `stale_revision`，模型相同不新增版本。供应商行锁串行化修订，审计记前后模型。投影取最新修订，已取得的尝试保留原快照的模型和成本计划，历史端点和成本行不重写。
- **声明格式**：适配器推不出的调用格式（如 new-api 的 OpenAI 类型不区分旧补全）由映射接口的 `formats` 声明，省略不改、空数组清除、未知格式 422；投影与适配器的格式取并集。

### 凭证

- 加密存储（见[安全基线](../security.md#安全基线)）；刷新令牌时比较版本后再写。
- **模型与到期**：同步完整 key 清单时投影上游的模型允许清单和到期时间：NULL 不限，空数组全拒，按实际发给上游的名字匹配。模型在重建快照时过滤，到期在每次 `Acquire` 按受控时钟判断（到期瞬间不可选）。清单里没有的 key、明确换了组的 key 全拒，凭证和密文保留、不自动擦除或重建，由运营确认后删除或重新绑定；部分清单不改策略。
- **上限**：每个凭证有并发上限（新绑定 4）和每分钟请求上限（1 到 100,000，空为不限）。RPM 按上游账号计数：同一供应商的全部凭证和端点共用一个滚动 60 秒窗口，各凭证拿自己的上限与账号计数比较；共享一份额度的 key 应设相同值，未设上限的 key 也计入账号。同一账号下各 key 的并发之和应不超过上游账号并发，账号级并发准入未做。窗口与多节点份额见[模块 README 的「并发与速率」](../../internal/suppliers/README.md#并发与速率)。
- **状态**：`credentials.status` 筛可用凭证（`active`）；冷却只在进程内，`cooldown_until` 列没有代码写入。唯一持久化的例外是 BYOK 的 `rejected`。检测和真实流量走同一个调用面，不另存凭证健康。
- 凭证可以绑定固定出口（见[总体架构的「部署拓扑」](../architecture.md#部署拓扑)）；现在只有 `direct`，调用路径不读 `credentials.egress_id`。

### 自带的供应商 key

账户自带 key 是一行账户归属的供应商（需要 `AXIOM_BYOK=on`，默认关）：`owner_scope='account'`、`status='byok'`、`kind='openai'`、地址 `https://api.openai.com`，没有登录行，不参与同步。`CreateByok` 在一个事务里写齐：一个倍率 1 的分组，装着作者为 `openai`、已上架、非 `:free` 的目录模型，每个模型一个端点和一份全零成本计划；一条 `active` 凭证（信封加密，`hint` 是末四位）；金额 1 的 `usd` 余额和值 1 的单位价值，让路由条件成立而成本为 0。

- **上游名字**取目录里厂商的公开名（`catalog.Snapshot.OfficialName`）：固定版本只接受带日期的名字、取最长的，浮动模型取最短的，排除带作者前缀、`:free` 或 `@` 版本的；固定版本只有移动名字、或没有可确认名字的模型不建端点，以免按旧规格调用或猜出厂商不认的名字。
- **接口**：`CreateByok`、`ListByok`、`SetByokEnabled`、`RemoveByok`、`RevealByok`、`SetByokTestResult`，控制台处理器用账户范围的事务调用（控制台 API 见[账户](accounts.md#自带的供应商-keybyok)）；key 只在创建入参里出现一次，`ListByok` 只给名称、provider、末四位、状态、是否允许回落和创建时间。
- **测试**：经出站客户端 `GET /v1/models`，10 秒；200 恢复 `active`，401 标 `rejected`，403（可能是地区封锁）和其余失败不可判定、不改状态。测试不写成本、不占并发位。
- **被拒**：调用中 401 归为 `CredentialRejected`，凭证写成 `rejected` 不再被挑，直到测试成功；403 是 `NotPermitted`，不标记 key；其他失败只冷却。
- **移除**：供应商 `removed`、凭证 `erased` 且清空密文；成本行仍指向凭证。

### 同步与变化

每个供应商一份同步引擎，只做决定；状态整份读出、整份提交，每一步的事件、成本计划版本、扣费记录和投影与状态同一事务，持租约栅栏。

- **频率**：余额 1 分钟、目录（分组、模型、价格）5 分钟、key 清单 5 分钟、扣费记录 2 分钟，每个任务各提交一次；同步严格遵守适配器声明的限速，先用便宜的接口，一次能拿到的不分多次拿。普通账号被限流或封号会连带损失预付余额。
- **失败**：网络错误和 5xx 指数退避（1 分钟起、上限 30 分钟、带抖动），别的任务照跑，成功清零；桶不够不算失败，到时再来；响应认不出（成功响应缺必需成员也算，不当成空结果）只停这个任务、什么也不写、发事件。**登录被拒**停掉这个供应商的全部轮询，状态 `needs_attention` 并告警，适配器不再登录。
- **换登录唤醒**：`ReplaceLogin` 在同一事务里复位同步状态：失败、退避和停止清零，所有任务立即到期；余额、已读完的清单和扣费位置保留，已读过的记录不重读；版本和租约栅栏加一，握着旧登录的节点写不进任何东西。
- **清单接着读**：报价和 key 清单可能比一个限速窗口长。被限速时这次读到的位置随提交存下、任务当场结束，下一次（任何节点）接着读，不占工人、不从头读、不跳页；一页可能读两次，按 ID 去重。位置读不懂、上游清单在下面变了（key 变少、分组变了）、或配置代次变了，就整份从头读。没读完时路由看到的是上一份完整的清单。位置里没有凭证。
- **变化即事件**：目录规范化后与上次比较，只把差异写成 `sync_events`：分组和模型增减、倍率、分组事实、格式和能力、资金来源、新成本计划、余额越过 0 和告警线。同一份响应读两次没有新事件、新计划，投影的表一行不写。
- **投影**：分组写 `supplier_groups`，上游名字及其映射写 `supplier_models`，端点写 `endpoints`，成本计划只追加进 `cost_schedules`（按指纹一版一行）。路由和后台读这些行。
  - 只有映射到上架目录模型、且有成本计划的名字才有端点；同一分组两个名字指向同一模型时，取名字带日期的，都不带取排序第一个。
  - 下架的分组和模型标为不存在而不删，端点改为"成本未知"退出路由；清单再出现时还是原来那些行。分组卖不了给我们（订阅、按小时计价）时同样处理。
  - 人的开关（`enabled`）、量化级别、首次列出时间和对账写的"估算偏低"同步都不改，有新一版计划时才清掉后者。`last_seen_at` 是分组最后一次被改动的时间，不是最后一次出现。
  - `Reload` 读到不认识的格式只跳过那一个端点（`suppliers.unsupported_format`），不摘整家供应商。
- **可路由**：供应商 `active` 或 `low_balance`、余额大于 0（没读到过的也不行，新接入的在第一次余额同步前约 1 分钟不可路由，节点报 not ready 是预期的）、单位价值已确认、分组选中、端点启用且成本已知、至少一个 `active` 有密文且模型匹配的凭证。按请求的完整生成成本上界过滤余额见[路由](routing.md#决策与理由)。余额低于告警线发一次 `BalanceLow`，回升后才再发；据此降权尚未接入。由运营 agent 补充值，受资金上限约束。
- **资金来源**：一笔不是从钱包扣的扣费记录（订阅）让供应商停为 `needs_attention`（`funding_not_wallet`）。
- **调度**：每 15 秒扫一次到期且没人持租约的供应商（`connecting`、`active`、`low_balance`），最久的先来，一次最多 200 个入队；每个供应商同时最多一个任务，失败不由队列重试，退避由引擎定。任务取到租约后先核对状态，已暂停、移除或需处理就直接结束；接不上的供应商记为任务失败并退避，不挤占别人。租约 5 分钟，每次提交续期；一轮最多 50 页、一次任务最多 10 分钟；每节点同步队列 4 个工人。优雅停机时在跑的一轮最多等 `AXIOM_SHUTDOWN_TIMEOUT`，已提交的页保留；崩溃留下的任务运行满 15 分钟后被放弃，下一次扫描补上。
- **告警**：每分钟把登录失效、同步需处理、任务停止和低余额事件转成平台告警（每页 20 家、每家最多消费 1000 条，余下跨分钟继续，消费位置与信号同事务）。首次只上报当前未恢复的问题；信号只带内部标识和固定任务名，不带上游文字；登录和停止只在后续真正成功后恢复，换登录不算。同一消费者报告全平台货源耗尽 `suppliers.exhausted`，并每轮最多检查 100 家的 `suppliers.sources_unavailable`；暂停或移除不算恢复。规则见[告警设计](observability.md#告警信号事件与规则e5-3)。

### 号池

- **接入**：号池是自建的 sub2api 或 CPA，以管理员身份接入；new-api 不提供账号层信息，它的管理接口尚未适配。号池自己在账号间调度，我们按分组路由。
- **读数**：每轮目录任务读完后读一次账号目录和额度窗口，最多 2 分钟。失败账号是 `status=error`；可服务账号是 `active` 且可调度的（CPA 还要未停用、未不可用、重试时间已过）。每个可服务账号取五小时和七日窗口里更紧的剩余百分比（重置已过的按 0 用量），按账号平均并向下取整；没有账号报告窗口时余量未知，不当满余量。有效容量 = 余量 × 可服务占比。
- **上限**：sub2api 目录最多 20 页（2000 个账号），每组最多抽 100 个账号问窗口；CPA 最多 40 页、每页 500。目录没读完时保留上次读数、不提交部分结果；窗口值或分组编号读不懂（如带引号的数字）按认不出拒绝，不猜。不是管理员的登录（sub2api `/auth/me` 的 `role` 不是 `admin`，或管理接口回 403）不发或不再发管理请求，也不是失败。
- **反应**：有效容量不高于 20%，或失败账号占一半及以上，该分组 `pool_low`，端点权重减半，并发 `suppliers.pool_capacity` 告警（账号数、失败数、余量、有效容量）。告警桥每分钟比较投影的 `pool_low` 行与上次报过的集合：新低的发信号，恢复或离开回答的发恢复；号池容量不写同步事件。
- **出网**：号池账号的出网代理在号池里配置；我们的出口只管 Axiom 到号池这一段。
- **部署**：sub2api 存凭证不加密，所以号池部署在内网、磁盘加密，管理端口只对 Axiom 开放。管理员凭证只给号池专用、权限尽量小、定期轮换；泄露即吊销并重置号池账号。
- **支出**：订阅费、代理、封号损失记入计费，算号池成本。自写号池模块只作预留，它也只是一个适配器。

### new-api

- **识别**：`/api/status` 有应答且带 `X-Oneapi-Request-Id`；有 `/api/user/login/encryption-key` 是 1.0，否则 0.13（不接入，`Open` 报凭证被拒）。
- **登录**：个人访问令牌加过期时间，需要 `api_key:read`、`api_key:write`，读原文还要 `api_key:reveal`。管理接口的 401/403 按固定的 `code` 清单报凭证被拒（缺权限时带权限名），错误里没有对方的文字。key 的 ID 只许数字。
- **读取**：余额是整数 `quota`，单位提示是 `quota_per_unit`；有生效订阅即资金来源不支持。倍率写 `auto` 的分组不收，倍率缺失或不是数字是认不出。key 状态 1 到 4 对应正常、停用、过期、额度用尽，模型限制读 `model_limits_enabled`、`model_limits`，到期读 `expired_time`（-1 不到期），权限字段缺失时全拒。
- **成本计划**（币种 `XXX`，单位是每 token 多少 quota）：输入 = `model_ratio × 分组倍率`，输出 = 输入 × `completion_ratio`，缓存读 × `cache_ratio`（缺省 1），缓存写 × `create_cache_ratio`（缺省 1.25），一小时缓存写 = 缓存写 × 1.6；精确分数计算，向上取整到 15 位小数，不低于对方的价。按次计费、`tiered_expr`、倍率缺失或超上限的没有成本计划；`image_ratio` 显式且不为 1 的不声明图片能力；推理按输出价。
- **建 key**：响应不回 ID，按名字和分组找回最小 ID，还没列出就是任务失败、下一轮认领；`ACCESS_TOKEN_SCOPE_DENIED` 是无权限，200 `success:false` 是拒绝。
- **报价**：一轮只读一次价格表，各组价格才一致；续读时重读分组列表，分组变了从头读。
- **桶**：`global` 90 次/180 秒，`critical`（读原文）5 次/1200 秒，是对方默认的四分之一。
- **失败归类**：只认 `type` 为 `new_api_error` 的错误（同样的码没有这个类型是渠道透传的）：403 `insufficient_user_quota` 供应商余额不足；401 且 `code` 为空凭证被拒；403 `pre_consume_token_quota_failed` 凭证额度用尽；503 `model_not_found` 端点过载；429 限流，`Retry-After` 接受秒数和 HTTP 日期（暂停上限 2 小时），执行状态不确定；400 请求格式错、执行状态不确定。对账键是 `X-Oneapi-Request-Id`；默认传递取消。
- **扣费扫描**：`/api/log/self?type=2` 新的在前。前进遍读 `[max(水位 − 5 分钟, 开始扫描时刻), min(水位 + 跨度, 现在 − 30 秒)]`，读完水位升到终点、只升不降，不足一分钟不发请求；每天一遍补扫最近 24 小时、不动水位，补扫晚了也不留空隙。跨度默认 1 小时，一遍超过 20 页减半（最短 1 分钟），连续三遍短加倍（最长 1 天）。第一次从现在开始，不读接入前的记录。`Ref` 是 `request_id`，金额是整数 quota；没有缓存 token 时才报告输入，从不报告输出（`completion_tokens` 含推理），只有金额能校正。缺请求号、key、整数金额的记录让这一遍失败而不是跳过。

### sub2api

- **登录**：邮箱密码或令牌，刷新令牌只能用一次。访问令牌剩四分之一寿命时刷新；只有对方说刷新令牌无效才用密码重登，结果不明时留给下一轮；写回比较版本，输了就用已存的。账号被撤销、停用、会话绑定变化、密码被拒或要二步验证是登录被拒，不再登录。调用中途令牌过期只续一次。
- **桶**：登录 5/分、刷新 7/分（按 IP），面板 60/分、用量 15/分、号池 30/分（按账号），是对方默认的四分之一。
- **读取**：有生效订阅即资金来源不是钱包；每个分组用一把可用的 key 读模型和含高峰的倍率，key 余额为 0 读不了时保留上次的模型。key 没有模型级限制，到期读 `expires_at`。普通用户看不到价格，成本计划为空，直到人确认底价，按目录官方价乘分组倍率生成（与售价同一取整）。报文里的数字只接受 JSON 数字。
- **建 key**：带 `Idempotency-Key: <name>`；403 `GROUP_NOT_ALLOWED` 是分组不可用，其他 403 是无权限，404 分组不在，400/409 拒绝。
- **调用面**：`anthropic` 分组服务 Messages，`openai` 分组服务 Responses 和 Chat；订阅、高峰和其他平台的分组不服务。对账键是 `client:` 加 `X-Client-Request-Id`；不传递取消（对方读完上游并全额扣费）。
- **扣费扫描**：同一套水位（重叠 5 分钟、滞后 30 秒、每天补扫 24 小时）；接口只认日期，所以按 key 逐把读，每页 200 条。只有记录写了的计费项算已报告；非 token 计费带未知用量；`billing_type` 不是 0 的不是钱包。

### CPA（CLIProxyAPI）

Go 适配器加常驻采集器，不在声明式里：它的用量队列读一条删一条、只在内存里保留（默认 60 秒，最长 3600 秒），不能实现可重读的扣费读取。

- **识别**只读 `GET /` 的公开回答，不探测管理接口（管理鉴权失败五次封地址三十分钟）；接入时也不发管理请求。
- **账号**：可服务账号数作为余额（单位提示 1），只为让"余额大于 0"和低余额告警有意义。
- **分组**只有 `default`：CPA 的 key 是没有分组的全局列表。模型取可服务账号的模型并集，每次最多读 20 个账号、接着读；没有可服务账号时保留上次的模型。所有模型服务 Messages、Responses、Chat。
- **窗口**只读账号文件里的被动配额信号：Claude 的 5h/7d（0 到 1），Codex 的 primary/secondary（0 到 100）；认得的值读不懂就报认不出，其他 provider 不猜。
- **key**：引用是 key 的 SHA-256 前 128 位，不是 key 本身；不限模型、不过期；CPA 不能建 key，只能绑定已有的。
- **调用面**：流式；不传递取消（没有样本证明会停）；对账键是 `X-CPA-TRACE-ID` 的最后 36 个字符，不是 UUID 就不给。
- **成本**：CPA 没有每模型价格，成本计划保持未知，端点不进路由，直到管理员确认基础价后按确认价乘分组倍率生成。每条扣费记录金额 0、资金来源钱包：队列没有逐笔金额，号池支出另行记账。缓存写不分 5 分钟和 1 小时，数量放进未知用量、不算已报告，不参与校正。
- **采集器**：River leader 每 5 秒入队一次。先离线重放 `usage_records` 里的新行（供应商不在线、已移除也能重放）；再对 `connecting`、`active`、`low_balance` 的 CPA 供应商各拿一把会话级 advisory lock（拿不到跳过），每批弹出 100 条、最多 20 批，弹出后**先**写 `usage_records`（三次短重试）、再解析入账并删 staging 行（同一事务）。只存脱敏字段，`api_key` 只存 SHA-256；解析失败的标 `rejected` 保留；按 `(supplier_id, request_id)` 去重。管理 key 被拒时这个登录版本在所有节点退避 30 分钟，换登录即失效；网络错误、5xx、被限速只结束这一轮。采集器不改供应商状态。
- **崩溃窗口**：队列没有 ack，弹出后、写入 staging 前崩溃会丢这一批；保证是 CPA 侧至多一次弹出加本地至少一次重放。
- **部署前提**：打开用量统计、保留 3600 秒、启用管理路由（有管理密钥），不配置 Home 或其他订阅者，不挂第二个采集器，否则记录被抢走；记录缺失时先查这两件事。

### 对账

- **入库**：同步把扣费记录写进 `charge_records`，按 `(supplier_id, charge_ref)` 唯一，读两次只存一次；保留每项数量、声明了哪些项、没有计费项的用量、等级和物理输入。
- **周期任务**：River leader 每分钟（启动和换主时也）投递一次，任何节点可执行；匹配、暂挂、摘牌、事件和下一页游标同一事务提交，重复执行不改归属、不重复加版本。不挂在同步后面，因为同步暂停时已有记录也要对账。
- **匹配**：只有一个尝试持有这个键时才对上，两个以上共用一个键都不对上；已暂挂或已人工归属的记录，尝试迟到时改归尝试。
- **判定**：只判估算完整的尝试，检测的尝试从不判。|实际 − 估算| ≤ 供应商取整（quota 1，美元 1e-10）+ 估算 × 1%。偏高且端点仍用这份成本计划时，端点改为成本未知（`under_estimated`）退出路由；已换计划的不动，只记一次。偏低只报告。
- **暂挂**：过了宽限（30 分钟）没对上的扣费改为 `held`；有键的尝试过了宽限仍没有扣费，每个身份告警一次。人工经 `AssignToLostRequest`、`AssignUnattributed` 处理 `held` 记录，不按冻结路线猜用户。
- **有界**：每种语句每轮最多 20 批、每批 500 行，剩下的下一轮；等待的尝试按游标跨轮推进，最终都报告一次。
- **事件**：每次版本变化写一行 `charge_events`，billing 据此把暂估校正到供应商的用量（[暂估校正](../../internal/billing/README.md#暂估校正)）；检测的事件带 `test: true`，billing 跳过。差异按类计数并上报 `suppliers.reconciliation_difference`，具体对象记 `suppliers.reconcile.*` 日志。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 适配器分成管理面和调用面 | 对方运行的系统和支持的协议是两件独立的事，分开后自由组合 |
| 三档适配器 | 自研中转站大多只是路径和字段名不同，用配置就能接；配置做不到的才交给浏览器 |
| 声明式是启动时编译的部署文件，不存数据库 | 坏声明在启动时就失败；保存即生效要另一套分发、版本和回滚 |
| CPA 另写 Go 适配器和常驻采集器，用 staging 表 | 读一条删一条的队列不满足可重读的契约；弹出后马上落一份持久副本，重放幂等、坏记录可查 |
| CPA 成本保持未知，等管理员确认基础价 | 给零成本会让 `cost_plus` 售价也成零，把订阅费摊到每次调用是没有来源的单价 |
| 每个适配器独立成包，移除只删目录和一行 | 自研中转站的适配以后要能干净移除 |
| 号池用自建的现成系统、以管理员接入、按分组路由 | 订阅账号的登录和风控由这些系统的社区维护，账号调度交给它们 |
| 官方 API 只做主流基础适配，暂不接入 | 三种主流协议本来就是转换和检测的基准 |
| 别名和待映射归本模块，不进目录 | 上游名字只在该供应商内有意义；目录在依赖上位于本模块之下 |
| 接入只填网址、账号和单位价值，key 由同步自动建 | 产品要求添加供应商只填网址、账号并确认单位价值；确定性名字让响应丢失也不重复建 |
| 自动选中只碰 `codename IS NULL` 的分组 | 人的选择（包括取消）不被同步推翻 |
| 清单里消失的 key 只全拒，不自动擦除 | 清单短暂漏报不触发不可逆的销毁或换 key；擦除改变凭证销毁规则，要负责人批准 |
| 移除当场擦密文、保留凭证行，不删对方的 key | 密文留得越久越危险；成本行的外键要凭证行在；最后不到 2 分钟的扣费记录可能丢 |
| 地址和账号创建后不改；换登录、移除各是单独操作 | 凭证只发往原地址；高风险操作分开才能单独审批和审计 |
| 换登录就唤醒同步 | 多一步"恢复"会被忘掉，供应商看起来只是"需处理"却一直停着 |
| 分组别名用只追加修订 | 保留纠错历史；显式 `rev` 防止过期页面覆盖别人的选择 |
| 凭证模型限制在重建快照时过滤，到期在准入时判断 | 调用路径不读库、不扫清单；只在重建时判到期会漏掉快照期间的过期 |
| 单位价值按供应商存只追加表，回执带行 id | 它是余额的属性；复算按 id，不靠时间推断，旧账不动 |
| RPM 按上游账号共用、上限按凭证设、计数在节点内存 | 新增 key 不增加上游额度；调用路径只是一次比较交换和一次加锁计数 |
| 并发和有限 RPM 按存活核心静态分份额 | 守住调用路径预算；共享槽位每次调用多一次共享计数和清理 |
| 新绑定默认并发 4、每分钟不限 | 对方允许多少还不知道，并发保守；限流值猜错会拒掉能发的请求 |
| 快照 30 秒过期后整节点停路由 | 不往无法确认的端点发；一家读不出只摘那一家，不写全局状态 |
| 限速桶放数据库 | 多节点共用一个出口时各自计数会超过对方的限速，被封的是预付账号 |
| 被限速时存下清单位置并结束任务 | 每节点只有 4 个工人，持租约等限速会堵住其他供应商 |
| 号池读数存在分组的 `pool_*` 列，告警桥比较行 | 读数属于分组；只写变化；不是清单变化，不进同步事件 |
| 号池按分组抽样最多 100 个账号，≤20% 或失败过半降权 | 逐个问几千个账号会耗尽限速；这是运营还能搬流量或补号的时间点 |
| BYOK 是 `status='byok'` 的账户供应商 | 复用加密、行级安全、容量、失败分类和路由，不另造一套（见[账户](accounts.md#自带的供应商-keybyok)） |
| 对账是独立周期任务 | 同步暂停、尝试迟到时已有记录也要核对；下一页游标不能只在某个 worker 内存里 |
