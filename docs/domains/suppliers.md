# 供应商

怎么把官方 API、中转站、号池接进来，读懂它们的余额、分组、价格和用量，并在调用时挑选凭证、发出请求。对应代码模块 `suppliers`。概念之间的关系见[术语与核心概念](../glossary.md)，成本计划和对账见[计费](billing.md#供应商成本)。

## 要求

- 三类供应商通过同一套接口接入（见[产品需求的「供给侧」](../product.md#供给侧)）。
- 中转站多数基于 new-api、sub2api，约一成是自研系统；我们通常只有普通用户账号。
- 自研系统需要单独适配；以后不再接入的，适配可以干净地移除。
- 号池一般是自建的 sub2api、new-api、CPA 等系统；除非必要，不自己写号池模块，但要预留。
- 官方 API：实现主流的基础适配，暂不接入，只作预留。
- 接入、同步、变化处理尽量自动，人只处理例外。

## 设计

### 适配器：管理面和调用面

| | 管理面 | 调用面 |
|---|---|---|
| 做什么 | 登录、读余额、读分组和价格并生成成本计划、读模型列表、读逐笔扣费记录、创建 key | 用哪种协议发请求（OpenAI、Anthropic、Gemini、Responses）、鉴权方式、路径和各家怪癖 |
| 由什么决定 | 对方运行的系统 | 对方支持的协议；一个中转站通常支持好几种 |

- **两者独立组合**：一个管理面可以搭配多种调用协议，不为每种组合重写。
- **能力声明**：每个适配器声明自己能做什么，例如能否查逐笔记录、能否自动建 key。系统按能力决定怎么使用它，比如查不到逐笔记录的供应商被标为高风险（见计费）。

### 三档适配器

| 档 | 用于 | 怎么加 |
|---|---|---|
| 内置适配器 | 常见系统和官方 API | 写代码 |
| 声明式适配器 | 自研中转站中只是接口路径和字段名不同的那些 | 在后台填一份配置（登录地址、余额字段位置等），不改代码 |
| 浏览器自动化 | 前两档做不到的事 | 运营 agent 操作网页 |

第一版的内置适配器：

- **普通用户身份**：
  - new-api：适配新版的个人访问令牌和登录令牌，也兼容旧版的访问令牌；
  - sub2api：登录令牌加刷新令牌；
  - 通用 OpenAI 兼容：只有 API key，通过 OpenAI 兼容的余额接口读取余额。
- **管理员身份，用于自建号池**：sub2api 管理接口、new-api 管理接口、CPA（CLIProxyAPI）。CPA 的管理接口管账号；它不再内置用量统计，所以逐笔用量从它的用量队列读取（CLIProxyAPI 文档，2026-10）。
- **官方 API（预留）**：OpenAI、Anthropic、Gemini 三种协议的调用面，加上最基本的管理面。这三种协议的调用面同时也是转换和检测的基准。

### 代码组织：适配器可以干净地移除

- 每个适配器是 `suppliers` 内部的一个独立包，带着自己的测试样本（录制的真实响应）和契约测试。
- 所有适配器在一张注册表里登记，各占一行。
- 其他模块不能引用任何具体的适配器，由 depguard 强制，见[总体架构的「AI 好写好维护」](../architecture.md#ai-好写好维护)。
- 移除一个适配器：删除它的目录和注册表里的那一行，不影响其他代码。声明式适配器只是一条后台数据，直接删除即可。
- 适配器能识别对方系统的版本，按版本选择对应的接口，不靠到处写特殊判断。

### 接入方式逐级兜底

每个适配器按顺序尝试：

1. 账号密码登录，调接口；
2. 遇到人机验证，由人登录一次，之后用刷新令牌或个人访问令牌保持登录；
3. 只用 API key 能访问的接口，例如 OpenAI 兼容的余额接口；
4. 浏览器自动化兜底，由运营 agent 操作。

### 接入流程

1. 填写网址和账号。系统先识别对方是什么系统：new-api 有公开的状态接口，sub2api 有特征接口。据此自动选择适配器。
2. 读出分组和倍率，由人选择要使用哪些分组。
3. 能自动建 key 的，系统为每个选中的分组在对方站点创建 key。
4. 确认这个供应商的单位余额价值（见计费）。
5. 生成成本计划和端点，进入检测队列（见[端点评估](quality.md)）。

### 凭证

- 加密存储（见[总体架构的「安全基线」](../architecture.md#安全基线)）。
- 刷新令牌时"比较后再写"，防止并发刷新互相覆盖。
- 每个凭证有自己的速率和并发上限；遇到限流自动退避。
- 凭证可以绑定固定出口（见[总体架构的「部署拓扑」](../architecture.md#部署拓扑)）。

### 同步与变化

- **同步频率随风险调整**：价格、分组、模型列表默认几分钟一次；余额更频繁；逐笔扣费记录按对方接口的限制拉取，例如 new-api 的 key 日志接口每 20 分钟只允许 20 次（new-api 源码，2026-10）。
- **发现变化就发事件**：改价、改倍率、新模型、下架、余额不足。接到事件后重算价格、重建快照、安排检测、告警。
- **余额是路由条件**：余额低于阈值时降低端点权重并告警，由运营 agent 补充值，受资金操作上限约束。

### 号池

- 号池是自建的 sub2api、new-api 或 CPA，我们以管理员身份接入。能看到的比普通中转站多：每个账号的健康状况、额度窗口（如 5 小时、每周）和逐笔用量。
- 号池里的账号通过我们的出口节点或固定 IP 代理出网。
- 号池的支出（订阅费、代理、封号损失）记入计费，用于计算号池成本。
- 自己写号池模块只作预留：它在系统里也只是一个适配器，需要时替换即可，其他部分不受影响。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 适配器分成管理面和调用面 | 对方运行的系统和支持的协议是两件独立的事；分开后可以自由组合，不用为每种组合重写 |
| 三档适配器 | 约一成的自研中转站大多只是接口路径和字段名不同，用配置就能接；配置也做不到的才交给浏览器自动化 |
| 每个适配器独立成包，移除只删目录和一行登记 | 负责人要求自研中转站的适配以后可以干净移除，避免代码冗杂 |
| 接入方式逐级兜底 | 来自团队成员的实践经验：多数站点用接口即可，遇到人机验证由人登录一次，剩下的交给浏览器自动化 |
| 号池用自建的现成系统，以管理员身份接入 | 负责人决定。订阅账号的登录、刷新和风控对抗由这些系统的社区持续维护；自写模块只作预留 |
| 官方 API 只做主流基础适配，暂不接入 | 负责人决定。三种主流协议本来就是转换和检测的基准 |
| 刷新令牌时比较后再写 | 并发刷新互相覆盖会让账号掉线；sub2api 采用同样做法（sub2api 源码，2026-10） |
