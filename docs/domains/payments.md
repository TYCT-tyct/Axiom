# 支付

用户怎么给账户充值：收款渠道、订单流程、手续费、退款与拒付、防欺诈、收据。对应代码模块 `payments`。充值到账后怎么记账、额度批次和退款金额怎么算，见[计费](billing.md)。

## 要求

- 第一版支持人民币和美元充值，收款渠道包括支付宝、微信支付、Stripe（见[产品需求的「范围」](../product.md#范围)）。
- 收款渠道做成插件并预留配置，开通哪些由负责人在后台自行配置。
- 支持加密货币（USDT）充值。
- 渠道手续费由用户支付。
- 二级站点用站长自己的收款账户（见[术语与核心概念的「关键关系」](../glossary.md#关键关系)）。

## 设计

### 收款渠道

| 渠道 | 适合 | 开通条件 |
|---|---|---|
| 支付宝（官方） | 国内用户 | 需要企业或个体工商户的主体 |
| 微信支付（官方） | 国内用户 | 需要企业或个体工商户的主体 |
| Stripe | 海外用户，信用卡 | 需要在 Stripe 支持的国家或地区注册的主体 |
| 聚合支付（易支付这类协议） | 没有主体时收国内款 | new-api、sub2api 都支持这类协议；资金先进入聚合平台，有平台跑路和合规的风险 |
| 加密货币（USDT） | 海外用户，或没有主体时 | 经支付处理商接入，或由我们自己监听链上转账 |

- **每个渠道是一个插件**，第一版全部实现，是否启用、怎么配置由负责人决定。
- **收款配置是控制面的一部分**：商户号、密钥、收款地址只有负责人能修改，需要两步验证（见[运营的「控制面」](operations.md#控制面只有负责人能改的设置)）；密钥按[安全基线](../security.md#安全基线)加密存储。
- **二级站点**各自配置自己的收款渠道和商户账户，钱直接进站长的账户。

### 一笔充值怎么走

1. 用户选择金额和渠道，系统显示要付的总额（含手续费）。
2. 创建订单，记下金额、币种、渠道、手续费和当时锁定的汇率。
3. 跳转到渠道付款。
4. 渠道回调：验签 → 核对金额和币种与订单一致 → 按订单编号防重复处理。
5. 入账：生成一个付费额度批次，按锁定的汇率记账（见[计费的「额度批次」](billing.md#额度批次)）。

- **只认渠道的回调和主动查询**：用户付款后跳回的页面只用来展示结果，不作为到账依据，防止伪造。回调验签失败或密钥缺失时一律拒绝。
- **订单状态**：已创建 → 已支付 / 失败 / 过期 → 已退款 / 被拒付。
- **每天与渠道的账单对账**，对不上就告警。

### 加密货币

- **网络与币种**：支持哪些网络和币种（例如 USDT 的 TRC-20、ERC-20）是后台配置。
- **识别付款**：每笔订单生成唯一的收款地址或唯一金额，达到配置的区块确认数后才入账。
- **金额不符**：少付或多付时，按实际到账金额入账还是转人工处理，是后台配置。
- **换算**：USDT 按后台配置的汇率换成额度（见[计费的「汇率」](billing.md#汇率)）。
- **退款**：加密货币充值默认不退款，与 OpenRouter 一致（OpenRouter《FAQ》，2026-10）；可以由站点配置为人工处理。

### 渠道手续费

- 手续费由用户支付：每个渠道按"比例 + 固定金额"配置手续费，付款前明确显示，订单金额 = 充值金额 + 手续费。
- 退款时手续费不退，可以由站点配置。

### 退款与拒付

- **退款**：按计费的规则人工或运营 agent 审核，原路退回，按这笔额度当初的付款价计算（见计费）。
- **拒付**（信用卡持卡人事后向银行申诉）：账户转入"暂停"状态，余额可能变成负数，按计费的规则记一笔拒付损失（见[计费的「风控状态」](billing.md#风控状态)）。

### 防欺诈

以下都是配置项：

- 每个账户每天的充值上限、单笔上限；新账户首笔充值的上限。
- Stripe 启用 3D 验证和它自带的风控（Radar）。

### 收据与发票

- 每笔充值自动生成收据，用户可以在控制台下载。
- 正式发票以后再做。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 渠道全部做成插件，开通由负责人自行配置 | 负责人决定。能开哪些渠道取决于主体情况，插件化后不改代码 |
| 支持加密货币充值 | 负责人决定。海外用户和暂无主体时都能收款；OpenRouter 也支持加密货币 |
| 手续费由用户支付 | 负责人决定。OpenRouter 也在充值时收取手续费（OpenRouter《Pricing》，2026-10） |
| 只认渠道回调和主动查询 | 跳转页面可以被伪造；new-api 曾出现 Stripe 回调验签可被绕过的漏洞（见[安全基线](../security.md#安全基线)） |
| 加密货币默认不退款 | 链上转账无法原路撤回，退款需要人工核实地址；与 OpenRouter 一致 |
| 收款配置属于控制面 | 收款账户被改掉，钱就进了别人的口袋，必须只有负责人能改 |
