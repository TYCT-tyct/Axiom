# 支付

用户怎么给账户充值：收款渠道、订单、手续费、加密货币、退款与拒付、防欺诈、对账、收据。对应代码模块 `payments`。充值到账后怎么记账、额度批次和退款金额怎么算，见[计费](billing.md)。

## 要求

- 支持人民币和美元充值（见[产品需求的「范围」](../product.md#范围)）。
- 收款渠道做成插件，配置预留好，开通哪些由负责人在后台自行配置。
- 支持加密货币（USDT）充值。
- 渠道手续费由用户支付。
- 二级站点用站长自己的收款账户（见[术语与核心概念的「关键关系」](../glossary.md#关键关系)）。

## 设计

### 收款渠道

| 渠道 | 适合 | 开通条件与风险 |
|---|---|---|
| 支付宝（官方） | 国内用户 | 网站需要 ICP 备案；个人账号也能开通电脑网站支付，资质不全时额度受限（支付宝文档《电脑网站支付申请条件》，2026-10） |
| 微信支付（官方） | 国内用户 | 网站扫码支付只对个体工商户、企业等有执照的主体开放，网站需要 ICP 备案（微信支付文档《Native 支付》，2026-10） |
| Stripe | 海外用户，信用卡 | 需要在 Stripe 支持的国家或地区有主体和银行账户（Stripe 帮助中心，2026-10） |
| 聚合支付（易支付这类协议） | 没有官方渠道时收国内款 | new-api、sub2api 都支持（源码，2026-10）。资金先进入聚合平台，有平台跑路和合规的风险；协议没有统一标准，签名一般只有 MD5 |
| 加密货币（USDT） | 海外用户，或没有其他渠道时 | 经支付处理商接入，或自己监听链上转账（见下文「加密货币」） |

- **每个渠道是一个插件**，配置预留好，是否启用、怎么配置由各站点决定：主站由负责人配置；二级站点由站长配置，钱直接进站长的账户。下文提到的配置项都按站点设置。
- **主站的收款配置属于控制面**：商户号、密钥、收款地址只有负责人能改，需要两步验证（见[运营的「控制面」](operations.md#控制面只有负责人能改的设置)）。
- **二级站点的收款配置只有站长本人能改**，同样需要两步验证；每次修改都记入审计并通知站长。
- **站点之间隔离**：每个站点的渠道密钥按[安全基线](../security.md#安全基线)分别加密存储；回调地址按站点和渠道区分，只用该站点自己的密钥验签。
- **卡号不经过我们**：信用卡只在 Stripe 托管的页面或组件里输入，我们的服务器不接触卡号。

### 订单

1. 用户选择充值金额和渠道，系统显示要付的总额（含手续费）。
2. 创建订单：记下充值金额、付款币种、手续费、总额，以及按[计费的「汇率」](billing.md#汇率)锁定的汇率。付款币种与站点的记账货币相同时不换算。
3. 跳转到渠道付款。
4. 渠道通知到账：验签 → 核对金额和币种与订单一致 → 入账。
5. 入账：生成一个付费额度批次（见[计费的「额度批次」](billing.md#额度批次)）。

- **金额用整数**：真实货币按该币种的最小单位保存和比较（人民币、美元为分，USDT 为百万分之一），不用浮点数。
- **只认渠道**：到账以渠道的回调或我们主动向渠道查询的结果为准。用户付款后跳回的页面只用来展示，不作为到账依据。回调验签失败或密钥缺失时一律拒绝。聚合支付的回调验签通过后，只要渠道提供查询接口，还要再查询一次确认。
- **防重复入账**：订单状态的变化和入账在同一个事务里完成，状态只按下表规定的方向变化，例如只有待支付、已过期、待处理的订单能变成已支付，所以重复或乱序的回调不会重复入账。
- **补单**：回调可能丢失，系统定期主动查询未完成的订单。
- **有效期**：订单和锁定的汇率在有效期内有效，有效期按渠道和币种配置。到期时先调用渠道的关单接口（渠道支持时），避免关单时用户正在付款。

| 订单状态 | 什么时候进入 |
|---|---|
| 待支付 | 创建订单 |
| 已支付 | 确认到账 |
| 已过期 | 有效期内没有到账 |
| 失败 | 渠道明确告知支付失败 |
| 待处理 | 金额或币种与订单不符；按配置自动入账或经人工处理后变成已支付 |
| 部分退款、已退款 | 办理退款 |
| 被拒付 | 持卡人向银行申诉 |

- **过期后才到账**：按到账时的汇率重新换算后照常入账，相当于到账时新建了一笔订单。用户不会丢钱，也无法拿过期前锁定的汇率套利。
- **金额不符**：少付或多付时，按实际到账金额入账还是转人工，是配置项。
- **重复付款**：已支付的订单又收到一笔付款时，订单状态不变，这笔付款单独记为一条待处理的记录，由人工退回或入账。

### 渠道手续费

- 每个渠道按"比例 + 固定金额"配置手续费，付款前明确显示。
- 渠道按用户付的总额扣手续费，所以总额要反推：总额 = (充值金额 + 固定金额) ÷ (1 − 比例)，向上取到最小单位。例如充值 100 元、比例 3%、固定金额 0 时，总额为 103.10 元，渠道扣费后实收仍不少于 100 元；直接按 100 × 3% 收 3 元，实收只有 99.91 元。
- 记账见[计费的「账本」](billing.md#账本)：用户付的手续费记手续费收入，渠道实际扣的记渠道手续费。

### 加密货币

接入方式待定（见「待定问题」），无论哪种都要满足：

- **网络与币种**：支持哪些网络和币种（例如 USDT 的 TRC-20、ERC-20）是配置项；只认配置里登记的代币合约地址，防止假币。
- **识别付款**：优先给每笔订单分配一个收款地址；用唯一金额区分订单时，同一金额在订单过期后的一段时间内不再分配。
- **确认**：达到配置的区块确认数才入账，确认数按网络设置，足以抵御区块重组。
- **少付**：用户从交易所提币时，交易所可能扣掉手续费，按上文「金额不符」的配置处理。
- **充错网络或币种**：系统无法自动识别，转人工。
- **私钥**：服务器只保存派生收款地址用的公钥；归集和转出用离线或硬件签名。归集产生的链上手续费记渠道手续费。
- **换算**：按订单锁定的汇率换成额度；非稳定币的价格波动大，订单有效期要设得很短。

### 退款

- **退多少、谁审核**：按[计费的「额度批次」](billing.md#额度批次)，只退付费、没用掉、没过期的部分。二级站点的退款由站长审核，从站长的商户账户退回。
- **怎么退回**：渠道有退款接口的原路退回，支持部分退款；没有退款接口（多数聚合支付）或超过渠道退款期限的，由人工线下退回，照常记账。
- **加密货币**：链上转账无法原路撤回，只能退到用户提供并核实过的地址，链上手续费从退款中扣除。
- **退款政策由站点配置**（见计费），其中两项的初始值由开发者先定，与 OpenRouter 一致，负责人可以随时修改：
  - 加密货币充值不退款（OpenRouter《FAQ》，2026-10）；
  - 退款时不退手续费：Stripe 退款时不退还原交易的手续费（Stripe 文档《Refund and cancel payments》，2026-10），OpenRouter 也不退平台手续费（OpenRouter《FAQ》，2026-10）。

### 拒付

拒付指信用卡持卡人事后向银行申诉，银行把钱从商户账户拉回。

- 扣回这笔充值的额度，已经用掉的部分让余额变成负数，账户转入"暂停"（见[计费的「风控状态」](billing.md#风控状态)）。记账见[计费的「账本」](billing.md#账本)。
- 系统整理该账户的充值和调用记录（不含对话内容）作为申诉材料，由人工在渠道规定的期限内提交；申诉胜诉后冲正。
- 二级站点的拒付发生在站长的商户账户上，记在该站点的账上，并通知站长处理。

### 防欺诈

以下都是配置项：

- 每个账户每天的充值上限、单笔上限；新账户首笔充值的上限。
- 每个账户、每个 IP 的下单次数和支付失败次数上限，防止有人用盗来的卡反复试卡。
- Stripe 启用 3D 验证和它自带的风控（Radar）。

### 对账

每天下载各渠道的账单，逐笔比对订单的金额、手续费和状态（包括退款和拒付），再比对汇总金额，对不上就告警。渠道结算的币种与付款币种不同时，差额记入汇兑损益。

### 收据与发票

- 每笔充值自动生成收据，用户可以在控制台下载。
- 正式发票以后再做。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 渠道全部做成插件，配置预留，开通由各站点自行配置 | 负责人决定。能开哪些渠道取决于主体情况，插件化后不改代码 |
| 支持加密货币充值 | 负责人决定。海外用户和暂无官方渠道时都能收款；OpenRouter 也接受加密货币（OpenRouter《Terms of Service》，2026-10） |
| 手续费由用户支付，按总额反推 | 负责人决定由用户支付，OpenRouter 也在充值时收取手续费（OpenRouter《FAQ》，2026-10）。渠道按总额扣费，直接用充值金额乘比例会少收 |
| 只认渠道回调和主动查询 | 跳转页面可以被伪造；new-api 曾出现 Stripe 回调验签可被绕过的漏洞（见[安全基线](../security.md#安全基线)） |
| 过期后到账按到账时的汇率入账 | 不吞用户的钱；如果仍按过期前锁定的汇率，用户可以等汇率变得有利时再付款 |
| 主站收款配置属于控制面，站点收款配置只有站长能改 | 收款账户被改掉，钱就进了别人的口袋 |
| 加密货币充值不退款、退款不退手续费，作为初始值 | 开发者先定，负责人可以随时修改。与 OpenRouter 一致；链上转账无法原路撤回，退款要人工核实地址；Stripe 退款时不退还手续费，退给用户等于平台承担 |
