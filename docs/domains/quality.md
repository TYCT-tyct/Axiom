# 端点评估

一个端点到底能做什么、是不是真的、好不好、稳不稳，全部靠测量得出。对应代码模块 `quality`。端点属性的种类和获取原则见[产品需求的「端点属性」](../product.md#端点属性)，这里写怎么测、怎么合并。

## 要求

- 评估尽可能全面、自动；人只处理机器判断不了的情况。
- 端点属性靠实测，不靠自报；可以借助外部评测结果，但只辅助、不单独决定结论。
- 端点坏了自动摘除、有限地试探、好了自动恢复；重新检测仍异常则下线并告警；人停用的端点永远不被自动恢复。

## 设计

### 依据与合并

"依据"指一个属性值从哪里得来：目录基线、供应商自报、主动检测、线上观测、外部评测、人工或运营 agent 覆盖。运营测量、真伪与产品成绩各有置信度和有效期；结构事实不按时间过期，来源类别随配置和证据重判。尚无通用合并器，已实现的分支以下文为准，目标规则：

- 能力和真伪类：任何可信的失败证据都降低置信度，但要多次独立确认才判"不支持"或"假冒"，一次失败不下结论；
- 速度和稳定类：以线上观测为准；
- 人工覆盖必须写理由，与实测冲突时告警。

路由预设按属性和置信度筛选端点；`min_score` 用的是产品成绩（0–100），不是运营质量分（0–1），见[路由](routing.md#路由预设)。

### 主动检测

当前主动请求只有恢复试探和随机真伪挑战；固定题库提供评分入口。通用后台题库、官方参考响应采集和结构事实检测器尚未实现。检测要求覆盖：能力、真实上下文与最大输出、真伪、来源指纹、注入与虚报用量、输出篡改、协议与计费合规、固定题质量。其中篡改检测是必测项：编程工具会执行模型给出的命令和代码，中转站篡改输出等于在用户机器上执行别人的代码。

**检测要像真实流量**：恢复试探和真伪检测走生产出口、生产凭证与同一调用面，题目参数和发送时刻随机化；固定题库不通过接口暴露。线上工具参数检查不另发请求。

### 真伪检测
`Verified` 表示随机挑战最近通过、仍在有效期内且此后没有矛盾；调用路径只读快照。它核对目录声明的型号、变体和作者，不证明权重与官方一致。该功能不再追加设计。

- **挑战题**：一次真实生成，按 JSON 模板回答：回显随机十六进制串、两个随机数的和与积、随机字符串的倒序与字符数、它正在服务的精确模型名和版本、创造它的公司。模板不告诉它声称的型号，题面和答案不落库。型号与目录模型的身份（`Claimed.Model`、`Claimed.Name`，取自目录快照而非上游名）比对，公司名与目录作者显示名比对。只检测平台端点：站点和账户自带的端点花的是 key 所有者的钱。
- **型号比对**（`modelVerdict`）：规范化后（小写，去提供商前缀、`@`/`:` 后缀、日期和发布号，保留型号线、功能限定词和变体词）相等为相符；只有同一条可识别型号线、变体不同或声称无变体而回答是更小变体（`gpt-4o` 对 `gpt-4o-mini`）才判矛盾；别名归不到声称型号线、不同型号线、带额外功能后缀的只算不确定；日期快照之间的差异不算降级。
- **判定**（`judgeVerification`）：通过 = 全部对上；矛盾 = 作者是目录里另一个作者，或同型号线的变体不同；不确定 = 拒答、答非所问、没有可解析 JSON、算错已知答案、型号归不到型号线、超时或传输失败，不改变上次结论也不增加矛盾计数。取第一个可解析 JSON 对象且 nonce 必须存在，先判矛盾再核对已知答案。
- **调度**：仅选未熔断、无在途检测、未暂停且有资金的平台端点；通过后置信度在有效期（默认 24 小时）内线性衰减到 0，检测周期（默认 6 小时）后重查，带 ±10% 抖动；沿用试探的并发上限和每小时预算，预算不够记 `deferred`；改周期或首次重试时已排定的下次检测重算。
- **未知与失败分开**：从未检测或通过已过有效期为未知，`:exacto` 不选它；一次矛盾使 `Verified` 立即为假（失败关闭）但不断言"假冒"，默认 15 分钟后重查并退避（封顶检测周期）；累计 `verifyFailures`（3）次矛盾（不确定不增不清）判定假冒，仍按退避重查直到通过。
- **证据边界**：通过只证明这次挑战的自报与已知答案相符；能伪装自报的模型、同型号不同日期快照及量化差异区分不了。`:exacto` 仅承诺使用有效验证结果，无已验证端点返回 503 `no_endpoint`（原因 `not_verified`）。
- **证据绑定配置**：证据记下目录模型、上游名字和所用格式，任一变化即作废（`Verified` 为假、矛盾计数清零、假冒告警解除）并立即重查；检测途中配置变了，回来的答案丢弃，记 `stale`。
- **按节点、不落库**：结果只在进程内（模块边界规则第 3 条）；重启后未知、`:exacto` 失败关闭。`AXIOM_MODEL_VERIFICATION` 默认 `on`，`off` 时不发检测、所有端点未验证。

### 来源类别与指纹

[产品需求](../product.md#端点属性)要求"来源类别在后台增改，每个类别可配识别规则（指纹）"。类别是质量模块的后台数据，路由只按类别 slug 筛选，不自己猜来源，新增类别不用改路由代码。

#### 数据模型
- `slug`：稳定标识（`^[a-z][a-z0-9-]{0,31}$`），创建后不改、停用后不复用，预设和调用记录里的 slug 因此永远指同一个类别。`official`（厂商自己的 API）、`cloud`（云托管）、`relay`（其余）是迁移写入的三个种子，不能删除或改 slug；`official`、`cloud` 可改规则和顺序，`relay` 是唯一的回退类别（没有规则匹配、或端点还没有成功响应时归入它，规则必须为空，固定排最后）。
- `name`、`name_zh`、`description`、`position`（小的先匹配，第一个匹配的胜出）、`rules`、`revision`、软删除（停用只写 `deleted_at`，slug 保留）。
- 上限：类别 32 个，每类最多 8 个条件，所有类别引用的不同响应头合计最多 32 个，让每个端点的指纹证据大小固定。

#### 识别规则
一条规则是若干条件加组合方式（`all` / `any`），只读两类证据：响应头（`header` 头名大小写不敏感，比较第一个值；运算 `present`、`absent`、`equals`、`prefix`、`suffix`、`contains`）和用量项（`item` 计费项名，见 `catalog.Item`；运算 `present`（上游报告了非零值，网关估算的不算）、`absent`）。

- 头值按原样比较，不折叠大小写；头名规范成 `textproto.CanonicalMIMEHeaderKey` 存储；比较值 1–256 字节。
- `absent` 只在观测时规则实际查过这个头、且响应里没有它时成立；没被任何规则引用的头是"未知"不是"缺失"，所以新规则引用旧证据里没有的头时 `present` 和 `absent` 都不命中，失败关闭落到回退。
- 不支持正则、脚本或响应正文：正则会被不可信头值拖进灾难性回溯，正文会把调用内容带进质量模块。
- 修改规则就是修改类别本身，不保留旧版本；审计记录保留每次完整前后值。

#### 怎么评估
- **证据只来自成功的响应**：网关在每次判为成功的尝试结束时，把响应头和上游报告的用量项放进 `quality.Observation`；失败、超时、空正文、断流不算，错误页的响应头不能改变类别。头和用量取自同一次响应（服务端搜索多跳时只取第一跳）。
- **只留规则用得到的头**：按当前规则引用的头名取第一个值（超过 256 字节截断；`prefix` 和找到的 `contains` 仍准确，`equals`、`suffix` 判不匹配），连同用量位图存在端点的进程内状态；`Observe` 不查库、不分配。
- **按顺序判定**：规则每次类别刷新时编译，第一个匹配的类别写进端点状态，否则回退类别。证据绑定端点的目录模型、上游名字和可调用格式：配置变了清掉证据，迟到结果丢弃。节点每 5 秒重读类别表（`quality.source_classes`）并用已存证据重判；新规则引用以前没人看过的头时，该端点在下一次 2xx 之前失败关闭落到回退。
- **到路由**：路由快照每 5 秒重建，`MeasuredFor` 把类别 slug 按值写进 `routing.Endpoint.Class`，配置不符时给回退类别。类别定义重启后恢复，端点证据不落库、不跨节点（模块边界规则第 3 条）；类别和规则改动不需重启。类别不是端点的持久属性：在途调用用计划时冻结的端点完成，新请求按新类别过滤；类别停用后引用它的预设只是不再匹配（失败关闭）。

#### 后台与审计
- 管理接口：`GET/POST /api/admin/v1/source-classes`、`PUT/DELETE /api/admin/v1/source-classes/{slug}`，需要 `sites.manage` 和两步验证；写带 `Idempotency-Key`、`reason` 和（更新/停用）读到的 `rev`，过期返回 409 `stale_revision`，幂等键绑定 slug 和请求体（同键换类别重放 409 `idempotency_key_reused`）。
- 审计：`source_class.create`、`source_class.update`、`source_class.delete`，带理由和完整 before/after，与表的写入同事务。

### 线上观测
每次尝试提交延迟、吞吐、错误、结束原因和工具调用语法检查结果；缓存与用量信息由网关记录。工具错误率目前只测参数是否为合法 JSON：

- **怎么测**：协议层读上游流时，把每个客户端工具调用的参数片段交给固定状态的 JSON 语法检查（不缓存参数，嵌套最多 `jsonx.MaxDepth` 层），调用结束时看它是否恰好一段 JSON（Messages 在 `tool_use` 的 `content_block_stop`，Responses 在 `function_call` 的 `response.output_item.done`，Chat 在 `[DONE]`）。重复成员名不算错；没有任何参数算合法，宁可漏判；Chat 只逐个检查前 8 个调用。结果 `protocol.Progress.ToolChecks` 与 `ToolErrors` 在回答结尾报告，跨格式转换照样带上。回答因输出上限停下时两个数都不报：调用是被截断的，不是模型写错的，与 OpenRouter 一致。
- **怎么算**：正常结束、判为成功且检查过调用的回答算一个样本，任一调用出错记 1 否则 0，一个回答只算一次。网关因客户端格式接不住参数而让尝试失败时（`protocol.FaultToolInput`），只要协议层已检查过，也记 1：错误样本与健康度分开判定，健康度不计它。聚合成 Messages 回复时分不清写错还是被 `max_tokens` 截断，所以不计。样本进与首字延迟相同的加权平均（α = 0.2），样本 ≥ 5 且最近一个在 30 分钟内才算"测过"，否则 `ToolErrorRate` 为 0，路由不因没数据而重排。各节点各自统计，不落库。
- **还没测的**：工具名是否在请求里、参数是否符合 schema，见「待定问题」。

### 外部评测
尚未接入；外部结果只辅助自有实测；正式 key 不交给第三方检测网站，需要时只用可撤销、低额度的测试 key。

### 实测的能力与上限

端点的能力和上限按实测覆盖目录：

| 字段 | 实测怎么覆盖目录 |
|---|---|
| 能力（工具、图片、PDF、推理、提示缓存、结构化输出、服务端工具）、请求参数 | 测出可用的位加上（目录没声明的也加），测出不可用的位去掉；没实测的位保留目录值 |
| 上下文长度、最大输出 | 有实测值就替换目录值（更高或更低都换）；没测过用目录值 |

- **按调用格式分开保存**：Chat 的检测结论只用于 Chat，Responses 的只用于 Responses。路由按请求实际调用的上游格式读取对应那份（`endpointOf` 写入 `routing.Endpoint.Specs`，`Plan` 按 `callFormat` 选）。对外的模型页和端点发现没有格式参数，取所有原生格式的交集与下限（`Endpoint.Surface`）：只有一个格式支持的能力或上限不声称。
- **只收确认结论**：须多次独立确认后调用 `Measure`，单次失败不能写成不支持；结构事实检测器尚未实现，目前全部沿用目录。
- **新鲜度按配置绑定，不按时间过期**：事实只属于测它时的目录模型、上游名字和调用格式，任一变化立即作废。`Monitor.Prepare` 在每次成功的路由重建前发布当前配置并记录供应商快照的单调 `Routable.Generation`，旧 Generation 的 `Prepare` 被拒；`Measure` 在端点锁内比较当前配置，旧配置结果返回 `false`。能力与上限是结构事实，不会自己恢复，按时间回退目录会把实测证明做不了的请求重新发过去，所以不设过期；后来的检测可以翻转它。
- **重启与节点**：只在节点内存，重启回到目录值；不跨节点采纳。
- **发布不需要重启**：每次成功的快照重建由 `MeasuredFor` 按格式取回事实，翻转最迟约 5 秒后进入 `Plan`；构建失败沿用上一份快照。调用路径只读快照，不加锁、不查库（[性能的「调用路径上的规则」](../performance.md#调用路径上的规则)）。
- 新增能力或参数若缺配套方言、参数清单或计费项，请求准备或计费仍会拒绝或标缺项，不按未知价格放行。

### 健康与熔断

端点近期失败达到窗口与独立来源阈值时熔断；实际摘除由启动模式控制。已实现本节点测量、降权、离线、告警、慢启动、持久化、租约试探和管理员重新启用时重置；独立管理重置、立即试探、按端点自动摘除开关、线路健康与跨节点定期采纳尚未实现。

#### 三条摘除通道，各归各的主人
一个端点能被路由，要三样同时成立；每样只有它的主人能改，所以"自动不覆盖人工"靠数据归属保证：

| 通道 | 存在哪 | 谁写 | 怎么回来 |
|---|---|---|---|
| 人停用 | `suppliers.endpoints.enabled` | 只有管理员；同步从不写它（[供应商的「同步与变化」](suppliers.md#同步与变化)） | 只有管理员重新启用 |
| 成本未知 | `suppliers.endpoints.cost_state` | 供应商的同步与对账（见[供应商成本](billing.md#供应商成本)） | 同步拿到新的成本计划 |
| 熔断 | `quality.endpoint_health`（本节） | 本模块：真实流量证据、试探结果、管理员重置 | 试探通过；没有试探的端点由真实请求成功恢复；管理员重置或重新启用 |

- 熔断从不写 `enabled` 或 `cost_state`：每个模块只读写自己的表（[总体架构的「模块边界规则」](../architecture.md#模块边界规则)第 1 条），由测试守住（扫描本模块 SQL 不得出现 `suppliers.` 的表；熔断、恢复、重置前后这两列不变）。人停用的端点不在 `Routable()` 里，既不被路由也不被试探。
- **人重新启用时清掉自动状态**：`PUT /api/admin/v1/suppliers/{supplier_id}/endpoints/{endpoint_id}/enabled` 写 `enabled: true`（本来就启用也算）时，`cmd/axiom` 在同一事务里先调 suppliers 的 `SetEndpointEnabled`，再调本模块 `ResetHealth`，同成同败（第 5 条）。重置总让 `epoch` 加一（旧状态的变化写入时落败），关上熔断、退避归零、清离线标记和试探租约、从此刻起慢启动，记 `reset` 事件，并在同事务解除这次事故的告警。重新启用就是"人认为它好了"；它要是真坏，会按规则再次熔断。
  - 处理请求的节点用 `AdoptReset` 立即换上新状态；其他节点只在基于旧 `epoch` 的下次变化或试探认领落败时采纳，这个时刻没有上界（既不试探又因有别的候选而收不到真实请求的端点，可能一直按旧熔断当最后备选，直到有新变化或节点重启）。
  - 运营 agent 的启用（`endpoint_set_enabled`）不重置：自动证据不由另一个自动操作推翻。停用不碰熔断。

#### 健康的对象

- **端点**（分组 × 模型）是熔断的对象：路由只选端点（[术语表](../glossary.md)第 6 条）。
- **线路尚未实现**：供应商 × 出口的建连、DNS、TLS 失败不计入端点；独立线路熔断、HTTP 层恢复试探和无出口排除属待定。
- **疑似出口拦截**（响应是 HTML 页面，适配器的 `quirks.go` 归为出口范围加 `SuspectedEgressBlock`）既不计端点也不计线路，只记日志和指标 `axiom.quality.suspected_block`：租户提示词里的代码片段就可能触发供应商 WAF 返回 HTML，按它熔断一个租户就能把整家供应商摘掉。
- **凭证的健康归[供应商的「凭证」](suppliers.md#凭证)**：检测和真实流量走同一调用面，被拒的凭证同样歇着，本模块不另存一份。

#### 什么算一次失败

按一次尝试说明了端点本身的什么来判，不看请求内容；拿不准的一律不计，因为误计会让一个租户替所有人摘端点。网关在尝试结束时报给 `quality.Observe`（带账户、凭证、结局类别和预估输入 token 数）；判定表只有这一份，表驱动测试逐项覆盖：

| 尝试的结局 | 对健康 | 理由 |
|---|---|---|
| 上游正常结束；已提交（交付了首段正文、推理或工具调用）之后客户端离开 | 成功 | 端点在正常回答 |
| 端点范围的 5xx（`UpstreamError`）、过载或"无可用渠道"（`Overloaded`）、状态码 ≥ 500 的 `Unknown`、模型不存在（`ModelNotFound`） | 失败 | 与请求内容无关。`ModelNotFound` 的模型名来自 `upstream_name`；没有该模型权限的 key 也会这样回答，所以受"独立来源"约束 |
| 状态码 < 500 的端点范围 `Unknown`（未分类的 404、408、413、415、422） | 不计，记指标 `unclassified` | 多半由请求引起；认出来的再补进适配器分类 |
| 请求已写出、连接断了或没有回应（`Transport`，端点范围） | 失败 | 上游收下请求却不回答 |
| 等响应头超时（`errHeaderWait`）、提交前空闲超时（`errIdle`） | 预估输入 ≤ 32768 token 时记为**辅助**失败，否则不计 | 长输入预填充、隐藏推理本来就可能很久没有内容；阈值是代码默认值。辅助失败进窗口、算进失败数，但单靠它们不能熔断（见「摘除」） |
| 2xx 之后：连接断开、流在结束事件前中断、事件无法解析、200 没有正文；提交后断流、空闲超时 | 失败 | 正常流未完成 |
| 流里的错误事件 | 服务端错误类别（Anthropic `api_error`、`overloaded_error`，OpenAI `server_error` 及同义类别）失败；限流、上下文超长、内容审核、请求错误和认不出的类别不计 | 类别由 `protocol.FaultOf` 给出 |
| 模型输出不合规，如工具调用参数不是 JSON | 不计 | 模型生成的内容；错误率另记（「线上观测」） |
| 限流（`RateLimited`） | 不计 | 由路由暂停（`Router.Block`）和 429 降权处理 |
| 上下文超长、内容审核、其他 400 | 不计 | 换个请求就会成功。上下文超长另作"真实上限"证据 |
| 凭证范围（401、403、额度用尽、`NotPermitted`）、分组范围、供应商范围（余额不足） | 不计 | 凭证歇着归 suppliers；余额不足归供应商暂停和余额过滤 |
| 出口范围 | 不计入端点 | 见「健康的对象」 |
| 失败时客户端已离开（`isGone`），单次调用最长到期，网关自己的原因（内存不足、追加没批准、持有者失效、退出） | 不计 | 取消、我们自己的期限和资源，不是端点的错 |

"不计"的结局不进窗口：既不算失败也不算成功。

#### 摘除

- **窗口**：每个端点在本节点记最近最多 32 个计入的结局（成功或失败），每个带来源、凭证的固定大小标识和是否辅助失败，存在固定大小结构里，由端点自己的锁保护，`Observe` 不分配。**来源**是账户的所有者用户：同一人的几个账户算一个来源，由准入结果带给网关。暂时取不到所有者的账户仍按原规则准入，结局只更新实测、不进熔断窗口；不能把缺失标识当独立证据。与上一个计入的结局相隔超过 10 分钟时窗口清空。取舍：每隔 10 分钟以上才有一个请求的死端点永远凑不满窗口、不会熔断，代价是这样的请求白耗一次尝试再回退（每小时最多约 6 次），健康度仍会下降。
- **熔断条件**，同时满足：
  1. 窗口里有 n 个结局时，失败 ≥ max(5, ⌈n/2⌉)，且最近 3 个都是失败；
  2. **至少一个硬失败**：失败中至少一个不是辅助失败（即 5xx、过载、模型不存在、传输错误或流中断）；
  3. **独立来源**：失败至少来自 2 个来源；端点在 `Routable()` 里有至少 2 把可用凭证时，还要来自至少 2 把凭证。窗口里全部计入的结局只来自 1 个来源时（自带端点、只有一个租户的站点），条件 1 提高到失败 ≥ max(10, ⌈3n/4⌉) 且最近 5 个都失败，凭证独立条件仍适用。
- 试探和真伪检测的可编辑项见「调度与预算」；摘除窗口和测量阈值是代码常量。
- **全局模式**：启动变量 `AXIOM_HEALTH_MODE` 默认 `observe`，照常计数、判定并记 `would_remove` / `would_restore`，不排除端点、不发恢复试探、不发健康告警；下一个计入的成功结束观察中的熔断。`enforce` 才实际降权、离线与试探。不是后台热更新设置；真伪检测由独立开关控制。
- 熔断在**本节点立即生效**：路由快照里的端点持有指向本模块实时状态的指针（与 routing 自己的暂停和在途数同一种做法），`Plan` 的过滤和 `Router.Blocked` 的复查都读它，不等快照重建。
- **先降权后离线**：熔断端点有健康候选时不接流量；候选全部熔断时保持原排序作最后备选，`Blocked` 只拒绝已离线的端点。第一次失败试探标记离线后，正常路线与最后备选都排除它；全部离线时返回 503 `no_endpoint`，原因 `breaker_open`，带 `Retry-After`。平台生成端点即使最后备选真实请求成功，也仍需试探确认恢复。
- **重新检测仍失败才下线并告警**：平台端点熔断本身只记 `removed` 事件、不告警（自带端点熔断时发 `owned_endpoint_removed` 通知所有者）；第一次到期试探仍失败时标为离线（`offline` 事件）并发 `endpoint_still_down` 警告，之后的失败试探只更新退避，不重复告警。离线标记复用持久行的 `warned` 列；试探通过或管理员重置时清除并解除告警。
- 熔断不调用 `Router.Block`：暂停是上游说了"等多久"，熔断是我们判断它坏了，两者分开记、分开到期；暂停也不清空窗口。

#### 健康度

- 健康度是成功率的指数加权平均：每个计入的结局（成功 0、失败 1）按 α = 0.2 更新错误率，健康度 = 1 − 错误率；没有样本为 1。
- 它是质量分的可靠性因子；低于 0.5 时会话不再粘在这个端点（路由的 `stickyMinHealth`）。"最便宜""最快"不乘健康度，部分失败的端点在这两个策略下不降权，只有熔断管它们。
- 试探结果也按一次结局计入健康度和质量分（通过 0、失败 1，不确定不计），但不进熔断窗口：试探是我们自己的请求，不满足"不同来源"。
- 熔断前发出、熔断后才结束的请求更新健康度，但不改变熔断状态。

#### 试探
- **时间**：熔断后默认 30 秒第一次试探（起点后台可改）；没通过间隔翻倍，最长 10 分钟，共 10 级；每次加 ±25% 抖动。到期的试探按到期时刻出队。
- **上限**：每个端点同时最多一个试探；每节点同时最多 4 个、每小时最多 600 个（后台可改）；到上限则到期试探顺延、端点继续降权，记指标并告警。试探是平台生成端点的主要恢复证据。
- **暂停期间不试探**：端点或供应商在暂停中（上游给了 `Retry-After`，或余额不足）时推迟到暂停结束，不计结果、不占预算；quality 不能引用 routing，所以由 quality 定义只读接口、`routing.Router` 实现、`cmd/axiom` 接上（模块边界规则第 5 条）。`Routable()` 报错（供应商快照陈旧）时不发检测。
- **发什么**：一次真正的生成，用 `suppliers.Service.TestEndpoint`（[供应商的「用真实生成测试端点」](../../internal/suppliers/README.md#用真实生成测试端点)）走真实调用面，端点原生的一种生成格式，流式，输出上限 16 token，不开推理；只有直接格式的端点答不了生成题，不排试探。凭证选与上次不同的一把。题目随机组合；这些小题只判断生成通路，不作真伪证据。
- **怎么判**：2xx 且流正常结束，或出现首段内容后正常结束，算通过；失败按上表判。试探**不提前取消**，读到流结束：不传递取消的供应商照样生成到底并收费，提前断开只会让我们记的成本少于对方扣的。
- **不确定的结果不算**：拿不到凭证、限流、凭证范围失败、出口失败、预算用完，既不通过也不失败，按原间隔再排。通过与失败各按一次结局更新质量分和置信度，但不进熔断窗口。
- **谁付钱**：平台承担，不经 billing 预留和结算。`RecordTest` 在发起检测的事务里写带"检测"标记的成本行，事务提交后对账认领，检测扣费不参与估低判定；缺行时按供应商规则暂挂，见[测试端点](../../internal/suppliers/README.md#用真实生成测试端点)。
- **谁的端点试探**：只试探熔断中、仍在 `Routable()` 里的平台生成端点；站点和账户自带端点、仅支持直接格式的平台端点不试探、不自动离线，熔断后只作最后备选，熔断之后发出的真实请求成功即恢复，熔断时通知所有者；人停用的端点从不试探。
- **试探通过不等于真实可用**：16 token 的生成说明不了带工具、长上下文、推理的请求能成功，也挡不住专门放行试探的中转站；真伪由「真伪检测」单独判定。

#### 恢复

- 关上熔断的方式：本轮（当前 `epoch`）试探通过；没有试探的端点由一次真实请求成功；管理员重置或重新启用。关上时清空窗口、清离线标记并解除告警，`epoch` 加一；过期的试探结果丢弃。
- **慢启动**：恢复后它在本节点的并发上限从 1 开始，每 5 秒翻倍，约 1 分钟后取消，用路由已有的满载判断（`MaxConcurrent`、`full()`，`full()` 也检查凭证容量，见[路由的「容量感知」](routing.md#容量感知)）；只在这个请求还有别的端点可用时生效，单端点模型不因此排队；对所有策略有效。
- 恢复后健康度仍低，均衡策略分给它的流量也少，随成功回升；会话要等健康度回到 0.5 以上才粘过来。
- **退避级别**在恢复后保留，直到恢复后连续 10 个计入结局都成功，或稳定运行 10 分钟没再熔断，才回到起点：试探能过、真实请求却总失败的端点会等得越来越久。

#### 持久化与多节点

- **调用路径只用进程内状态**（模块边界规则第 3 条）：窗口、健康度、熔断开关都在内存，`Observe` 不查库、不分配。
- **状态与事件**：后台写 `quality.endpoint_health`（状态、epoch、熔断时刻与原因、失败数、退避级别、下次/上次试探时刻与结果、租约所有者与截止时间、所用凭证、离线标记）。条件更新要求 epoch 等于已读版本，成功后加一；仅获胜者在同一事务写 `quality.health_events` 和持久告警信号。每秒刷新，失败按 1–30 秒退避；调用路径经容量 1024 的值通道交接，满时推迟新变化并计 `axiom.quality.health.deferred`，下个计入结局重新判定；崩溃可能丢掉尚未提交的变化。
- **试探用租约认领**：比较后再写，一个端点同一时刻只有一个节点在试探。
- **启动时**读出熔断中的行，照原退避接着试探，重启不会让坏端点重新接流量。
- **多节点边界**：健康行没有定期跨节点采纳；启动、回收后重新出现、条件更新或租约竞争失败时才读库。窗口与健康度由各节点独立统计。
- **保留与回收**：`health_events` 保留 90 天按天删除；同一端点 10 分钟内来回的熔断与恢复合并成一行"反复"。不在 `Routable()` 里超过一天的端点从进程内表回收，行留库；再次出现时先读回自己的行，再发布路由快照。

#### 告警与指标
- **事件**（`quality.health_events`，经 `platform` 的告警信号报告，规则、去重和投递归 observability）：`removed`（只记事件不告警）→ `offline`（警告：重新检测仍失败）→ `endpoint_still_down` 信号；`endpoint_restored`（信息）；`owned_endpoint_removed`（熔断即通知站点或账户所有者，不发平台运维）；`model_unavailable`（严重：上架模型的平台端点全部离线；自带端点不参与）；`probe_budget_exhausted`（警告）；`observe` 模式只记 `would_remove` / `would_restore`。同一端点同一种变化只报一次；恢复时同事务解除 `endpoint_still_down`。真伪的 `endpoint_fake`（严重：累计三次身份矛盾）只发信号，通过或检测配置变化时解除。
- **指标**（不带端点 ID 标签，避免高基数）：`axiom.quality.health.transitions`、`axiom.quality.health.open`、`axiom.quality.probes`、`axiom.quality.probe.duration`、`axiom.quality.verification`、`axiom.quality.unclassified`、`axiom.quality.suspected_block`。

#### 产品成绩（固定测评题）
产品需求把质量分定义为「固定测评题的成绩，以官方直连为 100」（[product.md 的「端点属性」](../product.md#端点属性)）。它回答"答得好不好"，与「质量分、吞吐与延迟」的运营质量分分别记录、分别过滤，不互相折算。该功能已冻结：运行器未接入，没有自动基准请求，官方账号、预算、频率、触发条件待定；站点和账户自带端点不跑基准。

- **题库**：编进二进制的 `internal/quality/benchmark-v2.json`，34 道题，判定只用固定运算（精确相等、包含、JSON 字段或值相等），不用正则、脚本或另一个模型。题库 `version` 加文件字节 SHA-256 是身份，改任何字节即换题库，旧成绩和基线全部失效；题库不通过任何接口暴露。
- **官方基线**：每个目录模型在官方直连（平台端点、来源类别 `official`、目录作者自己的 API）上跑同一套题得到锚，只存每题官方题分；一个模型一个题库版本一条基线，更新的运行替换旧的。没有官方基线、官方覆盖不到题库 90%、或官方一个题分都没拿到时，所有端点没有产品成绩（失败关闭），绝不拿运营质量分冒充。
- **评分**：一次运行绑定一个生成格式（`chat`、`messages`、`responses`），官方和候选必须同格式，换官方格式等于换基线；embeddings、rerank、legacy completions 不跑基准。`Score = 100 × 候选题分 ÷ 官方题分`，只比官方答过的题，封顶 100，候选没答记 0。每题只生成一次，答错不重试。
- **覆盖与置信度**：官方覆盖题库 ≥ 90%、候选覆盖官方答过题 ≥ 90%、配对题 ≥ 20 道才有成绩，否则没有成绩而不是 0 分。置信度 = 配对差的 95% 区间因子（`max(0, 1 − 半宽/100)`）× 覆盖率 × 时间因子（120 天后失效，线性衰减），不是成绩为真的概率。
- **到达路由**：`MeasuredFor` 输出成绩、置信度和运行时刻，网关复制到路由端点的 `Score` / `ScoreConfidence`。预设显式或继承了 `min_score` / `min_score_confidence`（含 0）就先要求置信度大于 0 再比阈值，未测、过期、置信度 0 都不命中。公开列表的成绩字段尚未接入。
- **只证明什么**：同一套固定题上答得和官方直连一样好或差多少，不证明通用能力、长上下文、工具、图片或真伪；预设可同时要求 `min_score` 和 `verified_only`。
- **持久化**：`quality.benchmark_baselines`、`benchmark_scores`、`benchmark_configs`，都带题库 `version` 与 `hash`，节点只读本进程题库版本的行；只有更新的运行能替换；端点配置（`model_id, upstream, formats`）变化时 `epoch` 加一并删掉旧成绩，写入时比较配置与预期代次，旧运行不能复活；先写库后发布内存；节点每 5 秒重读，重启不需重跑。

#### 质量分、吞吐与延迟
路由快照里端点的这几项，各自的来源：

| 字段 | 来源 | 没有数据时 |
|---|---|---|
| `BreakerOpen`、`Health` | 健康与熔断 | 健康度 1，熔断关 |
| `Latency`（首字延迟） | 真实流量：发出到提交点的时间，只取预估输入 ≤ 4096 token 的尝试，α = 0.2 加权平均 | 未测 |
| `Throughput`（输出速度） | 真实流量：判为成功、正常结束且输出 ≥ 50 token 的尝试，输出 token ÷（结束 − 提交点），加权平均 | 未测 |
| 延迟与吞吐的 p50/p75/p90/p99 | 同一批样本，每条指标一个 128 样本环形缓冲，只取五分钟内样本，最近秩分位数；快照重建时复制进 `routing.Endpoint`，调用路径不加锁、不排序 | 窗口内少于 5 个样本全 0 |
| `Quality`（运营质量分）、`Confidence` | 质量分 = 健康度 × 性能；置信度 = 计入结局数 ÷ 10（上限 1）× 最后一个结局之后 4 小时内线性衰减到 0 | 质量分中性 1、置信度 0（未知） |
| `ToolErrorRate` | 见「线上观测」 | 少于 5 个样本或 30 分钟无新样本为 0 |

- 延迟、吞吐与工具错误率的首个样本直接作为平均值；健康错误率从 0 起。
- **性能**是已测项的平均：首字延迟 ≤ 1 秒记 1，否则 1 秒 ÷ 延迟；输出速度 ≥ 50 token/s 记 1，否则 速度 ÷ 50；只测过一个只取它，都没测过记 1。这些阈值（含 10 个结局、4 小时）是代码默认值（`scoreLatency`、`scoreSpeed`、`scoreSamples`、`scoreMaxAge`），无后台入口。没有计入结局的端点质量分恒为中性 1、置信度 0（延迟与速度样本仍留给"最快"和"最低延迟"）。路由因此把"没测过"排在"测过"之后、彼此按价格加权随机，而不是给 0 分（见[路由的「排序的先后」](routing.md#排序的先后)）。
- 它和产品里的"质量分"不是一回事：产品质量分是「产品成绩」的 0–100，`Verified` 由「真伪检测」给出，运营质量分不冒充它们；三个信号分别过滤。
- **"测过"**：样本数 ≥ 5 且最近一个样本在 30 分钟内，否则按"未测"，旧值不永久决定排名。质量分和置信度只用于排序，不排除端点。

### 调度与预算
- **当前触发条件**：健康熔断到期发恢复试探；真伪检测按新配置、周期或失败重试到期发出。改价、改倍率、上下文测试和整套测评尚无自动触发器；产品成绩的预算和调度尚未接入。
- **预算、频率和重试间隔**在后台配置（`quality.probe_settings`，管理接口 `/api/admin/v1/settings/quality-probes`，保存校验并审计，节点每 30 秒重读）：每小时检测数（默认 600，1–100,000）、并发检测数（4，1–64）、首次恢复试探延迟（30 秒，1 秒–10 分钟）、真伪检测周期（6 小时，1 分钟–30 天）、真伪结果有效期（24 小时，1 分钟–30 天且不短于周期）、真伪首次重试（15 分钟，1 分钟–24 小时且不长于周期）。0 或未存值采用默认，记录只存有意偏离；启动读取失败或值无效则启动失败，运行中则保留旧值；缩小预算不抹掉已消费次数。调度资格是代码规则：恢复试探要求熔断打开；两种检测都要求未暂停、有可用余额、并发和预算未用完；检测的上游成本按尝试成本记账并打"检测"标记。

### 数据政策

官方供应商的数据政策已知（是否留存、是否用于训练）；中转站多半无从得知，标"未知"。用户可以要求只走数据政策明确的端点。

## 决策与理由

| 结论 | 理由 |
|---|---|
| 以端点为健康边界，人工开关、成本状态和熔断各自归属 | 一种自动恢复不能覆盖另一种摘除依据。 |
| 失败判定保守，要求硬失败、窗口和独立来源 | 请求特征或单把坏凭证不能轻易替所有人摘掉端点。 |
| 熔断先降权，失败复查后离线，恢复用慢启动 | 保留最后备选并让恢复有新证据，避免立即涌回全部流量。 |
| 状态与事件用条件更新和租约持久化 | 重启保留坏端点状态，多节点只让获胜者记事件和认领试探。 |
| 高频测量留节点内，低频变化后台写入 | 调用路径不增加数据库或缓存 I/O。 |
| 测量按值进快照，熔断与慢启动提供实时状态 | 排序允许一次重建延迟，摘除必须对下一次规划生效。 |
| 结构事实替换目录、不按时间过期，按配置与格式作废 | 目录是基线，时间流逝不能证明已失败的能力恢复。 |
| 运营质量、产品成绩和真伪分别给出 | 运行速度与稳定性不能证明答题水平或模型身份。 |
| 运营质量用绝对性能基准与独立置信度 | 单端点即可计算，未知不会被冒充成差分或已验证好分。 |
| 随机真伪挑战使用精确自报与已知答案 | 复用现有生成通路，但不能识别有意伪装或证明权重血统。 |
| 固定题库以版本和字节 hash 标识，官方锚定 100 | 所有节点只比较同一题库，少量题的抽样优势不被宣称为超过官方。 |
| 每题一次作答，使用配对区间而不重试错题 | 避免挑答案抬分，并用覆盖与时间表达证据强度。 |
| 产品成绩和基线先落库再发布，自动运行仍待批准 | 跨节点和重启无需为找回成绩重复花钱，运行支出需明确预算。 |
| 来源类别使用稳定 slug、软删除与回退类别 | 预设不会因重用标识而悄悄改变含义。 |
| 指纹仅取头与用量的固定运算，工具参数流式验 JSON | 避免保存用户正文、执行脚本及按参数长度增长内存。 |
| 试探设置为平台单条记录，只存偏离默认的字段 | 平台承担检测费用，统一校验与审计且不复制默认值。 |

## 待定问题

- 结构事实检测器、可编辑检测题库和定期轮换；上线、改价、倍率变化和线上异常触发的贵检测。
- 官方基线账号、自动基准运行的月度预算、频率与触发条件；真伪的官方参考响应、tokenizer 和 logprob 等第二层证据。
- 线路健康：只对建连、DNS、TLS 失败计数，供应商全部线路失效时按无出口排除；恢复拟经出口向无副作用固定路径发 HTTP GET，任意 HTTP 响应为通，尚无执行器。
- 健康状态跨节点定期采纳、独立重置与立即试探、按端点自动摘除开关、测量阈值后台编辑；端点管理视图需并列人工、成本与熔断状态、原因和窗口、测量与样本、下次/上次试探及历史，写操作须理由与审计。
- 来源指纹的消息 ID、正文特征及 TLS/证书证据需协议或出站层提供；单端点人工类别覆盖须定义理由、审计与冲突告警。
- 工具名和 schema 校验需传递请求工具声明、决定参数保存方式与 JSON Schema 实现（OpenRouter 用 Draft 7）；当前错误率只表示参数 JSON 语法错误。
- 六类属性依据的通用合并、外部评测与人工覆盖，以及真实流量签名、token 数和协议合规检查。
