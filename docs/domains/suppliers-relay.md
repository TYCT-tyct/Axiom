# 中转站与号池

中转站和自建号池的适配器：声明式适配器，new-api、sub2api、CPA 三个内置适配器，以及号池的读数和反应。它们和直连、云平台共用[供应商](suppliers.md)的接入流程、管理操作、调用面、凭证、同步和对账，这里只写各系统自己的规则。对应代码在 `suppliers` 模块，公开接口和不变量见[模块 README](../../internal/suppliers/README.md)；上游出处和 CPA 的上游事实在[存档](../archive/suppliers.md)。

## 设计

### 声明式适配器

声明是 `AXIOM_SUPPLIER_ADAPTERS` 指向的目录里的 JSON 文件。启动时注册表读取、校验并把每份编译成与内置适配器相同的接口，之后同步和调用都按同一套契约使用它。它只是固定操作的字段映射和少量开关，没有条件、循环、计算或任意 HTTP；需要这些就写 Go 适配器。

一份声明（`v: 1`）的部分：

| 部分 | 成员 | 内容 |
|---|---|---|
| 身份 | `kind`、`native_unit` | 稳定的小写种类，存进 `suppliers.kind`；余额的原生单位 `quota` 或 `usd` |
| 限速 | `buckets` | 每个接口组一个桶：按 IP 或账号、窗口、次数；必须有 `global`，操作不写桶时用它 |
| 登录与鉴权 | `auth.fields`、`auth.header`/`auth.query`、`auth.login` | 登录字段；令牌放哪个请求头或查询参数；登录的路径、请求体模板、令牌和过期字段 |
| 识别 | `detect` | 一个公开路径，和只有这个系统才有的响应头、版本、代次或人机验证标志 |
| 余额 | `account` | 余额、单位提示（或固定值）和资金来源字段 |
| 分组、模型、价格 | `offer.groups`、`offer.models`、`offer.prices`、`offer.formats` | 分组与倍率、每组的模型、每百万 token 价格及缩放、对方格式名到规范格式名的映射 |
| key | `keys.list`、`keys.secret`、`keys.create`、`keys.policy` | 分页清单、按对方 ID 读原文、按名字建 key、模型和到期限制 |
| 扣费 | `charges` | 按时间窗和页码读逐笔记录，映射请求号、key、时间、金额、模型、资金来源和 token 数 |
| 调用面 | `calls` | 格式、能否流式、是否传递取消、对账键响应头、状态码或错误码到固定原因和范围的映射 |

- **字段与模板**：字段位置是点分成员加数组下标（`data.items[0].key_id`），最多 16 步。路径模板只认操作允许的变量：登录 `{email}`、`{password}`，读原文 `{ref}`，读模型 `{group}`，分页 `{page}`、`{size}`，扣费 `{start}`、`{end}`、`{page}`、`{size}`（`charges.path` 必须带齐，起止是 Unix 秒）；页码从 1 起。`?` 之前按路径段转义，之后按查询值转义，所以 `+`、`&`、`=`、空格和斜杠改变不了请求的资源和查询成员。金额按十进制字面量读（字符串或数字），不经浮点、不接受指数；余额可以为负，扣费金额不行。时间接受 RFC3339 或 Unix 秒。`keys.create.body` 必须恰好有一个成员的值是 `{name}`（不带前后缀），body 的值都是字符串；启用 `keys.create` 时 `keys.list` 必须能读回 `name` 和 `group`，否则建 key 的响应丢了就认领不到、会重复建。
- **加载时校验**：未知成员（`jsonx.UnmarshalKnown`）、`v` 不是 1、`kind` 格式不对或重复（含与内置同名）、没有 `global` 桶、字段路径或模板变量不合法、路径不以单个 `/` 开头或含无效 `%` 转义、请求头名不是 HTTP token、引用未声明的桶、原因/范围/执行状态不在固定表里、可能命中 5xx 的规则声称"未执行"、声明了 `detect.captcha` 却不接受 `access_token`，都让启动失败，错误带文件名。环境变量未设置表示没有声明；设置了但目录读不了是错误。随后 `CheckAdapters` 要求数据库里仍在用的每个 `kind` 都有适配器。
- **读管理面**：必需列表只接受 JSON 数组，`null`、对象和缺失都是"认不出"；有 `total` 的 key 清单提前空页或总数不符也报错，不清空已有 key、不推进位置。401/403 是登录被拒，429 是被限速（默认 1 分钟），5xx 是任务失败，其他 4xx 是认不出。
- **价格与格式**：价格先乘 `scale × 分组倍率`，向上取整到 10⁻¹⁵，再按平台单价上限（1000）校验，原始价超限而缩放后合法仍可读。分组没声明格式用 `calls.formats`，模型没声明用分组的；规范名本身总被接受。报价位置带声明指纹，声明（含 `scale`）一变就丢弃旧位置、重读分组和价格。
- **扣费扫描**：用模块共用的扫描（重叠 5 分钟、滞后 30 秒、初始 1 小时、最长 24 小时、每天补扫、每遍至多一天），页大小改变时从水位重开这一遍；保存的位置读不懂时只停这个任务。
- **调用面**：对账键只接受可打印 ASCII、最长 128 字符；错误规则先于通用默认生效，HTML 响应按出站拦截，未列出的 4xx 是未知，429 默认是限流。
- **探测**：多个适配器认出同一个站时按 `kind` 排序取第一个，所以声明不要模仿 new-api、sub2api 的通用状态接口。
- **登录**：没有刷新操作。`access_token` 由人提供，`expires_at` 到了要求重新提供；`email`/`password` 每次打开管理会话都重新登录，受登录桶限速，生产优先用令牌。
- **版本与身份**：`v` 是声明格式的版本，新增成员或改变含义时升到 2，旧程序拒绝而不是猜。`kind` 是供应商身份的持久键，改名等于新供应商；同一 `kind` 下改路径、字段和错误映射是普通配置发布。不热加载，改文件后重启；所有核心节点挂同一份目录。
- **部署与移除**：目录只读挂载，只给部署账号权限；文件里没有密码，但暴露内部管理接口的形状，按内部配置保护。移除时先移除用它的供应商（或确认已 `removed`），再从所有节点删文件并重启；反过来启动检查失败。声明不写数据库。
- **不支持**：解人机验证、阶梯价和上下文价、删对方的 key、非 JSON 管理面、分组/模型/价格列表分页、后台编辑器。CPA 的用量队列读一次就没，不能实现可重读的扣费读取，所以不在这一档（见「CPA」）。

### 号池

- **接入**：号池是自建的 sub2api 或 CPA，以管理员身份接入；new-api 不提供账号层信息，它的管理接口尚未适配。号池自己在账号间调度，我们按分组路由。
- **读数**：每轮目录任务读完后读一次账号目录和额度窗口，最多 2 分钟。失败账号是 `status=error`；可服务账号是 `active` 且可调度的（CPA 还要未停用、未不可用、重试时间已过）。每个可服务账号取五小时和七日窗口里更紧的剩余百分比（重置已过的按 0 用量），按账号平均并向下取整；没有账号报告窗口时余量未知，不当满余量。有效容量 = 余量 × 可服务占比。
- **上限**：sub2api 目录最多 20 页（2000 个账号），每组最多抽 100 个账号问窗口；CPA 最多 40 页、每页 500。目录没读完时保留上次读数、不提交部分结果；窗口值或分组编号读不懂（如带引号的数字）按认不出拒绝，不猜。不是管理员的登录（sub2api `/auth/me` 的 `role` 不是 `admin`，或管理接口回 403）不发或不再发管理请求，也不是失败。
- **反应**：有效容量不高于 20%，或失败账号占一半及以上，该分组 `pool_low`，端点权重减半，并发 `suppliers.pool_capacity` 告警（账号数、失败数、余量、有效容量）。告警桥每分钟比较投影的 `pool_low` 行与上次报过的集合：新低的发信号，恢复或离开回答的发恢复；号池容量不写同步事件。
- **出网**：号池账号的出网代理在号池里配置；我们的出口只管 Axiom 到号池这一段。
- **部署**：sub2api 存凭证不加密，所以号池部署在内网、磁盘加密，管理端口只对 Axiom 开放。管理员凭证只给号池专用、权限尽量小、定期轮换；泄露即吊销并重置号池账号。
- **支出**：订阅费、代理、封号损失记入计费，算号池成本。自写号池模块只作预留，它也只是一个适配器。

### new-api

- **识别**：`/api/status` 有应答且带 `X-Oneapi-Request-Id`；有 `/api/user/login/encryption-key` 是 1.0；其余（1.0 之前的 new-api、one-api，看 `data.setup` 分辨）识别时就 422「这个版本暂不支持」，写明版本，不给登录项。
- **登录**：个人访问令牌加过期时间，需要 `profile:read`（账号、分组、模型）、`wallet:read`（订阅）、`usage:read`（扣费记录）、`api_key:read`、`api_key:write`，读原文还要 `api_key:reveal`。管理接口的 401/403 按固定的 `code` 清单报凭证被拒，错误里没有对方的文字；缺权限同样停掉轮询，但原因写明缺哪个权限，告警是「同步需处理」而不是登录失效。key 的 ID 只许数字。
- **读取**：余额是整数 `quota`，单位提示是 `quota_per_unit`；有生效订阅即资金来源不支持。倍率写 `auto` 的分组不收，倍率缺失或不是数字是认不出。key 状态 1 到 4 对应正常、停用、过期、额度用尽，模型限制读 `model_limits_enabled`、`model_limits`，到期读 `expired_time`（-1 不到期），权限字段缺失时全拒。
- **成本计划**（币种 `XXX`，单位是每 token 多少 quota）：输入 = `model_ratio × 分组倍率`，输出 = 输入 × `completion_ratio`，缓存读 × `cache_ratio`（缺省 1），缓存写 × `create_cache_ratio`（缺省 1.25），一小时缓存写 = 缓存写 × 1.6；精确分数计算，向上取整到 15 位小数，不低于对方的价。按次计费、`tiered_expr`、倍率缺失或超上限的没有成本计划；`image_ratio` 显式且不为 1 的不声明图片能力；推理按输出价。
- **建 key**：响应不回 ID，按名字和分组找回最小 ID；找回失败或还没列出都算「已建、ID 不明」，占用留着，不再建（见[供应商的「一个分组只建一把」](suppliers.md#接入流程)）。`ACCESS_TOKEN_SCOPE_DENIED` 是无权限，200 `success:false` 是拒绝，只有这两种是建 key 本身被拒。回答里没有 `success` 说不清建没建，不算拒绝。按名字找用 `/api/token/search`：不带 `%`、`_` 时整段匹配，翻到对方报的总数为止，没翻完或同一个 ID 出现两次是「不知道」。按 ID 读 `/api/token/{id}`，答 `success:false`、`record not found` 是这个 ID 没有了；new-api 对重复的建 key 不幂等。
- **报价**：一轮只读一次价格表，各组价格才一致；续读时重读分组列表，分组变了从头读。站点关掉定价模块时价格表对登录用户回 403（只有 root 能读），这时当作价格不公开：分组和模型照读，成本计划为空，等人确认底价；带登录被拒 `code` 的 403 仍是登录被拒。
- **桶**：`global` 90 次/180 秒，`critical`（读原文）5 次/1200 秒，是对方默认的四分之一。
- **失败归类**：只认 `type` 为 `new_api_error` 的错误（同样的码没有这个类型是渠道透传的）：403 `insufficient_user_quota` 供应商余额不足；401 且 `code` 为空凭证被拒；403 `pre_consume_token_quota_failed` 凭证额度用尽；503 `model_not_found` 端点过载；429 限流，`Retry-After` 接受秒数和 HTTP 日期（暂停上限 2 小时），执行状态不确定；400 请求格式错、执行状态不确定。对账键是 `X-Oneapi-Request-Id`；默认传递取消。
- **扣费扫描**：`/api/log/self?type=2` 新的在前。前进遍读 `[max(水位 − 5 分钟, 开始扫描时刻), min(水位 + 跨度, 现在 − 30 秒)]`，读完水位升到终点、只升不降，不足一分钟不发请求；每天补扫最近 24 小时、不动水位，从上次补扫覆盖处往前接，不留空隙。跨度默认 1 小时，一遍超过 20 页减半（最短 1 分钟），连续三遍短加倍（最长 1 天）。站点可把普通用户的日志范围限到 1 天（`log_setting.max_range_days`，超了回 200 `success:false`），所以每遍至多一天，补扫分两遍。第一次从现在开始。`Ref` 是 `request_id`，金额是整数 quota；没有缓存 token 时才报告输入，从不报告输出（`completion_tokens` 含推理），只有金额能校正。缺请求号、key、整数金额的记录让这一遍失败而不是跳过。

### sub2api

- **登录**：邮箱密码或令牌，刷新令牌只能用一次。访问令牌剩四分之一寿命时刷新；只有对方说刷新令牌无效才用密码重登，结果不明时留给下一轮；写回比较版本，输了就用已存的。账号被撤销、停用、会话绑定变化、密码被拒或要二步验证是登录被拒，不再登录。调用中途令牌过期只续一次。
- **桶**：登录 5/分、刷新 7/分（按 IP），面板 60/分、用量 15/分、号池 30/分（按账号），是对方默认的四分之一。
- **读取**：有生效订阅即资金来源不是钱包；每个分组用一把可用的 key 读模型和含高峰的倍率，key 余额为 0 读不了时保留上次的模型。key 没有模型级限制，到期读 `expires_at`。普通用户读不到渠道把模型映射成什么、按哪个名字计费，公布的价不算数（见「决策与理由」），成本计划为空，直到人确认底价，按目录官方价乘分组倍率生成（与售价同一取整）。报文里的数字只接受 JSON 数字。
- **建 key**：带 `Idempotency-Key: <name>`（期限由站点配置，Axiom 不靠它重发）；403 `GROUP_NOT_ALLOWED` 是分组不可用，其他 403 是无权限，404 分组不在，400 和 409 拒绝，但 409 的 `IDEMPOTENCY_*` 说的是同名请求还在处理或另有一次，不算拒绝。按名字找用 `/api/v1/keys?search=`（名字或原文包含即中），本地按整段名字和分组筛、翻完所有页，页数没到就空了是「不知道」；按 ID 读 `/api/v1/keys/{id}`，404 `API_KEY_NOT_FOUND` 是这个 ID 没有了。
- **调用面**：按平台所走的网关定格式：`anthropic` 服务 Messages；OpenAI 网关的平台（`openai`、Kimi、GLM、Grok、DeepSeek、MiniMax 等）服务 Chat，`openai` 另加 Responses。不服务的：订阅分组（高峰倍率只能开在订阅分组上）、只许 Claude Code 客户端的（`claude_code_only`）、`typesafe`、`gemini`、`antigravity`、`composite` 和表外平台，后四种的原因在事实的 `unsold`。对账键是 `client:` 加 `X-Client-Request-Id`；不传递取消（对方读完上游并全额扣费）。
- **扣费扫描**：同一套水位（重叠 5 分钟、滞后 30 秒、每天补扫 24 小时）；接口只认日期，所以按 key 逐把读，每页 200 条。只有记录写了的计费项算已报告；非 token 计费带未知用量；`billing_type` 不是 0 的不是钱包。

### CPA（CLIProxyAPI）

Go 适配器加常驻采集器，不在声明式里：它的用量队列读一条删一条、只在内存里保留（默认 60 秒，最长 3600 秒），不能实现可重读的扣费读取。

- **识别**只读 `GET /` 的公开回答，不探测管理接口（管理鉴权失败五次封地址三十分钟）；接入时也不发管理请求。
- **账号**：可服务账号数作为余额（单位提示 1），只为让"余额大于 0"和低余额告警有意义。
- **分组**只有 `default`：CPA 的 key 是没有分组的全局列表。模型取可服务账号的模型并集，每次最多读 20 个账号、接着读；没有可服务账号时保留上次的模型。所有模型服务 Messages、Responses、Chat。
- **窗口**只读账号文件里的被动配额信号：Claude 的 5h/7d（0 到 1），Codex 的 primary/secondary（0 到 100）；认得的值读不懂就报认不出，其他 provider 不猜。
- **key**：引用是 key 的 SHA-256 前 128 位，不是 key 本身；不限模型、不过期；CPA 不能建 key，只能绑定已有的。
- **调用面**：流式；不传递取消（没有样本证明会停）；对账键是 `X-CPA-TRACE-ID` 的最后 36 个字符，不是 UUID 就不给。
- **成本**：CPA 没有每模型价格，成本计划保持未知，端点不进路由，直到管理员确认基础价后按确认价乘分组倍率生成。每条扣费记录金额 0、资金来源钱包：队列没有逐笔金额，号池支出另行记账。缓存写不分 5 分钟和 1 小时，数量放进未知用量、不算已报告，不参与校正。
- **采集器**：River leader 每 5 秒入队一次。先离线重放 `usage_records` 里的新行（不需要供应商在线，移除后也能重放）；再对 `connecting`、`active`、`low_balance` 的 CPA 供应商各拿一把会话级 advisory lock（拿不到跳过），每批弹出 100 条、最多 20 批，弹出后**先**写 `usage_records`（三次短重试）、再解析入账并删 staging 行（同一事务）。只存脱敏字段，`api_key` 只存 SHA-256；解析失败的标 `rejected` 保留。按 `(supplier_id, request_id)` 去重，重放只留一条扣费。管理 key 被拒时这个登录版本在所有节点退避 30 分钟，换登录即失效；网络错误、5xx、被限速只结束这一轮。采集器不改供应商状态。
- **崩溃窗口**：队列没有 ack，弹出后、写入 staging 前崩溃会丢这一批；保证是 CPA 侧至多一次弹出加本地至少一次重放。
- **部署前提**：打开用量统计、保留 3600 秒、启用管理路由（有管理密钥），不配置 Home 或其他订阅者，不挂第二个采集器，否则记录被抢走；记录缺失时先查这两件事。
## 决策与理由

| 决策 | 理由 |
|---|---|
| 声明式是启动时编译的部署文件，不存数据库 | 坏声明在启动时让节点起不来，而不是首次同步才失败；后台保存即生效要另一套分发、版本和回滚 |
| CPA 另写 Go 适配器和常驻采集器，用 staging 表 | 读一条删一条的队列不满足可重读的契约；弹出后马上落一份持久副本，重放幂等、坏记录可查 |
| CPA 成本保持未知，等管理员确认基础价 | 给零成本会让 `cost_plus` 售价也成零，把订阅费摊到每次调用是没有来源的单价 |
| 号池用自建的现成系统、以管理员接入、按分组路由 | 订阅账号的登录和风控由这些系统的社区维护，账号调度交给它们 |
| 号池读数存在分组的 `pool_*` 列，告警桥比较行 | 读数属于分组；只写变化；不是清单变化，不进同步事件 |
| 号池按分组抽样最多 100 个账号，≤20% 或失败过半降权 | 逐个问几千个账号会耗尽限速；这是运营还能搬流量或补号的时间点 |
| new-api 没写 `billing_source` 的扣费记录，账号没有生效订阅时算钱包，有就不是 | 出处是 new-api 的 `appendBillingInfo`：只在计费会话选了钱包或订阅时写这一项；没写的是订阅出现前的版本、没有计费会话的旧路径（都从钱包扣），或跟着请求来源扣的违规费（`postConsumeQuotaWithResult`，请求用订阅就从订阅扣）。这种记录不指向它所跟的请求，所以读到它的那一页同时读一次订阅：有生效订阅就算非钱包、供应商停下；一律当非钱包会让每笔违规费停掉没有订阅的供应商 |
| new-api 价格表被隐藏时成本未知，不改读 `/api/ratio_config` | 那份配置只有运营者写下的倍率，多数模型的补全倍率在 new-api 代码里（`getHardcodedCompletionModelRatio`，有的锁定、盖过配置），照它算会把输出价算低几倍；它是给同版本 new-api 之间同步倍率用的，默认也关着 |
| sub2api 公布的价（模型广场、可用渠道）不当成本，成本等人确认底价 | 渠道可以把模型 A 映射到 B 并按 B 计费（默认 `channel_mapped`），模型广场却按展示名 A 询价（sub2api 的 `fillDisplayPricing`），可用渠道列的渠道价卡在计费时会被分组价卡盖过；普通用户读不到渠道的映射（用量记录里的也是映射前的名字），所以公布价证明不了就是实收，照它算会少算映射到更贵模型的调用 |
| 每遍扣费扫描至多一天 | new-api 允许站点把普通用户的日志查询范围限到 1 天；按最严的设置切，不用探测每个站点 |
| sub2api 只许 Claude Code 的分组不卖 | 对方按 User-Agent `claude-cli/x.y.z` 放行，其他请求改走降级分组（另一个价）或被拒；Axiom 不转发也不伪造客户端身份 |

## 待定问题

- 声明式的后台新建、编辑、试连和停用尚未实现；要加先决定"保存即生效"还是"保存后重启"、多节点分发和坏声明的回滚。
- sub2api 的管理接口要管理员先提交它的「部署与运营合规承诺」确认语，实测由测试替一次性容器的管理员提交；这样做是否可以，待定。
