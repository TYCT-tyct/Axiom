# 接入与对外接口

客户端怎么调用 Axiom：路径、鉴权、转发规则、用量与费用、错误、路由参数、给其他中转站对接的接口。对应代码模块 `gateway`；格式之间的转换由 `protocol` 模块负责（见[总体架构的「协议转换」](../architecture.md#协议转换)）。对外的模型调用接口沿用 OpenAI 和 Anthropic 的规范，本文只写与它们不同或需要特别注意的地方，字段细节以接口契约为准。

## 要求

- Claude Code、Codex、OpenRouter 的客户端只改地址和 key 就能接入。
- 第一版支持三种调用格式：OpenAI Chat、OpenAI Responses、Anthropic Messages（见[产品需求的「范围」](../product.md#范围)）。
- 其他中转站可以把 Axiom 当上游，用它们习惯的方式查余额、判断错误。
- 行为默认对齐 OpenRouter。

## 设计

### 路径与格式

| 格式 | 路径 | 主要使用者 |
|---|---|---|
| OpenAI Chat | `POST /v1/chat/completions` | 大多数 SDK、Cursor、OpenRouter 客户端 |
| OpenAI Responses | `POST /v1/responses`，以及按 ID 查询、删除 | Codex |
| Anthropic Messages | `POST /v1/messages`、`POST /v1/messages/count_tokens` | Claude Code |
| 模型列表 | `GET /v1/models` | 所有客户端 |

- **兼容 OpenRouter 的路径**：以上路径同时以 `/api/v1/...` 的形式提供，OpenRouter 的客户端只改地址就能用。
- **模型列表**：
  - 带 Anthropic 版本头的请求返回 Anthropic 的格式，否则返回 OpenAI 的格式；
  - Claude Code 启动时用它发现模型，超时只有 3 秒，任何跳转都算失败，所以必须在原地址直接、快速地返回（Claude Code《Gateway compatibility guide》，2026-10）。
- **token 计数**：没有这个接口时，Claude Code 只能按字符数粗估上下文用量。计数优先交给支持该接口的端点；没有这样的端点时，用本地估算。
- **鉴权**：`Authorization: Bearer` 和 `x-api-key` 两种写法都接受。key 只能在所属站点登记的 API 域名上使用（见[账户与租户的「API key」](accounts.md#api-key)）。

### 转发规则

依据 Claude Code 官方的网关兼容指南（Claude Code《Gateway compatibility guide》，2026-10）：

- **请求头原样转发**：`anthropic-beta` 和 `anthropic-version` 不做筛选。Claude Code 每个版本发的值都不同，筛选会让长上下文、交替思考等功能悄悄失效，或者直接报 400。
- **请求内容不改**：缓存标记和块状的 system 内容保持原样，否则每一轮都按无缓存计费。
- **格式特有的能力只走原格式的端点**：请求用到只有原格式才能表达的能力时（例如 Anthropic 的 beta 功能、推理签名），路由只选支持这种格式的端点（见[路由](routing.md#一个请求的路由步骤)）。
- **利用 Claude Code 发来的提示信息**：
  - 会话 ID 请求头：用于会话粘性；
  - 请求类别（主对话、子 agent、压缩、辅助请求）：可以作为路由提示。预设可以配置"辅助请求走便宜端点"，默认不启用；
  - "上下文已压缩"标记：之前的缓存已经作废，粘性借这个时机重新选择端点。

### 用量与费用

- **每次调用都返回用量和费用**：输入、输出、缓存读、缓存写、推理 token 和费用，与 OpenRouter 的用量统计对齐（OpenRouter《Usage Accounting》，2026-10）。流式输出放在最后一个事件里。
- **费用的单位**：用本站的记账货币（见[计费的「钱的表示」](billing.md#钱的表示)），并附带币种字段。主站是美元，与 OpenRouter 客户端的预期一致。
- **各格式的放置位置**：各格式按自己的习惯放用量字段，费用字段附加在该格式允许扩展的位置。
- **调用编号**：每个响应都带一个调用编号。凭它可以查询调用记录，包括每次尝试、路由过程和费用明细。

### 错误

- **外壳与类型**：各格式使用自己原生的错误外壳；三种格式里都另带一个统一的错误类型字段，程序判断它就够了。这与 OpenRouter 一致（OpenRouter《Errors and Debugging》，2026-10）。
- **状态码**：

| 状态码 | 含义 |
|---|---|
| 400 | 请求有误 |
| 401 | key 无效或已过期 |
| 402 | 余额、key 上限或工作区预算不足，带"上限来源"字段 |
| 403 | 无权限，或被策略拦截 |
| 404 | 模型不存在 |
| 408 | 超时 |
| 413 | 请求过大 |
| 429 | 限流，带 `Retry-After` |
| 502 | 上游返回了无效响应，或所有尝试都失败 |
| 503 | 没有满足条件的端点，附原因（各种情况见[路由的「没有可用端点时」](routing.md#没有可用端点时)） |

- **流中途出错**：状态码保持 200，在流里发一个错误事件并正常结束；非流式请求则把错误和已生成的部分一起返回。
- **不泄露上游细节**：5xx 类错误的提示统一改为通用说法，不出现中转站的名字或原始报错。
- **对中转站对接方友好**：
  - 计费类问题绝不返回 401；
  - 可以恢复的临时状况，不使用会触发 new-api 自动禁用渠道的措辞（new-api 源码，2026-10）。
- **保活**：长时间等待期间只发 SSE 注释行，不发 JSON 格式的心跳。sub2api 出现过 JSON 心跳导致严格客户端崩溃的问题（sub2api issue #7946，2026-10）。

### 路由参数

- **接受 OpenRouter 的参数**：
  - `provider` 对象：只走、排除、指定顺序、是否允许回退、要求支持全部参数、数据政策、排序、最高价、性能条件；
  - `models` 备选模型；
  - 模型名后缀 `:floor`、`:nitro`；
  - `@preset/名称`；
  - `session_id`、`prompt_cache_key`；
  - `user`：终端用户标识，用于防滥用和归因。

  这些参数的语义见[路由的「请求覆盖」](routing.md#请求覆盖)。
- **我们自己的扩展**：放在单独的 `axiom` 对象里，也可以用 `x-axiom-*` 请求头传，方便无法修改请求体的工具。
- **转发前删除**：所有路由参数和扩展字段在转发给上游之前一律删掉，防止上游因为不认识的字段报错。

### 给其他中转站对接的接口

| 接口 | 用途 |
|---|---|
| `GET /api/v1/key` | key 的上限、剩余额度、各时间窗口的用量（OpenRouter 格式） |
| `GET /api/v1/credits` | 账户余额（OpenRouter 格式；new-api 对 OpenRouter 的余额地址有专门处理） |
| `GET /v1/dashboard/billing/subscription`、`GET /v1/dashboard/billing/usage` | OpenAI 旧版的余额接口，new-api 用它查询渠道余额（new-api 源码，2026-10） |
| `GET /api/v1/generation?id=` | 按调用编号查询单次调用的详情 |

### Responses 的会话状态

- **支持两种续接方式**：OpenAI Responses 接口可以只发"接着上一条回复继续"（`previous_response_id`）而不重发完整历史，我们支持这种方式，也支持 `store` 参数。
- **怎么实现**：会话状态按账户隔离保存。续接时由我们把历史拼回完整的输入，再发给上游，所以不依赖上游自己保存状态，换端点也能续接。
- **保留时间**：由站点配置，默认 30 天，与 OpenAI 的默认一致（OpenAI《Conversation state》，2026-10）。
- **对话内容保存被关闭时**：如果平台或站点为某个账户关闭了对话内容保存，续接请求返回明确的错误，说明需要发送完整历史。

### 版本与兼容

- OpenAI、Anthropic 格式跟随它们的官方规范。
- 我们自己的扩展只增不改。
- 确实需要不兼容的修改时，使用新的版本路径；旧版本经过公告期后才下线，公告期在发布时说明。
- 管理接口（控制台、管理后台、运营）用 OpenAPI 契约，版本规则相同。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 同时提供 `/v1` 和 `/api/v1` 路径 | 负责人同意。OpenRouter 的客户端只改地址就能接入 |
| `anthropic-beta` 等请求头原样转发，请求内容不改 | Claude Code 官方的网关兼容指南明确要求；筛选或改写会让功能失效或多计费 |
| 格式特有的能力只走原格式端点 | 转换会丢失这些能力，用户却不知道 |
| 辅助请求走便宜端点作为预设可选规则，默认关闭 | 负责人同意。能省钱，但这类请求的质量会和主对话不同，由预设自行选择 |
| 错误用原生外壳加统一错误类型 | 各家 SDK 只认自己格式的错误；统一类型让程序可以跨格式判断，与 OpenRouter 一致 |
| 计费类问题不返回 401，避开自动禁用的措辞 | 把我们当上游的 new-api 收到 401 或特定措辞会自动禁用渠道，临时问题会被放大成停用 |
| 扩展字段放在独立的 `axiom` 对象，转发前删除 | 不与 OpenRouter 的字段冲突；上游遇到不认识的字段可能报错 |
| 提供 OpenRouter 和 OpenAI 旧版的余额接口 | 负责人同意第一版就支持其他中转站接入；这是它们查询上游余额的既有方式 |
| Responses 的会话状态由我们保存并负责拼接 | 负责人同意。不依赖上游保存状态，换端点也能续接 |
