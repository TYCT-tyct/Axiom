# 计费

钱怎么表示、成本怎么算、售价怎么定、余额怎么预留和结算、用量从哪来、账怎么记。对应代码模块 `billing`，公开接口和不变量见[模块 README](../../internal/billing/README.md)，调研、实测数据和长篇推导见[计费存档](../archive/billing.md)。概念关系见[术语与核心概念](../glossary.md)，钱的通用规则见[总体架构的「工程原则」](../architecture.md#工程原则)。

## 要求

- 售价 = 实际服务该请求的供应商端点成本 + 加价；同一模型走不同端点，售价可以不同（[产品需求的「计价」](../product.md#计价)）。
- 计算必须正确；除显式确认并审计的豁免外，售价不低于已知成本乘站点保本倍率。
- 加价方式多样且可配置；供应商改价后自动跟随。
- 内部用美元记账；真实汇率可以作为开关，为防波动可以略贵。中转站一般用固定货币和固定分组倍率，涨价体现为倍率变化。
- 其他中转站会把 Axiom 当上游高频调用，单个账户的高并发不能成为瓶颈。
- 额度默认不过期，可以单独设置；退款需要人工审核；政策都可以按站点修改。
- 订阅套餐按窗口发放额度：每窗口额度、窗口长、期限、售价都是后台数据，代码里没有默认套餐；窗口用不完不结转，套餐到期后没用完的作废。
- 用户自带供应商 key（BYOK）时 Axiom 成本为 0，按同模型参考价的固定比例收服务费；费率是站点数据，默认 5%。
- 六条红线，每条由下文的机制和[怎么验证](#怎么验证)守着：
  1. 钱守恒：每次变动都是借贷平衡的账本记录，余额等于记录之和；
  2. 不重复扣：同一请求的同一次尝试只结算一次；
  3. 不会算不出钱：上架前检查价目表完整，运行中缺价有兜底，不因此拒绝结算或不收钱；
  4. 欠款有硬上限：调用收费从不让余额低于余额底线（拒付不是调用收费，见[风控状态](#风控状态)）。每个预留含超额额度，准入把在途预留一起计入；收费写入时检查，超出部分由平台承担、记录并告警；
  5. 可解释：每笔费用有明细和用量来源，改账只追加冲正；
  6. 可对账：每天自己对平，并与供应商对平。

## 设计

### 钱的表示

- **额度**是站点的记账单位：1 额度 = 1 个单位的站点记账货币。主站用美元，二级站点可选美元或人民币；中转站的"¥1 = $1"只是显示符号。
- **金额**：最小单位是十亿分之一额度，int64 存储；汇总用更宽的类型。
- **单价**：十进制定点 int64，单位 10⁻¹⁵ 币种单位每计费单位（token、次、张、秒、字符）：最多 15 位小数、每单位最多 1000 币种单位，超出拒绝保存。录入的单价只能从十进制文本构造；算出来的单价（如官方价 × 分组倍率）从精确分数向上取整到 10⁻¹⁵。
- **计算**：一个请求的精确金额用 128 位整数（单位同单价），逐步检查溢出；汇率和倍率不是有限小数（1 CNY = 10/71 USD），乘它们时用精确大整数分数，全部算完只取整一次。转成金额时向上取整，越界只可能是程序错误，用断言守住，不回绕。
- **取整一律对平台有利**：向用户收的向上，估算成本向上，汇率朝不亏的方向；充值换额度向下。
- **显示与存储分开**：存精确值，汇总先精确相加再格式化；真实货币按各自最小单位（分、美分）。
- **余额字段是账本合计的物化值**，与记账同事务更新，对账持续核对。**可用余额** = 余额 − 在途预留 − 退款冻结。

### 汇率

- **表示**：`1 base = numerator / denominator quote`，支持 USD、CNY、EUR、GBP、JPY、HKD、SGD、AUD、CAD、CHF，拒绝未知币种、`XXX` 和同币种对。每对货币按字母序规范化、只有一条只追加的版本历史，反向用精确倒数；分子分母 1 到 10¹⁸、约分保存，汇率在 [10⁻⁶, 10⁶]。同币种不读汇率。
- **人工写入**：`initial`（预期版本 0）、`adjustment`（与上一版最多五倍，含边界）、`correction`（须写纠错理由，只跳过相对偏差检查；首值反填如 7.1 写成 0.14 由录入者确认、可直接纠正）。写入带理由、预期版本和幂等键，与审计同事务；同一货币对串行分配版本，当前值看版本不看时间。
- **自动参考源 ECB**：全部节点设 `AXIOM_EXCHANGE_SOURCE=ecb` 启用，缺省 `manual` 不联网。读 [ECB 日汇率 XML](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml)，每对取两项 EUR 报价的精确比值并存来源日期；syncs 队列每小时检查，每 24 小时最多下载一次，请求 20 秒、64 KiB、不跟重定向。整批验证日期、重复、十种货币齐全、数值边界和五倍偏离后一笔事务追加全部自动货币对与审计；失败不部分更新，同来源日期不追加，旧日期不倒退。人工货币对永不覆盖，手动写入自动对即转为人工值。
- **陈旧告警**：源日期距今超过 8 天（容纳周末、TARGET 连休和一次失败），或首次尝试起 8 天从未成功，经持久信号 `billing.exchange.stale` 报警与恢复；保留最后有效汇率，人工值不过期。关闭自动源时先把要用的货币对写成 `manual`、人工关闭现有告警事件（`POST /api/admin/v1/alerts/events/{event_id}/resolve`），再把所有节点改回 `manual`；关闭不改历史、不解除告警。
- **充值缓冲**：异币种充值的成交汇率 = 参考汇率 ×（1 + 站点缓冲），多付付款币种；缓冲以百万分之一存 `billing.top_up_buffers`，0–10%，缺省 2%；订单锁定所读的参考汇率版本（[支付的「金额与汇率」](payments.md#金额与汇率)）。
- **请求冻结汇率**：路由快照与汇率同次读取；预留冻结路线需要的每个异币种对（缺失也冻结），所有尝试、回退和结算重试沿用。刷新失败保留旧快照时间，超过 `MaxStale` 拒绝新请求。
- **成本只取整一次**：原生精确成本 × 尝试开始时的单位余额价值 × 冻结的汇率，最后转成十亿分之一站点货币；尝试成本行存单位价值 ID、汇率 ID、币种与转换状态，丢失的依据保持未知，不用今天的配置补。
- **利润未知**：缺汇率或换算溢出不改原生 `CostFlag`；任一尝试不能完整换算，或最终原生标记不是 `complete`，利润为 `NULL`；没有尝试就释放的利润为 0，清理的丢失请求利润未知。异币种供应商缺汇率时每轮刷新记日志与指标，持续缺失不重复报。
- **二级站点币种**：站长设定"1 本站额度 = 多少主站额度"尚未接入，节点路由按主站币种构建。

### 资金来源

- 一次调用只从一个资金来源扣：余额钱包，或账户名下一个有效套餐，不拆分。两者是同一接口的两个实现：钱包预扣余额，套餐占住一个窗口的额度，结算按同一差额调整；只有「请求结算」的借方从用户余额换成套餐未用额度。
- **扣费顺序是账户的计费偏好**：`subscription_first`（缺省）先套餐、当前窗口罩不住整笔预留时回退钱包；`wallet_first` 先钱包、不够回退套餐；`subscription_only`、`wallet_only` 只用一个，不够就拒绝。账户没选用站点默认（[账户的「站点设置」](accounts.md#站点)），站点没设用 `subscription_first`。
- 有不认识偏好的节点在线时（节点心跳声明支持并绑定 `share_session`，汇总在 `platform.billing_preference_readiness`），准入按 `subscription_first`，设置接口拒绝非默认值；旧节点退出后自动开放。

### 订阅套餐

- **套餐是后台数据**：名称、每窗口额度、窗口长、期限、标价（记账货币最小单位）、启用。保存时检查额度为正、窗口 ≥ 1 小时、期限 ≥ 窗口、最多 400 个窗口、秒数在 `time.Duration` 内；标价是目录价，发放时记下的实收可以不同。
- **账户的套餐是快照**：`subscriptions` 一行、`subscription_windows` 每窗口一行（起止、额度、已用、在途），连续铺满期限，最后一个在期限结束时截断。条款在发放/续期时复制，改套餐不影响已售窗口。一个账户最多一个有效套餐（部分唯一索引）；已有另一个有效套餐时发放被拒。
- **发放与续期**：`CreditSubscription` 按调用方 ID 幂等（同参数无操作、不同参数冲突）；续期从 max(现在, 原到期) 往后延并续上窗口。
- **准入**：余额行锁内读当前窗口，到期先推进指针（不记账）；窗口剩余 = 额度 − 已用 − 在途。按计费偏好报价，窗口罩得住整笔才记 `funding = plan` 及 `subscription_id`、窗口序号。工作区预算和 key 上限照常检查，套餐用量也计入花费。追加记回冻结窗口，不够时按余额不足截断（`credits_insufficient`），不换钱包。
- **结算与释放回原窗口**：按冻结的窗口记账，即使窗口已结束、套餐已过期或续过期；收费上限是该预留的在途额，超出记平台承担。释放、清理、孤儿结算把在途额退回同一窗口。
- **到期**：套餐过 `ends_at` 后不参与准入；没有在途套餐预留时把未用额度一次作废并转 `expired`，有则推迟。任务每分钟（领导节点插入），扫期限或窗口已到的 `active` 和未作废、无在途的 `expired`；准入也会就地推进。
- **退款只由管理员发起，须另一个管理员批准**：用户没有入口。`RefundSubscriptionGrant` 只登记申请（`credits.grant`、MFA、理由、幂等键），另一个账号 `ApproveSubscriptionRefund` 批准后执行，两边写审计。只有付费发放、只有订阅最新一笔发放能退，额度不超过剩余付费额度；现金按原付款比例，跨币种走原汇率和汇兑损益。
- **退多少收回多少期限**：累计退完收回整段；部分退款收回 `ceil(窗口数 × 累计退款 ÷ 付费额度)` 个未来窗口，当前窗口已开始的拒绝。现金按累计值向下取整，最后一笔补足余数；报价为 0 现金的拒绝。收回窗口只标 `voided_at`；有在途预留的拒绝。没有剩余窗口撤销，最后存活窗口已结束转 `expired`，两者都写 `closed_at`。
- **过期后进来的钱**：清理释放后的迟到结算改从钱包收（最多到底线），预留行改为 `wallet`、清空窗口列；暂估校正仍记回原窗口，套餐已作废时多出部分从额度过期收入转回。
- **不变量**：①每窗口 `used + reserved ≤ quota`，各窗口 `used` 之和不超过发放总额度；②每个套餐的 `plan_liability` 合计是剩余未用额度的负数，作废后为 0；③选套餐当且仅当窗口剩余 ≥ 预留金额，且同时写下 `subscription_id` 与窗口序号；④窗口 `reserved` 只在余额行锁内变；⑤结算与释放记回冻结窗口。账务见[账本](#账本)。
- 先把所有 billing 节点升到认识套餐的版本，再建套餐、发套餐。

### 额度批次

- **每次额度进账一个批次**：来源是赠送（`gift`）、兑换码（`redeem`）或付费（`paid`），记金额和可选过期时间；付费批次另记付款币种、实付和其中手续费、入账额度、收款渠道（商户账户或线下渠道，恰好一个）和参考汇率版本，成交汇率 = (实付 − 手续费) ÷ 入账额度。入账额度不超过按参考汇率折算的值；同 ID 再次入账一致无操作，否则报错。赠送和兑换码不能退款。人工调整来源未实现。
- **写入口**：`AddCredit`（赠送）、`CreditPaid`（付费）、`CreditRedeem`（ID 是兑换记录 ID，过期沿用码上的，[支付的「兑换码」](payments.md#兑换码)）。管理员手动加额度选赠送或线下付款（实付、币种、渠道，服务端按参考汇率向下取整折算、不加缓冲），缺省赠送，须带幂等键和理由。
- **过期**默认没有；站点可给某类来源设默认有效期，管理员可给单个批次设。
- **分配规则**：先用最早到期的，不过期的最后；同时到期先赠送后付费，再按先后。由后台按账本序号重放余额变动，不在调用路径上写：进账开批次并先还欠款；扣费用未冻结额度，不够记欠款；冲回（[#277](https://github.com/TYCT-tyct/Axiom/issues/277)）先还欠款，再按花费逆序还给批次；校正的冲正加重结按净额处理。用完的批次留在重放集合里。不变量见[模块 README](../../internal/billing/README.md#额度批次的分配与到期)。
- **控制台批次视图**：`GET /api/console/v1/balance` 的可选 `batches` 列出仍有剩余或冻结的批次。读取复用分配缓存，最多推进 8 页（每页 5 000 笔）或 2 秒并保存位置；余额、批次和账本上界同一快照读，没追上就不返回 `batches`（页面显示"暂不可用"），余额照常。
- **到期**：剩余额度作废、记"额度过期"。任务每分钟（领导节点插入）：每账户先无锁分页预放，再在余额行锁内作废 min(未花未冻结部分, max(0, 余额 − 在途预留 − 全部冻结))——底线给扣费用，不给作废用，所以作废不制造欠款、在途结算总收得下。余下留给下一轮；"额度过期"的版本号是作废前的累计作废额。重放与余额对不上的账户不作废、报错。每账户 30 秒、每轮 5 分钟预算，失败的账户不让任务失败；扫描位置存 `billing.expiry_cursor`。
- **排障**：失败计 `axiom.billing.expire.failures`、记 Error 日志「credit could not be written off」（一轮最多列 20 个），常见原因是绕过账本改过余额或长事务占锁。重新分配一个账户：持余额行锁把 `balances` 的 `allocated_seq`、`allocated_at`、`allocated_id`、`unfunded` 改回默认，把 `credit_batches` 的 `consumed`、`expired`、`freeze_total`、`unfreeze_total`、`refunded` 清零（保留 `balances.frozen`）。没作废完的到期批次计 `axiom.billing.expire.deferred` 和 `.amount`，连续增长时查 `reserved`（超过截止时间仍挂起，清理没接上）或 `frozen`（退款冻结未落定）大的账户。不手改 `credit_batches.expired`。
- **退款**：只有付费、没用掉、没过期、没冻结的部分能退。先无锁预放（`PrepareRefund`），再在账户锁内补齐；可退 = min(批次剩余 − 已冻结, max(0, 余额 − 在途预留 − 全部冻结))。随后**冻结**：不改余额、不记分录，但准入、追加和结算上限扣除它，分配跳过、到期不作废；渠道成功转"退款"分录，失败解冻，冻结期间的欠款由解冻额先还。冻结和解冻是余额行锁内带序号的重放事件。**金额**：净付款额 = 实付 − 手续费（政策为退手续费时就是实付；第一笔成功退款定下政策，之后不可改），每笔退 ⌊退款额度 × 净付款额 ÷ 入账额度⌋，累计达入账额度的那笔补足；退还手续费按累计现金 × 原手续费 ÷ 原实付向下取整的增量分配。与今天的汇率和订单报价无关。须人工或运营 agent 审核，受资金操作上限约束。
- **拒付**：`ChargeBack` 扣回入账额度减已退、已扣（已用或过期的部分让余额和批次剩余变负，不进 `unfunded`），现金扣回实付减已退，手续费冲回原手续费减已退；要求批次冻结中为 0。`ReverseChargeBack` 以同金额和版本反向记账，订单仍保持被拒付。两者以批次 ID 为 `request_id`、版本是第几笔拒付，重复由 payments 的 `order_disputes` 挡住（[支付的「拒付」](payments.md#拒付)）。

### 供应商成本

- **结算货币和单位余额价值**（"1 单位余额 = 多少钱"）由供应商模块存和确认（[供应商的「接入流程」](suppliers.md#接入流程)），每行固定确认时的结算币种和原生单位，只在两者与当前配置一致时生效；确认之前供应商不进路由。之后按每次充值的实付和到账余额加权平均追加新值，节点从下一次 Reload 起使用。每次尝试按开始时快照里的值换算，`attempt_costs.unit_value_id` 存行 id，可复算。结算币种限定为记账货币或支持的币种，否则 422（`/settlement_currency`）。
- **成本计划**：适配器为每个端点生成"用量 → 成本"表（原生单位、币种 `XXX`、目录的[价目表结构](catalog.md#价目表的结构)），按次价、分档、价格覆盖、长上下文倍率都翻译进来，计费只认它。分时段价格不支持（Issue #24），这类和其他表达不了的端点不使用。按请求项按每次已执行的尝试计一次，上游没报用量也计。
- **官方 API** 按原价算，折扣体现在对账后的利润；**号池**可选"官方价 × 系数"或"实际支出平摊并平滑"，实际支出单独记账。
- **每次尝试都记成本**，包括失败和被回退的；向客户端转发任何内容之后不再换端点；没有用量的先按估算记并打标记。
- **以供应商记录为准**：逐条匹配、容差、摘牌、暂挂和告警由 River 每分钟运行（[供应商模块的「对账」](../../internal/suppliers/README.md#对账)）；按 key 按天总数和余额变化的对账未接入。
  - 对账键：new-api 的 `X-Oneapi-Request-Id`；sub2api 的 `X-Client-Request-Id`（列表里带 `client:` 前缀）；自有号池按请求号。
  - 一次尝试至多对上一笔扣费，反之亦然；对账键相同的尝试有两个以上时都不对上。容差 = 供应商取整（new-api 1 quota、sub2api 十位小数）+ 估算的 1%（可调）。实际高于估算超容差时，端点仍用这次的成本计划就改回"成本未知"、退出路由并告警，否则只记 warning 并上报估低笔数；低于估算只告警。
  - 扣费 30 分钟（可调）没对上改"暂挂"：不记账，由运营归到某个丢失的请求或确认为"未归属成本"；真实尝试后到时改归它。
  - 扣费每次变化版本加一并同事务写 `ChargeSettled`；billing 按（扣费记录，版本）幂等。只支持钱包资金，其他来源的暂停并告警。
  - 用户售价按锁定版本，不随记录变；估算成本与实际扣费的差额记成本调整。
  - **用户收费校正**：billing 每分钟按 `(created_at, id)` 游标读事件，只处理结算已完成、整笔暂估、属于被收费的尝试、供应商标 `complete` 的请求；用 `charge_records.usage` 和锁定的售价版本重算，在事件版本上冲正再重结，受余额底线约束。预留未结算的进重试表，1 分钟起退避到 30 分钟，每轮最多 10 页。只校正暂估，已报告的项已是实际值。
- **供应商余额**：低于阈值告警；路由按这次请求的完整生成上界（`billing.ReservedCost`）比较供应商余额，付不起的端点不进路由，也检查供应商的实时自动暂停（[路由](routing.md#一个请求的路由步骤)）。

### 定价

- **规则**由定价对象、适用人群、方法、约束组成，先比对象再比人群，对象和人群都相同的两条拒绝保存：
  - 对象从具体到宽泛：端点 → 分组 → 供应商 → 模型 → 模型厂商 → 来源类型 → 全部，**只生效模型、模型厂商、全部**，其余保存或预览 422（`/rule/target/kind`）；
  - 人群：指定账户 → 指定等级 → 全部；ID 必须是规范 ID 且属于本站。账户专属的全部模型规则不会盖过面向全部账户的单模型规则。
- **加价只在这里**：给等级或账户的加价是一条人群指向它的规则，等级表不存加价（[账户的「等级」](accounts.md#等级)）。
- **方法**：
  - 成本加成：每个端点**自己的**成本计划 × 单位余额价值 × 汇率得到保守成本，乘（1 + 比例）或按毛利率换算、加固定加价（每个服务等级都加），得到该端点的售价；缺完整换算依据时不发布该模型；
  - 参考价倍率：参考价（[目录基线](catalog.md#目录基线)）× 倍率。必须显式选 `face`（只用本站币种参考价）或 `exchange`，缺省 422（`/rule/method/currency_conversion`）；`exchange` 依次选本站币种、USD、字母序的参考价，缺汇率时该模型不发布、不改选更宽规则，相乘后向上取整一次；
  - 固定价：直接写各项价格。固定价和固定加价过目录的新项开关（`catalog.Config`），关闭时含 `file_search`、`file_parse` 的规则 422。
- **BYOK 服务费**：BYOK 端点在路由快照里把同模型基础参考价表（不乘人群专属层）乘站点费率得到售价表，成本计划为 0，计费不需要知道 BYOK。费率存 `billing.price_policies.byok_fee_bps`（0–10000，缺省 500），随 `PUT /api/admin/v1/pricing/policy` 读写（`pricing.manage`，写要 MFA、幂等键、理由并审计；省略时保留当前值）。`usage.is_byok` 在服务的条目是 BYOK 时为 true；`:free` 不进 BYOK 端点。按 list-price 的每月免费额度未实现。
- **计费项**：输入、输出、缓存读、缓存写（5 分钟 / 1 小时）、推理、音频进出、图片进出、按次工具（联网搜索、代码执行、文件搜索、文件解析）、按请求（每个生成请求一次），每项一个单价；按张的图片、按整秒的音频、按字符的朗读文本各是一项。
  - 联网搜索：`web` 插件和 `:online` 一次请求一次，`openrouter:web_search` 每次成功搜索一次；代码执行按调用次数；文件搜索按调用次数，价格只来自模型价目表，声明该能力的模型须在 `items` 里同时声明它。
  - 文件解析按页计：`mistral-ocr` 每页一个 `file_parse`，`cloudflare-ai` 免费，`native` 按输入 token；PDF 页数是 Docling `json_content.pages` 的条目数（空页也计），非 PDF 才用 `md_page_break_placeholder` 的出现次数加一，PDF 缺页数字典按上游失败拒绝。价格只来自模型价目表；它不由上游报告、不在规格 `items` 里。`Config.FileParse` 关闭时每个解析的文件按一次 `web_search` 计。
  - 推理缺价按同档输出价，图片缺价按同等级同档的普通输入、输出价，显式零价不回落；按请求项缺档位价时按最高请求价（预留、结算、`max_price.request` 同规则）。
  - 长上下文按用量分档；flex、priority、fast 各有完整单价，没录的是缺价，不沿用标准档（[价目表的结构](catalog.md#价目表的结构)）。
- **约束**：
  - **规则约束**尚未实现：带 `min_margin_ratio`、`reference_min_ratio`、`reference_max_ratio` 的规则保存、修改和预览一律 422（`/rule/constraints/<成员>`）。库里已有的带约束规则不改写，它命中的模型没有售价（路由排除、预览 `unpriced`、写日志），不落到更宽的规则。
  - **保本线逐端点**：端点保守成本 × 站点保本倍率（缺省 1，允许 1–10），向上取整；售价与保本成本合并上下文门槛，逐区间、逐服务等级、逐计费项取高（推理和图片用回落价）。分档口径不同、缺单位价值或缺汇率时整个模型不发布。节点建快照时用本节点成本逐端点过滤，模型没有安全端点才停卖；固定价和参考价倍率任一端点不满足即整个模型不进快照。
  - **触线提价**：端点旧价低于新保本线时，未超过单次自动提价上限（缺省 100%）就立即按保本价发布，超过才暂停新调用等待确认；同一提案里一个端点需保本提价、另一个需确认时保持旧版本。
  - **豁免**：管理员可显式确认低于保本线的规则原价，须写理由并审计；豁免绑定这次规则、成本、汇率、政策的完整依据，任一变化重新检查，不跨受众借用。
  - **价格取整**：单价向上取整到展示精度，页面显示的就是实收的单价。
- **作用范围**：平台和每个二级站点各有一套规则；二级站点的成本是站长进价（主站对其等级的售价），同样有保本线，站长可调最低利润率。
- **上架门槛**：上游可能报告的每个计费项都有售价，模型才能上架；联网搜索和代码执行缺模型单价时用站点默认价（[价目表缺项](#价目表缺项)），文件搜索没有默认价、缺了不上架；文件解析不在门槛里（缺 `file_parse` 时准入按缺价拒绝，不借 `web_search` 的价）。门槛按模型检查、查售价本身：模型只声明标准档时只有标准档售价就是完整的。站点默认价只补售价，不补参考价。
- **参考价安全阀**：自动同步的参考价先过合理性检查（单位、缓存读不高于输入），不过不采用并告警；变化超过阈值须确认后才用于重算。
- **自动重算与发布**：River 每 5 秒一个唯一发布任务，锁站点政策行后从数据库读目录、端点成本和汇率生成提案，不读节点的适配器、密钥或快照；路由只读已发布版本。发布者超过 30 秒未确认成功，路由停用旧版本，在途请求按冻结版本结算。首次安全价格自动发布；之后端点有效单价相对它当前价变化超过确认阈值（缺省 10%，恰好 10% 自动发布），或零价变非零、计费项、服务等级或端点集合增删，提案等待确认，期间保留仍满足保本线的旧价。通知是持久信号 `billing.price.review`；无端点或无规则的模型只记未定价，有端点的停卖才升 critical，持续同类故障不重复发。
- **价格版本**：每次发布追加一行不可变版本，存价目表、规则版本、参考价行、各端点成本计划、单位价值版本、汇率与政策；成本加成另存 `endpoints`（端点 UUID → 售价），模型级 `schedule` 是它们的逐项上包络，其他方法 `endpoints` 为空。确认时同时核对提案依据摘要和原已发布版本。预留按条目冻结价目表与版本 ID；旧记录版本保持未知，不补。
- **预览**：`PreviewPricing` 给各模型的保本后提案（成本加成按端点一行），可选 `current_sale`、`current_version` 显示当前发布价；显式发布须确认模型与理由。运营 agent 改规则走 `pricing_rule_create`、`pricing_rule_update`，立即发布的变动按价格包络计数（[运营的「售价的累计变动上限」](operations.md#售价的累计变动上限)）。规则把某模型单价乘过上限时只有那个模型无售价并告警。
- **`:free` 的售价必须为零**，非零时该模型不发布。

### 预留与结算

- **预留**是一笔挂起的转账：先从余额划出、结算时过账、多余作废（两阶段转账），存在 PostgreSQL，不是账本分录、不改余额。状态：挂起 → 已结算 / 已释放 / 清理已释放（转移见[模块 README 的「预留的状态」](../../internal/billing/README.md#预留的状态)）；每次状态变化比较后再写，每个请求恰好由一次结算或清理落定。
- **分段**：一段大小与超额额度是后台数据（`billing.segment_settings`，平台一条；`/api/admin/v1/settings/segments` 校验、审计；空记录用代码默认 1000 输出 token、2 秒），能否分段取决于模型规格的 `output_speed`（不大于 0 不分段；现有规格都没写，所以当前预留都是全额）。路由和计费读同一个 `billing.SegmentPolicy`，节点每 30 秒重读，路由把计划时的 `Segments` 冻结进计划；可分段却没有分段大小时报错而不少预留；超额额度短于追加等待的记录保存时拒绝，重读到不可用记录保留旧值。
- **准入**（调用上游之前，一个事务）：
  - **三层限额同时预留、取最严**，窗口按 UTC 在准入时锁定，追加和结算记回它：账户余额（不够 402）、工作区预算、key 花费上限（不够 403，`limit_source` 为 `openrouter_workspace_budget`、`openrouter_key_limit`）。预算和上限是金额加重置周期（日、周、月、不重置，[账户的「工作区」](accounts.md#工作区)）；`spend` 按 UTC 日记、工作区和 key 各一行，限额按窗口覆盖的日子求和；工作区预算由其所有 key 共用，调低到已用之下即拒新调用。
  - **每个条目自己报价**：可分段的报第一段 = 输入上界 + 首段输出 + 按请求价 + 按次项目最大次数 + 请求写明的张数、秒数、字符数 + 超额额度；不可分段的报全额，输出按上限。计数项按该条目最贵单价乘请求声明的数量，每次内部采样一份；按次项目一开始预留足。预留取保留条目报价的最大值，回退不会落到更贵的条目。
  - **`web` 插件**按所选搜索引擎的对外价：锁定售价表的 `web_search` 换成 每次搜索价 +（`max_results` − 1）× 每条结果价，价格存在搜索引擎行（`price_search`、`price_result`、`price_version`），为 0 沿用模型价。原生搜索按模型价乘 `web_search_requests`。
  - **只按计数项计费的模型**（`Model.Reports` 与 token 项交集为空，如 `tts-1`、`whisper-1`）不要求 token 单价；`Reports` 为空表示未知，仍要求。
  - **输入按可证明的上界**：文本 token 不超过字节数；每张图片按单张最大 token 数，每个文件按单页最大 token × 最大页数，没有上界时按上下文长度（当前模型数据没有这些，带图片或文件的请求按上下文长度预留）；合计不超过上下文长度。文件解析的页数只用于 `file_parse`。
  - **多次内部采样**：采样次数 = 1 + 各服务端工具最大次数之和（请求没写用该条目模型的默认值），开启服务端压缩（`context_management`、`compaction`）再乘 2；第一次按上界、之后每次按上下文长度，各按自己的分档相加。`openrouter:web_search` 的输出预留乘 1 + `MaxUses`（`max_uses` 与 `max_tool_calls` 较小者，缺省 30）。`web` 插件、`:online` 和 `file-parser` 在采样前执行，不增加采样：前者把注入上界 `protocol.WebSearchMaxBytes` 加进首次输入，后者按 `Request.FilePages` 预留 `file_parse`；与原生搜索同在时原生工具仍各自要上限。
  - **批量**：embeddings、rerank 不要求输出价、不预留输出，rerank 的 `search_units` 是只收一次的 `web_search`；旧版补全的 `prompt` 数组输出按 `n × prompt 数 × max_tokens` 一次预留、不分段，`best_of > 1` 在准入前 400。两者的输入、按次价、分档和路由最高价过滤都按全批总量，上下文按最大一份检查（`Request.MaxInputBytes`）。
  - **服务端工具必须有上限**：开启联网搜索、代码执行或文件搜索却没写次数（Messages `max_uses`、Responses `max_tool_calls`）、模型也没有 `max_uses` 默认值的，调用上游前 400 `invalid_request`；Chat 的联网搜索和 Messages 的代码执行没有上限字段，回"该格式暂不支持这个工具"；路线上任一条目没有上界整个请求拒绝。
  - **服务等级**取请求允许的与端点提供的交集再加标准档。上游报告了列表外的等级，那次各项按兜底价收并标暂估，未声明档记入 `unknown_items`（[价目表缺项](#价目表缺项)）。
  - **输入不假设缓存命中**：按最贵输入侧单价预留（含缓存写价，可能报告缓存读时含缓存读价）；Chat、Responses 调用读写可能重叠，输入上界 N 按 `N × max(输入侧最高价, 缓存读最高价 + 缓存写最高价)`、输入侧固定含缓存写和图片输入；Messages 取单项最高。输出含图片输出。
  - 用户和站长两边都要求"余额 − 在途预留 − 本次预留 ≥ 余额底线"；付不起的条目一遍删掉，首选条目被删才在调用上游前 402 或 403 并指明哪一项不够。
  - **余额行是账户资金写入的唯一串行点**：预留、追加、结算、退款、清理都先锁它，花费计数只在持锁时改；两个账户（二级站点）按编号从小到大锁。
  - 预留写入数据库之后才调用上游。
- **转发中追加**：
  - 从读到上游第一个字节起边读边累计：已报告的输入侧项用准数；输出按内容字节计（[protocol 的「转发（草图）」](../../internal/protocol/README.md#转发草图)）加每个客户端工具调用的框架（`billing.ToolCallTokens`：Claude 45，OpenAI 0），最终用量之前取它与已报告数的较大者。联网搜索按事件计数；`web` 插件搜索和 `file-parser` 每页解析成功即记一次，只加到用户侧、不进供应商成本。模型侧循环的已结束跳由 `Meter.Complete` 并入累计。
  - 当前段用掉 40%–60%（每请求随机一次）时申请下一段：按这次尝试绑定条目的价格版本计价，申请累计目标，只增不减，各项限额一起查。
  - 当前段在追加提交前用完时暂停转发，最多等追加等待期限（后台数据，缺省 1 秒）；超时或失败就中断上游并结束回答：余额或 key 额度不足发 `credits_insufficient`，数据库出错发 `billing_unavailable`（[接入的「错误」](gateway.md#错误)）。
  - **超额额度** =（追加等待 + 生成到看见、取消到停止计费的延迟上限）× 模型最快输出速度 × 输出单价，在第一段一起预留、保留到结算，所以并发请求各自用满也不越底线。
  - 每段大小和每个模型的默认输出上限是后台数据；请求没写输出上限用模型默认值。
- **一次预留足**（按条目和请求判断，准入按上限报价，不追加、不截断）：不能持续观测计费进度（网关在适配器允许时一律以流式调用上游、自己聚合；推理不在流里显示或上游不能流式的仍属此类，推理可见性是模型数据 `reasoning_visible`）；端点不传递取消（[客户端断开](#客户端断开)）；超额额度接近输出上限。
- **结算**（回答结束前同步完成，一个事务）：
  - 去重键是"请求 ID + 尝试序号"。
  - **按实际服务端点的售价收费**：结算读实际服务条目冻结的价目表，其余释放；调用记录、明细和 `charge_details` 显示这个条目的版本。
  - 按[免单规则](#免单规则)收费、记账本（二级站点同时记站长那一笔），释放预留，更新 key 和工作区花费，记每次尝试的供应商成本和对账键；同一事务写供应商侧的尝试行，成本与账本同成同败（[模块边界规则](../architecture.md#模块边界规则)）。
  - 进入终态（已结算、已释放、清理释放）的事务里调用 `EndRequest`，时间取数据库时钟；清理释放同时写一行带冻结路线的丢失的请求。
  - 实际金额在预留之内；万一超出按余额底线的写入规则处理。费用写进流的最后一个事件，估算的标暂估。
  - 结算写不进时，执行它的进程带着准确用量重试到截止时间，之后由清理接管。客户端看到什么见[接入的「用量与费用」](gateway.md#用量与费用)。
- **余额底线**：按账户设置，缺省由站点配置，缺省 0，可以为负。
  - 每笔收费（结算、迟到补扣、兜底价收费）最多收 余额 − 底线 − 其他请求的在途预留 − 全部冻结，超出部分记「平台承担」，提交后记 Error 日志并计入 `axiom_billing_platform_borne_total`、`axiom_billing_platform_borne_amount_total`。只在假设被打破时发生：输出快过设定速度、不认识的计费项首次出现、清理后的迟到补扣、上游按更贵等级服务。
  - 余额不够新请求的预留时拒绝新请求，充值后自动恢复，不是封号。
- **热点账户按批合并**（[#296](https://github.com/TYCT-tyct/Axiom/issues/296)、[#304](https://github.com/TYCT-tyct/Axiom/issues/304)）：
  - 网关在进程内按账户排队（[gateway 的「账户闸」](../../internal/gateway/README.md#账户闸)），同一账户同时只有一个批次进数据库，每批一个事务、一把余额行锁：准入批最多 32 个，完成批（追加、结算、孤儿结算）最多 16 个，完成先于准入。已有两个以上请求时才最多等 1ms 收集同伴；在闸上最多等 `AccountGateWait`，等不到 429；取进批次后按 `AdmissionBudget` 计时。完成类不设闸期限。
  - 同批后面的请求看到的余量扣掉前面将预留的金额；业务拒绝只作用于那个请求，数据库错误整批回滚、按请求 ID 幂等重试（[模块 README 的「同一账户的合并预留」](../../internal/billing/README.md#同一账户的合并预留)）。
  - 节点本地额度块仍待定（RFC 4006 的按段授予）。
- **二级站点**：同时预留终端用户和站长两个账户，一个事务分别记账。站长余额不足时对终端用户返回通用错误，不泄露站长财务，同时通知站长；终端用户被封顶少收的部分记平台承担，不转成站长欠款，也不向用户补收（随 M2，[#28](https://github.com/TYCT-tyct/Axiom/issues/28)）。

### 持有者与截止时间

进程崩溃、活着但漏了结算、数据库长时间不可用，都要有人把挂起的预留收尾。

- **持有者**：每个核心进程启动时生成一个，它准入的预留挂在它名下，靠心跳续期；停跳超过有效期加宽限由清理回收，此后它名下不能新增或追加预留，清理再处理它仍挂起的预留。
- **`Billing.Run`**：心跳周期不超过 TTL 的三分之一（缺省 TTL 60 秒、心跳 10 秒、宽限不小于 TTL）；`Alive` 在最近成功心跳加 TTL 减 5 秒后为假，网关据此不发新尝试。启动时和每 30 秒回收过期持有者并接管到期预留，一次最多 5 批 × 200 个。回收只在本进程持有者活着、且连续 TTL + 宽限没有失效时进行，回收事务以半个心跳周期为限。心跳和回收走池外的专用连接（`pg.Dedicated`）。发现自己被回收时返回 `ErrReaped`，节点退出重启；其他心跳失败只记日志。
- **截止时间**：每笔预留另有截止时间（准入 + 单次调用最长 + 结算宽限），过了仍挂起的不论持有者死活都由清理处理。
- **清理只释放、不收费**（`cleanup_released`），同时让供应商侧记一行带冻结路线的丢失的请求（[suppliers 的「没有对账日志」](../../internal/suppliers/README.md#没有对账日志)），每笔记一条警告日志。内容已交付、结算未提交时崩溃的尝试没有成本行，由供应商逐笔记录补齐。
- **迟到的结算**按完整结局和真实用量正常收费，与清理多退少补，补扣按余额底线的写入规则，并把丢失的请求标为已解决；没有任何尝试的不收费，也标为已解决。结算永远不来的请求，成本由平台承担。

### 用量来源与暂估

- **优先用上游报告的用量**；超出上限或自相矛盾（如输入侧减出负数）视为没有报告并告警。
- **按调用事件计数的按次项目**：网关数 Responses 的 `file_search_call`、`code_interpreter_call` 输出项和 Messages 里名为 `code_execution` 的 `server_tool_use` 块（`output_item.done` 不重复），结算取上游报告次数与事件数的较大者；没有报告时标暂估。
- **报告不全或无效**（流断、失败帧）：已报告的项保留，只估缺的：输入按请求估，输出按已转发文本估，按次项目按事件计，标暂估。失败帧（Anthropic `error`、Chat 出错块、Responses `response.failed`/`error`）的用量过同样校验后，明确报告的项算最终值；Responses 在第一个失败事件结束尝试。
- **先接受、后变无效的报告**：计数变小时整份作废但保留第一次接受的计数；输入侧合计取保留各项之和与估算的较大者，物理总数另提到估算值（只增不减），结算不超过预留（[#339](https://github.com/TYCT-tyct/Axiom/issues/339)）。
- **暂估用最好的估计，不用预留上界**，之后由校正按供应商记录重算（[供应商成本](#供应商成本)）：
  - 输入文本：OpenAI 的 o200k_base、cl100k_base 本地精确计数；Claude 分两族（Opus 4.7 之前、之后，读不出版本按新族）按文本形状乘族的 token 权重。只数解码后的字符串值；token 数组每个 ID 记一个 token，旧版补全的 `suffix` 对第二份起每份按 4 字节 1 token 再计。每族每会话最多分词 256 KiB，余量、未知族和计数失败按 4 字节 1 个 token。
  - 每张图片 1600 个 token、每个文件 4096 个，模型数据的上界更小时取上界。
  - 输出按已读内容的形状乘该族每字节 token 数，无权重的族按 3 字节 1 个 token，再加客户端工具调用的框架；不低于已报告数，不超过字节数和预留上界。
  - 请求写明、上游未报告的张数、秒数、字符数按请求的数量估。
  - 误差实测见[计费存档](../archive/billing.md#暂估的误差)。

### 客户端断开

- 传递取消的端点：立即中断上游，按已产生的用量收费，从不免单。
- 不传递取消的端点（断开后上游照读完、按全量向我们扣费）：继续读完上游（不再转发），拿到完整用量照常结算，用户按全量付费，计费说明里写明。
- **是否传递取消是端点属性**：适配器按所接系统给默认值（new-api 传递，前提是流式调用，Axiom 对它一律流式；sub2api 不传递），端点级实测以后覆盖它。站点前有不传递断开的代理时，平台多付的差额由对账发现（[#227](https://github.com/TYCT-tyct/Axiom/issues/227)）。当前预留都是全额，所以这个属性只决定断开后立即取消上游还是读完它。
- 取消不直接动钱：预留只经结算或清理落定。

### 价目表缺项

上游报告了价目表没有的计费项，或这次调用落在没定价的地方时，从不免费：

- **有站点默认价的按次项目**（联网搜索、代码执行）：默认单价存 `billing.fallbacks`，每个记账币种一行，只含币种和这些项目的单价；必须有 USD 行；每项必须有效（币种和单位正确、大于 0、不超过 1 个币种单位），启动和保存时检查，不合格不启动或拒绝保存。初始 USD：联网搜索 0.025/次，代码执行 0.05/次（一小时容器价）。模型没有这一项单价时准入补上默认价并锁进预留。文件搜索和文件解析不在这里，价格只来自模型自己的价目表。
- **不认识的计费项**：第一次出现时该模型移出路由（`unknown_items`）并告警，直到管理员定价后清除；在途请求按兜底价收、标暂估：像 token 的按该模型最高 token 单价，否则按最高按次默认单价，受余额底线约束；之后供应商记录完整且声明了该项时会被校正。清除后同一字段再出现不再移出。
- **定价不了这次调用**（上游服务在售价没定价的等级，或某项在那个等级没价）：用量不为零的各项按兜底价收并标暂估：token 按全部等级和档位里最高 token 单价；有默认价的按次项目按默认价（不取模型在别的等级写的价）；文件搜索、`mistral-ocr` 文件解析按价目表里它自己的最高价，一项都没有时按最高 token 单价；按张、按秒、按字符的项按同单位最高价（显式零价也算有价），同单位一个价都没有时按最高 token 单价，绝不为零。已声明档位内的单纯缺价不移出路由；报告了模型声明之外的已知档，按 `service_tier.<名称>` 写入 `unknown_items`，下一次路由快照排除该模型（不作为一次工具使用计费）。免单时 token 和按张、按秒、按字符的部分不收，按次项目照收。

### 免单规则

- **免单条件**：上游报告的输出为 0（普通输出、推理、音频输出、图片四项 token 之和，加交付的图片张数与音频输出秒数，且每次采样都报告了输出），并且结束原因为空或出错，并且不是客户端主动取消。只有推理、音频、图片或工具调用的回复照常收费；图片交付后失败不免单。按张、按秒、按字符的项是交付的产物，免单时一并免掉。没有上游用量的不免单。免单与金额无关，也没有次数上限。
- **收费的尝试**：收费的是最后一次尝试，按它的结局；之前被回退的只记成本。`openrouter:web_search` 循环的每次采样是同一条目上的一次尝试（`AttemptResult.Continues`），各有序号、成本行和对账键，最后一次连同循环全部采样一起收费（`reservations.charged_seq` 记 NULL，供应商对单次的记录不能修正整笔）；循环最后一次确知未执行时按"没有内容交到客户端"那行收。
- **没有内容交到客户端的失败不收模型用量**。"交到客户端"：流式指已写出正文、推理或工具调用，非流式指内容随响应返回。

| 最后一次尝试的结局 | 向用户收费 |
|---|---|
| 确知未执行：请求没写完，或适配器把非 2xx 归为执行前拒绝（参数 400、401、403、402、429） | 不收，尝试成本记 0 |
| 没有内容交到客户端：2xx 之后、转发之前失败；结果未知（请求已写完、没拿到响应头或用量，或 5xx、504、认不准的状态，成本按估算记）；非流式聚合失败且不返回内容 | 模型用量不收，平台记成本（免单损失）；已执行的按次项目照收。`web` 插件搜索和 `file-parser` 解析在模型调用前：它们自身失败不收，成功后模型无内容失败照收这一次；`openrouter:web_search` 循环中途失败时已成功的搜索照收 |
| 内容已交到客户端后出错、截断、超时；非流式聚合失败而内容随错误返回（Chat、Responses） | 按用量（缺的项暂估），再套免单条件 |
| 客户端取消 | 按用量或暂估，从不免单 |
| 正常结束 | 按用量，再套免单条件 |

- 以收费那次尝试的结局为准：第一次尝试失败、无内容交付，准备下一次时客户端才断开，仍按"没有内容交到客户端"收；只有收费那次本身因客户端离开而结束才算取消。
- 按次项目和按请求项照常收费；上游不收费的拒答跟着不收。解析在准入之前，准入被拒时解析的成本由 key 速率上限、文件大小上限和解析超时兜底（[接入的插件表](gateway.md#服务端工具)）。

### 账本

- **一张表**，以"站点 + 货币"区分各本账。分录不写币种的是记账货币，写了的是付款币种；金额都是该币种一个单位的十亿分之一（分是 10⁷，日元是 10⁹），现金按实付原样入账。每笔交易在每个币种里合计为 0：写入时断言，每日自平按币种核对。用户余额只用记账货币。
- **科目**：现金（按收款渠道和币种）、用户与站长余额、平台收入、二级站点收入、手续费收入、渠道手续费、供应商预付余额（按供应商和币种）、供应商成本、号池支出、赠送支出、套餐折让、套餐未用额度（负债）、汇兑损益、拒付损失、额度过期收入、平台承担。

| 事件 | 借 | 贷 |
|---|---|---|
| 用户充值 | 现金（实付，付款币种） | 手续费收入（付款币种）、用户余额（入账额度）；跨币种时付款币种贷汇兑损益（实付 − 手续费）、记账货币借汇兑损益（入账额度）；同币种取整零头贷汇兑损益 |
| 渠道扣费（交易手续费、拒付手续费、链上归集费） | 渠道手续费 | 现金 |
| 赠送、兑换码 | 赠送支出 | 用户余额 |
| 套餐发放（赠送） | 赠送支出（总额度） | 套餐未用额度（总额度） |
| 套餐购买 | 现金（实付）；套餐折让（总额度 − 折合额度） | 手续费收入、套餐未用额度（总额度）；折合额度高于总额度时差额贷平台收入；汇兑同充值 |
| 请求结算 | 用户余额（实收）、平台承担（应收 − 实收） | 平台收入（应收；二级站点为站点收入） |
| 请求结算（套餐） | 套餐未用额度（实收）、平台承担 | 平台收入 |
| 站长进货 | 站长余额 | 平台收入 |
| 尝试成本 | 供应商成本 | 供应商预付余额 |
| 成本调整（对账差额，为负时对调） | 供应商成本 | 供应商预付余额 |
| 给供应商充值 | 供应商预付余额 | 现金 |
| 号池实际支出 | 号池支出 | 现金 |
| 退款 | 用户余额（退手续费时另借手续费收入） | 现金 |
| 套餐退款（`plan_refund`） | 套餐未用额度（收回窗口额度 − 已用）、收入冲回（已用部分）、手续费收入 | 现金；折让或溢价按收回比例冲回；汇兑各自平衡 |
| 额度过期 | 用户余额 | 额度过期收入 |
| 套餐到期作废 | 套餐未用额度（剩下的） | 额度过期收入 |
| 拒付 | 用户余额（扣回未退额度，可为负）、手续费收入（冲回）；差额记汇兑损益 | 现金（被拉回的总额） |
| 坏账核销 | 拒付损失 | 用户余额 |
| 补扣（结算丢失后补回） | 用户余额 | 平台收入 |
| 冲正 | 原分录借贷对调 | |

- **费用校正**：冲正当前有效的请求结算，再按新金额记一笔请求结算，同事务提交、都引用原请求；幂等键为 请求 ID + 尝试序号 + 种类（`reverse`、`settle`）+ 供应商记录版本号，再次校正用更新的版本。校正先锁余额和预留、重放分配，写完保存分配。事件生产者和消费者共用事务级 advisory lock，事件时间用插入时的 `clock_timestamp()`，先开始后提交的事件不会落在游标之后。
- **平台承担**既是科目，也是请求明细里应收（`price`，封顶前）与实收（`charged`）之差；少收只有余额封顶一种机制，不设原因字段。
- **免单不额外记账**：只是不记"请求结算"，尝试成本照记并打"免单"标记。
- **每日自平**：周期任务 `billing.reconcile`，启动时先跑一次、之后每 24 小时，领导节点插入。只读账本，找出分录合计不为 0 的交易和余额与账本不符的账户，每个问题一条 Error 日志（最多列 20 条）并计入 `axiom_billing_reconcile_problems_total`；同事务持久发布差异数量与恢复信号，并从正向平台承担分录补发丢失的即时告警（[告警设计](observability.md#告警信号事件与规则e5-3)）。
- **去重与更正**：交易按 `(request_id, attempt_seq, kind, revision)` 唯一；记错了不改原记录，记冲正。带版本号的有迟到结算（−1）和暂估校正（供应商事件版本，从 1 起）。
- **合并写入**只合并 SQL 和余额更新，不合并交易：批内每个事件仍是自己的交易，余额终值等于起始余额减各事件扣款之和。
- **余额提醒**：余额实际变化和付费批次到账在账本事务里写提醒 journal，由 accounts 消费（[账户的「用户提醒与站内公告」](accounts.md#用户提醒与站内公告)），调用路径上不发网络请求；只有钱包实际过账穿越阈值触发，赠送不算充值。

### 风控状态

- **账户状态**：正常、余额不足（拒绝新请求，充值后自动恢复）、暂停（只用于拒付和欺诈，人工解除）。Stripe 的 `dispute_open`、`dispute_lost` 在记拒付的同一事务把账户置为暂停（`accounts.SetAccountSuspended`），准入以 `ErrAccountSuspended` 拒绝新调用；登录、建 key 不受影响；胜诉不自动解除。暂停和解除写 `account.status_change` 审计，持久化 `accounts.account_suspended` 信号（[支付的「拒付」](payments.md#拒付)）。
- 退款与预留都先锁账户余额行，防止先退款再花钱。
- 管理员动钱的操作（加额度、改价、冲正、退款）都记审计；套餐退款和支付退款须另一个管理员批准，超过阈值再二次确认。

### 用户看得到什么

- **模型与端点价**：`/api/v1/models` 和公开页面给可服务端点中最便宜的售价；`/api/v1/models/{author}/{slug}/endpoints` 和页面逐端点列代号、属性和售价，`provider.max_price` 与价格排序按端点价。同一分组的代号跨模型相同，是 `provider.only`/`ignore` 和预设顺序用的公开身份。不返回供应商名称、上游、内部 UUID、采购价、成本或发布依据。
- **调用明细**：控制台调用列表/详情和 `/api/v1/generation` 返回可选的 `charge_details`：逐采样列出收费项、数量、单位、实际服务档与上下文档、冻结售价版本、精确单价/金额和暂估标记；小计保留 15 位，整次向上取整到十亿分之一，单列余额底线减收，三者合计等于实收。免单省略模型项、仍列工具；未执行为空明细；未知用量只以 `unknown_tokens`/`unknown_uses` 展示，不回显原始字段名；历史或判定依据缺失的不返回明细。
- **余额**：控制台余额接口返回余额、在途预留、底线、可用额度和本月花费，被拒的用户能看懂为什么。
- **额度流水**：按账本顺序列出每笔余额或退款冻结事件（充值、赠送、兑换码、调用扣费及退费、到期、退款冻结、解冻、退款完成、拒付扣回、拒付冲正），带每笔之后的总余额和冻结额；账本序号之前的记录先后不确定，不给变动后余额（显示「不可用」，CSV 留空）。可翻页、可导出 CSV（最新 10 000 条）；只给用户自己这一本的金额，不给分录、账本名和内部账户。套餐扣费不动余额、不进流水，用户在 `GET /api/console/v1/subscriptions` 看套餐名、状态、起止、当前窗口额度/已用/剩余和发放来源。
- 低余额提醒的收件人、模板和品牌见[账户的「给用户的邮件」](accounts.md#给用户的邮件)。

### 自带货源的服务费

- BYOK 按"参考价 × 站点费率"收服务费（见[定价](#定价)），缺省 5%，站点可设为 0 免收；不用成本加成，因为成本为 0 时加成结果仍是 0。按月免费额度未实现。

### 怎么验证

- **性质测试**：随机请求序列（崩溃、重试、并发、截断）始终满足账本平衡、余额等于记录之和、不重复扣、调用收费不越底线、平台承担只出现在记录在案的情形；迟到结算重复、并发投递结果确定；套餐和额度批次各有性质测试。
- **批量**：随机金额的准入批与逐个单元素批结果逐项相同；多批并发总量不越底线；一个请求的拒绝不影响同批其他；写失败整批回滚、按请求 ID 重试各收一次；告警只在提交后。
- **验收用例**：追加写库被阻塞而上游继续生成时，到期中断并截断，消耗不超过超额额度；同账户多请求同时用满超额额度不越底线；多个暂估请求同时结算不越底线；清理后迟到补扣最多到底线、其余平台承担；输出快于设定速度时只扣到底线并告警；不认识的计费项首次出现时模型移出路由、在途按兜底价暂估。
- **回放**：录制的真实流（正常、断开、`message_start` 之前出错、无最终用量、用量无效、搜索循环、非流式长输出）的结算结果固定。
- **故障注入**：结算前后杀进程、数据库超时。
- **监控**：暂估占比、缺项次数、平台承担的金额和次数、作废推迟的批次和金额、对账偏差、成本漂移、截断和拒绝次数；新 key 用量突增告警。

## 决策与理由

参考实现的源码位置、实测数据和被否决方案的比较在[计费存档](../archive/billing.md)。

| 决策 | 理由 |
|---|---|
| 站点各用自己的记账货币，主站美元 | 负责人同意；二级站点用人民币时"¥1 = $1"不需要假"美元"。 |
| 计算中途不取整，取整对平台有利 | 逐项取整会累积误差；每次最多多收十亿分之一额度。 |
| 参考汇率贯通成本与售价；自动源 ECB、缺省关闭，人工对优先 | ECB 无密钥、覆盖全部币种；缺省关闭保留现有经济行为。 |
| 汇率规范化、精确分数、串行版本；调整限五倍，纠错只豁免相对限制 | 正反向不能有两套历史；首值反填须能带理由纠正。 |
| 换算未知使利润未知，不影响原生对账 | 不能把已知部分当全部成本。 |
| 充值缓冲缺省 2%，按站点存 | 人工汇率滞后于市场，2% 约等于卡组织换汇价差。 |
| 二级站点的换算率由站长设定 | 负责人同意；平台不承担其汇率风险。 |
| 钱包与套餐的先后是账户偏好，四个值 | 同 new-api，满足 #310「耗尽后回退钱包」。 |
| 一次调用只用一个资金来源 | 中途换来源要部分结算，无法从预留行复算。 |
| 套餐条款发放时快照，一账户一个有效套餐 | 改套餐不改已售窗口；"当前窗口"唯一。 |
| 发放记负债，标价差额记套餐折让，到期转额度过期收入 | 负债等于能扣的上限；账本收入与按调用汇总一致。 |
| 窗口重置只推进指针 | 准入热路径不写账本，迟到结算能记回原窗口。 |
| 清理后迟到结算走钱包，作废后校正从额度过期收入转回 | 重新占窗口会把同一份额度卖两次；负债保持非负。 |
| 套餐退款管理员发起、第二人批准、按累计比例收回未来窗口 | 负责人要求；固定扣整段会让退一半也失去整个套餐。 |
| 额度批次先用最早到期的，后台按账本序号重放分配 | 结算不多写一行；做法同 Stripe、Metronome 的额度授予。 |
| 兑换码写 `redeem` 批次，ID 用兑换记录 ID | 不收钱的额度不能退出现金；同 ID 重放幂等。 |
| 重放按交易序号，不按时间 | 时钟会回拨；序号在余额行锁内取，就是提交顺序。 |
| 作废不用底线 | 否则赠送到期会制造真欠款。 |
| 冻结、解冻是带序号的重放事件 | 否则今天的冻结额会作用到全部历史扣费。 |
| 批次视图有界重放，追不上不返回 `batches` | 余额读不能为解释余额无界重放账本。 |
| 退款按批次实付与入账额度之比折算 | 按今天汇率或订单报价退会被套利或多退。 |
| 线下付款按参考汇率向下取整、不加缓冲；入账额度由服务端算 | 缓冲属于渠道报价；实付与入账之比是退款依据。 |
| 分录带可空币种，现金按实付入账 | 现金账逐分对上渠道账单，取整只在入账额度一次。 |
| 平台承担不设原因字段 | 少收只有一种机制，原因枚举会漂移。 |
| 成本计划由适配器生成 | 计费模块不随中转系统变。 |
| 售价按锁定的价目表，成本以供应商记录为准 | 用户价格必须确定；对账能发现偷改倍率和虚报用量。 |
| 单位余额价值按供应商存、只追加，回执带行 id | 换算是纯内存计算，历史可按 id 复原。 |
| 每次尝试都记成本，去重键含尝试序号 | 回退的尝试同样花钱。 |
| 定价规则两条轴固定顺序；加价只写成规则 | 多维"最具体优先"比不出先后；一套规则一个存储处。 |
| 售价按端点发布；阈值 10%、保本倍率 1、自动提价上限 100% | 产品要求同模型不同端点不同价（同 OpenRouter）；统一价让用户为没服务的端点付费。 |
| 保本线逐端点、逐区间、逐计费项，触线提价立即发布 | 只看总价时单项可能低于成本。 |
| 不支持的约束和对象拒绝保存，已有带约束规则命中的模型不卖 | 拒绝胜过一个不会执行的承诺。 |
| 没有规则就没有售价 | 悄悄按参考价卖让规则形同虚设。 |
| 新计费项的发布开关也约束固定价规则 | 旧节点读不到新项会让售价读取整站报错。 |
| BYOK 按参考价比例收费，费率是站点数据 | 成本为 0 时加成算出 0；同 OpenRouter 5%。 |
| 分段预留、追加不到就截断，底线缺省 0 | 负责人同意（#28）；"先放行事后扣"欠款无上限。 |
| 分段设置是后台数据，路由与计费共用 `SegmentPolicy` | 它是资金风险参数，须审计；共用保证报价与"可分段"一致。 |
| 速度、推理可见性写在模型规格，缺省不分段 | 速度是模型属性，不猜。 |
| 看不到进度或不传递取消的端点一次预留足 | 分段只有看得见、截得断时才有上限。 |
| 预留输入按上界，暂估用最好的估计 | 输入一开始就花掉；暂估用上界会系统性多收。 |
| 每个条目自己报价，预留取最大值 | 不误拒只够付首段的用户，回退不越预留。 |
| 输入上界按采样次数乘；Chat、Responses 预留缓存读写之和 | 每次采样重读上下文；读写重叠时单项最高价罩不住。 |
| OpenAI 缓存读写按报告量，普通输入取余量；图片先扣缓存交集，视频并入图片 | 交叉统计不能收两次。 |
| 图片缺价回落同档普通价；计数项缺价按同单位最高价，否则最高 token 价 | 有效价格只有一种解析；兜底不为零。 |
| 图片、音频秒数、朗读字符各自是计费项，按请求声明预留 | 一项一个单价；它们是交付的产物。 |
| 只报告计数项的模型不要求 token 单价 | 否则 `tts-1`、`whisper-1` 报不了价。 |
| 批量按全批总量计价 | 负责人批准（[#514](https://github.com/TYCT-tyct/Axiom/pull/514#issuecomment-6539368675)）；上游只报一个总量。 |
| 服务端工具必须有上限，无计费映射的拒绝 | 无上界的费用任何预留都罩不住。 |
| 文件搜索、文件解析的价只按模型定 | 站点默认价会按错币种收。 |
| 代码执行默认价取一小时容器价 | 只有次数没有时长，宁可短调用多收。 |
| 不认识的计费项让模型停止接新请求，在途按兜底价暂估；未声明档位按模型隔离 | 不会算不出钱，也不拒绝已发生的调用；目录以模型为单位。 |
| 兜底行去掉 `markup` 一次完成，锁定旧文本读时忽略 | 没有生产部署；预留行是成交输入，不改写。 |
| 用量以上游为准，缺的才估，之后按供应商记录校正 | 估算最小；不为等记录留着预留。 |
| 校正由 billing 消费供应商事件 | 收费须由持余额锁的 billing 写；事件游标不怕重试和换主。 |
| 输出按文本形状估，Claude 4.7+ 中日韩权重 1.24 | 负责人批准（[#309](https://github.com/TYCT-tyct/Axiom/issues/309#issuecomment-6566970847)）；本项目语料测出 1.40 让中文多收。 |
| Claude 3+ 输入也按形状估 | 没有准确且可内置的词表，远程计数是结算路径上的网络依赖。 |
| 工具调用暂估加 45 个 Claude token，OpenAI 0 | 框架不在可见文本里，45 是实测保守端。 |
| 暂估每张图片 1600、每个文件 4096 token | 按上界会多收约百倍；按尺寸计数随 [#203](https://github.com/TYCT-tyct/Axiom/issues/203)。 |
| 分词器 `tiktoken-go/tokenizer` v0.8.1，启动预热 | 纯 Go、内置词表；0.10.0 分配翻倍（[#555](https://github.com/TYCT-tyct/Axiom/issues/555)）。 |
| 是否传递取消按适配器默认，端点实测覆盖 | 两家中转不同；一律不传递会让每次 ESC 付整段。 |
| 没有内容交付的失败不收模型用量 | 同 OpenRouter；内容交付后出错仍收，因为中转照收、内容已交付。 |
| 免单只三条规则，无每日上限 | 只看输出为 0 可被利用；金额不决定收不收。 |
| 预留在数据库、挂在可回收持有者上、带截止时间 | 缓存里的预留故障时只能放行。 |
| 回收只在回收者自己连续 TTL + 宽限没失效后 | 数据库中断后一连上就回收会让每个节点都退出。 |
| 清理不收费，收费留给迟到结算 | 清理没有用户看到的用量。 |
| 同一账户的资金事务按批合并 | 逐请求提交时热点账户尾延迟不够；保留唯一串行点和幂等重试。 |
| 不用 TigerBeetle，只借两阶段转账模型 | 部署要求与单机起步冲突。 |
| 分项明细读取时由预留重建 | 热路径不分配，没有第二份会漂移的金额。 |
| 受众定价用稀疏受众发布表 | 没有账户 × 等级的乘积；容量见存档。 |

### 服务端工具的准入

准入范围由完整计费映射决定，没有映射的工具在 `Inspect` 返回 400，不因请求写了次数就放行。

| 格式与工具 | 处理 |
|---|---|
| Messages `web_fetch_*` | 拒绝：增加上下文与采样，fetch 用量没有映射 |
| Messages `mcp_servers` / `mcp_toolset`；Responses `mcp` | 拒绝非空连接器与远端工具 |
| Messages `tool_search_tool_*` | 拒绝：服务端执行，搜索结果展开后继续采样 |
| Messages `advisor_*` | 拒绝：额外顾问调用没有报价 |
| Responses `file_search` | 接受：每次调用一个 `file_search`，`max_tool_calls` 或模型 `max_uses.file_search` 给上限，按 `file_search_call` 计数；向量存储的存储费不计；供应商账号必须拥有请求的 `vector_store_ids` |
| Responses `image_generation` | 拒绝：工具自己的图片模型单独计价 |
| Responses `shell` | 只接受显式 `environment.type:"local"`（客户端工具）；托管、缺省或未知环境拒绝 |
| Responses `tool_search` | 只接受显式 `execution:"client"` |
| Responses `programmatic_tool_calling` | 拒绝：托管运行时没有计费映射 |
| 三种格式的 `openrouter:*` | 只接受 `web_search`（循环最多 `platform.MaxServerToolSteps` = 30 步），其余按名字拒绝（[接入的「服务端工具」](gateway.md#服务端工具)） |

Anthropic 的 bash、text editor、memory、computer / browser 是客户端工具，照客户端工具处理。

## 待定问题

- 套餐的在线购买、自动续费、拒付和套餐之间的升级/换套餐未定，需要负责人决定；当前账户已有有效套餐时换另一个会被拒绝。
