# 模型目录

有哪些模型、叫什么名字、官方规格和参考价是什么。对应代码模块 `catalog`，表、不变量和接口见[模块说明](../../internal/catalog/README.md)；概念之间的关系见[术语与核心概念](../glossary.md)；调研和条款取证见[存档](../archive/catalog.md)。

## 要求

- 模型的标准 ID 采用 OpenRouter 的 `厂商/模型` 格式，厂商原生的名字也能直接使用。
- 目录基线自动同步，主要参考 OpenRouter，并与其他公开来源交叉核对。
- 价格一律按原价计算，不考虑任何优惠。
- 按上下文长度变化等复杂价格必须正确获取、正确计算。

## 设计

### 模型与名字

- **模型**：后台和日志里用 `厂商/模型` 标识（slug），厂商给出版本标识时加 `@版本`，如 `anthropic/claude-sonnet-4.5@20250929`。
- **版本依据**：每个模型声明一种。
  - **固定版本**：厂商的带日期名字或页面写明的版本号，附证据。模型不可变，厂商下线那个版本时它才下线。
  - **移动名字**：厂商的名字背后版本会变（如 DeepSeek 旧名的请求由新版本服务）。模型就是这个名字本身：厂商换版本时原地改规格、发布新的参考价，审计里记下版本标识的变化。
- **名字**分两类：

| | 公开名字 | 内部名字 |
|---|---|---|
| 谁用 | 用户请求、模型列表、回退列表 | 供应商的名字映射、数据集条目的对应、日志 |
| 允许 | 标准 ID；厂商原生的名字，带日期的（`-YYYYMMDD`、`-YYYY-MM-DD`、`-MMDD`、`-MM-DD`，如 `claude-sonnet-4-5-20250929`、`gemini-2.5-pro-preview-06-05`）和不带日期的（如 `claude-sonnet-4-5`）；免费条目的 `标准 ID:free` | 另允许 `-latest` 结尾的写法 |
| 永不允许 | `-latest`、含 `~` `@` 的写法，`:free` 之外的冒号 | 含 `~` 的写法，`:free` 之外的冒号 |

- 名字长度 1 到 200 字节。中转站里的写法和 `:batch` 这类后缀是[供应商别名](suppliers.md#供应商别名与待映射)，不进目录。`:free` 是例外：OpenRouter 把它当独立模型，有独立的规格、上下文、端点和价格，所以本站也建独立模型，标准 ID 和公开名字都是 `基础标准 ID:free`，价格为零。
- `~作者/系列-latest` 是目录里的**别名**，一次一行 `(名字, 目标模型)` 追加，快照读最近一次。运营在同系列新版本上架后把别名指过去，`change` 和审计留下改前改后。目标必须是已上架、同作者、非 `:free` 的模型；别名不按前缀或日期猜目标。别名现在只能经 `axiom catalog save-alias` 写，HTTP 管理接口没有它的路径。
- **名字归一化后全局唯一**，公开和内部名字一起算：归一化结果已被占用时拒绝保存。
- **归一化**：去首尾空白 → ASCII 小写 → `.`、`_`、空白改成 `-` → 合并连续的 `-`，去掉 `/` 两侧的 `-` → 结尾的 `-YYYY-MM-DD` 改写为 `-YYYYMMDD`。不去日期、不去厂商前缀、不猜版本号，所以不同日期的版本不会被合并。
- **同一版本的两个名字**：厂商同时给出不带日期和带日期的名字时，建一个固定版本的模型，标准 ID 之外挂这两个公开名字。厂商把不带日期的名字换到新版本后，它仍指向旧版本，直到「切换与迁移」实现。
- **OpenRouter 的名字**：它的带日期名字（如 `anthropic/claude-4.5-sonnet-20250929`）与厂商原生名字词序不同，归一化不会合并，上架时要把它加成模型的内部名字，否则数据集对不上；`axiom catalog check` 的 `unrecognized` 列出漏掉的。

### 名字解析

- **用户请求**：只查公开名字和别名，归一化后精确匹配，不切后缀：`:free` 只命中它自己的条目，没有该条目就是"模型不存在"，永远不会落到基础模型；`:batch` 等其他后缀同样不存在。`:nitro`、`:floor` 这类路由变体由网关在查目录之前读掉，从不新建模型（见[接入与对外接口的「模型名变体」](gateway.md#模型名变体)）；模型详情和 endpoints 查询同样先去掉路由后缀。别名返回它最新指向的模型；目标或模型已下线时返回"已下线"。
- **内部识别**：供应商的名字映射和数据集核对用。公开和内部名字都查（别名不参与），并说明这个名字能否当作版本证据：带日期的名字、移动名字的模型的名字能；绑定到固定版本模型的不带日期名字不能，因为厂商可能已把它换到新版本。不能当证据的结果，数据集不采用，供应商要经真伪检测确认（见[供应商的「供应商别名与待映射」](suppliers.md#供应商别名与待映射)）。已下线模型的名字仍认得出，供应商据此不把它映射到别的模型。
- **发给厂商的名字**：账户自带的供应商 key 用模型的厂商名字建端点（[供应商的「自带的供应商 key」](suppliers.md#自带的供应商-key)）。从公开名字里挑：带作者前缀、`:free`、`@版本` 的写法不选；固定版本的模型只选带日期的名字，取最长的；移动名字的模型取最短的。一个都没有就不给这个模型建端点，不拿 slug 去猜。

### 模型的生命周期

- **状态**：草稿 → 上架 → 已下线。草稿只在平台范围可见，它的名字和参考价也一样。名字上架后不改指向，下线即刻生效（最多在快照的陈旧上限内仍可被调用），改价在发布时生效。计划下线（带下线日期）、切换与迁移、预约改价待定，见[待定问题](#待定问题)。
- **新模型**：上架时由审核者确定标准 ID、公开和内部名字、版本依据和价格来源，并发布首个参考价。
- **目录的上架门槛**：规格写了 `items` 和 `tiers`（可为空，但必须写）；标准 ID（slug 去掉 `@版本`）是它的公开名字；至少一个币种有当前参考价；每个当前参考价对规格声明的计费项和服务等级都有价（见「上架门槛与缺项」）。`:free` 条目还要求基础模型已上架且有公开名字，每个币种的每个价都是 0。能否被调用还要过计费的上架门槛：售价覆盖上游可能报告的每个计费项（见[计费的「定价」](billing.md#定价)）。
- **已上架模型的规格修改**：新规格仍要写 `items` 和 `tiers`，且声明的每一项每个当前参考价都定了价。下线的模型不能加名字、不能改规格。
- **切换与迁移**（待定）：不带日期的名字换版本、下线模型的名字迁移到替代模型，都会改变用户实际用的模型和价格：切换前通知受影响的用户（邮件见[账户与租户的「给用户的邮件」](accounts.md#给用户的邮件)）；新版本更贵或能力更低时默认需要人确认；切换时刻之后开始的请求按新模型的价格版本计费；切换记入审计。

### 目录基线

- **内容**：上下文长度、最大输出、输入输出类型、能力、支持的参数、知识截止时间、参考价；以及计费要用的模型数据。规格存在 `model.spec`，原地更新，旧值留在 `change` 里。
- **端点接请求的四个键**：`context_length`（一次请求最多的 token，输入加输出）、`max_output_tokens`（输出上限，也是默认输出上限）、`streams`、`abilities`（`tools`、`images`、`documents`、`reasoning`、`prompt_cache`、`structured_output`、`web_search`、`code_execution`、`file_search`）。缺一个，端点就不进路由，绝不补默认值；直接格式（embeddings、rerank）只要求 `context_length`。长度不是正数、能力名不认识或重复，解析时拒绝。
- **上游可能报告什么**：`items` 和 `tiers` 是上游可能报告的计费项和服务等级，按输入输出类型、工具和厂商的服务等级在审核时确认（支持音频输入就有 `audio_in`，有联网搜索就有 `web_search`，OpenAI 有 flex、priority）。声明 `file_search` 能力时 `items` 必须同时有 `file_search`。
- **可缺的模型数据**：缺了就是不画一条上界或不分段，不猜一个值。
  - `reasoning_visible`：流里显示推理进度的调用格式（`messages`、`responses`、`chat`）；列了格式而 `abilities` 没有 `reasoning` 时保存被拒。
  - `output_speed`：最快输出速度（每秒 token 的正整数），计费据此算超额额度。
  - 单张图片和单页文件的最大输入 token 数、单个文件的最大页数：计费据此算输入上界（见[计费的「预留与结算」](billing.md#预留与结算)）。
  - `max_uses`：服务端工具的默认最大次数，键为 `web_search`、`code_execution`、`file_search`，值为 1 … 10¹⁰ 的整数；不写、null 或空对象表示没有默认。报价优先用请求的上限，否则用它，都没有就拒绝。只有确认该模型所有可路由端点都保证此上界时才填，理由里写明端点依据；不能把搜索结果条数当作调用次数。网关给 `web` 插件的 `engine:"native"` 用 `max_uses.web_search`，没有就用 1，夹在 1 到 10 之间（[gateway 的「服务端工具」](gateway.md#服务端工具)）。
  - `always_searches`：`true` 表示模型每次调用都自己联网搜索（如 Perplexity 的 sonar）。网关据此丢掉 `web` 插件，不再搜索一次也不收插件费。只有所有可路由端点都这样时才填。
- **请求写法的键**：说请求怎么写给这个模型，`Model.Dialect()` 读出，缺了不是 no：转换遇到要用它的请求就拒绝（见 [protocol](../../internal/protocol/README.md)）。

| 键 | 值 | 谁要 |
|---|---|---|
| `thinking` | `adaptive`、`manual`、`none`（明确不思考） | Anthropic 有 `reasoning` 能力的模型 |
| `mid_system` | 对话中途的系统消息 | Anthropic |
| `untrusted_system_after_tools` | 工具结果之后的系统消息当不可信文本 | Anthropic 且 `mid_system` 为 yes |
| `default_sampling_only` | 不接受非默认的 `temperature`、`top_p` | Anthropic |
| `forced_tool_choice` | 不思考时接受强制调用工具 | Anthropic |
| `encrypted_reasoning` | 推理项带加密内容 | OpenAI 有 `reasoning` 能力的模型 |
| `cache_breakpoints` | 显式缓存断点 | OpenAI |

  - 只有 Chat 转 Messages（Anthropic）和发往 Responses（OpenAI）的请求读这些键，别家的模型在被这两种端点服务之前不要求它们。
  - 保存规格（`CreateModel`、`UpdateSpec`）时拒绝不认识的值和自相矛盾的写法：有 `reasoning` 而 `thinking` 是 `none`，`thinking` 是 `adaptive` 或 `manual` 而没有 `reasoning`。解析不查这一条，免得一行旧数据让快照加载失败；「有 `reasoning` 而没写 `thinking`」由 `axiom catalog check` 报告。
  - 值照厂商文档逐型号写在 `deploy/catalog/dialects.json`，不按名字前缀推断。`axiom catalog apply-dialect [--apply] <文件>` 经 `UpdateSpec` 写入（有审计、按 `rev` 检查、其余键原样保留）：不带 `--apply` 只显示会改什么，已相同的不动，目录里没有的 slug 只报告，一个模型被拒不拦其他模型但最后非零退出。入口是 `just catalog-dialect-plan`、`just catalog-dialect-apply`、`just catalog-check`，步骤见[发布前](../ops/release.md)。数据文件里没有的型号由 `check` 报缺键，对着文档补进文件再应用；厂商改了行为也走这条路。每个值的出处见[存档](../archive/catalog.md#请求写法的键的出处)。
- **规格以厂商文档为准**：各来源一致才自动更新，不一致不自动采用，告警交运营 agent 判断，必要时请人确认。规格的核对与价格来源无关。
- **价格以模型选定的来源为准**：
  - 每个模型选一个价格来源：LiteLLM、OpenRouter、官方价格页或手填。选定来源表达不了这个模型的分档时不能选它；不拿别的来源补全；
  - 手填的价格不会被自动同步覆盖；
  - 选定来源的价格变化超过阈值时，由管理员确认后才采用；
  - 选定来源不可用时，保留最后的价格并告警，从不自动换来源；
  - 改选来源时立即按新来源发布每种币种的参考价，新来源没有的币种撤下，计费改用其他币种按汇率换算；
  - 价格每次变化都记一个新版本（参考价的版本，与计费的价格版本不同）；
  - 其他数据集只用来核对：与选定来源不一致时告警，不替换。
- **OpenRouter 作为可选来源**：它的条款第 7 条禁止为建设竞争服务而访问和抓取；仍保留为可选来源，这项风险已接受，不因条款自动停用。
- **只用原价**：限时优惠、批量折扣不进目录，只录标准档的原价。不做分时段价格，DeepSeek 这类按时段定价的只录高峰价。
- **币种**：每个模型、每个币种一条参考价的历史。DeepSeek 英文页的美元价和中文页的人民币价不是汇率关系，所以各存一条；计费选用与站点币种一致的那条，没有时按汇率换算。
- **改价**：选定来源的每次价格变化都发布进目录；售价是否跟着变由计费的发布阈值决定（见[计费的「定价」](billing.md#定价)）。售价在路由快照重建时现算，参考价的改动在两个快照轮询周期内进入售价。

### 参考价怎么进入目录

1. **手填**：管理员录入整张价目表并写明理由，同步从不覆盖它。
2. **发布**：一个事务里锁模型行，确认来源等于模型的价格来源，带上审核时看到的当前参考价（`base`）比较，期间已有别的发布就拒绝，参考价的历史不会分叉。每一行记下来源，证据（非空 JSON 对象）记进 `change`。已上架的模型要过目录的上架门槛；新价目表不能丢掉旧价目表有价的位置（`Lost`），门槛口径变化要操作明确确认。改参考价属于资金相关操作，审批策略由[运营](operations.md)定。
3. **改选来源**：一次发布，同一事务里改价格来源、为新来源的每个币种发布一行（价目表相同也发布，`source` 变了）、为新来源没有的币种各写一行撤下，所以改选后每个币种的当前价都来自新来源。至少一个币种；请求带审核时每个币种的当前行，多或少都拒绝；每张新价目表对每个现有币种的价格都过 `Lost`。选官方价格页或手填时由操作带上价目表和证据；改选到数据集时价目表只取自该数据集里模型的条目（要能对应、可用、过合理性检查，并带有当前参考价的每一档），不能把手工价格记在数据集名下。

#### 数据集

- **来源**：LiteLLM 的 `model_prices_and_context_window.json`（`raw.githubusercontent.com`）和 OpenRouter 的 `/api/v1/models`，经统一出站客户端只读这两个固定地址，只收 200，不跟随重定向，超时 60 秒，正文上限 32 MiB。币种固定 USD。
- **定时**：每天一轮，在 `syncs` 队列上，`axiom serve` 启动或换主时也先跑一轮；未结束的任务按参数唯一，重启不堆积。取数或解析失败时这一数据集整轮不发布，模型保持最后的价格，失败写进持久化的同步状态后任务照常完成（只尝试一次），等下一日轮次。节点开始关停即取消网络取数。
- **数字**：从 JSON 原文取，十进制系数加指数（如 `3e-06`）精确展开，指数限 ±30，展开后超过 15 位小数的条目拒绝，全程不经浮点。条目有错（负数、越界、字段不是数）时整条不可用，原因随结果报出，不取其余字段。
- **LiteLLM 的读法**：只读厂商自己的 provider（`openai`、`anthropic`、`gemini`→google、`deepseek`），不读 `vertex_ai`、`bedrock`、`azure` 这类转售方；只读 `mode` 为 `chat`、`responses`、`image_generation`、`audio_speech`、`audio_transcription` 的条目，条目名去掉 `<provider>/` 前缀。字段先去服务等级后缀（`_priority`、`_flex`），再去 `_above_<N>k_tokens`，再按字段表认计费项；同一字段在不同 mode 下含义不同的只在一个 mode 下读：`output_cost_per_image` 只认 `image_generation`，`output_cost_per_second` 和 `input_cost_per_character` 只认 `audio_speech`，`input_cost_per_second` 只认 `audio_transcription`；`input_cost_per_image` 和 `_batches` 等字段不读。联网搜索取 `search_context_cost_per_query`，三种上下文大小同价才取。
- **OpenRouter 的读法**：取 `pricing` 里单位明确的 `prompt`、`completion`、`input_cache_read`、`input_cache_write`、`input_cache_write_1h`、`internal_reasoning`、`web_search`；`image`、`image_output` 不读（实际数据里它们是 token 价，不是每张的价）。条目以 `id` 和带日期的 `canonical_slug` 为名；`:free` 只以 `id` 为名（它的 `canonical_slug` 是付费模型的名字）；其他带 `:` 的变体是供应商别名。带 `overrides` 的条目不可用，所以 OpenRouter 只表达无分档的价格；它没有 `file_search` 价，声明文件搜索的模型选它会被上架门槛挡住（held）。
- **对应**：模型的公开和内部名字归一化后查条目，只有名字本身是版本证据（与内部识别同一规则）才算；只靠不带日期的名字找到的是 held。对应到几个条目时，若有一个说出了其余所有条目所说的，取它，否则有歧义，held；不从不同条目各取一个字段。
- **分档的口径来自当前参考价**：数据集只说门槛在哪，不说哪些用量相加。条目的门槛与当前参考价逐个相同时沿用当前口径；没有当前价、门槛不同、条目没有分档而当前价有，都不发布，由人发布后同步才接手。
- **自动发布**：本轮取数成功后，对价格来源是这个数据集的每个草稿或上架模型，把条目与当前美元参考价按整张价目表比较（规范字节相同为 unchanged）。不同就过安全阀：合理性（token 项不超过每百万 1000 美元，其他单位的项不超过每单位 1 美元，缓存读价不高于输入价）、结构（门槛口径与门槛和当前价相同）、变化阈值（任一服务等级、档位、计费项相对当前价变化不超过 `PriceChangeLimit`，默认 25%），再过发布本身的检查（`Lost` 为空、上架门槛、在锁住的模型行上复核来源）。通过就以 `system:catalog.sync` 发布，证据是条目原文、数据集名、整份正文的 SHA-256 和取数时间。不通过、条目不可用、有歧义、少了档位或价格就是 held：不发布，日志记 warn，报告写原因，价目表有效时附上候选和它对着的当前价行，管理员可用 `publish-price` 带上这个 `base` 采用。取数早于当前价发布时间的一轮不发布，所以两轮逆序完成时旧数据盖不掉新价；两个时间都取自数据库时钟。
- **同步状态与告警**：持久化的同步状态记最后成功、连续失败的起点和次数，以及待确认改价数（有候选价的 held）。读全两个数据集才写最后成功、清零连续失败并重算待确认数；失败只累加连续失败，第一次失败记下起点，最后成功和待确认数不变。两个 gauge `axiom_catalog_sync_last_success_age_seconds`（从未成功时从连续失败的起点算，没跑过为 0）和 `axiom_catalog_sync_consecutive_failures` 每次采集都读持久化状态和数据库时钟，没有新轮次也会增长；读库失败返回采集错误，不报 0。时间和次数阈值、严重程度和渠道由运维节点的后台数据配置（[记录与告警的「监控与告警」](observability.md#监控与告警)）。节点另有兜底：失败的轮次距最后成功超过 48 小时（代码默认，启动配置可覆盖）时记 `catalog.sync.overdue` 日志和 `axiom_catalog_sync_overdue_total` 计数。
- **核对**（待定，未实现）：没被选定的数据集与当前参考价按整张价目表比较，不一致开审核项、不改价；本轮取数失败的来源整批不参与；对不上任何模型的条目开新模型审核项。现在数据集没有审核项，候选每轮重算，只在报告和日志里。

#### 官方价格页

- **登记**：管理员审阅条款后用 `axiom catalog watch-page` 登记厂商、HTTPS URL、币种（一页一种）和截取价格段的开始、结束标记。检查间隔缺省 3600 秒（3600 … 604800），同源请求间隔缺省 10 秒（1 … 60），后者是同源共享的设置，新登记可改它但不缩短已预约的等待。配置不可原地改，换 URL 或范围要新登记；`unwatch-page` 停用。安装不预置页面；清单 `deploy/catalog/price-pages.json` 是登记的依据，不自动启用。
- **调度**：每分钟及启动时找到期的页，串行处理，每轮最多 9 分钟。每页取 5 分钟的租约并增加代次，网络和站点等待合计最多 4 分钟；节点关闭或轮次到期时取消网络，不记失败、不推迟下次检查，等租约自然到期。写回前检查代次、租约和启用状态，旧的执行者写不进。下一次检查等页面间隔加 0 … 10% 的正向抖动。
- **取数**：只 GET 登记的 URL 和同源 `/robots.txt`，走统一出站客户端（Axiom User-Agent、不登录），每次请求 60 秒，robots 上限 512 KiB、页面 32 MiB，不跟重定向。robots 只有 404/410 算没有规则，其他非 200、解析失败或拒绝时不读价格页。同源的每个请求都经数据库预约，跨节点共享间隔，取登记值与本次 robots `Crawl-delay` 的较大值；`Crawl-delay` 超过 60 秒时拒绝取页，仍留下延后的预约。429/503 尊重 `Retry-After`，没有有效值时等一小时，本轮不重试。等待超过本次预算就失败，保留旧快照；被站方拦截（如 403）时同样保留旧快照并告警，不换 UA 绕过。
- **截取**：取 `article`，否则 `main`，否则整个文档；去脚本、样式、导航、页头页脚和隐藏节点；表格单元格、块标签、flex 列/网格、`display:block` 和图标前后补词边界，连续的内联文本（`$0` + `.10`）保持粘连；解码实体、去零宽字符、归一空白。两个标记必须各自唯一、结束在开始之后、中间不空，否则失败。快照按页面、抽取版本和正文 SHA-256 复用；内容变回旧的就指回旧快照，所以证据始终是页面现在的内容。当前指针不能回退到更低的抽取版本。
- **审核**：快照、当前指针、观测、审核项和告警信号同事务提交。首次成功和每次内容变化都开审核项，每页最多一个未结项：新变化保留未结项原来的基线、重算从基线到最新内容的差异（去掉公共前后缀的替换段），后续小改动掩盖不了未审的涨价。`review-page` 按审核项和审核时的内容序号标 done 或 dismissed，内容又变了就拒绝；它不发布价格。驳回过的快照再出现不重开，内容回到它时未结项自动结束。首次登记的基线为空。处理审核和写回按页面锁串行。
- **告警**：`catalog.page_changed`（审核或回到已驳回内容后恢复）、`catalog.page_failed`（每次取数失败，成功或停用后恢复）、`catalog.page_overdue`（距最后成功超过两倍页面间隔，从未成功则从登记时算）。信号只含页面 ID 和分类，不含 URL 和正文；管理员须另配这三类规则和渠道。
- **录入**：运营 agent 按页面写出完整的价目表（全部档位），引用页面当前快照并附逐字摘录提交。发布时先锁页面行再锁模型行，代码检查页面仍启用、证据引用它的当前快照、厂商和币种一致、每段非空摘录逐字出现在正文里，单价在允许范围内、门槛口径合法；每一档是否完整且对应厂商原文由审核者判断。页面监测从不自动发布。
- **live 检查**：`axiom catalog check-pages <清单>` 不打开数据库，逐页面输出正文与 hash，失败非零退出，带 `excluded` 的目标不发 GET；它不代替连接真实目录的 `axiom catalog check`。

#### 验收的检查

`axiom catalog check` 只读，对 OpenAI、Anthropic、Google、DeepSeek 四家每个模型输出一行 JSON：是否上架、公开名字、选定来源、有当前价的币种，以及问题（未上架、没有公开名字、规格解析不了、缺请求写法的键、规格没写 `items` 与 `tiers`、没有当前价、某币种的价目表缺规格声明的项或等级；官方来源的价格另查证据引用当前快照、摘录在正文里、没有未处理的页面审核）。规格解析不了的行只记在它自己的问题里，一次列出所有要改的行；快照加载遇到这样的行会整个失败，`axiom serve` 启动即退出。再对两个数据集演习：跟随它的模型 `unchanged`、`differs` 还是为什么 held，以及 OpenRouter 列出而目录里没有能确认版本的名字的纯文本模型（`unrecognized`）。有问题就非零退出，最后一行是汇总。四家在售哪些模型它不知道，要对着价格页看。

### 价目表的结构

目录里的参考价、计费的价目表、适配器生成的成本计划用同一个结构：目录记选定来源的原价，成本计划记供应商的原价，计费记我们的售价。单价用精确小数存储（见[计费的「钱的表示」](billing.md#钱的表示)），格式见[模块说明的「存储」](../../internal/catalog/README.md#存储)。

#### 计费项与用量

每项只有一种单位（`Item.Unit()`），价目表的一项只有一个单价，所以同一侧可以同时有按 token 和按张的两个项，互不重叠。同一个 token 只计一次：模态项从总量里拆出，只有 OpenAI 兼容上游的缓存读写可以重叠。`protocol` 按下表把上游报告的用量折成 `Usage`：

| 计费项 | 单位 | OpenAI（Chat / Responses） | Anthropic Messages | Gemini |
|---|---|---|---|---|
| `input` | token | `max(总输入 − 缓存读 − 缓存写 − 音频 − 图片, 0)`（缺字段按 0） | `input_tokens`（含图片） | `promptTokenCount − cachedContentTokenCount` − 单独定价的模态 |
| `cache_read` | token | `cached_tokens` | `cache_read_input_tokens` | `cachedContentTokenCount` |
| `cache_write` | token | `cache_write_tokens` | `cache_creation.ephemeral_5m_input_tokens` | — |
| `cache_write_1h` | token | — | `cache_creation.ephemeral_1h_input_tokens` | — |
| `output` | token | `completion_tokens − reasoning_tokens − audio_tokens − image_tokens` | `output_tokens`（含思考） | `candidatesTokenCount` |
| `reasoning` | token | `reasoning_tokens` | 0 | `thoughtsTokenCount` |
| `audio_in` / `audio_out` | token | 输入、输出明细的 `audio_tokens` | — | `promptTokensDetails` 里 `AUDIO` 的数量 / — |
| `image_in` / `image_out` | token | 两侧明细的 `image_tokens`，输入另加 `video_tokens` | — | 单独定价时 `promptTokensDetails` 里 `IMAGE`、`VIDEO` 的数量 / — |
| `image_in_piece` / `image_out_piece` | 张 | 尚无端点 | — | — |
| `audio_in_second` / `audio_out_second` | 秒 | 尚无端点 | — | — |
| `character_in` | 字符 | 尚无端点 | — | — |
| `request` | 次 | 网关每个生成请求记一次 | 同左 | 同左 |
| `web_search` | 次 | Responses `output` 的 `web_search_call` 项 | `server_tool_use.web_search_requests` | 待核对 |
| `code_execution` | 次 | Responses `output` 的 `code_interpreter_call` 项 | `server_tool_use.code_execution_requests` | 待核对 |
| `file_search` | 次 | Responses `output` 的 `file_search_call` 项 | — | — |
| `file_parse` | 页 | 网关按页记 | 同左 | 同左 |

- **OpenAI 的输入**：物理输入总数及存在性单独保留（显式 0 不等于缺失），客户端回显用它，不把重叠的计费量重新相加。每项 0 … 10¹⁰ 且不大于总数；缓存读、写各按报告量收，普通输入取剩余量夹到 0（`100/80/80` 计费 `0/80/80`，回显仍是 100）。输入的缓存明细 `cached_tokens_details.image_tokens` 从图片量扣除、`audio_tokens` 从音频量扣除；明细不得超过图片、音频和缓存读的总量。模态限制在 `max(总数 − 缓存读 − 缓存写, 0)` 之内，先音频、后图片，全缓存的图片不再收一次图片价。`text_tokens` 只校验。交集里其他未映射的成员已含在 `cached_tokens` 里，只记进 `Unknown()` 供监控、不补收。输出明细的 `video_tokens` 只校验，按普通输出收。两种格式的 `input/prompt_tokens_details`、`output/completion_tokens_details` 别名都适用。工具次数从回复的 `output` 项计，每项一次，`output_item.done` 不重复计。
- **Anthropic**：缓存写入以顶层 `cache_creation_input_tokens` 为准；有 `cache_creation` 时 5m 与 1h 之和必须等于它，否则是用量错误；没有时按请求的缓存断点归类：没有 `ttl:"1h"` 的断点全记 `cache_write`，有就全记 `cache_write_1h`。输入和缓存读写互斥，物理提示词长度是它们之和。代码执行以 `server_tool_use` 为准，流断、没有用量时由事件计数补上。联网搜索带回的内容按普通 token 计入输入。
- **Gemini**：`promptTokenCount` 包含缓存的内容，所以 `input` 是两者之差。
- **模态**：只有上游单独报告、厂商单独定价的模态才折成自己的项（OpenAI 单独报告的图片直接折成图片项）；Anthropic 的图片按 token 计入输入、价格相同，留在 `input`。视频没有自己的计费项，计入 `image_in`。
- **按张、按秒、按字符**是独立的计费项，单价按每个单位，数量是整数（秒数不足一秒向上取整）；报价与结算已支持，还没有端点报告它们。
- **按请求**：`request` 由网关和计费每个生成请求记一次，不由上游报告，所以不在上游可能报告的集合里。价目表有它时预留加一个请求的价，结算对收费的那次尝试加一次，免单时照收。
- **代码执行按次计**，是按次工具，缺价时用站点默认单价。厂商不按次收费（按容器时长或只按 token），每次的单价是近似值；站点默认取一小时容器价作为保守上限（见[计费的「决策与理由」](billing.md#决策与理由)），模型知道自己的典型时长时写自己的按次价。用量里的次数不进 `Unknown()`。
- **文件搜索按次计**：只在 Responses 里声明，没有站点默认价，模型的价目表必须有它（上架门槛据规格的 `items` 要求）。预留取 `max_tool_calls` 或 `max_uses.file_search`，结算按 `file_search_call` 项的次数；向量存储的存储费不在其中。
- **文件解析按页计**：`file_parse` 是网关自己的项，上游不报告，规格里没有，上架门槛不查。没有站点默认价，模型要接 `mistral-ocr` 时售价表必须有它，否则准入按缺价拒绝，不借用 `web_search` 的价；`cloudflare-ai` 免费；`native` 不经网关解析，按输入 token 计。解析在采样前完成，是一次按页收费（`Request.FilePages`），不增加采样次数，免单时照收。页数怎么数见 [fileparse](../../internal/fileparse/README.md)。开关 `FileParse` 关闭时网关按旧规则每个解析的文件记一次 `web_search`；打开前要先补齐已有模型的 `file_parse` 价。
- **原生细项**：`video_input`、`accepted_prediction`、`rejected_prediction` 是供应商报告的、已含在计费总量里的拆分，只用于回显和存储，不计价；全零也算报告过，缺失不是零。
- **不认识的用量**：映射表外、数值不为零的字段和认不出的服务等级放进 `Usage.Unknown()`（字段路径和原样的值），不丢弃也不归进已有的项；计费据此按[计费的「价目表缺项」](billing.md#价目表缺项)处理。
- **服务等级**：`standard`、`flex`、`priority`、`fast`（快速模式），按每家的取值从响应读，响应没有就取请求里明写的，都没有是标准档。
- **输出的口径**：计费输出是普通、推理、音频、图片之和；免单判断另看交付的图片张数和音频秒数，纯图片或纯音频回复不免单。

#### 条件

- **按上下文长度分档**，计法是整单按档：门槛口径所选项的数量之和（不超过物理输入总数）严格大于某档门槛时，这一档列出的项换价，没列出的沿用基础价；取满足条件的最高一档。门槛严格递增，口径整张价目表一个、各档共用，在证据里引用厂商原文。口径含 `input` 而不含 `image_in` 时，图片输入也算进去（它拆出前本来在输入里）。从某个总量里拆出去单独计价的项仍属于那个总量。已知两种：Anthropic Haiku 5.5 超过 100,000 token，口径 {`input`, `cache_read`, `cache_write`, `cache_write_1h`}；Gemini 超过 200k，口径 {`input`, `cache_read`, `audio_in`, `image_in`}，输出和缓存价同时换档。
- **服务等级**：标准档以外的每个等级有自己完整的一套单价和与顶层逐个相同的门槛（不换价的档写空）。先按实际服务的等级选单价，再按上下文长度选档；不跨等级继承，等级没录的项就是缺价。价目表没列出的等级就是没有它的价格。快速模式是等级 `fast`，不用倍率。
- **缺价的回退**只有两条，在选定等级和档位之后：`reasoning` 没定价时按同档的 `output` 计（Gemini 的输出价包含思考）；图片没定价时按同侧的普通价计，显式 0 不回落；同价回落只是兼容默认，真实图片更贵时要录独立价。OpenAI 对没有写入价的模型把缓存写入按输入收，录入时就把缓存写的单价写成与输入相同。
- **尚不支持**：超出部分按档、倍率型条件（中转站的"满足条件时整体乘一个倍率"）、分时段价格。随第一个需要它的价目表带着完整规则加入；在那之前解析时拒绝它们和任何不认识的条件，也拒绝门槛不递增、有档位没口径、等级门槛与顶层不同、等级重复或写成标准档。拒绝的是价目表：需要它们的成本计划端点不用，数据集条目不能被选为来源。

#### 上架门槛与缺项

- **`Missing`**：这份价目表对规格声明的项和等级有哪些没定价（算上回退）：标准档在任何一档缺价的项，以及价目表没有、或任何一档缺任何一个声明项的等级。目录的上架门槛用它；计费的上架门槛和路由也用它检查售价，先去掉有站点默认价的按次项。它答"能不能定价"，不答"上游会报什么"。
- **`Lost`**：旧价目表有价、新价目表没有的位置（等级、区间、计费项），替换参考价前用它防退化。两边都有分档而口径不同时不可比较，返回 `ErrTierBasisChanged`，要操作明确确认；只有一边有分档或两边都没有时照常比较。区间按两边门槛的并集切分，每个区间里两边的价各自不变，所以逐个比较是精确的。不用 `Missing` 比较：它把一个等级的缺项合成一个等级，看不出新 priority 连输入价都没了。
- **`Cost` 不因缺价失败**：它给有价的项计价，并返回用量不为零却没价的项；等级没定价时各项都缺价。计费按「价目表缺项」给这些项兜底，所以"不会算不出钱"不靠目录拒绝请求。
- **`Ceiling`**：给预留的单价上界，取这些项在这些等级、提示词长度不超过给定值时可能落入的每一档中的最高价，任一处缺价返回 false。计费在每次采样的物理输入上界 N 上取 `N × max(输入侧最高价, 缓存读最高价 + 缓存写最高价)`，读写只在 Chat 和 Responses 上合并（Messages 的各项互斥，取单项最高价），这时输入侧固定含图片输入；两项分别相乘再比较精确金额。
- **`Fill`**：给每个等级缺基础价的项补上给定价格，已有的不动；计费用它把站点的按次默认单价补进锁定的售价。
- **能力不归这里**：模型根本不支持的功能（如纯文本模型收到音频）由[路由](routing.md)按端点能力过滤，目录不在调用前按请求特征拒绝。

#### 公开读取

`Schedule.View()` 把整张价目表展开成 `ScheduleView{Currency, Basis, Rates}`，每个 `ScheduleRate` 带服务等级、`Base`、上下文档门槛、计费项和精确单价。展开的是每个档位的实际生效价：某档没写的项继承基础价；`Base` 与显式 `above: 0` 分开，后者是 0 以上的第一档。每条单价带 `headline`（有基础档价格的项各一条：标准等级的基础档，标准等级不定这项的价时取第一个提供它的等级的基础档；只在门槛之上定价的项没有标题价）和 `display_amount`/`display_per`（token 项每百万 token，其他单位每 1 个，精确相乘不取整）。网站和控制台的模型与价格页用它，不读成本、来源或供应商页。

### 计算正确的保障

- 每个模型家族都把厂商文档里的计价示例做成测试用例：给定用量，算出的金额必须和文档一致。
- 价目表和供应商实际扣费持续对账（见[计费的「供应商成本」](billing.md#供应商成本)），规则写错时对账差额会立刻暴露。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 标准 ID 用 OpenRouter 的 `厂商/模型`，厂商原生名字作为公开名字 | 兼容 OpenRouter 的客户端，同时让 Claude Code、Codex 这类只认原生名字的工具开箱可用 |
| 名字分公开和内部；中转站的写法是供应商别名 | `-latest` 承诺最新版本，没有切换就会悄悄落后，所以只用于识别；同一写法在不同中转站可能指不同模型 |
| `:free` 建独立模型；别名指向具体模型、只追加 | `:free` 有自己的上下文、端点和价格，独立成行就沿用发现、上架门槛和路由；按前缀或日期猜别名目标会把 `acme/gpt-5` 和 `acme/gpt-50` 串族，新上架也会改变已发布名字的含义 |
| 归一化不去掉日期 | 去掉会把价格和能力可能不同的版本合并 |
| 切换版本或迁移名字要通知，变贵或能力下降默认需人确认 | 否则用户的价格会被悄悄抬高 |
| 计划下线、切换与迁移、预约改价暂不做 | 它们要可靠的事件、通知和审批才能做对；预约生效还会因节点时钟偏差各自为政 |
| 只用原价，不做分时段，DeepSeek 只录高峰价 | 按原价和高峰价估成本只会偏高，不会亏；上游也不按时段卖 |
| 分档必须声明门槛口径、计法和受影响的计费项 | 各家口径不同，两种计法在门槛之上差额很大，不声明就会算错 |
| 服务等级各带一整套单价和同样的门槛，不跨等级继承 | 每个（等级、档位、计费项）只有一个价；沿用标准档会把 priority 下没录的项悄悄少收 |
| 按张、按秒、按字符、按请求各自是独立的计费项 | 一项只有一个单价，给已有项加第二种单位会让同一项有两种量纲 |
| 价格写入不设置节点版本门禁，只有文件解析留一个开关 | 服务未部署，没有读取旧枚举的节点；文件解析的开关还决定结算单位，留到计费口径调整时处理（见[模块说明](../../internal/catalog/README.md#文件解析计费开关)） |
| 规格多来源交叉核对，厂商文档为最终依据 | 单一数据集可能滞后或出错，错的规格会让路由和检测用错默认值 |
| 请求写法的键逐型号照厂商文档写进数据文件，缺了拒绝而不是按通例补 | 同一代 Claude 里各型号的这些行为各不相同，按名字前缀猜一个默认，换一代就悄悄错 |
| 服务端工具次数是可选的规格数据，不给所有模型补常量 | 硬编码的默认管理员改不了，还会把没有上界的上游声明成有界 |
| 价格以模型选定的来源为准；手填不被覆盖；不自动换来源 | 参考价经定价规则传导到售价，只有一个权威来源，售价的每次变化才说得清来自哪里 |
| OpenRouter 保留为可选来源，不因条款自动停用 | 条款风险已记录并接受；是否选用由每个模型决定 |
| 每个模型每个币种一条参考价的历史 | 中国厂商的人民币和美元价不是汇率关系，只存美元就不再是原价 |
| 数据集取数失败写进持久状态后完成任务，等下一日轮次 | 短退避重试会在一次短暂故障后耗尽尝试、触发队列丢弃告警，与过久未成功告警重复 |
| 同步状态导出为 gauge，阈值在运维节点；节点只留代码默认的兜底 | gauge 不依赖下一轮执行，任务不再跑时也看得出陈旧 |
| 只有名字本身是版本证据才对应条目 | 数据集里不带日期的条目可能已换到新版本，把它的价发布给固定版本的模型就是错价 |
| 多个条目时取说出其余所有条目所说的那一个，否则 held | 取并集或逐字段表决会拼出没人发布过的价目表；全部 held 会让 DeepSeek 永远同步不了 |
| OpenRouter 带 `overrides` 的条目 held | 它的 `min_prompt_tokens` 没说求和口径和门槛本身算不算进该档，还有按时段的覆盖，猜一个就是错价 |
| 分档口径取自当前参考价，没有当前价或门槛不同就不发布 | 口径是厂商的规定，数据集不给；代码里写厂商口径表会让没查实的厂商被猜 |
| 目录自带变化阈值（默认 25%）和合理性检查 | 计费的参考价安全阀在目录之上调用不了；超过的让人看一眼代价小，漏掉一次错价代价大 |
| 官方价格页靠页面监测、审核录入，不写解析器 | 页面版式一改解析器就静默出错；只靠人工录入则改价没人发现 |
| 四家官方价格页都登记抓取，抓取器的不变量就是条款风险的边界 | 只有 Google 的条文明确只禁违反 robots，其余三家是否覆盖公开价格页属法律解释，已决定接受；robots 变得禁止或站方明确拒绝时停用该页 |
| 页面用租约加代次，同源请求在数据库里预约 | 进程内计时约束不了多个节点；短事务预约不会在等网络时长期占锁 |
| 同源请求间隔 1–60 秒，robots 间隔只影响这次预约 | 两次 GET 在 4 分钟预算和 5 分钟租约内留有余量；延长租约会让失联节点长期占页 |
| 页面配置只增、可停用 | 改截取范围后，旧的执行者会把新配置的内容当作旧页面的证据 |
| 核对按整张价目表比较，只用本轮成功取到的数据 | 逐字段投票会拼出没人发布过的价目表；过期数据不能冒充当前证据 |
| `Cost` 返回缺价的项，不返回错误 | 缺项要按已定价部分加兜底价收，返回错误就丢了已定价部分；不选：调用前按请求特征拒绝 |
| 价格来源是模型上的一列，发布时在锁住的行上核对 | "手填不被覆盖""不自动换来源"变成同一事务里的一个比较；不选：来源配置表：同步与改选并发时写进旧来源的价 |
| 改选在同一事务里逐币种发布或撤下 | 当前价只看时间线头一行；改回旧来源时旧行不会复活；不选：当前价按 `source = price_source` 过滤 |
| 上架门槛检查目录自己的参考价覆盖规格声明 | 不完整的参考价能上架，计费的缺项兜底就成了常态；不选：只留给计费 |
| `SelectPriceSource` 不接受数据集来源，另设 `SelectDatasetSource` | 价目表只来自条目由方法保证；不选：放开原方法：手填的价能记在数据集名下 |
| 上游名字的映射在 `syncer.MapUpstream`：先别名，再内部识别，目标必须上架 | 与[供应商](suppliers.md)的映射步骤一致；不带日期的名字只是候选（`Unverified`）；不选：目录加「可路由」查询：映射规则进了 catalog |
| 同步记录在数据库的一行里 | 只有领导节点插入、任何节点执行，内存计数在换主和重启时归零；不选：节点内存；直接查 `river.river_job` |
| 公开和内部名字同表，`norm` 唯一 | 唯一性对两类一起成立；不选：两张表：要跨表检查 |
| 参考价叫 `reference_price` | `price_version` 是 billing 的售价版本；来源可能是数据集或手填；不选：`price_version`、`official_price` |
| `ModelID` 定义在本模块 | platform 只放被下层引用的实体 ID；不选：放进 platform |
| 1M 上下文、思考模式算端点能力，不另建模型 | 另建模型会让同一个模型分裂成多个条目 |
| 管理接口一个操作一个入口，原样带目录的 `Op` 和 `rev`、`base`；上架和下线合成「改状态」；改动返回整个模型 | 幂等、乐观并发和审核的形状在目录已定，接口不另造一层；返回整个模型页面少读一次。接口见 `api/admin.yaml`，约定见 [platform 的「接口约定」](../../internal/platform/README.md#接口约定) |
| 价目表在契约里是带类型的结构，与规范形式一一对应 | 前端能按计费项生成表单；两边不一致时以 `ParseSchedule` 为准并报 422 |
| 售价的公开投影展开全部等级、档位和计费项，标题价和显示数由服务端给 | 折成一个数会掩盖真实的计价条件；两个前端显示同一个数，不各自挑档、移小数点；每百万 token 与 OpenRouter 的模型页和 `max_price` 单位一致；标记放在原条目上，不另给一份可能说法不同的副本 |
