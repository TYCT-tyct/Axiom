# 模型目录

有哪些模型、叫什么名字、官方规格和官方价格是什么。对应代码模块 `catalog`。概念之间的关系见[术语与核心概念](../glossary.md)。

## 要求

- 模型的标准 ID 采用 OpenRouter 的 `厂商/模型` 格式，厂商原生的名字也能直接使用。
- 目录基线自动同步，主要参考 OpenRouter，并与其他公开来源交叉核对。
- 价格一律按原价计算，不考虑任何优惠。
- 按上下文长度变化等复杂价格必须正确获取、正确计算。

## 设计

### 模型与名字

- **标准 ID**：`厂商/模型`，例如 `anthropic/claude-sonnet-4.5`。
- **别名**：一个模型可以有多个别名，都能直接调用：
  - 厂商原生的名字，例如 `claude-sonnet-4-5-20250929`，这样 Claude Code、Codex 不改配置就能接入；
  - 中转站里各种写法的名字（只用于映射，不对外公开）。
- **版本**：不带日期的名字指向一个带日期的具体版本；换版本时记录切换时间。
- **能力差异不另建模型**：1M 上下文、思考模式这类差异是端点的能力（见[端点评估](quality.md)）。

### 模型的生命周期

- **状态**：草稿 → 上架 → 计划下线（带下线日期）→ 已下线。
- **新模型**：厂商发布新模型后，同步自动生成草稿，由运营 agent 审核后上架。
- **下线**：到期前提醒；别名按配置迁移到替代模型，迁移记入审计。

### 名字映射

中转站和供应商的模型名五花八门，按以下顺序映射到标准模型：

1. 查别名表；
2. 用规则归一化后再匹配，例如去掉日期、统一分隔符；
3. 仍然对不上，由运营 agent 提出映射建议；
4. 映射后，用真伪检测确认它确实是这个模型。

认不出来的名字进入"待映射"队列，不上架。

### 目录基线

- **内容**：上下文长度、最大输出、输入输出类型、能力、支持的参数、知识截止时间、官方价目表。
- **来源**：
  - OpenRouter 的模型接口：每个模型的价格和规格，无需 key 即可读取（OpenRouter《Pricing》，2026-10）；
  - models.dev：开源模型数据库，用 `tiers` 表达分档价格（models.dev，2026-10）；
  - LiteLLM 的模型价格表：用 `input_cost_per_token_above_200k_tokens` 这类字段表达超过 20 万 token 后的价格；
  - 厂商自己的模型列表和价格文档。厂商文档是最终依据。
- **交叉核对**：各来源一致就自动更新；不一致就交给运营 agent 判断，必要时请人确认。
- **只用原价**：厂商的限时优惠、批量折扣都不进入目录。

### 价目表的结构

目录里的官方价目表、计费的价目表、适配器生成的成本计划，三者使用同一个结构：

- **计费项**：输入、输出、缓存读、缓存写（5 分钟 / 1 小时）、推理、图片、音频、按次工具费（如每千次联网搜索）。
- **条件**：
  - 按上下文长度分档。每一档必须声明计法：是"整单按档"（输入超过门槛后，整个请求都按高档计价，Anthropic 和 Google 的长上下文就是这样），还是"超出部分按档"；
  - 分时段价格；
  - 服务等级，例如 flex、priority。
- **单价**用精确小数存储（见[计费的「钱的表示」](billing.md#钱的表示)）。

### 计算正确的保障

- 每个模型家族都把厂商文档里的计价示例做成测试用例：给定用量，算出的金额必须和文档一致。
- 价目表和供应商实际扣费持续对账（见[计费的「供应商成本」](billing.md#供应商成本)）。如果某条规则写错了，对账差额会立刻暴露。
- 多个来源对同一模型给出的价格不一致时，不自动采用，先告警。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 标准 ID 用 OpenRouter 的 `厂商/模型`，厂商原生名字作为别名 | 负责人同意。兼容 OpenRouter 的客户端，同时让 Claude Code、Codex 这类只认原生名字的工具开箱可用 |
| 只用原价，不考虑优惠 | 负责人决定。OpenRouter 也按供应商的原价计费（OpenRouter《Pricing》，2026-10）；按原价估成本只会偏高，不会亏 |
| 分档价格必须声明"整单按档"还是"超出部分按档" | 两种计法在超过门槛时差额很大；不声明就会算错 |
| 多来源交叉核对，厂商文档为最终依据 | 任何单一数据集都可能滞后或出错 |
| 1M 上下文、思考模式算端点能力，不另建模型 | 同一个模型在不同端点上能力不同；另建模型会让同一个模型分裂成多个条目 |
