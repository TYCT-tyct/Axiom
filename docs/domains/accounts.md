# 账户与租户

谁能登录、钱和 key 归谁、谁能做什么、站点怎么配置。对应代码模块 `accounts`。概念之间的关系见[术语与核心概念](../glossary.md)，这里只写本模块的要求和设计。

## 要求

- 用户、账户按站点隔离；C 类企业团队和 D 类二级站点的数据结构从第一版起具备（见[产品需求](../product.md#用户与市场)）。
- 第一版的登录方式：邮箱（密码或验证码）、GitHub、Google、LinuxDO、通行密钥（passkey）。手机号和微信登录暂不做。
- 站点之间的差异（登录方式、注册策略、等级、品牌）全部是站点的后台配置，不写死在代码里。
- 从第一版起记录"谁邀请了谁"；邀请返利以后再做。

## 设计

### 登录与会话

- **登录方式**：代码实现各种登录方式；每个站点在后台选择开启哪些，并填写自己的第三方登录应用凭证（二级站点用自己的）。
- **会话存在服务端**：浏览器里只放一个不透明的令牌（HttpOnly、Secure 的 Cookie）。用户可以查看登录设备、踢掉某台设备、一键退出全部设备。
- **两步验证**：支持验证器 App（TOTP）和通行密钥。管理员必须开启；普通用户自愿；站点可以要求本站用户必须开启。
- **注册策略**由站点配置：开放、邀请码、关闭；人机验证；邮箱域名黑白名单；注册频率限制。
- **验证等级**是数据：邮箱已验证、手机已验证、已实名；站点决定要求到哪一级。
- **唯一性**：邮箱和第三方登录身份在同一站点内唯一，不同站点之间互不影响。
- 密码用 argon2id 哈希。

### 账户、成员、工作区

- 每个用户注册时自动获得一个个人账户，并成为它唯一的成员。
- 企业账户有多个成员，每个成员在账户上有角色。一个用户可以同时属于自己的个人账户和同站点的多个企业账户，在控制台切换。
- 每个账户自带一个默认工作区，也可以另建多个，例如分开生产和测试环境。每个工作区有自己的 API key、预算和默认设置。个人用户的界面不显示工作区，直到他创建第二个。

### 授权

- **权限**是代码里定义的一件具体能做的事，例如创建 key、查看账单、调整用户余额。
- **角色**是一组权限，存在后台。系统自带一套默认角色（所有者、管理员、成员、财务、只读、客服），可以增改。
- **授予**：把一个角色在某个范围（平台、站点、账户、工作区）上授予一个操作者。
- 所有接口都调用本模块判断权限。资金额度上限、审批和操作审计由 `operations` 模块在授权之上再加一层。

### API key

- **两种 key**：调用 key 用来调模型；管理 key 只能管理 key 和预算，不能调模型，供 B 类用户的系统自动发 key。
- **可设置的属性**：名称、所属工作区、创建人、花费上限（可按日、周、月在 UTC 零点自动重置）、过期时间、可用模型、预设、IP 白名单、速率限制、启用或停用。
- **格式**：站点配置的前缀 + 随机串 + 校验位。前缀让二级站点使用自己的品牌；校验位能在离线时发现输错的 key。
- **存储**：只存带密钥的哈希（见[总体架构的「安全基线」](../architecture.md#安全基线)），完整的 key 只在创建时显示一次；界面上显示前缀和末四位。
- **使用范围**：key 只能在所属站点的域名上使用；域名和 key 的站点不一致就拒绝。

### 等级

- 每个站点定义自己的等级。等级决定加价（形式在计费中确定）、速率限制、可用的模型和预设。
- 账户进入某个等级的方式：手动指定，或按后台配置的规则自动升级，例如累计充值达到某个数额。

### 站点

- 主站、二级站点、站长和收款方式之间的关系见[术语与核心概念](../glossary.md#关键关系)第 2 至 4 条。
- 站点的配置：域名（可以有多个，证书自动签发）、品牌和主题、登录方式与第三方登录应用、注册策略、等级、key 前缀、收款渠道（二级站点用站长自己的商户账户）、数据留存的默认值、状态。
- 站长的员工按角色分工，例如客服只能查看用户、财务可以调整余额，角色的范围限定在这个站点。

### 配置链

- 范围从上到下：平台 → 站点 → 账户 → 工作区 → API key。
- 每项配置由负责它的模块在代码里声明：默认值、允许在哪几层设置、下层能修改的界限。
- 各层设置的值存在本模块，保存时校验并记审计；生效值算好后放进核心的内存快照。

### 停用与注销

- 站点、用户、账户、工作区、key 都能单独停用，停用立即生效。
- 注销用户时抹去个人信息，财务记录保留，因为账本不可修改。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 第一版登录方式为邮箱、GitHub、Google、LinuxDO、通行密钥 | 负责人决定，手机号和微信暂不做（需要公司主体和备案网站才能申请）。LinuxDO 在中转站用户中常用 |
| 会话存在服务端，不用 JWT | 可以立即踢掉设备、吊销会话；JWT 签发后在过期前无法收回 |
| 管理 key 与调用 key 分开 | 与 OpenRouter 一致：它的管理 key 不能调用模型，只能管理 key（OpenRouter 文档《Management API Keys》，2026-10）。泄露一把调用 key 不会危及整个账户 |
| key 的花费上限可按日、周、月重置 | 与 OpenRouter 一致（OpenRouter 文档《Create a new API key》，2026-10） |
| key 前缀由站点配置，带校验位 | 二级站点需要自己的品牌；校验位能在离线时发现输错 |
| key 只能在所属站点的域名上使用 | 负责人同意。避免"A 站的 key 在 B 站用，按哪个站计价"的歧义 |
| 从第一版起记录邀请关系 | 负责人同意。返利以后再做，但邀请关系只能在注册时记下，事后补不回来 |
