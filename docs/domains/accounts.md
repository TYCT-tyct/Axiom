# 账户与租户

谁能登录、钱和 key 归谁、谁能做什么、站点怎么配置。对应代码模块 `accounts`，公开接口和不变量见[模块 README](../../internal/accounts/README.md)，概念之间的关系见[术语与核心概念](../glossary.md)；外部对照和长推导在[存档](../archive/accounts.md)。

## 要求

- 用户、账户按站点隔离；C 类企业团队和 D 类二级站点的数据结构从第一版起具备（见[产品需求](../product.md#用户与市场)）。
- 第一版的登录方式：邮箱（密码；验证码登录待定，[#731](https://github.com/TYCT-tyct/Axiom/issues/731)）、GitHub、Google、LinuxDO、通行密钥（passkey）。
- 账户可以自带供应商 key（BYOK）：请求优先走自己的 key，失败后回落到 Axiom 的端点，除非这把 key 明确不许回落。key 保存后不再显示，也不进日志；供应商拒绝认证的 key 被标记并跳过；控制台可以添加、测试、停用和删除。
- 站点之间的差异（登录方式、注册策略、等级、品牌）全部是站点的后台配置，不写死在代码里。
- 从第一版起记录邀请关系。
- 站点发布服务条款和隐私政策时，注册必须接受每种文档一个当前版本；中英文各自成文、分别保存；已登录用户在当前版本未被接受时先接受才能继续。
- 停用 key、工作区、账户或站点后，下一次调用即被拒绝，多个节点同样成立。

## 设计

### 不变量

以下规则由数据库约束或代码断言保证，任何操作都不能破坏：

1. 账户、工作区、key 属于同一个站点。账户数据的每张表直接存 `site_id` 和 `account_id`（都不为空），由复合外键与"key → 工作区 → 账户 → 站点"保持一致，写入后不能修改。
2. 成员必须是账户所在站点的用户。
3. 每个账户恰好有一个默认工作区，不能删除；每个账户至少有一个所有者。
4. 个人账户只有它的主人一个成员。
5. 只有主站上的账户能开设站点。
6. 授权的范围必须在操作者所属的站点之内，唯一的例外见下文「授权」。
7. key 能否使用（key、工作区、账户、站点和域名的停用，key 的删除、过期、IP 白名单、可用模型）每次调用都以数据库为准，不以缓存为准。
8. 站点的 `logo_hash` 要么为空，要么指向本站点 `site_logos` 的一行；一个公开的 logo 地址永远返回同样的字节。前者由外键保证，后者由地址里的 SHA-256 保证。

### 登录与会话

- **登录方式**：邮箱 + 密码始终可用；GitHub、Google、LinuxDO 由每个站点在后台单独开启，填入站点自己的 OAuth 应用 client ID/secret 后生效，未配置即关闭；secret 信封加密，`site_oauth_providers` 只存密文。通行密钥由站点开关控制。邮箱验证码登录待定（[#731](https://github.com/TYCT-tyct/Axiom/issues/731)），设计保留，进第一版时再开卡。
- **注册方式**：站点在 `sites.registration` 选 `invite`（默认）、`closed` 或 `open`。邀请码注册在 `register` 的一个事务里建用户、个人账户、默认工作区、余额行和所有者成员关系；邮箱重复整体回滚。注册不自动登录，页面再用同一组凭证调登录。
- **邮箱与密码**：注册、找回和换邮箱都要求邮箱规范化（去空白、转小写）后是 3 到 254 个可打印 ASCII 字符，`net/mail.ParseAddress` 成功且解析结果等于原串；国际化地址不支持。密码 12 到 256 个字符，argon2id 哈希（19 MiB、2 遍、1 线程，参数写进 PHC 串，以后提高参数旧哈希照样能验）；不存在的邮箱也算一次假哈希。
- **开放注册**：页面在人机校验开启时先解证明，再提交邮箱和语言。服务端在库里读注册模式和默认等级，校验邮箱、域名名单和工作量证明，按（站点、规范化邮箱）写一条待验证请求：不保存口令，再次请求替换前一条并让旧链接失效。除了格式错误、域名不允许、人机校验失败和限流，一律返回 202 `verification_sent`。点击链接前没有用户、账户或工作区。
- **验证链接**：后台生成 256 位随机令牌、只存 SHA-256，链接是 `https://<控制台域名>/console/verify-email#token=…`，绑定待验证请求、站点和控制台域名，24 小时、一次性。页面在点击后设置密码；服务端先花一次该 IP 的认证预算，做未过期和域名名单的廉价检查，在锁外算 argon2id，再锁请求重查未过期、令牌哈希、域名名单和邮箱未被占用（不重查注册模式；站点停用后链接失效），然后同事务建用户、个人账户、默认工作区、余额行和所有者成员关系，写 `email_verified_at`，删除请求，记 `security.registration`。未知、过期、已使用或别站的令牌 422 `invalid_verification`；邮箱已被注册 409 `email_taken`。未点击的请求 24 小时后由每分钟的清理任务每批 1000 行删除。
- **人机校验**：自托管的工作量证明。页面找十进制 nonce，使 SHA-256(`axiom-registration-v1`、换行、站点 TypeID、换行、规范化邮箱、换行、nonce) 的前导零位数达到站点设定值（默认 18，可设 12 到 24）；服务端用同样的输入重算，不保存挑战。证明绑定站点和邮箱。
- **域名与频率**：邮箱域名 allow/deny 列表写入时转小写、去空白、去重，各最多 100 项；一项覆盖它的子域名，deny 优先，allow 为空表示不限；提交和点击链接时都检查。一次注册同时计入每 IP 桶和每（站点、邮箱域名）桶，成功不返还。后台 `/registration` 资源在同一事务写模式和设置并记 `site_registration.update`，审计只存名单的数量和 SHA-256。
- **注册同意**：站点用 `/api/admin/v1/sites/{site_id}/legal-documents` 发布服务条款（terms）和隐私政策（privacy），正文是站长的 Markdown 纯文本（标题、段落、列表，不解释 HTML，1 到 65536 字符），代码不内置真实条款（演示见[示例法律文本](../legal/README.md)）。文档按（站点、类型、语言 zh/en、版本）只追加；当前版本是每个（类型、语言）的最大版本。发布要 MFA、`sites.manage`、CSRF、幂等键和理由，审计只记类型、语言、版本、长度和 SHA-256。站点没有文档时不要求同意。
  - 注册必须为每种类型提交一个当前版本的（类型、语言、版本）：邀请码在 `register`，开放注册在 `verify-email`。服务端在建用户的事务里重读当前集合，缺失、过期、同一类型重复或不属于当前集合都是 403 `consent_required`，用户和接受记录同成同败。接受记录按（用户、类型、语言、版本）唯一，重复接受不改首次时间。
  - 已登录用户每次认证在会话查询里检查是否每种类型都接受了当前版本；未接受时 `getSession` 返回 `consent.required`，只放行 `getSession`、`acceptLegalDocuments` 和 `signOut`，其余 403 `consent_required`。控制台 `GET /api/console/v1/legal` 无需会话，带 `locales=all` 返回每种类型和语言的当前版本，省略时每种类型一个且不带 `locale`。
  - 兼容阶段：版本号按类型跨语言共享，服务端和会话检查只认每种类型的最新版本；页面在这个版本内按界面语言展示、缺失时回退，并提交实际显示的那份；省略 `locale` 的提交按类型和版本解析。历史游标接受 `kind:version` 和 `kind:locale:version`，只发出前者。清理迁移后才按语言独立编号。
- **会话**：存在服务端，浏览器只拿一个不透明令牌，放在 `__Host-axiom_session` Cookie（HttpOnly、Secure、SameSite=Lax、Path=/），库里只存 SHA-256。改数据的请求（含登录、注册）要求 `Origin` 等于该监听面登记的源、`Content-Type: application/json`，有会话的再核对 `X-CSRF-Token`；不开放 CORS，认证响应 `no-store`。登记的源是 `http://localhost` 时 Cookie 不带 `__Host-` 和 `Secure`。会话只在签发它的站点和监听面（控制台或管理后台）有效；空闲超时和最长有效期由站点配置，默认控制台 7 天、30 天，管理后台 30 分钟、12 小时。站点改短时长立即作用于已签发的会话，之后再放宽也不延长。
- **两步验证**：支持验证器 App（TOTP，RFC 6238：HMAC-SHA1、30 秒、6 位，接受前后各一个步长，同一步长只用一次）和通行密钥；TOTP 开启时发 10 个一次性恢复码（各 80 位，`xxxx-xxxx-xxxx-xxxx`，不分大小写、忽略连字符，只存 SHA-256）。只有通行密钥、没有 TOTP 的用户不发恢复码。会话接口另用 `mfa_enabled`（本监听面是否有可用第二因素：管理后台仅看 TOTP，控制台含 TOTP 或通行密钥）与可选的 `totp_enabled`（是否已配 TOTP）区分仅有通行密钥的账户，使其可首次开启 TOTP。
  - 有第二因素的用户密码通过后只拿到 `pending_mfa` 会话（5 分钟，只能调两步验证接口），一个挑战只换出一个 `mfa` 会话。
  - 持有敏感权限的人必须开启，平台管理员和站长的员工都包括在内；敏感操作只认本次会话做过两步验证，先登录、后开启或后被授权的会话不会因此变强。普通用户自愿开启；站点强制本站普通用户开启待定（[#731](https://github.com/TYCT-tyct/Axiom/issues/731)）。开启后第三方登录也要过两步验证。
  - 开启 TOTP 要密码和新密钥的一个码，已开启的拒绝；有通行密钥的用户必须在本次会话证明过通行密钥。重建恢复码要一个当前 TOTP 码。
  - **更换 TOTP**：已通过两步验证的控制台会话提交当前 TOTP 码或一枚未用恢复码，加上新密钥的一个码；因素未开启 409。两个码任一错误都计入每用户失败次数；消费当前码、换密钥、审计和新会话同一事务，失败时旧因素和恢复码保持可用。控制台不能关闭 TOTP，丢了验证器和恢复码的用户由运维用 `reset-mfa` 重置。
- **改了认证因素，旧的全部作废**：改密码、确认换邮箱、开启、更换或重置两步验证、重建恢复码、增删通行密钥、绑定或解绑第三方身份之后，这个用户的旧会话、旧恢复码和进行到一半的登录立即失效。它们共用一个收尾：加因素版本，TOTP 开着时重发恢复码，给当前设备签发原等级的新会话，与审计同一事务。绑定身份的答案是重定向，新恢复码加密存在新会话行上，控制台用 `takeRecoveryCodes` 读一次即清空。
- **第三方登录**：每次发起生成一次性 state（库里只存 SHA-256，10 分钟过期）、一个写入 `__Host-axiom_oauth` Cookie 的随机 nonce 和 S256 PKCE verifier；登录回调必须在发起它的浏览器里带回这个 nonce，state 才被消费。回调只接受登录域名，只按 provider 的 subject（GitHub 数字 `id`、Google `sub`、LinuxDO `id`）查已绑定身份；未绑定返回 `account_not_linked`，不注册、不按邮箱并入。登录计入每 IP 预算。回调 303 到 `/console/`（成功）、`/console/security`（绑定）或 `/console/sign-in?oauth=failed`。
- **绑定身份**：只能在已登录状态手动绑定，回调必须回到发起它的同一会话；同一 provider 每个用户一个身份，同一 subject 全站只属于一个用户。绑定和解绑走因素收尾，审计 `user.identity_link`、`user.identity_unlink`。
- **登录域名**：开启第三方登录或通行密钥的站点必须在本站已启用的控制台域名里指定一个登录域名；已有通行密钥、第三方身份或已配置 provider 后不能再移动（第一次设置不受限）。其他控制台域名上发起这两项会被拒绝，登录页把访客带到登录域名。
- **通行密钥**：WebAuthn，RP ID 是登录域名、origin 是它登记的源；都要求 user verification，注册要求 discoverable。它既是独立登录方式，也是密码之后的第二因素：有通行密钥的用户在登录域名上密码登录只得到待验证会话；其他控制台域名上只有通行密钥的用户被引导到登录域名，有 TOTP 的可用 TOTP；管理后台不跑 WebAuthn，保留密码会话，敏感操作仍要 TOTP。每个用户最多 10 个；注册和删除都要当前密码（计入用户失败桶），已开启第二因素时还要 `mfa` 会话。注册落库前在站点锁下重读开关和登录域名，与仪式登记的 RP ID/origin 不一致就拒绝。签名计数器只增不减：回退或从非零回到零的断言被拒，同一计数器的并发断言只有一个能写入。站点关闭通行密钥前用户须先删完自己的通行密钥。数据库触发器拒绝为有通行密钥的用户写入控制台 `password` 会话，也拒绝未经通行密钥证明的新 TOTP。
- **设备列表与撤销**：列表只含当前用户在本站控制台的有效会话（不含待验证登录和管理后台会话），按创建时间倒序最多 100 条，标出当前设备，给创建和最后使用时间、IP 分组（IPv4 原样、IPv6 取 /64）和 User-Agent 固定记号得出的客户端摘要，不回显原始值。撤销单台只接受列表里能看到的非当前会话，其他一律 404；退出全部其他设备连待验证登录一起结束，不越过监听面。撤销只写 `revoked_at`，不改因素版本；审计 `session.revoke`、`session.revoke_others`，没有结束任何会话时批量不写审计。
- **找回密码**：控制台提交邮箱和邮件语言（zh/en，默认 en），任何邮箱都返回相同的 202 空响应。请求路径只规范化、限流、写请求并入队，不查用户、不发信；数据库或队列故障对所有邮箱都报失败。后台只为本站启用的用户签发 256 位令牌（只存 SHA-256，绑定用户、因素版本和最新请求），请求提交起 30 分钟到期，新请求立即使旧链接失效，重试不重复签发。链接取数据库里本站启用的 HTTPS 控制台域名（优先请求时使用的那个，它不可用才按字典序回退），路径 `/console/reset-password#token=…`，不取 Host、转发头或调用方回调；邮件含站点名称、中英文正文和到期说明，经 outbox 与令牌同事务落库。
- **完成重置**：提交令牌与新密码；无效、过期、已消费、旧请求、别站或因素版本变化都是同一种无效链接错误，失败不消耗令牌。成功时同一事务消费令牌、写密码、加因素版本、记 `user.password_set`、入队不可关闭的变更通知。不自动登录；旧会话、恢复码和半完成登录失效，TOTP 保留，通知提醒登录后重新生成恢复码。
- **已登录改密码**：需当前密码、新密码、有效控制台会话与 CSRF；开了第二因素时要求本次会话 `mfa`。错误的当前密码计入用户失败桶。改动、`user.password_set` 审计与不可关闭的密码变更邮件（语言按请求，默认 en）同事务；走因素收尾，响应里可选的 `recovery_codes` 只显示一次。
- **换邮箱**：`POST /api/console/v1/profile/email` 要当前密码，开了第二因素时要 `mfa` 会话；错误密码计入用户失败桶，发送次数按用户复用找回密码的预算。新邮箱复用注册的格式、站点域名名单和站内唯一约束：格式或名单不通过时在扣发送预算前 422；这些检查都通过后才返回同站占用的 409 `email_taken`。验证信 24 小时有效，每用户一条待变更，重发替换；确认前登录和找回只认当前邮箱。`POST /api/console/v1/profile/email/confirm` 要本人登录及已开启的 MFA，令牌放请求体；到期和无效都是 422 `invalid_verification`（消息区分原因），发起后因素版本已变也拒绝。确认时重查最新域名名单，同事务更新邮箱、消费令牌、作废旧邮箱的找回令牌、记脱敏的前后邮箱审计、给旧邮箱发必发通知，并走因素收尾（200，带 Set-Cookie、可选 `csrf_token` 和 `recovery_codes`）。找回的后台按邮箱认出用户时锁用户行，并发确认后不会再向旧邮箱发有效链接。
- **个人资料**：`GET/POST /api/console/v1/profile/name` 读改个人账户的显示名，去掉首尾空白后 1 到 100 个 Unicode 字符，否则 400；只在变化时审计，审计只记前后长度。
- **历史无效邮箱**：改密码和换邮箱对不合格的现存邮箱返回 422，凭据不变。运维核验身份后可用 `axiom user set-password --email <现存邮箱>` 给主站用户重设密码（[命令行](../../internal/accounts/README.md#命令行)）：记审计、作废会话和恢复码、保留 TOTP，不发通知，不修正邮箱。没有修邮箱的命令；需要修复的要另行审查，保留原用户和账户，不能用新建用户代替。
- **邮件的失败与清理**：SMTP 未配置时注册、找回、改密码返回暂不可用（503）；入队失败回滚。发信失败由 River 重试，最终失败经 `queue.job_discarded` 日志和 `axiom.pg.queue.discarded_jobs` 指标告警。待处理邮箱只在有行级安全的请求行里，处理完清空；队列参数只有请求 ID。过期的找回请求、令牌和待变更每分钟由 archive 队列清理，每表每次最多 1000 行。没有可用域名、历史邮箱不合法这类永久失败清空邮箱后结束、不重试。任务期限 15 秒，错误日志 `accounts.password_reset.failed` 只记 job_id、attempt、类别和 SQLSTATE。
- **安全事件**：成功的注册、密码登录和两步验证与状态同事务写 `security.*` 审计；猜凭证的失败（错密码、错码、错通行密钥、无效邀请码）在独立事务里记 `*_failed` 并计入每站点每 UTC 分钟的失败数，只含固定分类和 ID，不含邮箱、IP、User-Agent 或任何凭证；限流拒绝、表单错误和过期会话不计。后台每站点每分钟最多发一条 `accounts.authentication_failures` 信号（完整窗口的峰值，之后第一个零窗口发恢复），按配置的阈值通知，不自动封号。
- **唯一性**：邮箱和第三方登录身份在同一站点内唯一，不同站点之间互不影响。**验证等级**是数据：邮箱已验证、手机已验证、已实名，站点决定要求到哪一级。

#### 登录前的尝试上限

次数用尽后等待，不锁账户；默认值在代码里，站点可改。配了 Valkey 时 IP、邮箱、用户的桶各节点共享，键里只有邮箱和 IP 的 HMAC；Valkey 不可用时退回进程内、按节点数等分，不拒绝登录（[kv 的登录设计](../../internal/platform/kv/README.md#每种用途)）。IP 按与网关相同的分组计（IPv4 映射还原，IPv6 取 /64），只认 `RemoteAddr`，`AXIOM_TRUSTED_PROXIES` 里的代理才读 `X-Forwarded-For` 最右一个不受信的地址。

| 计数 | 默认 | 站点设置 |
|---|---|---|
| 每 IP 的登录、注册、两步验证、找回 | 突发 20、每分钟 10 | `ip_attempt_burst`、`ip_attempts_per_minute` |
| 每邮箱域名的开放注册（子域名各自计） | 突发 5、每小时 30 | `registration_domain_burst`、`registration_domain_per_hour` |
| 每邮箱的登录失败；找回请求另计一份 | 每 15 分钟 10 次，不存在的邮箱也计 | `email_sign_in_failures` |
| 每用户的 TOTP、恢复码、改因素时的错密码 | 每小时 10 次，跨待验证会话累计 | `user_code_failures` |
| 每个待验证会话 | 5 次，用尽要重新登录 | `challenge_code_attempts` |
| argon2id 并发（按节点） | `GOMAXPROCS` 个，排队超过 2 秒 503 | `Config.HashConcurrency`、`HashWait` |
| key 未命中查库（按节点） | 每 IP 令牌桶加全局并发 32，超出 503 带 `Retry-After` | — |

失败次数先扣后退：尝试前扣一次，成功才退，所以同时到达的尝试也超不过上限；扣不到就不读凭证、不算哈希。IP 的次数不退。超限返回 429 和 `Retry-After`（至少 1 秒）。

### 账户、成员、工作区

- 每个用户注册时自动获得一个个人账户。
- 企业账户有多个成员。一个用户可以同时属于自己的个人账户和同站点的多个企业账户，在控制台切换。
- 每个账户可以另建多个工作区，例如分开生产和测试环境。每个工作区有自己的 API key、预算和默认设置。个人用户的界面不显示工作区，直到他创建第二个。

### 工作区

- **数据**：同一账户里未删除的工作区名称不分大小写唯一。每个账户的未删除工作区（含停用的）有上限：账户的盖过站点的，都没设是 50，可设 1 到 1000；管理接口 `/sites/{site_id}/workspace-limit`、`/accounts/{account_id}/workspace-limit` 修改，要 `sites.manage`、两步验证、理由和幂等键，审计 `site_workspace_limit.update`、`account_workspace_limit.update`。数量在插入的事务里锁账户行之后数（与建 key 同一把锁）；调低不影响已有的。
- **接口**（`api/console.yaml`）：`GET /api/console/v1/workspaces` 一次列出所有未删除的工作区，默认的在前，其余按建立顺序；`POST` 只要 `name`，新工作区启用、无预算、无自己的默认预设；`GET`、`PUT /workspaces/{id}` 读和整体替换 `name`、`disabled`。别的账户的、已删除的、不存在的 404，格式不对 400；同名 409 `name_taken`；超上限、停用默认工作区 409 `conflict`。工作区自己的默认预设在 `/workspaces/{id}/routing-default`。
- **权限**：读用 `api_keys.view`；建、改名、停用、启用和改预算用 `workspaces.manage`。管理 key 不能建或改工作区和预算。授权只有账户范围，账户上的角色覆盖它所有工作区。
- **停用**：停用后下一次调用即被拒绝（准入查询核对工作区状态），已通过准入的调用照常完成。停用工作区里的 key 仍在列表里、能改设置和删除，但不能在里面建新 key（409 `conflict`）。默认工作区不能停用；要停掉账户的所有 key，停用账户。
- **key 归属**：建 key 时可选 `workspace_id`，不选是默认工作区；之后不能换。key 的预设默认从它的工作区往上解析（[路由](routing.md#默认链与-key-落章)）。按别的账户的工作区筛选得到空列表。
- **审计**：`workspace.create` 记名称；`workspace.update` 只在有变化时记改了哪几项及前后值；都与改动同事务。
- **预算**：每个工作区一个预算（金额加重置周期），与 key 的花费上限同一种限额，在[计费的准入](billing.md#预留与结算)里与余额一起检查；准入查询本来就读工作区行，顺带读出预算，不多一次往返。`GET /workspaces/{id}/budget` 返回 `limit`（站点币种；没有预算时以下都省略）、`limit_reset`（`daily`、`weekly`、`monthly`，省略是不重置）、`used`（当前窗口已收加在途，即准入比较的数）、`limit_remaining`（不低于 0）、`resets_at`。`PUT` 整体替换：省略 `limit` 取消预算；金额是不为负的最小单位整数、币种是站点的；0 拒绝所有要预留金额的调用；只有 `limit_reset` 是 400。写在工作区行锁内，记 `workspace.update`。超过预算的下一次调用 403（`limit_source: openrouter_workspace_budget`）；改周期后按新窗口重算已用。管理 key 没有这个接口。
- **控制台**：只有一个工作区时菜单、key 表单和列表都不出现工作区，设置页给持 `workspaces.manage` 的人一个「管理工作区」入口；有第二个之后出现「工作区」页（列出、新建、改名、停用启用、看 key、预算和用量）。key 表单只列启用的工作区；选中的工作区后来被停用时说明原因并拒绝提交，不悄悄换。读不到工作区列表时按只有一个处理。

### 授权

- **权限**是代码里定义的一件具体能做的事，例如创建 key、查看账单、调整用户余额。每个权限声明自己能在哪些范围上授予，以及是否属于敏感权限。
- **角色**是一组权限，存在后台。系统自带一套默认角色（所有者、管理员、成员、财务、只读、客服）。平台可以定义在所有站点通用的角色；站点可以定义只在本站使用的角色。
- **授予**：把一个角色在某个范围（平台、站点、账户、工作区）上授予一个操作者，并遵守以下规则：
  - 授予的范围必须在操作者所属的站点之内；
  - 唯一的例外：站长账户的成员，可以获得这个账户所开设站点的范围；
  - 平台范围只能授予主站用户，平台管理员就是持有平台范围角色的主站用户；
  - 授予者只能授予自己拥有的权限，范围不能超出自己的范围，所以没人能借授权给自己升级；
  - 授予随成员关系存在：成员被移除或用户注销时，由此产生的授予在同一个事务里撤销。
- 每次授权只交出覆盖本次操作目标的租户范围，不是操作者所有授予的并集。
- 所有接口都调用本模块判断权限。资金操作上限和审批由 `operations` 模块在授权之上再加一层；改动由做改动的模块记入平台的审计日志。
- 现在只有两种授予：注册时成为个人账户的所有者；运维用命令行授予平台角色。管理后台能撤销平台授予（终态）和恢复（插入新授予，要求有历史授予且权限是操作者现有权限的子集）。
- **运营凭证**：运营 agent 是独立的操作者种类，权限名和角色里的同一套，由控制面直接授予权限集合、站点范围和是否平台范围，不经过成员关系；只在运营监听有效，不能登录、不能调用模型，也不能持有 `operations.approve`、`operations.manage` 或 `platform_grants.manage`。见[运营的「运营凭证」](operations.md#运营凭证)。

### API key

- **调用 key**用来调模型。可以设置：名称、所属工作区、花费上限（可按日、周、月在 UTC 零点重置，或不重置的总额）、过期时间（只能在创建时设）、可用模型（最多 256 个、每个 200 字）、路由预设、IP 白名单、业务速率限制、启用或停用。新建的调用 key 默认带每日花费上限，金额是站点设置（默认 10 额度），可以修改或取消。控制台用 `PUT` 整体替换设置，没写的限制就是不限。
- **路由预设**：建 key 时可以指定 `preset_id`，不指定时服务端按 工作区 → 账户 → 站点 → 平台 找最近一层设置，解析成具体预设 ID 写在 key 上；某层设置了却指向不可见、已停用或币种不符的预设时 409 `preset_default_invalid`，不跳过；都没设置用平台 allow-all。key 上没有"跟随默认"的状态，默认改变只影响新 key。只能选本站、本账户、本工作区可见的活预设；别的租户的、不存在的、停用的、系统预设和零 UUID 一律 400 `preset_not_selectable`。修改时省略保持，不能清空。管理 key 没有预设（表的 CHECK 保证）。控制台列表显示 key 的预设，绑定的不是现在的默认时标出现在的默认（[路由的「默认链与 key 落章」](routing.md#默认链与-key-落章)）。
- **管理 key** 是独立的程序化操作者，由同时持有 `api_keys.manage` 与 `api_keys.view` 的控制台用户签发（`kind: management`），必须在将来到期。范围固定为本站自己的账户，角色固定为调用 key 管理员；不能调用模型、创建或修改管理 key、修改账户或工作区预算、访问账单或支付；只读的 `/api/v1/key` 和 `/api/v1/credits` 例外（[接入的决策](gateway.md#决策与理由)）。
  - `/api/v1/keys` 和 `/api/v1/keys/{hash}` 只接受 Bearer 管理 key，无效或类型不符统一 401；响应用 OpenRouter 的 `data`/`key`/`deleted` 外壳和数字错误码，创建只返回一次明文，hash 是非秘密的 key UUID 十六进制。列表按创建时间倒序、每页 100、offset 分页，默认只列默认工作区里启用、未到期的 key（`include_disabled`、`include_expired`、`workspace_id` 可改）；`limit_remaining` 含在途预留、不低于 0，BYOK 用量恒为 0。请求最多 64 KiB、总期限 5 秒，未知字段拒绝。
  - 新调用 key 默认继承管理 key 的花费上限及重置周期、可用模型、IP 白名单和到期时间（预设不继承）。显式设置只能收紧：金额不更大且重置周期相同，名单是子集，到期不晚于管理 key；PATCH 区分省略和 `null`。修改已有调用 key 时，纯收紧（减额、缩名单、停用）即使原设置超出上界也允许；重新启用、扩权和换预设必须整体在上界内，否则 403。管理 key 的上限是每把调用 key 的签发上界，不是汇总池；之后收紧或停用管理 key 不追溯已签发的调用 key。
  - 每个操作都读库验证站点、域名、账户、工作区、状态、到期和 IP，改动与管理 key 行锁内的授权、审计同事务，审计主体 `management_key:<uuid>`。每把管理 key 每个数据库 UTC 分钟最多 60 个请求，跨节点共享，无效操作也计，429 带 `Retry-After`，数据库故障不放行。
- **格式**：站点配置的前缀（`[a-z0-9-]{2,16}` 且以 `-` 结尾；主站 `sk-ax-v1-`）+ 256 位随机串 + 校验位。校验位离线发现输错的 key；站点改前缀不影响已发出的 key。
- **存储**：只存带密钥的哈希并记下哈希密钥的版本（[安全基线](../security.md#安全基线)），轮换哈希密钥时旧 key 不失效。完整的 key 只在创建时显示一次，界面显示前缀和末四位。删除是终态。创建不做幂等键：响应丢失时用户删掉那把从未用过的 key 即可。
- **数量与创建频率**：每个账户最多保有的未删除 key（调用与管理共用，默认 100）和每小时最多创建的 key（含已删除的，默认 50）各自按 账户 → 站点 → 默认 取值，可设 1 到 1 万；在管理接口 `/sites/{site_id}/key-limits`、`/accounts/{account_id}/key-limits` 整体替换，要 `sites.manage`、理由和幂等键，审计 `site_key_limits.update`、`account_key_limits.update`。数量在插入的事务里锁账户行之后数，一小时按库的时钟数。到数量上限 409 `too_many_keys`；超频率 429 `rate_limited` 带 `Retry-After`（使数量降到限额以下的那把 key 满一小时的时间）；两种都写明生效的限额和真实数量。调低不删已有的 key。
- **列表、搜索与筛选**：`/api/console/v1/keys` 按创建顺序倒序列出账户的 key（含停用与过期），游标是上一页最后一把 key 的 ID。筛选：`name` 不分大小写的字面子串（`%`、`_` 不是通配符），`prefix` 不分大小写的前缀，`status` 取 `active`、`disabled`、`expired`（先判过期，按库的时间），`created_after` 含、`created_before` 不含，`workspace_id`。读一页的代价随本页读到的行数增长，不随 key 历史增长；不按 `last_used_at` 筛选或排序。`filters` 回显实际应用的筛选。可选字段：`retired_models`（可用模型里已被目录下线的名字）、`preset`（预设摘要，取不到时页面显示"未知"）、`created_by {user_id, display_name}`（显示名取创建人的个人账户名；离开账户、不可见或已删除时显示 `Unknown user`，保留用户编号）、`last_used_at`、`daily_spend`（含今天在内最近 14 个 UTC 日的已结算花费，按日期升序，缺日为零，从未花费为空数组，十亿分之一货币单位的十进制文本，不含在途预留）。
- **最近使用时间**：`last_used_at` 是 key 最近一次通过准入检查的时间，不表示上游成功或已结算；尽力而为（每节点暂存至多 4096 次、每秒批量写，可丢），只前进不倒退。
- **改动的审计**：`api_key.create`、`api_key.update`、`api_key.delete` 与改动同事务；修改记改了哪几项，名称、停用、花费上限、重置周期、预设 ID 记前后值，可用模型和 IP 白名单只记「变了」。key 的文本和哈希从不进日志。
- **使用范围**：key 只能在所属站点登记的 API 域名上使用；域名与 key 不属于同一站点时，返回与"key 不存在"完全相同的错误。
- **接入地址**：新建 key 的对话框给出三种调用格式的 curl 示例和 Claude Code、Codex、Cursor 的配置，地址取本站启用的 API 域名的 origin（`getSite` 的 `api_base_url`；多个时优先 HTTPS，再按字典序），不按控制台域名或 Host 拼；OpenAI 形状的客户端用 `origin/v1`，Anthropic 客户端用 `origin`。没有 API 域名时省略，查询失败时可重试并保留明文。
- **认出与准入分两步**：认出 key（它是谁、属于哪个工作区和账户）查内存缓存，缓存只存创建后不会变的对应关系；能否使用在准入事务里读数据库判定，预设、可用模型、等级、限额也在这里读出交给路由和计费。满载排队在事务之外，不占数据库连接。已经通过准入的调用照常完成，与计费"请求一旦开始不中途掐断"一致。
- **限额怎么生效**：一次调用同时满足所有适用的限制，以最严的为准：账户余额、工作区预算、key 的花费上限、等级和 key 的速率限制。花费计数和预留由 `billing` 在同一个准入事务里检查（[计费的「预留与结算」](billing.md#预留与结算)）。
- **扣费顺序**：账户在设置页（`/api/console/v1/billing-preference`）选 `subscription_first`、`wallet_first`、`subscription_only`、`wallet_only` 之一，没选用站点默认，站点没设是 `subscription_first`。生效值随 key 的准入快照带下来，网关不再查；一次调用只用一个来源，两个 `only` 不互相回退（[计费的「资金来源」](billing.md#资金来源)）。还有不认识偏好的节点存活时，生效值固定为默认、设置接口拒绝非默认值；新节点心跳确认后自动开放。

### 业务速率限制

账户、等级、调用 key 的 `rate_requests` 是后台数据：null 继承，0 不限，正数为一个网关速率窗口（默认一分钟）内的请求数，最大 10 亿。账户覆盖等级，等级未设置时用代码默认 6000；key 未设置时继承账户的有效值。等级是每个账户的默认值，不是整个等级共用一个池。账户计数聚合所有 key，key 自己的限制和节点保护同时生效；key 不限也不能绕过账户或节点保护。管理 key 不参与模型调用限流。

计数在准入前按不可变的账户和 key 标识取一次，准入事务读最新策略再判定，排队或上游重试不重复计数；调用与 count_tokens 分开计数。key 的尝试总是计数、不返还；超过节点保护 KeyRate/CountRate 的尝试不推进账户池，所以失控的 key 不挤占兄弟 key 的额度。业务 key 限额只在准入事务里读到，被业务 key 限额拒绝的尝试仍消耗账户池：给 key 设低额度不提供完全隔离。Valkey 超时退回同步维护的本地计数，故障期间可能按节点数放大。

后台 `GET/PUT /api/admin/v1/rate-limits/{target}/{id}` 支持 tier、account、key；PUT 要平台 MFA、`sites.manage`、CSRF、幂等键和理由，前后值审计同事务。普通 key 设置和管理 key API 不写这些字段。

### 等级

- 每个站点定义自己的等级。等级是一组账户层级的默认值：速率限制、可用的模型。路由预设不按等级（见[配置链](#配置链)）。加价不在这里：给某个等级用的加价是计费的一条定价规则（[计费的「定价」](billing.md#定价)）。
- 账户进入某个等级的方式：手动指定，或按后台配置的规则自动升级，例如累计充值达到某个数额。
- **默认等级**：每个站点指定一个默认等级。新账户注册时进入站点当时的默认等级（在库里读，不取快照）；以后改默认等级不影响已有账户。未登录的访客看到的价格也按默认等级算（[前端的「页面清单」](../frontend.md#页面清单)）。
- **调整等级**：`PUT /api/admin/v1/accounts/{account_id}/tier` 提交目标等级和理由，要 MFA、`users.manage`、CSRF、幂等键，成功 204；同一等级不写审计；等级不属于账户的站点 422（`fields./tier_id`）。账户行锁内写并记 `account.tier_change`（前后等级名），下一次调用即按新等级。

### 站点

- 主站、二级站点、站长和收款方式之间的关系，见[术语与核心概念](../glossary.md#关键关系)中的「主站也是站点」和「二级站点由主站上的一个账户开设」。站点只有两层，上级只能是主站。站点的币种创建时写定，主站只能是 `USD`，之后不能改。
- **站点的配置**：域名（可以有多个，每个标明用途：控制台、API、管理后台；证书自动签发）；品牌和主题（品牌色、站点名称和 logo）、登录方式与第三方登录应用、注册策略、等级、key 前缀；收款渠道（二级站点用站长自己的商户账户）、数据留存的默认值、状态。
- **配置项由负责的模块各自声明**，例如收款渠道由 `payments` 声明，登录方式由本模块声明。第三方登录应用和收款渠道的密钥按[安全基线](../security.md#安全基线)信封加密存储。
- **只认登记过的域名**：请求按域名认出站点，只接受站点登记过的域名，其他一律拒绝。生成链接一律用站点配置的域名，不用请求头里的 Host。
- **站长员工按角色分工**：例如客服只能查看用户、财务可以调整余额，角色的范围限定在这个站点。
- **后台的站点设置**：每项一个独立资源，都要 MFA、`sites.manage`、CSRF、幂等键和理由，在站点行锁内读前值、写、同事务审计；改动的节点立即重载快照，其余节点 30 秒内跟上。
  - `/settings`：整体替换会话时长、新 key 每日上限（0 到 100 万额度）、模型价格是否对未登录访客公开（默认公开；还有旧节点时拒绝关闭）和站点默认扣费顺序；请求没带后两项时保留原值。时长最短 5 分钟，最长依次为控制台空闲 30 天、控制台最长 90 天、后台空闲 12 小时、后台最长 1 天。审计 `site_settings.update`。
  - `/login-limits`：整体替换上文的五项尝试上限（最小 1，最大依次 1 万、1 万、1000、1000、100）。
  - `/system-settings`：读站点名称和注册方式、改名称；省略 `registration` 时保留当前值（含 open），给出时只接受 invite/closed。响应的 `name_editable` 说明本节点是否接受只改名称。收款开关和充值额度由同路径的 `/payments` 交给 payments。
  - `/brand`：品牌色 `#rrggbb`（转小写）或空（默认配色），审计 `site_brand.update` 记前后值。控制台 `GET /api/console/v1/site` 在设置时返回 `brand_color`，页面据此生成深浅两套配色（[前端](../frontend.md#主题与自由度)）。
  - `/logo`：见下条。
- **站点 logo**：一个站点至多一个，后台 `/api/admin/v1/sites/{site_id}/logo` 读、换、清，审计 `site_logo.update` 只记 hash、类型、尺寸和字节数。只收 SVG、PNG、WebP，最大 256 KiB；PNG 和 WebP 每边 1 到 1024 像素（PNG 读头核对，WebP 限制尺寸后完整解码）。SVG 保存前按允许列表重建：只留绘制用的元素和表现属性，去掉 `script`、事件属性、`style`、`foreignObject`、图片、链接、动画和外部引用（`href` 只能是本文件的 `#id`），带 DTD 的直接拒绝；保存、哈希和发送的都是重建后的字节。字节按（站点、SHA-256）追加，换 logo 只移动指针，旧地址继续返回旧字节。公开地址是控制台域名下的 `/api/console/v1/site/logo/<sha256>`，管理域名下另有同内容的 `/api/admin/v1/site/logo/<sha256>`，都返回 `Cache-Control: public, max-age=31536000, immutable`。`getSite` 在 `logo_url` 给出地址；管理后台登录前由公开的 `getAdminSite` 给名称和同源的 `logo_url`，设置页用 `data_url` 预览。没有 logo 或加载失败时显示站点名称。
- **SMTP 设置**：平台 `/api/admin/v1/settings/mail` 读写共享 SMTP 覆盖配置，整包信封加密，只返回是否启用、非密连接设置和是否有密码，审计不存值。省略密码复用原密码，改服务器、端口或用户名必须重填；幂等指纹只区分是否提供密码。配置在节点启动时生效（`restart_required`），没有覆盖时用环境变量。保存和拨号都执行 egress 公网地址策略并钉住解析出的 IP。`/settings/mail/tests` 同步测试已保存的配置，返回 accepted/rejected/failed/disabled，不返回 SMTP 原文；要 MFA、`sites.manage`、CSRF、幂等键和理由，每会话每分钟最多 10 次。

### 给用户的邮件

- **归本模块**：收件人（用户和账户成员）、模板、站点品牌和多语言都在这里。投递在 `platform`：SMTP 发送、消息组装、按收件人的限流和重试都在 [platform 的 mail](../../internal/platform/mail/README.md)，经 outbox 与业务写入同事务。发给运维的通知渠道另见[记录与告警](observability.md#通知渠道)。
- **谁触发**：验证、找回、密码与邮箱变更、异地登录由本模块触发；余额不足、充值到账由 billing、payments；账户异常花费由 observability（[安全的「防滥用」](../security.md#防滥用)）；key 泄露由密钥扫描；模型切换与迁移由 catalog（[模型的生命周期](catalog.md#模型的生命周期)）。其他模块只交事件和值，不各自拼邮件。
- **写法**：只链到站点登记过的域名，不信任 Host 和转发头；正文不插入用户可控的内容；链接带一次性令牌，用完即失效。
- **送达**：登录必需的邮件发送失败要让用户重试并告警；其余提醒异步发送、失败重试，不影响调用和计费。用户关掉的提醒类型不发；密码变更、邮箱变更的安全邮件和模型切换与迁移的通知必须送达，不能关闭（[前端的「通知」](../frontend.md#页面清单)）。
- **下层怎么触发**：catalog 在本模块下面，不能引用本模块；它声明一个发送通知的接口，由 `cmd/axiom` 接到本模块（[总体架构的规则 5](../architecture.md#模块边界规则)）。billing、payments 可以直接调用。

### 用户提醒与站内公告

- **偏好**：低余额、充值到账、认证因素变化、账户异常花费各有开关，默认开启邮件；低余额阈值默认 5 额度；可选一个 HTTPS Webhook；语言 zh/en。偏好属于登录用户，目前只有个人账户。因素开关只控制后台的 TOTP、恢复码等因素邮件和因素 Webhook，不影响必发的密码安全邮件和找回邮件。提醒只是通知，不暂停 key，也不替代运维告警。旧客户端保存偏好时不带 `spend_anomaly`，服务端保留已存值。
- **来源**：billing 在账本写入的同事务记余额变化 journal，后台每分钟按集合消费（每批最多 1000 行）；低余额只在已过账钱包余额从不低于阈值跌到阈值以下时通知，充值恢复后再跌破可以再发，忽略在途预留。因素版本每次改变由 accounts 同事务记事件，覆盖控制台、命令行和管理员重置。账户异常花费由 observability 在检测事务里调 `RecordSpendAnomalyNotices`：同一账户一轮检测只写一条，三种信号合并，邮件只有站点名称、种类、金额和处置建议；关闭后不写新提醒，恢复不补发；全局开关 `spend_detection.notify_users` 默认关闭，全部节点认识这一种类后再打开。
- **二级站点收款变更**：支付模块保存商户配置的同一事务里调 `RecordSitePaymentNotice`，给该站点所有者账户的活跃用户写一条必发的 `site_payment_changed`（主站没有所有者，不写）；正文有主站品牌、被改的站点名（`detail`）和"若不是你操作"的处置建议，不含商户号、密钥、网关地址或前后值；保存失败时与审计一起回滚。
- **去重与派发**：同一来源、种类和用户只有一条提醒。开关、地址和语言在派发时读出并冻结到任务。派发器按编号领取未派发的提醒。邮件进 outbox，SMTP 不可用时连同 Webhook 保持待派发，不阻塞认证与充值；历史非法邮箱记 `email_failed`，不影响其他用户。已派发的通知保留 30 天。邮件与 Webhook 都是至少一次。
- **Webhook**：正文只有稳定通知 ID、种类、时间、`currency` 和字符串 `value`（金额是十亿分之一站点额度，因素事件是版本），收款通知另带 `detail`；不含调用内容、IP 原文或凭证，没有签名，接收方按 ID 去重。经 egress 防 SSRF、不跟重定向、10 秒期限，仅 2xx 成功，最多五次持久重试；URL 不进任务或审计。
- **站内公告**：本站的一般信息，对外 ID 是 `ann_` TypeID；不发邮件，没有已读或确认状态，独立于必须送达的迁移和切换通知。管理员经 MFA、`sites.manage`、幂等键和审计发布纯文本标题和正文，起止时间（UTC）必填，撤下后不可恢复，内容不可修改。控制台只列本站 `starts_at <= 当前时间 < ends_at` 且未撤下的公告，最新优先最多 100 条，正文按文本显示。

### 配置链

- **范围从上到下**：平台 → 站点 → 等级 → 账户 → 工作区 → API key。等级是一组账户层级的默认值；账户上显式设置的值优先于等级。
- **每项配置由负责它的模块在代码里声明**：默认值；允许在哪几层设置；下层能修改的界限；合并方式，共三种：默认值类最具体的那层生效；限额类各层同时生效、取最严；名单类（可用模型、IP 白名单）各层取交集。
- **路由预设是产品单独规定的默认值链**：平台 → 站点 → 账户 → 工作区，不经过等级；预设由 routing 保存，key 创建时解析成具体 ID 落在 key 上。某层默认无效返回 409，不回退到更宽的层（[路由](routing.md#路由预设)）。
- **存储与生效**：各层设置的值存在本模块，保存时校验并记审计；生效值放进内存快照。现在没有通用的配置链：key 的设置存在 key 上，站点参数存在站点设置里，默认值在代码里。
- **命名请求配置**：账户持有命名的请求配置（`{slug, name, config}`），由控制台的 `api_keys.view`/`api_keys.manage` 或管理 key 增删改查；它不能替代调用 key 的模型授权，也不是路由预设。存储见[模块 README](../../internal/accounts/README.md#命名请求配置)，合并与调用行为见[路由的「命名预设」](routing.md#命名预设)。

### 自带的供应商 key（BYOK）

账户可以保存自己的供应商 key。一把 key 是一个账户归属的供应商（`owner_scope=account`），由 suppliers 模块保存和管理：key 文本与供应商凭证走同一套信封加密，控制台只在保存时接收一次明文，之后只给末四位。能力默认关闭，部署设 `AXIOM_BYOK=on` 后才接受建 key。

- **支持范围**：OpenAI 官方的 key（适配器 `openai`，地址 `https://api.openai.com`，调用格式 chat、responses、completions、embeddings）。其他 provider 返回 422。
- **建一把 key**：一个事务写供应商（状态 `byok`，不参与同步）、一个分组（倍率 1）、该 provider 已上架且不带 `:free` 的目录模型各一个端点与全零成本计划、一条 `active` 凭证（8 个并发，不限每分钟请求）、一条金额和单位价值都为 1 的供应商余额，路由因此像普通端点一样挑它。售价按[计费的「定价」](billing.md#定价)的 BYOK 服务费收，调用仍先准入和预留。
- **列表**：名称、provider、末四位、启用、是否被拒绝、是否允许回落和创建时间，没有 key 文本、密文或上游地址。
- **测试**：`POST /api/console/v1/provider-keys/{id}/test` 用保存的 key 发一次 OpenAI `GET /v1/models`（10 秒期限）。成功把被拒绝的凭证恢复为 `active`；401 标记 `rejected`；403 和其他失败只报告不可判定、不改状态。
- **停用与删除**：停用置凭证 `disabled`，下一次调用不再选它；启用置回 `active`，被拒绝的仍是 `rejected`；删除把供应商置 `removed`、凭证置 `erased` 并清掉密文，已有的尝试成本行保留。
- **被拒绝**：供应商以 401 拒绝时调用路径把这把账户凭证写成 `rejected`，本节点立刻休息它；`rejected` 永不被挑选，只有测试成功才恢复。403 不标记。不许回落的 key 见[路由](routing.md#一个请求的路由步骤)。
- **路由预设**：对 BYOK 一视同仁，来源类别、数据政策、成绩、验证和最高单价照常过滤；没有记录的端点属性按最坏情形。优先级和 `fallback=false` 见[路由](routing.md#路由预设)。
- **权限与隔离**：控制台用 `api_keys.view`/`api_keys.manage`。一把 key 只对所属账户可见；端点只能引用本站、本账户的供应商；明文只在 `suppliers.credentials` 的密文里，不进任何接口、日志、审计和错误。
- **失败**：供应商故障、限流、请求错误走供应商已有的失败分类和回退；一把 key 失效只影响它自己，不影响同账户的其他 key 和平台端点。

### 停用与注销

- 站点、域名、用户、账户、工作区、key 都能单独停用。停用立即生效：每次调用在准入事务里读数据库核对 key、工作区、账户、站点和域名的状态，与缓存无关。账户停用只暂停调用，控制台登录仍可用（方便充值和申诉），其余条件有效的 key 在准入返回 403；其余无效 key 仍是 401。停用用户只阻止登录并吊销全部会话，恢复后需重新登录，不改因素版本；要让 key 不能用，停用账户或 key。
- 管理接口：账户 `/suspension`、用户 `/sign-in` 要 MFA、`users.manage`、CSRF、幂等键和理由，成功 204；平台授予 `/platform-grants/{role}` 撤销和恢复要 `platform_grants.manage`。状态变更同事务记审计，相同状态不重复写；账户暂停另记 `accounts.account_suspended` 信号（暂停 critical，解除时恢复），拒付也用它暂停。
- 本模块的停用是管理员的开关；计费的「余额不足」和「暂停」是另一回事，见[计费的「风控状态」](billing.md#风控状态)，两者在同一个准入事务里检查。
- **注销用户**（未实现）：抹去个人信息，财务记录保留，因为账本不可修改；剩余余额按站点的退款政策处理（[计费](billing.md#额度批次)）；对话内容和调用记录按[记录与告警](observability.md#待定问题)处理；注销后同一邮箱可以重新注册，得到全新的用户。账户的唯一所有者要先转让所有权，站长账户的所有者还要先停用自己的站点。

### 邀请关系

- 每个用户有自己的邀请码和邀请链接。通过它们注册时记下邀请人。邀请人在注册那一刻确定，之后不能修改；必须是同站点的另一个已有用户，不能自己邀请自己。
- 只有 `invite` 模式记录邀请人；`open` 模式忽略邀请码，`closed` 拒绝注册。开放注册的归属缺口见 [#763](https://github.com/TYCT-tyct/Axiom/issues/763)。
- 控制台 `GET /api/console/v1/invitations` 只读本人的邀请码、链接和邀请记录，不含返利与金额。链接用请求的控制台域名登记的源，路径 `/console/register?invite=<code>`。`invitees` 每条只有 `registered_at` 和 `available`（停用用户为 false），不读被邀请人的邮箱或姓名。按 ID 倒序键集分页：`cursor` 是上一页最后一条的 UUID，`limit` 默认 50、最大 200，末页 `next_cursor` 为 null。响应字段可选，路径 404 表示功能不可用。

## 决策与理由

比较过的方案和外部出处见[存档](../archive/accounts.md)；标「负责人决定」的改动要负责人同意。

| 决策 | 理由 |
|---|---|
| 账户下设工作区，每个账户自带不能删除、不能停用的默认工作区（负责人决定）；工作区停用而不删除 | 企业要按项目或环境分开 key 和预算；默认工作区是新 key 和默认预设解析的起点；删除要决定已删工作区的 key 和花费计数的去留，现在没有需求。 |
| 工作区名称在账户内不分大小写唯一，没有 `slug` | 名称是选工作区时唯一看得到的东西；路径用 ID，`slug` 只多一处要校验的字段。 |
| 每个工作区一个预算，放在独立的 `/budget` 资源，准入顺带读出 | 一个预算已满足"每个工作区可设消费上限"；独立资源让整体替换的旧客户端改名时不会抹掉预算；零额外往返且跨节点立即一致。 |
| 工作区和 key 的数量上限是后台数据，分站点和账户两层 | 产品要求阈值是后台数据，账户要能单独调整。 |
| 读工作区沿用 `api_keys.view` | 能看 key 的人本来就看得到 `workspace_id`；新增权限要迁移所有角色。 |
| 统一授权：权限在代码，角色是数据，按范围授予；授予只能是授予者权限的子集（负责人决定） | 所有操作者用同一套规则；杜绝借授权升级。 |
| 站长在主站登录管理站点；一个账户可开多个站点（负责人决定） | 站长只需一个身份，经营多个品牌不用开多个账户。 |
| 二级站点由站长自己收款（负责人决定） | Axiom 不经手终端用户的钱，不需要提现、分账或支付牌照。 |
| 手机号和微信登录暂不做（负责人决定） | 需要公司主体和备案网站才能申请。 |
| 会话存在服务端，不用 JWT | 可以立即踢掉设备；JWT 在过期前无法收回。 |
| 两步验证接口在控制台和管理契约里各一套，注册不自动登录 | 会话只在签发它的监听面有效；注册不多一种会话来源。 |
| 注册有邀请码和开放两种，开放默认关闭 | 邀请码留给受控发放；默认关闭让升级不改变任何站点。 |
| 开放注册先存待验证请求，点击才建用户，提交一律 202 | 未验证的邮箱不占用户；相同响应防匿名枚举。 |
| 待验证请求不保存口令，点击链接时才设置 | 否则知道受害者邮箱的人能替他预置口令并抢先登录。 |
| 验证链接 256 位、只存哈希、24 小时、一次性，绑定站点和域名 | 不可猜，泄露数据库后不能直接用，别站的链接不能在本站消费。 |
| 人机校验用自托管工作量证明 | 不把访客数据交给第三方，也没有外部可用性依赖。 |
| 域名名单写入时规范化，deny 优先，提交和点击时都检查 | 大小写不能绕过；紧急封禁不必先改 allow；24 小时窗口不能绕过新封禁。 |
| 开放注册同时按 IP 和邮箱域名限流 | 单靠 IP 挡不住分布式来源，单靠域名会让热门域名挤掉正常用户。 |
| 注册策略、品牌色、登录上限、key 和工作区上限、法律文档、账户等级都是独立资源，不并入整体替换的设置 | 旧页面整体替换时不会抹掉它不认识的字段。 |
| 法律文档只追加，当前版本取最大版本，不设当前指针 | 接受记录必须永远指向当时给人看的文本；没有指针就没有指针与行不一致的状态。 |
| 兼容阶段版本号跨语言共享、只认每种类型的最新版本 | 旧节点仍按旧主键写；按语言选较低版本会让新节点接受后旧节点又要求重签。 |
| 注册同意在建用户的事务里校验，已登录用户由会话查询检查，未接受时只放行读会话、接受和退出 | 不会留下没有接受记录的用户；新版本立即生效且不多一次往返；不放行接受和退出会把用户锁死。 |
| 没有文档的站点不要求同意；文档是公开数据，接受记录是账户数据 | 机制不替站长决定何时上线条款；注册页未登录就要显示文本。 |
| 第三方身份只按（站点、provider、subject）匹配，不按邮箱合并，未知 subject 不注册 | 邮箱可被更改或伪造，按邮箱合并能接管账户。 |
| 回调固定到登录域名，state 一次性且存哈希，登录另带浏览器 nonce，都用 PKCE | state 防 CSRF，nonce 防把回调 URL 交给别的浏览器完成登录，PKCE 防授权码被截获。 |
| 通行密钥要求 UV、注册要求 resident key，计数器只增不减；协议层用 go-webauthn | UV 证明是本人；计数器回退是凭证被克隆的信号；认证边界上自己解析 CBOR 和 attestation 容易写错。 |
| 登录域名在有通行密钥、第三方身份或 provider 后不可移动 | RP ID 和回调地址绑定域名，移动会让已注册的凭证失效。 |
| 所有认证因素变更共用一个收尾，与审计同事务 | 收尾只写一处，新操作不会漏掉版本或恢复码；审计失败则变更回滚。 |
| 数据库触发器拒绝通行密钥用户的密码会话和未经证明的新 TOTP | 两个版本的节点都会执行这条约束，旧节点不能绕过第二因素。 |
| 设备列表只列有效会话、只回 IP 分组和客户端摘要；撤销只写 `revoked_at` | 看到的一定能撤销；原始 IP 和 UA 是个人信息；结束一台设备不应作废别处的恢复码。 |
| 更换 TOTP 用当前因素码或未用恢复码，不用密码 | 只拿到密码或只拿到恢复码的人不能单独换掉因素。 |
| 找回密码持久化异步签发 | 请求路径不查用户，账户是否存在不进入响应时序。 |
| 重置链接只取库里本站的 HTTPS 控制台域名，令牌放 URL 片段 | Host 或转发头不能把凭证带到别处；片段不进请求日志和 Referer。 |
| 重置令牌 256 位、只存哈希、30 分钟、绑定最新请求与因素版本；重置不自动登录、不补发恢复码 | 抵抗猜测，消费一次性；邮箱证明不能代替 TOTP。 |
| 换邮箱用每用户一行的待变更，确认要本人登录并走因素收尾 | 令牌不和注册请求混用含义；被盗会话和旧恢复码不能继续控制身份。 |
| 密码和邮箱变更的安全邮件不能被提醒偏好关闭 | 仅持密码的登录者不能先关邮件再改密。 |
| 密码用 argon2id，恢复码和会话令牌只存 SHA-256 | 密码是人选的要慢哈希；80 位和 256 位随机串快哈希就够。 |
| Valkey 不可用时登录前的次数退回进程内并按节点数等分 | 缓存故障不能变成登录故障，等分后合计速度不超过设定。 |
| 统一安全事件写审计，只含固定分类和 ID；每站点一行失败计数，信号每分钟最多一条 | 不存个人信息；不争全局锁，固定内存保留峰值。 |
| key 能否使用每次调用在准入事务里读库，缓存只存不变的对应关系 | 缓存状态靠失效来停用的做法都有反例；代价是准入事务多一条查询。 |
| 租户表直接存 `site_id` 和 `account_id`，用复合外键保持一致 | 行级安全策略只看本行，不连表；复合外键让两列不可能不一致。 |
| 内部 ID 用 UUIDv7，对外显示带类型前缀的 TypeID | 索引友好；填错种类的 ID 直接报错。ID 暴露创建时间，可以接受。 |
| 主站的 key 前缀是 `sk-ax-v1-` | 用户一眼认出，带版本号以后能区分新旧格式。 |
| key 只能在所属站点的域名上使用（负责人决定） | 避免"A 站的 key 在 B 站用按哪个站计价"的歧义。 |
| 管理 key 与调用 key 同表分类别；管理 key 不能调模型、不能建管理 key、不能改预算 | 复用凭证哈希和生命周期；泄露一把管理 key 损失限在它的范围之内。 |
| 管理 key 的角色和范围固定，限制作为签发上界，变更在行锁内重验；分钟计数存在 key 行上、独立提交 | 不引入没有使用方的自定义角色；行锁挡住并发放宽；计数不依赖可降级的缓存。 |
| key 的花费上限可按日、周、月重置；过期时间只能在创建时设；设置用 PUT 整体替换 | 与 OpenRouter 一致；整体替换没有"没写"和 null 的歧义。 |
| key 数在插入的事务里锁账户行之后数；小时数按库的时钟、含已删除的 | 先数后插在并发下会超上限；各节点时钟有差；删掉再建不能绕过。 |
| 修改 key 的审计里可用模型和 IP 白名单只记「变了」 | 模型列表会超过条目 8 KiB 上限；地址是不进日志的个人信息。 |
| key 列表附创建人、异步的最近使用时间和近 14 日花费，随一页批读 | 不另开逐 key 接口，往返不随 key 数增加；最近使用不进准入事务。 |
| 业务速率复用账户、等级、key 的可空列，账户覆盖等级、key 与账户取交集 | 不需要策略表或快照失效；按等级汇总会让一个账户耗掉别人的额度。 |
| 节点保护超限的尝试不计账户池，业务 key 拒绝仍计 | 节点额度不查库就能隔离洪泛；补偿扣回会引入新的一致性问题。 |
| 账户暂停调用和用户禁用登录分开，暂停返回 403；禁用时吊销全部会话、不加因素版本 | 暂停保留控制台登录以便充值和申诉；不吊销的会话会在恢复后复活；恢复码保持有效。 |
| 平台授予撤销是终态，恢复插入新行 | 不破坏行级安全的终态保证，恢复不能创造新角色。 |
| 新权限写进角色的 `additional_permissions`，快照合并两列并忽略未知名字 | 旧节点读的 `permissions` 不变，不会因为不认识新名字而让快照失败。 |
| `balance.top_up` 给 owner、admin、finance | 财务可以买额度，成员和观察者不能发起支付。 |
| 新账户进入站点当时的默认等级，访客看到的也是它的价 | 访客注册后付的就是看到的价，改默认不影响已有账户。 |
| 站点 logo 存在 PostgreSQL，按（站点、SHA-256）追加 | 不为一项小配置引入对象存储；内容寻址的地址可以缓存一年。 |
| logo 只收 SVG、PNG、WebP，SVG 按允许列表重建 | 允许列表比删危险标签可靠；完整解码挡住解压炸弹；不需要动画。 |
| 品牌色只校验格式，对比度由前端调整 | 拒绝颜色会让站长无法使用自己的品牌色。 |
| SMTP 覆盖配置整包加密、重启生效，保存和拨号都校验公网地址并钉住 IP | 传输是节点启动参数；只在保存时检查挡不住 DNS 重绑定。 |
| 给用户的邮件归 accounts，投递是 platform 的通用 SMTP 经 outbox | 一个地方拼邮件，各模块只交触发和值。 |
| 用户提醒复用邮件 outbox，余额 journal 和因素事件同事务持久化，按集合消费 | 隔离 SMTP 和 Webhook 故障；消费变动而不是轮询当前值，不漏过快速的阈值穿越。 |
| 用户 Webhook 不签名，5 额度阈值和可关闭的因素提醒是本项目默认 | OpenRouter 没有可核验的对应契约。 |
| 邀请关系从第一版起记录，且不能修改（负责人决定） | 事后补不回来；不能修改才防得住刷返利。 |
| 邀请记录直接读 `users.inviter_user_id`，只返回注册时间和可用状态 | 不需要关系副本；不展示被邀请人的邮箱，最小披露。 |
| BYOK 复用 suppliers 的供应商、凭证、端点和成本计划，状态 `byok`，默认关闭 | 加密、隔离、挑选和失败路径都不写第二遍；所有节点认识新状态之后才打开。 |
| BYOK 端点成本全零、售价按 BYOK 费率，调用仍先准入 | 用户自己付给供应商；不准入就成了绕过预算和限流的通道。 |
| 被拒绝的 BYOK key 写 `rejected`，只有测试成功才恢复 | 持久化让重启和别的节点也不再选它，停用再启用不能把坏 key 放回去。 |

## 待定问题

- 邀请人是否可看到被邀请人的遮掩邮箱，需负责人对该用户数据展示规则明确同意，并在启用前补齐隐私告知；当前接口不读取或输出这类标识。
- [#317](https://github.com/TYCT-tyct/Axiom/issues/317) 的管理 key 界面尚未交付：控制台列表混合显示两种 key，需按 kind 加类型标识、区分签发上界与调用余额。
- 个人账户能否升级为企业账户、账户能否定义自己的角色，在开放企业功能时确定；企业账户成员关系的租户归类随之确定。
- 开放注册在各生产站点是否开启、采用何种难度和域名名单，由运营按站点配置；代码默认关闭，不预置站点数据。
- 生产邮件服务商（自建 SMTP 或第三方）及发信域名的 SPF、DKIM、DMARC，在上线邮件找回前配置并验证。
