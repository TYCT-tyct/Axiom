# 产品需求

## 定位

Axiom 是对标 OpenRouter 的 LLM API 网关：用户用一套统一的 API 调用多家模型，Axiom 负责路由、失败回退和计费。

与 OpenRouter 的区别是对供应商更好的兼容：除了官方 API，中转站和 Axiom 自有的号池也是正式的供应商，由系统自动接入和管理。

## 用户与市场

| 类型 | 说明 | 开放顺序 |
|---|---|---|
| A | 个人开发者、编程工具用户（Claude Code、Codex、Cursor 等） | 首批 |
| B | 应用开发者、中小企业 | 首批 |
| C | 企业团队：多成员、预算、权限、审计 | 后续 |
| D | 二级站点运营者：在 Axiom 上开设自己的站点，有自己的用户和售价 | 后续 |

C、D 后续开放，但它们需要的数据结构（站点、账户、成员，见[术语与核心概念](glossary.md)）从第一版起就要具备。

市场：国内和海外同时服务，涉及人民币与美元两种币种、国内外两类支付渠道、多地部署。

## 供给侧

三类供应商，通过同一套接口接入：

| 类型 | 说明 |
|---|---|
| 官方 API | 模型厂商的原厂接口，如 OpenAI、Anthropic、Google |
| 中转站 | 第三方转售站点，多数基于 sub2api、new-api 等系统搭建。按所用系统做适配，自动同步余额、模型列表、分组和价格，发生变化时调整路由或告警。我们在中转站上通常只有普通用户账号，适配只能用用户权限能访问的接口和页面 |
| 自有号池 | Axiom 自己运营的订阅账号，用自建的 sub2api、new-api、CPA 等系统管理；以管理员身份接入，管理账号健康状态、额度和轮换 |

## 计价

售价 = 实际服务该请求的供应商成本价 + 加价。同一模型走不同端点，售价可以不同。记账货币、汇率、成本、定价、冻结与结算的规则见[计费](domains/billing.md)。

## 售卖形式

像 OpenRouter 一样以模型为中心售卖：用户先选模型，再看到服务这个模型的各个端点。

- **逐个列出端点**：每个端点显示[端点属性](#端点属性)。按供应商类型显示：我们直接接入的官方 API（含云厂商）如实显示名称；中转站的分组一律显示匿名代号，即使检测出它走的是官方渠道。同一分组在所有模型上用同一个代号，用户可以按代号指定或排除。
- **预设**：一组命名的筛选和排序规则，例如只走官方来源、能力和质量达到官方水准、价格优先；规则可以按模型厂商或模型分别设定，也可以排除某类来源、限定最高单价。用户可以使用平台提供的预设，也可以自己组合。
- **预设挂在 API key 上**：Claude Code、Codex 这类工具无法在请求里加自定义参数，只能通过 key 选择；会写代码的用户还可以在单次请求里覆盖。新 key 的默认预设沿 平台 → 站点 → 账户 → 工作区 逐层配置。
- **能力匹配默认强制**：请求用到的能力（图片、工具、长上下文等）实测不支持的端点，不参与路由。
- **价格规则不变**：仍按实际服务的端点计价（见[计价](#计价)）；预设只决定允许走哪些端点，不是固定价格的档位。
- 调用记录写明最终服务的端点和费用，并保留回退过程中每次尝试的端点和成本。

## 端点属性

端点属性靠实测，不靠自报。

| 属性 | 内容 |
|---|---|
| 来源 | 上游从哪来，如官方直连、云厂商、订阅号池、第三方产品逆向。来源类别在后台增改，每个类别可配识别规则（指纹） |
| 能力 | 上下文长度、最大输出、工具、图片、PDF、推理、提示缓存、支持的参数 |
| 质量分 | 固定测评题的成绩，以官方直连为 100 |
| 真伪 | 是否是声称的那个模型 |
| 速度与稳定 | 首字延迟、吞吐、成功率 |
| 价格 | 成本加价后的售价 |

**获取方式**：每个属性值有六种依据，按可信度合并（检测与合并的细节见[端点评估](domains/quality.md)）：

1. 模型目录基线：自动同步公开数据集和厂商接口，多个来源交叉核对，作为默认值；
2. 供应商自报：适配器读取的模型、分组、倍率、价格和分组说明，只作线索；
3. 主动检测：我们发给端点的测试请求；
4. 线上观测：从真实调用中统计速度、稳定性、真实上下文上限、用量是否虚报、工具调用是否出错；
5. 外部评测：外部评测网站和数据服务的结果，权重低于自己的实测；
6. 人工或运营 agent 覆盖：必须写理由并留审计，与实测冲突时告警。

**自动化**：同步发现新模型或变化 → 自动建端点，先继承目录基线并标为待验证 → 检测后用实测值替换 → 端点按属性自动进出预设 → 上线后线上观测到异常时降权、重新检测，仍异常则下线并告警。待验证的端点能否接流量，由预设的规则决定，预设可以要求只走已验证的端点。

- 添加供应商时只需人工填写网址、账号，并确认这个供应商"1 单位余额 = 多少钱"（见[计费](domains/billing.md#供应商成本)）；能从页面读到的不用填。
- 运营 agent 处理规则判断不了的情况，人只处理 agent 上报的事项。
- 检测要花钱：便宜的检测在上线前必做并定期抽查；贵的检测只在上线、变价或出现异常时触发。检测预算、频率和触发条件在后台配置。

## 运营

运营由 AI agent 执行：巡检各供应商的余额、模型、分组、价格和健康状态，据此调整路由、上下架模型并告警。系统为 agent 提供专用的运营接口；涉及资金的操作（如修改售价、给供应商充值）有资金操作上限，并保留操作记录。

## 数据留存

- 调用记录全部保存，不能关闭。
- 对话内容完整保存，包括图片、文件等上传的内容；是否保存由平台统一决定，站点和账户不能关闭。存储空间就绪前先关闭；打开后默认保留 90 天，后台可调，也可以长期保存。
- Axiom 是 API 调用平台，任何人都不能通过产品查看对话内容；内容只能由负责人受控导出，用于追溯和将来可能的模型训练。
- 记录、分类、存储、导出的设计见[记录与告警](domains/observability.md)。

第一版要求全套可用：架构按全部用户类型和供应商类型设计，功能分块实现，下表「第一版」一列全部可用才算第一版完成。

| 模块 | 第一版 | 以后 |
|---|---|---|
| 对外 API | 三种调用格式全支持：OpenAI Chat、Anthropic Messages、OpenAI Responses（Claude Code 和 Codex 分别依赖后两种）；流式输出、工具调用、结构化输出、推理参数、图片和 PDF 输入；模型和价格查询；统一的错误格式；每次调用都返回用量和费用；被其他中转站当上游所需的接口：查询 key 余额与用量、OpenAI 兼容的余额接口、与 OpenRouter 一致的错误码 | 向量化（Embeddings）、重排（Rerank）、图片/视频/语音生成、批量调用 |
| 路由与回退 | 按价格和健康度自动选端点；失败自动换端点、换模型；同一会话尽量走同一端点，以提高缓存命中；预设（见「售卖形式」）；用户可以按名称或代号指定或排除端点、设最高价 | 自动为用户选模型（类似 OpenRouter 的 Auto Router） |

## 成功标准

- **第一版完成**：同时满足以下三条。
  - 「范围」表中「第一版」一列全部可用；
  - [底线指标](architecture.md#底线指标)全部达标，以压测和恢复演练的结果为证（见[性能](performance.md)）；
  - 安全检查没有未解决的高危问题（见[安全](security.md)）。
- **业务目标**：付费用户数、月流水、毛利率、留存等目标值是运营数据，由负责人在管理后台设定和调整，运营看板对照实际数据展示，不写进文档。

## 质量要求

- 代码质量：模块清晰、精简不冗长，仓库不因堆砌而膨胀；改动按[开发规范](../CONTRIBUTING.md)经过评审。
- 可扩展：新增供应商类型（如一种新的中转站系统）、支付渠道等，通过增加扩展模块实现，不修改核心、不打补丁。
- 可配置：分类、预设、默认值、阈值等取值都是后台数据，管理员或运营 agent 可以修改，系统只带初始值；代码只提供机制。配置保存时校验，改动留审计。
- 可维护：代码和接口易读易懂。

这些要求在架构设计中落成具体的工程原则。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 按实际供应商的成本加价，不按质量档位定价 | 负责人判断供应商无法分出档位。按实际服务的供应商计费也与 OpenRouter 一致：它透传各供应商的价格，用户可用供应商偏好和最高价格参数控制（OpenRouter 文档《FAQ》《Provider Routing》，2026-10） |
| 用加价获利，而非 OpenRouter 的充值手续费（OpenRouter 文档《FAQ》，2026-10） | 负责人定的方案。开发者的分析：加价可以按模型、客户等级、二级站点分别设定，手续费只能统一收取 |
| C、D 放在第一版之后，但多租户结构从第一版起具备 | 负责人决定第一版先把 A、B 做全。二级站点和企业团队虽然后续开放，事后再加租户层级只能打补丁 |
| 以模型为中心逐个列出端点，中转站分组用匿名代号 | 负责人决定，与 OpenRouter 一致，便于用户比较。中转站的名字对用户没有意义，还会暴露货源 |
| 端点属性实测，不信自报 | 中转站分组名里的"官K""满血"不可信。OpenRouter 的量化等级由供应商自报，它无法独立验证（Pinggy 博客《OpenRouter in Production》，2026-09）；它的 Auto Exacto 则按实测的工具调用成功率和测评成绩排序路由（OpenRouter 文档《Auto Exacto》，2026-10） |
| 预设可挂在 API key 上 | 编程工具无法在请求里加自定义参数，只能通过 key 选择 |
| 能力匹配默认强制，偏离 OpenRouter（其 `require_parameters` 默认关闭） | 我们的货源能力差异远大于 OpenRouter，不强制就会悄悄降级 |
| 分类、预设、默认值做成后台数据 | 负责人要求高自由度和可配置；这些是运营数据，写死在代码或文档里只会过时 |
| 第一版完成以底线指标和安全检查为门槛 | 负责人同意。功能可用但扛不住量、丢数据或有高危漏洞，不能算完成 |
| 业务目标做成后台数据 | 负责人同意。目标随经营调整，属于运营数据（见 [CONTRIBUTING 的文档规则](../CONTRIBUTING.md#文档规则)） |
| 官网纳入第一版；接入文档和模型与价格页放在官网，无需登录 | 负责人决定。文档和价格要能被搜索到、能直接发给别人；模型与价格页在官网和控制台共用一套展示，登录后只多出操作。是否公开做成站点配置，因为二级站点可能不愿公开价格 |
| 对话内容由平台统一决定是否保存，任何人都不能通过产品查看 | 负责人决定。记录要全面完整，用于追溯和将来可能的训练；Axiom 是 API 调用平台，不提供查看对话的功能。OpenRouter 默认不保存（OpenRouter 文档《Data Collection》，2026-10），这一点我们有意不同 |
