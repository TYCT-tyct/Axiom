# 前端与设计

官网、用户控制台、管理后台三类页面要做什么、按什么标准验收、外观能改到什么程度。前端的技术选型见[总体架构的「技术选型」](architecture.md#技术选型)，站点的品牌和主题配置见[账户与租户的「站点」](domains/accounts.md#站点)。

## 要求

### 基线

- 页面内容以 OpenRouter 为功能基线，再加上 Axiom 独有的部分：端点实测的属性与依据、预设挂在 key 上、免单、按实际端点计费的明细。管理后台没有可参照的公开页面，内容从各领域文档推出。
- 参照的网站只是学习目标，不模仿；设计和内容都是 Axiom 自己的。
- 中文优先，英文同样讲究：两种语言都完整，都像母语。

### 页面清单

优先级：「M1」在里程碑 M1 先做，「第一版」属于[产品需求的「范围」](product.md#范围)，「以后」只预留结构。

OpenRouter 的页面构成（openrouter.ai 页脚与 llms.txt，OpenRouter 文档《Workspaces》《Logs》《Activity》，2026-10-12 查证）：公开的有模型列表与详情、文档、价格等；工作区内有 API key、预设、路由、成员、预算；账户级有用量、调用日志（详情含尝试瀑布图和费用明细）、额度与账单、隐私、偏好。

### 验收门槛

任何一条不过，设计方案就打回：

- **无障碍**：WCAG 2.2 AA；文字对比度不低于 4.5:1；所有操作都能用键盘完成，焦点看得见；读屏软件能读。
- **换主题**：用纯红、纯黄、近黑、近白、荧光绿这类极端品牌色生成的深浅两套配色，全部达到上一条。
- **中英文**：两种语言都完整，不溢出、不截断；数字、货币、日期按语言格式化。
- **极端数据**：超长名字、空列表、巨大数字、上万条记录都不破版。
- **尺寸**：360px 宽的手机到 2560px 宽的大屏都能用；控制台的核心任务在手机上能完成。
- **动效**：尊重系统的"减少动态效果"设置，动画不掉帧。
- **性能**：达到下面的前端性能指标。

### 可用性任务

找真人测，达到以下用时和步数：

- 新用户从首页到把 key 配进 Claude Code（不含付款）：不超过 3 分钟。
- 在模型价格页说出"哪个端点最便宜且已验证"：不超过 30 秒。
- 从调用日志找到一次失败的原因和每次尝试：不超过 2 次点击。
- 进控制台不点击就能看到余额和本月花费。
- 充值不超过 3 步；管理员在后台给用户加额度不超过 30 秒。

### 前端性能指标

初值，用小样实测后定稿（见「待定问题」）。

| 指标 | 官网 | 控制台、后台 |
|---|---|---|
| 首屏主要内容出现（LCP） | 手机限速下不超过 2.0 秒 | 电脑不超过 1.5 秒，手机不超过 2.5 秒 |
| 点击到画面响应（INP） | 不超过 100 毫秒 | 不超过 100 毫秒 |
| 页面跳动（CLS） | 不超过 0.05 | 不超过 0.05 |
| 首屏脚本（压缩后） | 不超过 150KB；3D 另计，不超过 1MB，在页面可以操作之后才加载 | 不超过 200KB；每多打开一个页面增加不超过 50KB |
| 字体 | 西文和数字不超过 60KB；中文正文用系统字体，大标题可以用按页面裁剪的定制字体，不超过 100KB | 西文和数字不超过 60KB；中文用系统字体 |
| 长列表 | — | 1 万行滚动不掉帧 |

## 设计

### 设计原则

1. **改不坏**：换任何站点、颜色、语言、数据量，页面都成立。
2. **数字有出处**：价格、速度、成功率、质量分都能看到依据和时间。
3. **状态先于功能**：余额、花费、key、报错一眼可见；出了问题直接给出原因和下一步。
4. **中文优先**：中文按中文的排版规矩来，英文同样讲究。
5. **一处惊喜，处处克制**：每个页面只有一个招牌时刻；常用操作不加动画。

### 主题与自由度

外观是主题，不是每个站点各做一套页面：

- **页面结构只有一套**。控制台和管理后台只换颜色和 logo。
- **首页是一个插槽**：站点配置里从几套首页设计中选一套。第一版只做 Axiom 自己的首页；给二级站点用的首页模板，等开放二级站点时再做。
- **颜色自动配比**：站长选一个品牌色，或上传 logo 自动取色，系统生成浅色、深色两套完整配色；文字对比度自动达标；成功、失败、警告色自动避开品牌色，并且始终配图标。没有配置时用自带的浅色、深色两套。
- **高对比主题**：用同一套机制，调高对比度参数生成。
- **用户个人**：可以选浅色、深色或跟随系统，再加一个自选主题色；站长可以关闭这项。
- **不开放**：字体、字号、间距、动效节奏。以后要开放，也只给几套精选组合。
- **官网也跟随站点**：模型与价格页、接入文档从第一版起使用站点的配色。
- **3D**：只用来表达产品本身；首屏不等 3D 加载；低端设备、省电模式、"减少动态效果"时换成静态画面；没有 3D 美术资源时，只做程序生成的 3D。

### 视觉方向

第一版的默认外观叫"设计 1"：

- 视觉语言向 Linear 学，信息内容向 HeyRoute 学，结构和功能向 OpenRouter 学。
- 深色优先；只有一个强调色，是冰蓝色 `#7AA2FF`；字体用 Inter 加思源黑体，中等字重；主视觉用真实的控制台界面，不用概念插画；动效克制。
- 首页依次是：导航、主视觉、数据条、四个优势卡、一次调用怎么走、热门模型、实时性能、价格与计算器、选工具接入、安全与付款、常见问题、页脚。内容从中转站的优点和机制出发。
- 设计系统（颜色、圆角等变量和组件）在设计 1 定稿后随代码放进 `web/`，以代码为唯一来源，本文只链接，不复述。

### 内容规则

- 页面上的价格只和官方原价比；不点名比较，也不贬低其他平台。
- 不编造客户标志、评价和数字；演示用的界面和数字标明"示例数据"。
- 数据隐私只写做得到的事，例如"对话内容按账户加密存储，任何人都不能通过产品查看"；不写"不用于训练"（见[产品需求的决策](product.md#决策与理由)）。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 外观做成主题：一套页面结构，换颜色和 logo；首页做成可选的插槽 | 负责人提出（2026-10-12）："他类似于主题，首页我们做多个版本可以选择，控制台也差不多，可以切换主题和颜色"。一套结构只需维护一份，换站点不会改坏 |
| 颜色由一个品牌色自动生成深浅两套，不开放自由写样式 | 负责人提出颜色自动配比。自动生成能保证对比度达标、状态色不和品牌色撞色；自由写样式很容易做出看不清的页面 |
| 不开放字体、字号、间距、动效节奏 | 这几项决定排版质量，随意改最容易破版；以后要开放只给精选组合。负责人对自由度边界的答复："你自己判断，实现最优，基本同意" |
| 首页第一版只做一套 | 负责人提出首页可以有多套设计供选择、第一版只做一套；先把一套做精 |
| 放弃比喻和概念创意的方向，视觉、内容、结构分别向 Linear、HeyRoute、OpenRouter 学 | 比喻类方向和两个演示稿都没有通过，负责人认为"太抽象""和 ai 也没那么贴合"，改为向这三家学习；视觉方向和首页章节负责人答复"行" |
| 参照的网站只学不仿 | 负责人："别人的网站只是一种学习目标，不代表模仿或者其他，我们要实现自己的内容" |
| 页面内容以 OpenRouter 为基线 | 负责人："其他的去仿造 openrouter 的页面内容就行吧"。与 CONTRIBUTING 中"产品行为默认对齐 OpenRouter"一致 |
| 3D 只用来表达产品，首屏不等 3D，低端设备换静态画面 | 负责人同意可以用 3D。首屏等 3D 加载会拖慢首屏，在低端设备上会卡 |
| 中文优先，英文同样讲究 | 负责人同意开发者的推荐："按照你说的做"。国内和海外同时服务，两种语言都要完整 |
| 退款在控制台申请、后台审核；通知第一版只发邮件，不做站内消息；中转站代号不单独成页；协议页面先有，内容待公司主体 | 开发者决定，负责人授权"你自己判断"，页面清单负责人回复"同意" |
