# 前端与设计

官网、用户控制台、管理后台三类页面要做什么、按什么标准验收、外观能改到什么程度。前端的技术选型见[总体架构的「技术选型」](architecture.md#技术选型)，站点的品牌和主题配置见[账户与租户的「站点」](domains/accounts.md#站点)。

## 要求

### 基线

- 页面内容以 OpenRouter 为功能基线，再突出 Axiom 要讲清楚的部分：端点实测的属性与依据、挂在 key 上的预设、按实际服务的端点计费的明细与免单标记。管理后台没有可参照的公开页面，内容从各领域文档推出。
- 参照的网站只是学习目标，不模仿；设计和内容都是 Axiom 自己的。
- 中文优先，英文同样讲究：两种语言都完整，都像母语。

### 页面清单

优先级：「M1」在里程碑 M1 先做（排期以 [Issue #30](https://github.com/TYCT-tyct/Axiom/issues/30) 为准），「第一版」属于[产品需求的「范围」](product.md#范围)，「以后」只预留结构。

OpenRouter 的页面构成（openrouter.ai 页脚与 llms.txt，OpenRouter 文档《Workspaces》《Logs》《Activity》，2026-10-12 查证）：公开的有模型列表与详情、文档、价格等；工作区内有 API key、预设、路由、成员、预算；账户级有用量、调用日志（详情含尝试瀑布图和费用明细）、额度与账单、隐私、偏好。

### 验收门槛

任何一条不过，设计方案就打回：

- **无障碍**：WCAG 2.2 AA；文字对比度不低于 4.5:1；所有操作都能用键盘完成，焦点看得见；读屏软件能读。
- **换主题**：用纯红、纯黄、近黑、近白、荧光绿这类极端品牌色生成的深浅两套配色，全部达到上一条。
- **中英文**：两种语言都完整，不溢出、不截断；数字、货币、日期按语言格式化。
- **极端数据**：超长名字、空列表、巨大数字、上万条记录都不破版。
- **尺寸**：360px 宽的手机到 2560px 宽的大屏都能用；控制台的核心任务在手机上能完成。
- **动效**：尊重系统的"减少动态效果"设置，动画不掉帧。
- **性能**：达到下面的前端性能指标。

### 可用性任务

找真人测，达到以下用时和步数：

- 新用户从首页到把 key 配进 Claude Code（不含付款）：不超过 3 分钟。
- 在模型价格页说出"哪个端点最便宜且已验证"：不超过 30 秒。
- 从调用记录找到一次失败的原因和每次尝试：不超过 2 次点击。
- 进控制台不点击就能看到余额和本月花费。
- 充值不超过 3 步；管理员在后台给用户加额度不超过 30 秒。

### 工程要求

负责人对前端工程的要求（2026-10-13）：

- 构建产物的文件名带内容哈希，可以长期缓存；入口页从不缓存。
- 新版本上线后，开着的控制台和管理后台提示刷新；按需加载的代码块因为已经换了版本而加载不到时，自动刷新一次。
- 静态文件压缩后发送，流式输出不压缩。
- 只用国内也能访问的资源，能自己托管的都自己托管，字体也一样。
- 每个数据视图都有加载中、空、出错、没有权限四种状态；切换页面不出现空白。
- 数字和时间按语言和时区格式化。
- 页面在严格的内容安全策略下工作，没有需要 `unsafe-inline` 的内联脚本和样式。

### 前端性能指标

下表的指标是定稿：首屏脚本、每多开一页的增量和西文字体由 `web/scripts/budget.ts` 在 `just check` 里强制，超出即失败；LCP、INP、CLS 和长列表由 `web/e2e/vitals.spec.ts` 在端到端测试里测量（见下文「实测」）。LCP 是当前唯一让任务失败的门禁（电脑档 1.5 秒、手机档的上限见「实测」）；INP、CLS 和长列表只报告，因为共享 CI 机器上的结果还没稳定到可以据此打回，先把实测、差距和原因写清，修一项收紧一项（判断见「实测」）。

| 指标 | 官网 | 控制台、后台 |
|---|---|---|
| 首屏主要内容出现（LCP） | 手机限速下不超过 2.0 秒 | 电脑不超过 1.5 秒，手机限速下不超过 2.5 秒 |
| 点击到画面响应（INP） | 不超过 100 毫秒 | 不超过 100 毫秒 |
| 页面跳动（CLS） | 不超过 0.05 | 不超过 0.05 |
| 首屏脚本 | 不超过 150KB；3D 另计，不超过 1MB，在页面可以操作之后才加载 | 不超过 200KB；每多打开一个页面增加不超过 50KB |
| 字体 | 西文和数字不超过 60KB；中文字体见「待定问题」，用定制字体时按页面裁剪，不超过 100KB | 西文和数字不超过 60KB；中文用系统字体 |
| 长列表 | — | 加载 1000 行（列表按游标分页，一页 50 行，一万行不是页面会有的状态）滚动不掉帧 |

测量条件：

- "手机限速"用 Lighthouse 的移动端默认配置（模拟慢速 4G、CPU 降速 4 倍），"电脑"用它的桌面配置；
- 脚本按 brotli 压缩后的传输大小计，字体取 woff2 文件本身的大小（已压缩）；首屏还算入口页打开的页面（控制台的概览、后台的首页）；
- INP 用 Playwright 驱动常用操作（筛选、翻页、打开详情、提交表单），在 CPU 降速 4 倍时用 web-vitals 采集，每种操作取最差的一次；
- "不掉帧"在 CPU 降速 4 倍时，滚动长列表或播放动画 5 秒，看两项：在固定 60Hz 的测试环境里用 requestAnimationFrame 记录帧间隔，间隔超过 25 毫秒（1.5 帧，留出计时误差）算掉帧，掉帧不超过 5%；主线程没有超过 50 毫秒的长任务。调用日志和用户列表各加载 1000 行来滚，两者都是按游标分页、一页 50 行。开始计时前回到列表顶部并等版面稳定；计时中每一帧都确认 `window.scrollY` 在增加，移动的帧不到九成就算这次测量失败，避免把已经触底后的静止页面算成平滑滚动。

### 实测

`web/e2e/vitals.spec.ts` 对着嵌入程序的构建产物测，用 web-vitals 采集；手机档是 Pixel 5 视口加 Lighthouse 的慢速 4G 和 CPU 降速 4 倍，电脑档是 10 Mbps 无降速；控制台的概览、key、调用、余额、流水和后台的用户、供应商、模型、价格、设置各取三次加载，LCP 取中位数、CLS 取最大值；INP 在 CPU 降速 4 倍下，对每个对话框的打开或提交，以及调用页的翻页、筛选、打开详情和后台用户的筛选、打开账户，各取页面上最差的一次；长列表（调用日志和用户列表）各加载 1000 行（列表按游标分页，一页 50 行，所以一万行不是一个页面会有的状态），滚动 5 秒，数掉帧和长任务。数字写进每项测试的注解和输出。

这些指标里只有 LCP 会让任务失败：电脑档按指标本身 1.5 秒，手机档按 CI 第一次实测最大值的 1.5 倍 6 秒（回归上限，不是 2.5 秒的目标）。其余三项只报告：CLS 同一页在两次测量之间从 0.02 跳到 0.83，滚动的掉帧率在本机调用页 0.36–0.38、用户列表 0.04–0.05，在 CI 0.68，INP 随共享 CI 机器的负载在 96–920 毫秒摆动（列车忙的时候，对话框的 INP 超过 500 毫秒），原因都还没查清，硬卡只会偶发失败。测出的值、与指标的对比和跟踪记录都在任务输出里，但不让任务失败；修一项就收紧一项的上限。测量是计时，所以单独在一个 CI 任务（`vitals`，`just web-vitals`）里一次一个测试地跑，不和别的测试抢 CPU。LCP 失败按退化处理。模拟的接口在浏览器里直接应答，不受网络降速影响，所以手机档的 LCP 比真机少了接口那一跳。

测量（2026-10-29–30：本机三次，8 核机器上同时有别的检查在跑；长列表在修正滚动起点后复测两次；CI 的 `vitals` 任务一次，是 LCP 上限的基线）：

| 指标 | 实测 | 指标本身 | 门禁上限 |
|---|---|---|---|
| LCP，电脑档 | 0.50–0.83 秒 | 1.5 秒 | 1.5 秒（已达标） |
| LCP，手机档 | 2.24–4.10 秒（CI：调用页 4.10，概览 3.66，其余 2.9–3.5；本机复测 2.24–3.22） | 2.5 秒 | 6 秒（CI 最大值的 1.5 倍） |
| CLS | 本机多数页 0–0.17；CI 上概览（手机）0.16、价格（手机）0.60、模型和流水（电脑）0.8 以上，同一页在两次测量之间差别很大 | 0.05 | 只报告 |
| INP，打开或提交对话框 | 本机 96–920 毫秒（CI 最大 280） | 100 毫秒 | 只报告 |
| 长列表 1000 行，调用日志 | 本机 36%–38%、47–49 个长任务；CI 68% 的帧晚于 25 毫秒 | 5%；没有长任务 | 只报告 |
| 长列表 1000 行，用户列表 | 本机 4.1%–4.5%、10 个长任务 | 5%；没有长任务 | 只报告 |

差距还没有逐项查清：手机档的 LCP 在慢速 4G 下受往返次数限制（页面、脚本、样式；接口那一跳还没计入），模型页和流水页的 CLS 是内容到达后版面重排，对话框的 INP 是打开时的渲染；长列表掉帧对应的长任务还没定位。逐项修复是后续工作，修一项就收紧一项的上限。

## 设计

### 设计原则

1. **改不坏**：换任何站点、颜色、语言、数据量，页面都成立。
2. **数字有出处**：价格、速度、成功率、质量分都能看到依据和时间。
3. **状态先于功能**：余额、花费、key、报错一眼可见；出了问题直接给出原因和下一步。
4. **中文优先**：中文按中文的排版规矩来，英文同样讲究。
5. **一处惊喜，处处克制**：每个页面只有一个招牌时刻；常用操作不加动画。

### 主题与自由度

外观是主题，不是每个站点各做一套页面：

- **页面结构只有一套**。控制台和管理后台只换颜色和 logo。
- **站点 logo**：站点在后台设置页上传、更换或清除 logo（SVG 清洗后保存，或受限的 PNG/WebP；存储和清洗规则见[账户与租户](domains/accounts.md#站点)）。控制台的侧栏、登录页和 1024px 以下的顶栏显示 `getSite` 给的 `logo_url`，官网页头也读同一个公开接口；没有 logo 或图片加载失败时显示站点名称和自带的标记。图片固定 20×20、`object-contain`，加载前后不改变布局，极端长宽比也不撑开页头。管理后台的登录页和侧栏同样显示站点名称和 logo（公开的 `getAdminSite` 在管理域名给出地址），设置页只用后台返回的 data URL 预览当前 logo；页面标题和导航仍表明这是管理后台。
- **首页是一个插槽**：站点配置里从几套首页设计中选一套。第一版只做 Axiom 自己的首页；给二级站点用的首页模板，等开放二级站点时再做。
- **颜色自动配比**：站长选一个品牌色，或上传 logo 自动取色，系统生成浅色、深色两套完整配色；文字对比度自动达标；成功、失败、警告色自动避开品牌色，并且始终配图标。没有配置时用自带的浅色、深色两套。配色由 `packages/ui/src/brand.ts` 的 `brandStyle` 生成：强调色在两套配色里都按 4.5:1 调整，主按钮的前景取黑或白中对比更高的，主按钮与页面、面板、对话框任一底色的对比不到 3:1 时加边线；只有不是 `#rrggbb` 的写法会被拒绝，其余颜色被调整而不是拒绝。站点契约为 `brand_color`，由后台 `/sites/{site_id}/brand` 设置、控制台 `GET /site` 读取，`AppShell` 和 `AuthFrame` 通过 `useBrandStyle` 把它写到文档根元素（`<html>`），渲染在页面之外的恢复码对话框也继承同一套变量；字段缺省或旧节点不返回时用默认配色。
- **高对比主题**：用同一套机制，调高对比度参数生成。
- **用户个人**：可以选浅色、深色或跟随系统，再加一个自选主题色；站长可以关闭这项。
- **不开放**：字体、字号、间距、动效节奏。以后要开放，也只给几套精选组合。
- **官网也跟随站点**：模型与价格页、接入文档从第一版起使用站点的配色。
- **3D**：只用来表达产品本身；首屏不等 3D 加载；低端设备、省电模式、"减少动态效果"时换成静态画面；没有 3D 美术资源时，只做程序生成的 3D。

### 视觉方向

第一版的默认外观叫"设计 1"：

- 视觉语言向 Linear 学，信息内容向 HeyRoute 学，结构和功能向 OpenRouter 学。
- 深色优先；只有一个强调色，是冰蓝色；西文和数字用 Inter，中等字重；控制台和后台的中文用系统字体，官网的中文字体见「待定问题」；字体文件一律自己托管；主视觉用真实的控制台界面，不用概念插画；动效克制。
- 首页依次是：导航、主视觉、数据条、四个优势卡、一次调用怎么走、热门模型、实时性能、价格与计算器、选工具接入、安全与付款、常见问题、页脚。内容从中转站的优点和机制出发。
- 设计系统（颜色、圆角等变量和组件）在 [web/packages/ui/src/styles.css](../web/packages/ui/src/styles.css) 和同级的 `components/` 里，以代码为唯一来源，本文只链接，不复述。

### 内容规则

- 页面上的价格只和官方原价比；不点名比较，也不贬低其他平台。
- 不编造客户标志、评价和数字；演示用的界面和数字标明"示例数据"。
- 数据隐私只写做得到的事，例如"对话内容按账户加密存储，任何人都不能通过产品查看"；不写"不用于训练"（见[产品需求的决策](product.md#决策与理由)）。

### 前端工程

- 代码在 `web/`，是一个 pnpm 工作区；结构、命令和必须遵守的规则见 [web/README.md](../web/README.md)。
- 官网在公网监听的 `/`，控制台在 `/console/`，管理后台只在管理监听上。
- 控制台和管理后台构建时写入同一棵代码树构建出的程序的版本号（`axiom version` 输出的整行），之后定时和切回标签页时向 `GET /api/console/v1/version`（后台是 `/api/admin/v1/version`）询问正在运行的版本，不同就提示刷新。
- 内容安全策略只在 `web/vite.shared.ts` 定义一次。构建产物嵌入 Go 程序时（`just web-embed`），这个字符串一并写进嵌入的文件，Go 服务原样发送，不另写一份；缓存、压缩和回退的规则见[平台的「前端文件」](../internal/platform/README.md#前端文件)。
- 西文和数字用自己托管的 Inter（只带字重轴，拉丁子集 48KB），数字用它的等宽数字对齐；中文和代码用系统字体。

站点 logo 的存储、公开地址和缓存按[负责人授权记录](https://github.com/TYCT-tyct/Axiom/issues/309#issuecomment-6478816797)落地，原文「遇到问题自己解决问题和判断最优而不是问我。」；数据模型和清洗规则见[账户与租户的「站点」](domains/accounts.md#站点)，这里只记前端可见的取舍。

| 决策 | 理由 |
|---|---|
| logo 由站点的公开接口按内容哈希提供，页面不直接引用上传文件或第三方地址 | 地址里的 SHA-256 让图片可以缓存一年且永不串图，换 logo 就是换地址；同源请求满足 `img-src 'self'`，不把站点品牌交给外部图床，也不需要 `blob:`。失败时回退到名称和自带标记，页面仍然完整 |

## 决策与理由

| 决策 | 理由 |
|---|---|
| 外观做成主题：一套页面结构，换颜色和 logo；首页做成可选的插槽 | 负责人提出（2026-10-12）："他类似于主题，首页我们做多个版本可以选择，控制台也差不多，可以切换主题和颜色"。一套结构只需维护一份，换站点不会改坏 |
| 颜色由一个品牌色自动生成深浅两套，不开放自由写样式 | 负责人提出颜色自动配比。自动生成能保证对比度达标、状态色不和品牌色撞色；自由写样式很容易做出看不清的页面 |
| 不开放字体、字号、间距、动效节奏 | 这几项决定排版质量，随意改最容易破版；以后要开放只给精选组合。负责人对自由度边界的答复："你自己判断，实现最优，基本同意" |
| 首页第一版只做一套 | 负责人提出首页可以有多套设计供选择、第一版只做一套；先把一套做精 |
| 视觉、内容、结构分别向 Linear、HeyRoute、OpenRouter 学，不走比喻和概念创意的方向 | 负责人否定了比喻类方向（"太抽象""和 ai 也没那么贴合"），选定向这三家学习；视觉方向和首页章节负责人答复"行" |
| 参照的网站只学不仿 | 负责人："别人的网站只是一种学习目标，不代表模仿或者其他，我们要实现自己的内容" |
| 页面内容以 OpenRouter 为基线 | 负责人："其他的去仿造 openrouter 的页面内容就行吧"。与 CONTRIBUTING 中"产品行为默认对齐 OpenRouter"一致 |
| 3D 只用来表达产品，首屏不等 3D，低端设备换静态画面 | 负责人同意可以用 3D。首屏等 3D 加载会拖慢首屏，在低端设备上会卡 |
| 中文优先，英文同样讲究 | 负责人同意开发者的推荐："按照你说的做"。国内和海外同时服务，两种语言都要完整 |
| 字体等静态资源自己托管，不依赖外部服务 | 负责人要求（2026-10-13）只用国内也能访问的资源，能自己托管的就自己托管；页面也因此少一次跨域连接 |
| 退款在控制台申请、后台审核；控制台的用户通知第一版只发邮件，不做站内消息（运营的告警和审批通知见[运营的「通知」](domains/operations.md#通知)）；分组代号不单独成页；协议页面先有，内容待公司主体 | 开发者决定，负责人授权"你自己判断"，页面清单负责人回复"同意" |
| 未登录时显示站点给新账户的默认等级的价格 | 负责人在对话中授权开发者按推荐决定（2026-10-13）。访客注册后付的就是看到的价，不会注册后才发现变了；新账户进入哪个等级由账户与租户的设计写明（Issue #23） |
| 官网是单独的应用，与控制台、管理后台共享设计系统和模型价格组件 | 负责人在对话中授权开发者按推荐决定（2026-10-13）。理由和放弃的方案见[总体架构](architecture.md#技术选型)「前端交付」 |
| 页面文字的检查用 Biome 的 `noJsxLiterals` | 架构已选 Biome，这条规则移植自 eslint-plugin-react 的 `jsx-no-literals`；它不查属性里的文字，由评审补上。不选 eslint-plugin-i18next：为一条规则要再引入 ESLint 和它的解析器，依赖多出约百个包 |
| 复杂度、长度、重复和未使用代码的检查与 Go 一侧对齐 | 阈值同 `.golangci.yml`。认知复杂度用 Biome 的 `noExcessiveCognitiveComplexity`，上限 15，实测 JSX 里的条件和回调也计入。圈复杂度上限 12，同 cyclop，由 `web/scripts/limits.ts` 检查：Biome 没有这条规则，两者也不能互相代替（12 个并列的 `if` 认知复杂度 12、圈复杂度 13）；分支按 cyclop 计 `if`、循环、`case`、`&&`、`||`，再加上 JavaScript 的三元表达式、`catch` 和 `??`，嵌套函数单独计算，同 ESLint 的 `complexity`。函数 60 行、文件 500 行（不计空行和注释，测试不限函数长度）也由它检查，按语法树的词法单元数行，注释不算，字符串、模板和 JSX 里的文字照算：Biome 有这两条规则，但实测不计 JSX 里的行（Biome 2.5.15，66 行 JSX 的函数只算 3 行），组件写多长都能通过；不选 ESLint 的长度规则，理由同上一行。未使用的文件、导出和依赖用 knip，包的入口导出也查：这些包只给本仓库的应用用，没有应用引用的导出就是多余的。重复代码用 jscpd，最少 50 个词法单元，即它的默认值；Go 的 dupl 100 按语法树节点计，单位不同，不照搬。测试不查重复，同 Go |
| 找不到页面时，回首页是普通链接 | 这样 `NotFoundState` 不依赖路由库（官网也用设计系统，但没有路由），控制台和后台直接用它作路由的默认组件，不再各写一份；找不到页面时多一次整页加载，还会拿到新版本。不选让设计系统依赖 TanStack Router：为一个链接要给官网拆出单独的导出路径 |
| 控制台在公网监听的 `/console/`，与官网同一个域名 | 二级站点配自定义域名时只需一个域名和一张证书，登录状态也不用跨域。不选单独的子域名：每个站点多一个域名要配 |
| 控制台和管理后台的版本号取自同一棵代码树构建出的程序，构建时写入 | 两边的字符串出自同一段代码，必然一致。不选在 Node 里按 Go 的规则重算伪版本：标签、未提交改动（`+dirty`）等规则要复刻一份，迟早不一致；不选由 Go 在返回入口页时写入：开发服务器上没有这一步。这一行含 Go 工具链的版本，经不需登录的接口公开：接受这点信息暴露，换来日志、命令行和接口用同一个字符串 |
| 路由在代码里定义，不用文件路由 | 少一份要提交、要检查是否最新的生成文件；页面不多，路由表放在一处一眼看全 |
| 端到端测试对着构建产物跑，由 Go 程序的静态服务（`webui/cmd/serveweb`）提供，不连数据库 | 页面在服务端真实的响应头、缓存和压缩下被测，而不是在另一个服务器的头下；不需要数据库，CI 时间短，接口用模拟的响应。CI 只装无界面的 Chromium。不选 `vite preview` 再加一份头：测的不是上线的那个服务器 |
| 西文字体只托管 Inter 的字重轴；不托管 Geist Mono，等宽文字用系统字体 | 实测拉丁子集：只带字重轴 48KB，再带光学尺寸轴 73KB，加上 Geist Mono 再多 23KB，后两种都超过 60KB 的预算。数字的对齐用 Inter 的等宽数字 |
| 颜色变量用 `light-dark()` 一次写出浅、深两个值 | 每个颜色只写在一处，强制浅色或深色时只切换 `color-scheme`。不选设计稿的写法：浅色值在系统偏好和手动选择两处各写一遍 |
| 手机上的侧栏抽屉用原生 `<dialog>` | 自带焦点限制和 Esc 关闭；Radix Dialog 锁定滚动时会插入 `<style>` 元素，被内容安全策略拦下 |
| 控制台只靠 `GET /session` 判断登录状态；会话中途失效时去登录页，登录后回到原页面 | 负责人在对话中授权开发者按推荐自行决定。状态只有服务端一份：页面不在本地记"已登录"，另一台设备踢掉会话、空闲超时都会在下一次请求时被发现。不选在浏览器存令牌：Cookie 是 HttpOnly（见[登录与会话](domains/accounts.md#登录与会话)），CSRF 令牌只放内存，刷新页面时用 `GET /session` 取回 |
| 两步验证的二维码在浏览器里本地生成，引入 `qrcode-generator`（无依赖，2.0.4，MIT）；开放注册的工作量证明也在浏览器里本地算，用自带的纯 JS SHA-256，不引入第三方 captcha 或哈希依赖 | 负责人在对话中授权开发者按推荐自行决定。扫码是验证器 App 的通用做法，只给密钥文字要在手机上手敲 32 个字符；密钥不能交给外部服务画二维码。不选自己写二维码编码：纠错码和掩码选择的细节多，不值得。开放注册按 `docs/frontend.md` 不把访客数据交给第三方，纯 JS 实现避免每个候选一次异步调用，并以已知向量测试守住正确性 |
| 控制台的调用记录用「加载更多」翻页，不做虚拟列表 | 负责人在对话中授权开发者按推荐自行决定。契约只给游标，翻页本来就是向后接；虚拟列表要引入依赖并牺牲页内查找。指标是加载 1000 行（一页 50 行，一万行不是页面会有的状态）滚动不掉帧，已由 `vitals.spec.ts` 测量（见「前端性能指标」）；以后实测掉帧或行数再增长时再加虚拟列表 |
| 验收门槛的无障碍用 `@axe-core/playwright`（仅开发依赖）在端到端测试里查 | 负责人在对话中授权开发者按推荐自行决定。WCAG 2.2 AA 的对比度、名称、结构等能机械判定的部分每次提交都查；键盘和读屏的实际体验仍靠评审和人工。不选只在发布前人工查：回退没有人发现 |
| 控制台和后台共用的会话、登录、外壳放进 `web/packages/app`，不放进设计系统，也不各抄一份 | 负责人在对话中授权开发者按推荐自行决定。设计系统不依赖路由（见上一条“找不到页面”的理由），而两个应用的登录、第二步、新版本提示几乎一样，抄两份迟早不一致。两个界面的登录调用形状相同，页面对着一个接口写，各给一套调用，也顺带检查两份契约没有分叉 |
| 后台的所有页面要求通过两步验证的会话；没有第二因素的账户只能开启它 | 契约规定后台除登录外的操作都需要 `mfa` 级会话。不开启就登录会得到永远 403 的后台，所以登录后单设一个开启页，开启成功换新会话后再放行；恢复码的对话框放在路由之上，换了会话页面跳转时也不会丢 |
| 后台的每个改数据的操作经同一个对话框：理由必填、有确认、一个操作一个 Idempotency-Key | 契约要求理由和幂等键；键在对话框打开时生成，页面显示结果是不是之前已完成的那次。请求发出后表单即锁定；只有服务端自己的拒绝（带错误内容的 4xx）证明没做，之后才换新键、可以改了再发。没收到响应、服务端出错、响应读不出来（例如代理的错误页）或成功却没有结果，都可能已做完：表单保持锁定，只能用同一个键原样重发第一次发出的请求，直到成功；之后的其他拒绝也不解锁，因为限流、会话失效在服务端查键之前就返回，证明不了第一次没做。收到 `idempotency_key_reused` 不当作普通拒绝、不换键：第一次可能已生效，对话框不再发送，只能关闭。关闭时重新取数据，但取回的数据证明不了第一次没做（它可能还在提交），提示里这样写明；结果未知的请求（函数，含请求体和键）留在内存里，按会话的用户、账户和对话框的 `operation`（改动种类加对象）索引：关闭后重开，或会话过期、重新登录后再打开同一项改动，对话框只提示上次的结果未知，提供“原样重发”和“放弃”，不显示表单、不生成新键；收到成功、`idempotency_key_reused` 或 `stale_revision`，或选了放弃，才清掉。放弃后它仍可能已生效，提示里这样写明。别的用户登录同一个浏览器看不到它；刷新页面或关闭标签页会丢掉它，之后的改动用新键。按修订号改的对话框（规格、状态、参考价、价格来源、定价规则）打开时固定一份数据，表单初值和修订号都取自它；收到 `stale_revision` 时提示冲突，不推进修订号，要重新载入最新内容才能再保存。高风险（移除供应商、下线模型）要输入对象的名字才发送。不选“点击时生成键”：那样断网重试会重复执行。不选把结果未知的请求写进 sessionStorage：有的请求体含对话框关闭后不该以可读形式留着的内容（供应商的登录），而函数在内存里就带着同样的请求体。不选结果未知后放开表单：改过的内容用同一个键会被拒绝，换新键就会再做一次（#179）。不选只推进修订号：非受控的表单还是旧内容，再保存就覆盖别人的改动。键用 `crypto.randomUUID` 生成，它只在安全上下文（HTTPS 或 localhost）可用；用 http 的局域网地址打开管理后台时对话框会直接报错 |
| M1 后台的目录页对价格表只编辑基础价格，按次计费的项另标；分档价格（按请求大小、服务层级）保持原样、只读，其他基线信息用 JSON 输入；更换价格来源一次一个币种 | 负责人在对话中授权开发者按推荐自行决定。价格表是 12 项 × 分档 × 3 个服务层级，完整编辑器是最大的一块界面；M1 的人工维护只需基础价格，分档来自同步。改基础价格时保留已有分档，不会丢；以后要手工维护分档再加编辑器 |
| 后台的站点设置页取“后台账户所在的站点”，不单列站点 | 契约在 M1 没有站点列表，设置的路径要站点 ID；账户详情带站点 ID，所以用后台自己的账户查出来。需要 `users.view` 权限；站点列表出现后改成选择站点（已记为契约缺口） |
| TypeScript 用 5.9，不用 7 | 架构选定的 openapi-typescript 调用 TypeScript 的编译器接口，7.0 没有提供（2026-10） |
