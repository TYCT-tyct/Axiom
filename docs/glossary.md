# 术语与核心概念

全项目统一的叫法和代码命名。文档、代码、界面都用这里的词；新概念先在这里登记，再在别处使用。

## 概念全景

需求侧（谁来买）：

```
站点（主站是根站点，二级站点挂在主站下）
├─ 用户：登录身份，只属于一个站点
├─ 等级：站点自己定义
└─ 账户：余额、等级、设置的归属，只属于一个站点
   ├─ 成员 → 同站点的用户，各有角色
   └─ 工作区（每个账户自带一个默认工作区）
      └─ API key
```

供给侧（我们从谁那里进货）：

```
供应商（一个官方 API 账号、一个中转站账号或自有号池）
└─ 分组：一条进货线路，有自己的价格倍率和上游
   ├─ 凭证：调用用的 key，或号池里的一个上游账号
   └─ 端点 = 分组 × 模型：成本价和各项属性 → 模型：统一目录里的标准模型
```

一次请求：

```
API key → 路由按预设选端点 → 供应商选凭证 → 尝试（失败则回退再试）→ 调用记录 → 记账
```

## 关键关系

1. **余额挂在账户上，不挂在用户上。** 用户只是登录身份，通过成员关系使用账户。每个用户自动拥有一个只有本人的个人账户；企业团队是一个账户加多个成员。账户下分工作区，API key 属于工作区；每个账户自带一个默认工作区，个人用户感觉不到它。
2. **主站也是站点。** 主站和二级站点走同一套代码，区别只是主站没有上级。站点只有两层，二级站点不能再开站。
3. **用户和账户都按站点隔离。** 同一个邮箱在不同站点是互不相干的用户；账户只属于一个站点，成员必须是同站点的用户；二级站点的用户看不到 Axiom。
4. **二级站点由主站上的一个账户开设。** 二级站点每产生一笔调用，主站就按这个账户所在等级的售价从该账户扣费；批发价就是这个售价，没有单独的批发概念。一个账户可以开多个站点，上限由平台配置；站长在主站登录，通过站长账户的成员和角色管理自己的站点。二级站点终端用户的付款直接进站长自己的收款账户，站长给自己在主站的账户预充值。二级站点的定价规则只影响本站用户，站长的成本永远是主站对其等级的售价。
5. **每一层的售价 = 下一层的成本 + 本层加价。** 供应商成本加平台加价是主站售价，也是二级站点的成本；再加站点加价，就是二级站点的售价。
6. **供应商、分组、凭证、端点是四个不同的东西。** 中转站的分组同时决定价格倍率和背后由哪批上游服务（见本文「决策与理由」的来源），所以分组是一条独立的进货线路：价格倍率由分组决定，属性和健康度按端点算。路由只选端点；端点内部用哪个凭证由供应商模块决定，号池轮换不进入路由。
7. **供应商有归属方：平台、站点或账户。** 平台的供应商所有站点可用；站点的只供该站点；账户的只供该账户，即用户自带厂商 key。站点能否自带货源由平台级开关控制，默认关闭。
8. **模型 ≠ 模型厂商 ≠ 供应商。** 用户请求的是模型，路由在服务该模型的端点之间选。
9. **请求 ≠ 尝试。** 回退时一个请求有多次尝试；每次尝试都记成本，只有最终成功的那次向账户收费。
10. **账本是唯一真实来源。** 每笔充值、扣费、退款都记一条，只追加不修改；余额字段是账本合计的物化值，由对账核对。冻结是单独的预留记录，不是账本分录。
11. **配置沿 平台 → 站点 → 等级 → 账户 → 工作区 → API key 逐层设置。** 下层只能在上层允许的范围内修改；合并方式见[账户与租户的「配置链」](domains/accounts.md#配置链)。每项配置开放到哪一层，在各自的设计里定。
12. **端点属性的每个值都带依据、时间和置信度。** 获取方式见[产品需求的「端点属性」](product.md#端点属性)。
13. **路由同时选端点和出口；凭证可以绑定固定出口。** 见[总体架构的「部署拓扑」](architecture.md#部署拓扑)。
14. **权限写在代码里，角色是后台数据。** 角色是一组权限，在某个范围上授予操作者；成员、管理 key、运营 agent、系统任务都走同一套授权。授予规则见[账户与租户的「授权」](domains/accounts.md#授权)。

## 术语表

| 中文 | 代码名 | 含义 |
|---|---|---|
| 站点 | site | 有自己域名、用户和售价的门户；主站是根站点 |
| 站长 | site_owner | 开设某个二级站点的主站账户；它的成员按角色管理这个站点 |
| 管理员 | admin | 平台的运营人员 |
| 用户 | user | 登录身份，只属于一个站点 |
| 账户 | account | 余额、API key、等级、设置的归属主体，只属于一个站点 |
| 成员 | member | 用户在某个账户里的身份和权限 |
| 工作区 | workspace | 账户下的一个分区，有自己的 API key、预算和默认设置 |
| API key | api_key | 属于某个工作区的凭证，分调用 key 和管理 key 两种 |
| 管理 key | api_key（kind = management） | 不能调用模型、只能在自己的范围内管理调用 key 的 API key |
| 等级 | tier | 站点给账户定的档次，决定加价 |
| 模型厂商 | author | 模型的出品方，如 Anthropic |
| 模型 | model | 统一目录里的模型，有标准 ID 和若干别名 |
| 目录基线 | baseline | 模型的官方规格，是端点属性的默认值 |
| 供应商 | supplier | 进货对象，三种类型见[产品需求的「供给侧」](product.md#供给侧) |
| 归属方 | owner_scope | 供应商属于平台、某个站点还是某个账户 |
| 分组 | supplier_group | 供应商内的一条进货线路，有自己的价格倍率 |
| 代号 | codename | 分组对用户显示的匿名名称，在所有模型上相同 |
| 凭证 | credential | 调用某个分组用的 key，或号池里的一个上游账号 |
| 端点 | endpoint | 分组 × 模型，是路由选择的单位 |
| 端点属性 | attribute | 端点的各项属性，见[产品需求的「端点属性」](product.md#端点属性) |
| 依据 | basis | 一个属性值的出处 |
| 来源 | upstream_kind | 端点的上游从哪来；类别是后台数据 |
| 指纹 | fingerprint | 识别来源的规则，如响应头、消息 ID 格式、用量特征 |
| 检测 | probe | 我们主动发给端点的测试请求 |
| 同步 | sync | 通过适配器拉取供应商的模型、分组、价格和余额 |
| 适配器 | adapter | 对接某一类供应商系统的插件，如 new-api 适配器 |
| 预设 | preset | 服务端保存的命名配置，第一版只含端点的筛选和排序规则，可挂在 API key 上；与 OpenRouter 的 Presets 是同一个概念，以后可以扩展到模型参数 |
| 请求 / 尝试 | request / attempt | 用户的一次调用，保存下来就是调用记录 / 对上游的一次调用 |
| 成本 / 售价 / 加价 | cost / price / markup | 付给上游的钱 / 向账户收的钱 / 两者之差 |
| 账本 | ledger | 余额每次变动的记录，只追加不修改 |
| 冻结 | hold | 请求开始前按预估费用预留的余额；单独存放，不是账本分录 |
| 额度 | credit | 站点的记账单位：1 额度 = 1 个单位的站点记账货币 |
| 额度批次 | credit_grant | 一次额度进账（充值、赠送、兑换、调整），可单独设过期时间 |
| 成本计划 | cost_schedule | 适配器为端点生成的"用量 → 成本"计算表 |
| 价格版本 | price_version | 一次发布的全部售价及其成本，请求开始时锁定 |
| 汇率 | fx_rate | 两种货币之间的换算值，交易时锁定 |
| 免单 | waiver | 符合条件时不向用户收费，上游成本记为损失 |
| 操作者 | actor | 做出改动的一方：管理员、站长、成员、管理 key、运营 agent、系统任务 |
| 权限 | permission | 一件具体能做的事，由代码定义 |
| 角色 | role | 一组权限，是后台数据 |
| 范围 | scope | 配置和授权所在的层级：平台、站点、账户、工作区；配置还可以细到单个 API key |
| 节点 | node | 运行 Axiom 的一台机器 |
| 节点角色 | node_role | 节点承担的职责，一个节点可兼任多个，见[总体架构的「部署拓扑」](architecture.md#部署拓扑) |
| 入口 | ingress | 节点角色之一 |
| 核心 | core | 节点角色之一 |
| 出口 | egress | 向上游发请求的位置：承担出口职责的节点，或外部代理 |

## 命名约定

- `provider` 只用作兼容 OpenRouter 的对外 API 字段，内部一律用 `supplier`。用户在 `provider` 里填的是官方 API 的名称或中转站分组的代号。
- 分组的代码名用 `supplier_group`，不单用 `group`：它是数据库保留字，而 new-api 里的 group 指用户等级，容易混淆。
- "账号"只指我们在上游（官方 API、中转站、号池）的账号，"账户"只指我们这边的账户。

## 决策与理由

| 决策 | 理由 |
|---|---|
| 余额和 API key 属于账户，用户通过成员关系使用 | 以后做企业团队只需给账户加成员，不用搬余额和 key。OpenRouter 也区分个人账户和组织，额度和 key 属于组织（OpenRouter 文档《Organization Management》，2026-10） |
| 主站也是站点 | 主站和二级站点共用一套代码，不为主站写特例 |
| 站点只有两层 | 负责人决定。层级越多，价格和对账越乱 |
| 用户和账户按站点隔离 | 负责人决定用户隔离。开发者的分析：贴牌站点的用户不应感知上级平台；账户随用户一起隔离，才不会出现跨站点的成员 |
| 二级站点的批发价就是站长账户等级对应的售价 | 复用等级机制，不另设批发概念 |
| 供应商带归属方；站点自带货源由平台开关控制，默认关闭 | 负责人要求三种归属都支持、站点自带货源做成开关，并预计自己只开放转售。一个字段统一了平台货源、站点货源和用户自带 key，以后不用打补丁 |
| 分组是独立的进货线路 | new-api 的分组同时隔离渠道访问和计费倍率（new-api 文档《分组管理》，2026-10）；sub2api 的分组是账号池，API key 绑定分组并按分组倍率计费（知乎《Sub2API 部署与账号导入教程》，2026-04；GitHub DeanZFC/sub2api-custom 说明，2026-10 查证） |
| 路由只选端点，凭证由供应商模块选 | 号池轮换、多 key 调度怎么变，都不影响路由 |
| 账本只追加，余额由账本合计 | 对账和审计有唯一依据 |
