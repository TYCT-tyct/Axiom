# 总体架构

模块化单体：一个代码库、一个程序，内部按模块分界、按节点角色启动；边界允许以后按需拆部署。概念见[术语表](glossary.md)，需求以[产品](product.md)为准，CI 运维见 [CI](ops/ci.md)。

## 整体形态

Go 承载调用与管理功能，TypeScript 承载页面，SQL 定义持久化访问；OpenAPI 和 sqlc 生成类型连接三者，避免核心语义重复实现。

## 部署拓扑

| 角色 | 当前职责与监听 |
|---|---|
| `core` | 鉴权、路由、计费、存储；公网、管理、探针监听，按配置开启节点和运营监听 |
| `ingress` | 公网反向代理到核心与探针；公网 TLS 由负载均衡或 Caddy 终止 |
| `ops` | 探针；设 `AXIOM_MCP_ADDR` 后在回环地址提供 MCP 桥，以 `ops` 节点证书和运营凭证访问核心 |
| 出口 | 向上游发请求的职责，不是第四种节点角色；也可用外部代理 |

`AXIOM_NODE_ROLES` 默认 `core`，可组合但 `core` 与 `ingress` 互斥，保证入口不访问数据库和主密钥。角色来自配置；后台节点数据、一次性注册、内部证书机构与自动轮换尚未实现。单机从核心起步；核心位置是部署选择，第一版不在中国大陆放节点，避免备案和上游地区限制。运维节点上线时应在另一云服务商，核心心跳和外部监测共同监控它。

- 入口使用 `httputil.ReverseProxy` 与启用 `ForceAttemptHTTP2` 的 Transport，流式逐块下发，客户端断开即取消核心请求。等待响应头最多 15 分钟，响应体空闲最多 5 分钟，请求总计最多 65 分钟（核心调用最多 60 分钟），每次客户端写入或刷新最多 10 秒，请求结束清写期限。多条长连接、HTTP/3 和入口自行终止公网 TLS 尚未实现。
- 入口经 `AXIOM_CORE_URL` 访问核心 `AXIOM_NODE_ADDR`，使用 TCP 上的双向 TLS，最低 TLS 1.3，验证客户端证书与用途；同一连接探 `/readyz`，核心不能路由则入口也未就绪。入口能看到明文，只部署在自控机器。
- 证书从 `AXIOM_NODE_TLS_DIR`（默认主密钥目录）读 `node.crt`、`node.key`、`ca.crt`；私钥仅属主可读写，目录不可被组或其他用户写。部署方签发、到期前替换并重启。
- 核心必须在 `AXIOM_TRUSTED_PROXIES` 登记入口地址才采信客户端地址和协议头。管理监听仅核心开启、默认回环，非回环且未设 `AXIOM_ADMIN_SOURCES` 拒绝启动；管理域名与两步验证另由守卫检查。
- 节点监听仅在配置地址后开启，提供公网路由和健康探针；运营监听 `AXIOM_OPERATIONS_ADDR` 默认关闭，只接受 `ops` 用途证书，按 `AXIOM_OPERATIONS_SOURCES` 的连接地址限来源。探针每节点都有、默认回环，只答健康检查和 `/metrics`。
- 数据库和缓存只在核心区域内网开放。路由同时选端点和出口，依据线路延迟和成功率；出口承担上游地区限制、优化线路、连接复用和固定 IP 的需求。

## 模块划分

模块与 `internal/<模块>` 对应；业务行为由[领域文档](README.md)负责，protocol 和 platform 由模块 README 负责。

| 模块 | 负责的边界 |
|---|---|
| gateway | 模型调用入口、鉴权编排、限流、转发、节点角色与传输 |
| protocol | 格式解析、同格式改写、跨格式转换、用量读取 |
| catalog | 模型、名字、规格、参考价来源与价目表结构 |
| suppliers | 供应商、分组、凭证、端点、适配器、同步、映射、成本计划与号池 |
| quality | 检测、指纹、线上观测、端点属性与线路测量 |
| billing | 定价、预留、结算、账本、额度批次、币种、汇率、对账 |
| routing | 预设、筛选排序、端点与出口选择、回退、会话粘性 |
| accounts | 站点、用户、账户、工作区、key、等级、登录、授权、配置链与准入事务 |
| payments | 收款渠道、订单、退款与到账入账 |
| observability | 调用记录、对话存储与清理、指标、告警、通知 |
| operations | 运营接口与 MCP、审批、资金上限、审计查询、agent、部署与节点管理 |
| websearch / fileparse | 搜索和文档解析后端适配器 |

`platform` 只放基础设施、生成的接口契约与共享值类型，不放业务规则。实体 ID 归所属模块；被下层引用的 ID、金额与单价放在所有使用者都能引用的 platform。`web` 是官网、用户控制台、管理后台三个应用。

## 模块边界规则

1. 模块只读写自己的表，其他模块经公开接口访问；跨模块只按 ID 引用，不建外键。
2. 跨模块后续动作使用与数据同事务保存、提交后发送的事件，处理方须幂等。定期比对仅限：只需最新状态、不需中间变化；状态带版本、处理方记已用版本；领域文档写周期和最长滞后。目前用于 billing 跟随官方价和 operations 跟随 agent 退款结局；通用事件设施尚未实现。
3. 调用路径不查库，只有五类例外：准入与转发中追加预留；回答结束前结算；key 缓存未命中；可选响应缓存；Responses 续接。响应缓存在准入后、首次尝试前查询，元数据与正文两次只读事务共用 2 秒期限，超时或失败视为未命中。Responses 按工作区和回复 ID 读一次，缺失不重试、不扫描。
4. 端点、属性、价格、预设、配置走内存快照；账户每 30 秒、目录与路由每 5 秒重建，本节点写入提交后立即重建。key 缓存仅存 `(站点, key 哈希)` 对应的不可变标识；停用、删除、过期、IP 白名单、预设、模型范围、花费上限、预算与等级在准入事务读库，停用不依赖缓存失效。accounts 传上限与预算，billing 在余额行锁下计数、占用与检查。
5. 只按下表引用；每行只能引用上面的行，`cmd/axiom` 可引用全部以完成组装。`tools/checkmodules` 检查全部 Go 文件，不受构建条件影响；新模块先登记。
6. 下层需要上层能力时由下层定义接口、上层实现、入口组装，或由调用方传数据。事件类型归发布方，订阅方在上层；下层对上层变化的反应由上层调用公开接口，同成败则同事务，否则由上层提交后的事件处理器调用。
7. 跨模块同成败由数据所有方提供接受 `pg.Tx` 的函数：billing 在 accounts 准入事务预留，suppliers 在 billing 结算和清理事务记尝试与丢失请求。各模块经 platform 发告警信号，由 observability 汇总去重发送，不反向引用。

### 模块之间的依赖

每个模块都可以引用第一行的 `platform`，表里不再重复。

| 模块 | 可以引用 | 为什么 |
|---|---|---|
| `platform` | — | 基础设施和共用值类型，不引用任何模块 |
| `websearch` | — | 多个搜索后端的适配器（自托管 SearXNG、付费 Firecrawl）及其配置；只依赖 `platform` 的出口、配置和密钥设施 |
| `fileparse` | — | 自托管的 Docling serve 文档解析适配器；只依赖 `platform` 的出口、配置和密钥设施 |
| `catalog` | — | 模型和价目表结构是最底层的业务概念 |
| `accounts` | — | 站点、账户、授权和配置链被所有面向租户的模块使用 |
| `protocol` | `catalog` | `Request` 用目录的计费项集合和服务等级集合表达请求可能用到什么，累计的用量按目录的计费项表达 |
| `suppliers` | `catalog`、`protocol`、`accounts` | 端点是分组 × 模型，成本计划用目录的价目表结构；调用面声明自己说哪种调用格式；供应商有归属方，并在配置链里声明配置项 |
| `quality` | `suppliers`、`catalog`、`protocol` | 检测经供应商的调用面发出；目录基线是属性的默认值；按官方格式构造请求、比对响应 |
| `billing` | `catalog`、`suppliers`、`quality`、`accounts` | 参考价取目录里模型选定来源的价格，成本取供应商的成本计划，定价对象包括来源类型，加价按等级，二级站点要同时预留站长账户 |
| `routing` | `catalog`、`protocol`、`suppliers`、`quality`、`billing`、`accounts` | 路由快照由模型、端点、属性、价格、预设和配置组成；按请求的调用格式过滤 |
| `observability` | `catalog`、`protocol`、`accounts` | 调用记录的用量按计费项保存、按租户查看；对话内容按消息去重，要懂调用格式 |
| `payments` | `billing`、`accounts`、`observability` | 到账在同一个事务里生成付费额度批次；收款渠道是站点配置；拒付申诉要整理该账户的调用记录 |
| `gateway` | `catalog`、`protocol`、`accounts`、`suppliers`、`quality`、`billing`、`routing`、`observability`、`websearch`、`fileparse` | 编排一次调用：认 key、解析、路由、预留、调上游、观测、结算、记录；`web` 插件经 `websearch` 搜索，`file-parser` 的 OCR 引擎经 `fileparse` 解析 |
| `operations` | `accounts`、`observability`、`gateway` | 授权、通知渠道、节点管理；审批经管理接口的中间层，不引用被审批的模块 |

## 一次调用怎么走

1. 入口接连接转核心；核心按登记域名认站点，只读请求头认 key，认出前不读请求体，缓存未命中才查库。
2. 解析请求能力与上下文，取限流计数和会话粘性；这是调用路径唯一一次共享缓存往返，未配置时用进程内实现。
3. accounts 打开准入事务，核对 key、读预设、模型范围与等级；按 key 预设、配置默认链、请求覆盖定规则。
4. routing 用内存快照选端点与出口、排回退顺序。候选全满则回滚，在事务外排队；醒来只重做准入，不再读缓存、不占数据库连接。
5. billing 预留首段费用，不足返回 402/403；提交准入事务后，suppliers 挑凭证并调用上游，protocol 透传或转换。
6. 开始输出前失败可换端点；输出后只在流中报错，HTTP 仍为 200。边收边转、分段追加预留，追加不到就截断。
7. 回答结束前结算成本与售价，追加账本、释放多余预留，费用写入最后事件；调用记录先写本机 WAL 再异步入库，对话正文按存储策略保存。

所有权、期限和故障矩阵见 [gateway](../internal/gateway/README.md#一次调用的步骤)。

## 协议转换

- 同格式按[改写清单](../internal/protocol/README.md#同格式改写)只改模型、路由、会话、用户标识等成员，其余字节透传，保留缓存标记与推理签名。
- 不同格式经统一中间格式转换，每种格式一对转换器，避免两两实现。
- 流空闲期限只由真实数据事件重置，心跳不算；累计所有事件的用量，中断或缺项时保留已报告项、只估缺项，按[暂估规则](domains/billing.md#用量来源与暂估)结算。
- 真实流录制为固定样本，每次改动回放比对；解析器做模糊测试。

## 技术选型

| 方面 | 当前选择与约束 | 理由 |
|---|---|---|
| 后端 / HTTP | Go 1.27、标准库 `net/http` | 调用与管理共享语义，流式控制直接 |
| JSON | 全部经 `platform/jsonx` 使用 `encoding/json/v2`、`jsontext`，拒绝非法 UTF-8、重复键，嵌套最多 256 层；depguard 禁止其他地方直接引用，豁免就地说明 | 解析口径统一，透传保留字节 |
| 数据库 | 只支持 PostgreSQL，pgx + sqlc，不用 ORM；动态列表查询集中参数化，禁止拼用户输入 | 事务与行锁保证账本，SQL 可审查 |
| 迁移 | goose，各模块独立序列、固定顺序执行、只向前；CI 禁改已合并迁移，运行时按已应用 SHA-256 核对 | 防止相同版本表示不同结构 |
| 缓存 | Valkey + valkey-go，只存限流、登录尝试、粘性、邮件冷却、辅助锁，不存余额与预留，不持久化；故障按用途有界兜底，主备切换未实现 | 正确性只依赖 PostgreSQL 行锁和幂等编号，详见 [kv](../internal/platform/kv/README.md) |
| 任务 / 邮件 | River 与业务同事务入队；SMTP 经 River 通知队列，固定版本、升级前读变更 | 不丢任务、不提前发、重启可继续 |
| 变更通知 | 当前轮询；LISTEN/NOTIFY 待实现：通知仅带 ID，独立直连连接，重连全量重建 | 通知在提交后送达，不经过事务池 |
| 对象存储 / 分析 | S3 接口，云桶或 SeaweedFS；调用记录用 PostgreSQL 分区，未来按量再选 ClickHouse | 正文与库分离，调用路径不读记录表 |
| 遥测 | OpenTelemetry + slog；Prometheus 经探针抓取，配置收集器后可用 OTLP/HTTP；稳定标签组合测量零分配 | 统一 API，基准守住稳态成本，标签与采样见 [platform](../internal/platform/README.md#遥测) |
| 配置 / 组装 | 环境变量转类型并启动校验，业务配置入库；入口手写构造函数 | 无隐式加载、依赖可见 |
| 契约 | OpenAPI 3.0.3，固定版本的 oapi-codegen、openapi-typescript、openapi-fetch | 先契约后生成，防止前后端漂移 |
| 前端 | React 19、严格 TypeScript、Vite、TanStack Router/Query、i18next；shadcn/ui 与 Tailwind 迁移至 CSS Modules 中，删除依赖待定 | 三应用共享设计系统和模型价格组件，详见[前端](frontend.md) |
| 前端交付 | 构建嵌入 Go；官网当前客户端渲染，公开模型页服务端写入数据待实现；`AXIOM_WEB_ASSETS_DIR` 补其他构建的哈希资源，入口页仍用本构建 | 单文件交付，普通用户拿不到管理应用，代价是改前端也须重启节点 |
| 测试 | `go test -race`、testcontainers 真实 PG/Valkey、协议回放、解析模糊测试、计费性质测试；Vitest + Playwright | 检查行为和不变量；数据库测试用 pgtest 新库，非输入的集群连接串经 `containertest.Untracked` 读取以保持有效缓存 |
| 工具 / 部署 | golangci-lint、deadcode、govulncheck、gitleaks、Biome；just 跨平台；静态二进制、非 root 最小容器、Compose | 保持工具链和起步部署简单；CI、缓存、runner 与容器细节见 [CI](ops/ci.md) |

具体小库按兼容性测试选择，记在模块 README；开发工具独立放在 `tools/go.mod`，版本及校验和不混进服务依赖。

## 工程原则

- 机制写在代码，取值放后台数据。
- **钱只在 PostgreSQL**：余额行锁下检查「余额 − 在途预留 ≥ 余额底线」再预留；金额用最小单位的 64 位整数并检查溢出，单价精确计算；数量入口限上下界，结算金额非负并断言；预留和结算带防重复编号，账本只追加。
- 配置错就拒绝启动。优雅退出先将 `/readyz` 置未就绪、新请求答 503，等入口摘流量再关监听；在途流和结算共用 `AXIOM_SHUTDOWN_TIMEOUT`，然后排空任务队列和调用记录。
- 参考 new-api（AGPLv3）、sub2api（LGPL-3.0）的代码按项目开源安排复用：可直接复用的协议、签名、错误映射、测试样本按 Axiom 类型改写，注释记来源仓库、路径、提交；绑定参考项目框架、金额或租户模型的实现重写，开源时整理许可证和版权声明。
- 日志、指标、链路随功能内置，不记录对话正文和密钥；跨模块安全规则见[安全](security.md)。

### AI 好写好维护

lint 限制文件与函数大小，编译器和依赖表限制模块引用。不同实体 ID 用不同类型；封闭接口表达多选一，由 gochecksumtype、exhaustive 检查穷尽；供应商凭证用类型化结构，不用字符串键值包。不用 ORM、依赖注入框架、反射配置。契约生成后由 CI 核对新旧；每模块 README 写不变量，测试与代码同放。

## 底线指标

上线目标需要至少两个核心节点和数据库热备；单机阶段不承诺可用性和恢复时间。

| 指标 | 目标 |
|---|---|
| 网关首字附加延迟 | p95 ≤30ms，不含网络和上游 |
| 月可用性 | ≥99.9%，停机约 ≤43 分钟 |
| 并发 | 单核心 ≥5000 路流式，可横向扩展 |
| 计费 | 每日自动对账，账本与余额零偏差，同请求不重复扣费 |
