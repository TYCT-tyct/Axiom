# platform

所有模块共用的基础设施，不放业务规则。总体规则见[总体架构](../../docs/architecture.md)。

## 包

| 包 | 做什么 |
|---|---|
| `config` | 把 `AXIOM_*` 环境变量读成带类型的值，收集全部问题后一次报告 |
| `secret` | 从受保护文件加载主密钥；供应商凭证的信封加密与明文脱敏 |
| `httpserver` | 所有监听共用的限制；公网监听的中间件；健康检查 |
| `consoleapi` | 由 `api/console.yaml` 生成的控制台接口类型和服务端接口，除包说明外不手写 |
| `pg` | 连接池、带租户范围的事务、迁移、启动时的数据库检查 |
| `pgtest` | 测试用的 PostgreSQL，按部署的方式准备好 |

配置项以 `cmd/axiom` 里的读取为准，不在文档里另列。

## 不变量

| 不变量 | 靠什么保证 |
|---|---|
| 配置有错就不启动，并指出是哪一项 | `config.Env.Err` 一次列出全部非法取值和未知变量；`serve` 在监听任何端口之前检查；地址被占用或不合法时启动失败 |
| 设了却没有被读取的 `AXIOM_*` 变量算错 | 同上 |
| 配置问题只报变量名和期望的格式，不报取值 | 密钥可能填错了变量或拼错了名字；监听失败只报原因，不报地址 |
| 密钥不出现在日志里 | 凭证明文用 `secret.Secret` 保存，格式化、slog、JSON 和文本序列化统一脱敏；只有显式 `Reveal()` 取出明文。主密钥加载错误只含变量名、行号和原因，不含文件内容或路径；调用方不得记录 `Reveal()` 的结果 |
| 空值等于未设定 | Docker Compose 把未设定的 `${VAR}` 传成空串，按未设定处理才不会把默认值意外覆盖成空 |
| 模块只能经带范围的事务访问数据库 | `pg.DB.Tx` 是唯一入口，先设范围再执行；`pg.Tx` 不暴露连接。目前只有 `QueryRow`，`Exec`、`Query` 随第一个用到它们的模块加入，届时查询结果也不能交出底层连接；depguard 禁止 `internal/platform` 之外引用 pgx 和 `database/sql` |
| 范围只在本事务内有效 | 用 `set_config(…, true)` 设定；测试在同一条连接上让事务分别提交、出错、panic，之后检查连接本身不带范围 |
| 没有范围就什么都查不到、写不进 | `platform.in_scope` 把未设定或空的参数当作空集合；测试覆盖读、插入、修改、删除。格式不合法时查询报错，不会放宽 |
| 范围是集合 | 平台 ∪ 站点集合 ∪ 账户集合；测试覆盖"整站 S1 加 S2 的账户 A3"不会扩大到 S2 的其他账户 |
| 应用的数据库角色受行级安全约束 | 表强制启用行级安全，所有者也受限；`serve` 启动时从登录身份本身（`session_user`，不是连接后切换成的角色）出发，检查它能成为或继承的全部角色：不是超级用户，没有 BYPASSRLS、CREATEROLE、CREATEDB，进不了 `axiom_owner`，也不在读写服务器文件、在服务器上执行程序的预定义角色里；迁移时已存在的 `axiom_owner` 不能是超级用户、带 BYPASSRLS 或能登录 |
| 数据库缺少本程序的迁移就不启动 | `serve` 启动时比较已执行的版本；数据库比程序新可以运行，因为迁移只做扩展 |
| 退出时停止接收新请求，在途请求在上限时间内完成 | 第一个 SIGINT 或 SIGTERM：就绪状态先改为否，随即关闭监听，在途请求最多等 `AXIOM_SHUTDOWN_TIMEOUT`；第二个信号立即退出 |

## 凭证加密

`secret.Load(path)` 在启动阶段加载主密钥：调用方用 `env.Required("AXIOM_MASTER_KEY_FILE")` 读出路径，`env.Err()` 为空后才调用 `Load`（否则变量未设定的错误会报两遍），加载失败同样不启动。当前包尚未接入 `cmd/axiom`。选择路径参数而不是另建环境变量读取器，复用 `config.Env` 的必填和未知变量检查。

文件为 UTF-8 文本，每行 `版本号:base64密钥`，允许 LF、CRLF 和末尾换行，不允许空行、注释、额外空白或 BOM（Windows PowerShell 5 的 `Out-File -Encoding utf8` 会写入 BOM，错误会落在第 1 行的版本号上）。版本号是无前导零的十进制正 uint32；密钥是带填充的标准 base64，解码后恰好 32 字节。至少一行，版本不得重复；数值最大的版本用于写入，读取按记录的 `KeyVersion` 选择，旧版本需保留至存量数据迁移完成。文件必须是普通文件；Unix 拒绝任何组或其他人权限（建议 0600 或 0400）。Windows 的 Go 文件模式不能表达 NTFS ACL，因此不检查权限位，由部署使用 ACL 限制到服务账户和负责人。

`secret.New(string)` 包装明文，零值表示空明文。`Keyring.Seal(Secret, aad)` 返回 `Sealed`，每次生成独立随机 AES-256 数据密钥，用 AES-GCM 加密数据，再用当前主密钥的 AES-GCM 包裹数据密钥。`Open(Sealed, aad)` 返回 `Secret`，失败不返回明文。空 AAD 会让密文在任何位置都能打开，属于调用方的错误，`Seal` 和 `Open` 遇到时 panic。`Seal` 唯一可能的失败是这个 panic，因此不返回错误。密钥环加载后只读，可并发使用；不支持热加载。

`Sealed` 包含 `Ciphertext`（含 16 字节认证标签）、`Nonce`（12 字节）、`WrappedDEK`（12 字节包裹 nonce + 32 字节加密数据密钥 + 16 字节标签）、`KeyVersion`（uint32）。两层 nonce 均由标准库随机生成。数据层认证调用方的原始 AAD；包裹层认证固定域标识 `axiom/secret/dek/v1`、一个零字节、4 字节大端版本号和原始 AAD，防止主密钥相同的不同版本被互换。版本不绑定到数据层，后续轮换只需重新包裹数据密钥。

调用方必须用无歧义编码构造表名、行 ID、用途的 AAD（如固定顺序的 JSON 字符串数组），读取时从预期的记录位置重新构造；不能直接信任随密文提供的 AAD。整条记录移到另一行、替换任何密文字段或改变 AAD 都必须认证失败。比起一把主密钥直接加密所有凭证，独立数据密钥允许轮换时保留数据密文；比起自行管理随机 nonce，采用标准库 `NewGCMWithRandomNonce` 避免调用方复用 nonce。每个主密钥版本最多包裹 2³² 个数据密钥，部署应在达到限制前轮换；包不持久化计数。主密钥轮换命令另做。

`Secret` 的所有输出方法都使用值接收者，嵌入结构体或通过指针输出也脱敏。明文保存在闭包中：`fmt` 的错误动词诊断会绕过格式化方法并递归输出私有字段，普通私有字符串字段仍会泄露；闭包不会被展开。`%T`、`%p` 和非法格式（如 `Sprintf` 的 `%w`）由 `fmt` 自行处理，输出类型、地址或诊断信息；交给 `Format` 的所有动词均输出固定脱敏值。它防止意外输出，不保证进程内存擦除，也不能保护已通过 `Reveal()` 取出的普通字符串。闭包也让 `Secret` 有意不可比较：不能做 map 的键，包含它的结构体不能用 `==`，非零值的 `reflect.DeepEqual` 为 false；比较时用 `Reveal()`，go-cmp 需要 `cmp.Comparer`。

## 监听

| 监听 | 默认地址 | 提供什么 |
|---|---|---|
| 公网 `AXIOM_PUBLIC_ADDR` | `:8080` | 控制台接口（`/api/console/v1/…`）；以后加模型调用接口、控制台页面、支付回调 |
| 运维 `AXIOM_OPS_ADDR` | `127.0.0.1:8081` | 健康检查 |

公网的每个请求都经过 `httpserver.Public`：
- **请求 ID**：自己生成 UUIDv7，放在 `X-Request-ID` 响应头和请求的 context 里（`httpserver.RequestID`）；不采用客户端传来的，免得伪造或冲突。
- **访问日志**：每个请求一行，记方法、路由模式、状态、字节数、耗时和请求 ID；记路由模式而不是路径，路径里可能有 ID 或密钥。
- **请求体限时**：带请求体的请求要在 2 分钟内发完（`cmd/axiom` 的 `bodyTimeout`），否则声明了请求体却不发送的客户端能一直占住连接。请求体读完后 net/http 自己清掉这个期限，长时间的流式响应不受影响，有测试守着；不带请求体的请求不设。
- **panic**：还没发出响应时返回 500（带请求 ID）；响应已经开始时（写过内容，或只刷新过响应头）中断连接，让客户端看到响应不完整，而不是一个状态码错误却"完整"的响应。被中断的请求也记访问日志。
- 包装响应时实现 `FlushError` 和 `Unwrap`，流式处理器通过 `http.ResponseController` 刷新和设置期限，刷新也算响应已开始。
- 生成的接口代码的每条出错路径都在 `cmd/axiom` 里设定，不留默认值：请求本身不合法时返回 400，说明只涉及客户端自己发来的内容；处理器出错时记日志、只返回 500，不把内部错误原文发给客户端。

## 健康检查

运维监听 `AXIOM_OPS_ADDR` 默认只听本机，不对公网：

- `/livez`：进程在运行；
- `/readyz`：能接新工作时 200，启动完成前和开始退出后 503。退出时就绪先改为否，公网监听等在途请求完成期间，运维监听仍然应答（`/readyz` 返回 503），之后才关闭。
- 探针读请求头、读整个请求（含请求体）、写响应各限时 2 秒：探针从不流式响应，不限时的话，声明了请求体却不发送的客户端能一直占住连接。

## 数据库

### 角色

| 角色 | 登录 | 用途 |
|---|---|---|
| `axiom_owner` | 否 | 拥有全部 schema 和对象，只在迁移时进入；没有 BYPASSRLS |
| `axiom_app` | 是 | 运行时唯一的登录角色，`AXIOM_DATABASE_URL`；由部署创建并设密码，密码不经过本程序 |
| 迁移管理员 | 是 | `AXIOM_MIGRATE_DATABASE_URL`；需要 CREATEROLE 和数据库的 CREATE 权限，不需要超级用户。建好 `axiom_owner` 和 schema，再切成 `axiom_owner` 执行迁移 |

[安全](../../docs/security.md#租户隔离)角色表里的后台任务角色和 key 查询函数，随第一个用到它们的模块加入。

### 范围

- 设定在 `axiom.scope_platform`、`axiom.scope_sites`、`axiom.scope_accounts` 三个事务级参数里，由 `platform.in_scope(site_id, account_id)` 读取。
- 表强制启用行级安全（`FORCE`，所有者也受限），读写用同一条 `platform.in_scope` 检查。
- **待定（负责人确认）**：账户数据的表是否直接存 `site_id` 和 `account_id`。确认后由 #23 加入生成策略的模板；在那之前不写进迁移，因为合并后的迁移不能再改。

### 迁移

- 每个模块的迁移在自己目录的 `migrations/` 下，版本表是 `platform.goose_<模块>`；`platform` 先执行。
- 迁移以 `axiom_owner` 在持有 goose 会话锁的连接上执行，并发的执行互相等待；初始化角色的 advisory 锁、goose 的会话锁和迁移里的每把锁都最多等约 5 秒，不让另一次迁移或长事务把部署和应用的查询堵住。中断后重跑，从记录的版本继续。
- 数据库连不上时，错误只说明是哪个变量和哪类失败（SQLSTATE、网络原因），不带用户名、库名和主机：误填在这些位置的密钥不会进日志。
- 合并后不改：CI 对比基准提交，`migrations/` 下只能新增文件（`just migrations <base>`）。
- 删除旧结构的收缩迁移怎么与滚动发布共存，随第一个收缩迁移确定。

## 测试

`pgtest` 每个测试二进制起一个 PostgreSQL 容器，用非超级用户的迁移管理员执行全部迁移，做成模板；每个测试复制一个独立的库，可以并行。容器关闭 fsync 以求快。

## 决策与理由

| 决策 | 理由 | 不选 |
|---|---|---|
| 配置只来自环境变量 | 架构规定不用反射加载配置；容器和 Compose 原生支持；只有一个来源，不用判断优先级 | 配置文件加环境变量覆盖：两个来源，要定优先级 |
| 未知的 `AXIOM_*` 变量算错 | 拼错的名字会悄悄落回默认值，到运行时才发现 | 忽略未知变量 |
| 运行时只有一个登录角色，没有任何角色有 BYPASSRLS | 迁移和回填也受行级安全约束，需要时显式设定平台范围；"能看全部数据"是看得见、能审计的设定，不是某个角色的隐藏能力 | 迁移角色带 BYPASSRLS：多一个能绕过的身份 |
| 登录角色和密码由部署创建 | 密码不经过本程序。部署的初始化脚本用 `CREATE ROLE … PASSWORD` 设置它，语句里有明文密码，数据库开启 DDL 日志时会记下来，所以初始化时不开 | `axiom migrate` 按连接串设置密码：密码要经过程序 |
| 迁移管理员不必是超级用户，测试也这样跑 | 生产上缺的权限在测试里就暴露 | 测试用超级用户：权限问题到部署时才发现 |
| 测试用 testcontainers，一个测试二进制一个容器，每个测试一份模板副本 | 对着真实的 PostgreSQL 测；复制模板只要几十毫秒，测试互不影响 | 每个测试一个容器：慢；共用一个库：测试互相干扰 |
| 契约按接口面分文件：`api/console.yaml`（控制台，公网监听），以后的管理后台和运营接口各一份，在各自的监听上 | 一个前端应用只引用它那一份；管理接口只挂在单独的监听上（[总体架构](../../docs/architecture.md)「前端交付」），分文件后不会被意外挂到公网 | 一份大契约：前端类型和服务端接口混在一起，管理接口容易挂错监听 |
| 控制台靠 `GET /api/console/v1/version` 发现新版本 | 页面和程序一起发布，版本相同就是同一份；不缓存的接口比轮询入口页更直接 | 前端轮询 `index.html` 的哈希 |
| 不设整体写超时，只设读请求头超时和空闲超时 | 流式响应的时长取决于模型，由处理器设自己的期限；请求头超时挡住迟迟不发完请求头的连接，空闲超时关掉客户端丢下的长连接 | 统一的写超时：会切断长流 |
