# nodetls

节点之间调用的双向 TLS：核心用 `Server` 接受入口，入口用 `Client` 连核心。两个函数都从同一个目录读证书，返回可以直接交给 `net/http` 的 `*tls.Config`。

## 文件

| 文件 | 用途 |
|---|---|
| `node.crt` | 本节点的证书，PEM |
| `node.key` | 本节点的私钥，PEM；权限必须是 `0600`（非 Windows 上组成员和其他人不能读写） |
| `ca.crt` | 签发节点证书的内部证书机构，PEM；可以有多张，作为信任根 |

目录由 `AXIOM_NODE_TLS_DIR` 给出；核心不设时默认与主密钥文件同一目录。错误只说变量名和文件角色，不打印路径。

## 检查

- 目录必须有，并且不能对组或其他用户可写（`0o022`）；三个文件都要能读，`node.key` 的权限不合格就拒绝启动。能写目录的人可以换掉节点出示的私钥，即使私钥文件本身是 `0600`。
- `node.crt` 和 `node.key` 必须配对；证书要能解析、现在有效，并且带对应用途的扩展密钥用法：`Server` 要 `serverAuth`，`Client` 要 `clientAuth`。没有扩展密钥用法的证书可以用作任一用途，这是 X.509 的含义。
- `ca.crt` 至少要有一张证书，否则没有信任根；`node.crt` 必须由它签发（可以带中间证书），否则节点启动后每个对端都会拒绝它，启动时就报出来。
- 最低 TLS 1.3；`Server` 要求并校验客户端证书，`Client` 用 `ca.crt` 校验服务端并核对 `AXIOM_CORE_URL` 的主机名。

## 部署

核心设 `AXIOM_NODE_ADDR` 开节点监听；入口设 `AXIOM_CORE_URL`（`https`，不带路径、查询和用户信息）和证书目录。证书由部署的内部证书机构签发：一次性令牌注册、签发和轮换尚未实现，到期前替换文件并重启。节点只保存自己的私钥，核心和入口不共享私钥。

## 决策与理由

| 决策 | 理由 | 不选 |
|---|---|---|
| 证书和主密钥分开成 PEM 文件，放同一个受保护目录 | 主密钥是 32 字节，证书和私钥是 PEM，生命周期也不同；同目录让权限和备份只有一处 | 把证书编码进密钥环：改密钥环的格式和轮换流程；放到任意路径：多一个要配的变量 |
| 最低 TLS 1.3，按用途校验证书 | 节点之间没有旧客户端要兼容；用途检查能在启动时发现把客户端证书配给服务端这类错误 | 允许 TLS 1.2：多一套旧密码套件要审；只看 CA 不看用途：证书互换后仍能握手 |
| 私钥和目录权限在加载时检查，错误只报变量和文件角色 | 权限错是部署错误，越早失败越好；路径可能带主机名或租户信息，不进日志和错误 | 只靠部署的 `chmod`：漏一次就长期带着可读私钥运行 |
